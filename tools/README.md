# tools/ — 元DB を取得・検索・集計する道具

**何をするものか。** jvdata-store が貯めた DuckDB（元DB）から、レース・馬・出走・事象（人気馬が負けた／穴馬が勝った）・成績を取り出す道具の集まり。コマンド（CLI）と検索画面（ブラウザ）の両方から、同じ条件で同じ結果が得られる。

**誰が使うか。** 利用者と Claude。Claude は DB の中身や列名を調べて SQL を組み立てる前に、まず「早見表」の道具で済ませる。

**使わないこと。** 取得・取り込み（jvdata-store の責務）。予想の理論づくり（`research/`）。元DB は読むだけ。

## 言葉

| 言葉 | 意味 | どこにある |
|---|---|---|
| 元DB | jvdata-store が作った DuckDB。1レコード種別 = 1表（`ra` `se` `hr` …）。列名は JV-Data 仕様書の日本語のまま、値は全部文字列 | `../jvdata-store/jvdata.duckdb` |
| rid | レースの鍵6列（開催年・開催月日・競馬場コード・開催回・開催日目・レース番号）を連結した16桁 | 例 `2026090606040211` |
| hid | 馬の鍵 = 血統登録番号（10桁） | 例 `2021100001` |
| 事実表 | 1行 = 1頭の出走。レース・馬・市場・結果・払戻・前走を型付きの列に並べた一時表。検索・集計・事象の土台 | `tools/共通/facts.py`（列の一覧は `出走検索/runners.py --columns`） |
| 成績7つ | 着別度数（`1着-2着-3着-着外`）・勝率・連対率・複勝率・馬券外率・単勝回収率・複勝回収率 | `tools/共通/perf.py` |
| 絞り込み | 競馬場・芝ダ・コース・距離・馬場・クラス・人気・オッズ・枠・性別・馬齢・頭数・騎手・調教師・期間・月。CLI のフラグ名 = 画面の URL パラメータ名 | `tools/共通/filters.py` |
| 出馬表 | これから走る1レースの出走馬の表。レース前に分かる材料（斤量・騎手・近走 …）だけを並べ、結果は載せない。木曜に出る「出走馬名表」は枠番・馬番が未定、金・土に出る「出馬表」で決まる（`ra`・`se` のデータ区分 1・2） | `tools/共通/card.py`（例: 2026-09-19 中山 11R = rid `2026091906040511`） |
| 事象 | 「人気馬が負けた」「穴馬が勝った」のように、条件に当てはまる出走 | `tools/共通/events.py` |
| 傾向スコア | 当日のレースと条件が同じ過去レースの傾向から、出走馬を項目ごとに +1 / −1 で採点して付けた順位。項目は 164 個（プラス 89・マイナス 75） | `tools/共通/trend.py`、項目の一覧は `tools/傾向スコア/score-items.md` |
| 能力指数 | 出走馬ごとの、過去の走破タイムから作った基礎能力の数字。近8走（2年以内）のスピード指数を、新しい走ほど・今回の条件（距離・競馬場・芝ダと馬場）に近い走ほど重く見た平均。初めての芝ダは、父と母の父の産駒の成績で補う。着順・人気・オッズは使わない | `tools/共通/ability/`、作り方を比べて決めた経緯は `research/能力指数の作り方/` |
| スピード指数 | 1回の走の速さ。走破タイムを、コースの基準タイム・その日の馬場差・斤量・ペース（展開の得・損）で補正した点数。80 が1勝クラスの古馬のふつうの走、10点 = 1%速い | `tools/共通/ability/speed_figure.py` |
| 母集団の段 | 傾向を出す過去レースの広さ。狭い順に 同レース → 4つ一致（競馬場・コース・距離・馬場状態）→ 3つ以上一致 → 2つ以上一致。開催日より前・同じ芝ダだけ | `tools/共通/trend.py` の `LEVELS` |
| 推定脚質 | 今回より前の直近3走の脚質の中央。脚質はレース後にしか分からないので、レース前の材料としてはこれを使う（事実表の `style_before`） | `tools/共通/facts.py` |
| 切り口 | 成績を分ける軸（単勝人気・オッズ帯・騎手・コース単位 …） | `成績集計/perf.py --list` |
| 決着の型 | 1レースの 1〜3着を人気・オッズで見た形（上位人気2頭+穴馬1頭、人気の和、1・2番人気の共倒れ …）。出走（1頭）ではなくレース（1つ）を数える | `決着の型/outcome.py --list` |
| 特別競走番号 | 特別競走（重賞を含む）に付く4桁の番号。競走名が年によって変わっても番号は変わらないので、「同じレースの過去の開催」を集める鍵にする | `ra` の列。重賞の同定は `tools/共通/stakes.py` |
| 合成DB | テスト用の小さな DuckDB。値は架空。実DB が無くても道具を試せる | `tools/合成DB/synth.py` |
| 共通 | ツール同士で使い回す部品。入口を持たない | `tools/共通/` |

## 実行の準備

1. `uv sync`（初回だけ。`.venv` と依存を作る）。
2. `uv` が PATH に無ければ `%LOCALAPPDATA%\Microsoft\WinGet\Packages\astral-sh.uv_Microsoft.Winget.Source_8wekyb3d8bbwe\uv.exe` を使う。
3. `uv` が無くても、`.venv\Scripts\python.exe tools\成績集計\perf.py --check` のように `.venv` の Python で直接動く。
4. 元DB の場所は既定で `../jvdata-store/jvdata.duckdb`。違う場所なら `--db PATH` か環境変数 `YOSOU_DB`。
5. 出力を保存するときは `reports/`（Git 対象外）に置く（例: `--out reports/tmp/x.csv`）。

## ツール（フォルダごと）

| フォルダ / ファイル | 用途 | 固有の引数 |
|---|---|---|
| `DBの状態/db_info.py` | DB の大きさ・表の数・中央の確定成績の期間と件数・年ごとのレース数・dm/tm/ck の開始日・同期の記録 | `--tables`（全表の行数と期間）、`--time-facts`（事実表の行数と作成秒） |
| `テーブル閲覧/table.py` | 表を1つずつ見る。列は 60 ずつ、行は `--limit`（既定 50） | `--list` `--describe` `--columns a,b` `--where 列=値`（複数可） `--offset` `--column-offset` `--from` `--to` |
| `任意SQL/sql.py` | 読むだけの SQL を1文実行（SELECT / WITH / FROM / DESCRIBE / SHOW / SUMMARIZE / EXPLAIN / PRAGMA） | 位置引数 SQL、`--file`、標準入力、`--timeout`（既定 60 秒） |
| `今週の出馬表/card.py` | 引数なしで今日以降のレースの一覧（確定前も出る）。1レースを指定すると出馬表（枠・馬番・斤量・騎手・所属・ブリンカー・馬体重・直前のマイニング順位・前走からの日数・近走着順・通算）と各馬の近走。近走は開催日より前の中央の確定成績だけ | 位置引数 rid、`--date`、`--from` `--to`、`--venue`、`--race`、`--runs`（既定 5、0 で近走なし）、`--all`（一覧の全レースの出馬表） |
| `レース一覧/races.py` | 条件に合うレース（1行 = 1レース、新しい順）。馬の条件を付けると「その馬が出たレース」 | 共通の絞り込み、`--offset` |
| `レース詳細/race.py` | 見出し・出走表と結果・ラップ・通過順・払戻。確定前の出馬表でも見られる | 位置引数 rid、または `--date --venue --race` |
| `馬の過去走/horse.py` | 馬名か hid → プロフィールと中央の過去走（新しい順）。候補が複数なら候補の表 | `--before YYYY-MM-DD`（その日より前だけ） |
| `出走検索/runners.py` | 条件を組み合わせて出走（1行 = 1頭）を検索 | 共通の絞り込み、`--sort date/odds/finish/pop`、`--offset`、`--columns`（事実表の列一覧） |
| `人気馬が負けたレース/lost_favorites.py` | 対象 = `--pop`（既定 1）と `--odds`、事象 = `--finish`（既定 `4-` = 馬券外。競走中止・失格を含む）。この3つは絞り込みではなく規則 | 共通の絞り込み、`--offset` |

## 共通の引数と絞り込み

すべてのツールに `--db PATH`、`--format markdown|csv|json`（既定 markdown）、`--out PATH`（省略で標準出力）がある。一覧を出すツールには `--limit N` もある。

絞り込みは次の項目。**省略した条件は効かない。** 範囲は `1600`（その値）、`1400-1800`（両端を含む）、`1400-`（以上）、`-1800`（以下）と書く。

| フラグ | 形 | 例 |
|---|---|---|
| `--venue` | 競馬場の名前かコード | `東京` / `05` |
| `--surface` | 芝 / ダート / 障害 | `芝` |
| `--course` | コースの名前かトラックコード | `芝・左` / `芝・右外` / `18` |
| `--distance` | 距離（m）の範囲 | `1600` / `1400-1800` |
| `--condition` | 良 / 稍重 / 重 / 不良 | `良` |
| `--class` | クラス名 | `未勝利` / `3勝クラス` / `G1` |
| `--pop` | 単勝人気（確定）の範囲 | `1` / `1-3` |
| `--odds` | 単勝オッズ（確定、倍）の範囲 | `-1.9` / `1.5-2.9` / `20-` |
| `--frame` | 枠番の範囲 | `1-2` |
| `--finish` | 確定着順の範囲（着順の付かない競走中止・失格は含まない） | `1` / `1-3` / `4-` |
| `--sex` | 牡 / 牝 / セン | `牝` |
| `--age` | 馬齢の範囲 | `3` / `5-` |
| `--field` | 出走頭数の範囲 | `-8` / `16-18` |
| `--jockey` `--trainer` | 略称の部分一致 | `<騎手の略称の一部>` |
| `--from` `--to` | 開催日（含む） | `2025-01-01` / `20250101` |
| `--month` | 開催月の範囲 | `6-8` |

対象は中央競馬の確定成績。出走取消・発走除外・競走除外は出走に数えない。競走中止・失格は「出走して馬券外」。馬場状態はダートのコースならダートの、芝と障害なら芝の馬場状態。

## 答え合わせとテスト

新しい集計や列を足したら、次の2つを通してから先へ進む。

```powershell
uv run python tools/成績集計/perf.py --check   # reports/成績集計 の東京 芝・左 1600m 良 の1番人気と、成績7つが一致すること
uv run python -m pytest -q                      # 合成DB のテスト（実DB には触らない）
```

`--check` はページを作った時点の DB の期間（`--from` の既定は `成績集計/check.py` の `CHECK_DATE_FROM`、`--to` の既定は `CHECK_DATE_TO`）で比べる。DB に古い年を足しても、この期間の外は数えない。ページは `成績集計/build_pages.py` が、perf とは別の道筋（元DB を直接読んで pandas で数える）で作る。作り直したら、この2つを合わせる。一致しないときは、確定成績の範囲（`共通/keys.py` の `FINAL_STAGES`）、異常区分 4・5 の数え方、払戻の結合の順に疑う。

## 落とし穴（元DB の約束）

- 列名は日本語で、`"開催回[第N回]"` のように角括弧を含む。SQL では必ず二重引用符で包む。
- 値は全部文字列。単勝オッズは 10 倍の4桁（`'0054'` = 5.4倍、`'0000'` は無し）。人気・着順は2桁ゼロ埋め（`'00'` は無し）。払戻金は9桁の円。
- `データ区分` で必ず絞る。同じ表に出馬表（1・2）、速報（5・6）、確定（7）、地方（A）、海外（B）が同居する。
- `競馬場コード between '01' and '10'` で中央に絞る。地方・海外が3割以上混ざっている。
- 馬場状態は `芝馬場状態コード` と `ダート馬場状態コード` に分かれ、片方しか埋まらない。
- 天候・馬場状態は `ra` から取る（`WE`・`WH` の表は無い）。
- 収録順序は当てにならない。必ず `ORDER BY` を書く（道具はすべて書いている）。
- 今週の出馬表は、木曜の夕方（出走馬名表）と金・土（出馬表）のあとに jvdata-store で取得すると入る。それまでは一覧が空。単勝オッズ・人気・直前のマイニング予想は、今の DB には確定後のものしか入っていないので、確定前のレースでは空（入れば出る）。
- 結果・払戻・確定オッズ・`dm`・`tm`・`ck`・坂路調教（`hc`）は 2011 年 1 月から、ウッドチップ調教（`wc`）は 2021 年 7 月 27 日から（2026-09-30 時点。それより前の行はごくわずか）。今の期間は `DBの状態/db_info.py` で確かめる。前走は、DB の最初の数か月で欠ける。
- 馬名・騎手名・オッズ・払戻など JV-Data 由来の実値を、docs・README・コミット・PR・報告に書かない。出力は標準出力か `reports/` へ。
- 傾向スコアで、確定前のレースの人気・馬場状態・馬体重は DB に無いので手で入れる。入れなければ、それを使う項目は 0 点で、馬場状態を問わない段（3つ以上一致から）で採点する。枠番・馬番は金・土の出馬表を取得すると入る。
- 同レース（同じ競走名）の過去は、DB にある年の数まで（2011 年からなら最大 15 回あまり）。平場には同レースが無い。特別戦は年によって競馬場や距離が違うことがあるので、画面の「同レースの過去」の表で確かめる。

## 部品を足すとき

- 絞り込みの項目: `共通/filters.py` の `FILTER_FIELDS` と `Filters` に1つ足す。CLI のフラグと画面のフォームは自動で増える。
- 切り口: `共通/perf.py` の `DIMENSIONS` に1つ足す。回収率探索の既定に入れるなら `共通/explore.py` の `DEFAULT_DIMENSIONS` にも足す。
- 前走・累積（逃げ経験・同コース勝利・持ち時計 …）の列は、事実表の `enriched` で「今回より前」の窓（`ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING`）から作る。当日の結果を混ぜない。
- 事実表の列: `共通/facts.py` の SQL と `FACT_COLUMNS` に足す。テスト `共通/tests/test_facts.py` が列の一覧を固定している。列の多い行のまま窓（`OVER`）を増やすと作成が遅くなるので、新しい累積は細い CTE（`narrow` → `experience`）に足す。確定前のレースの馬には `build_entry_facts` が同じ SQL を当てるので、足した列はそのまま当日の馬にも付く。
- 傾向スコアの項目: `共通/trend_items.py` の `FACTORS` に1行足す（切り口は1列のものだけ。レース後に分かる切り口は登録できない）。`傾向スコア/score-items.md` の表にも同じ ID を足す（テストが一致を見ている）。切り口に当日の材料が要るなら、`perf.Dimension` の `needs` に書く。
- 新しいツール: `tools/<日本語のツール名>/<英語のファイル名>.py`。先頭で `tools/` を `sys.path` に足し、`from 共通 import cli, db` で部品を使う。docstring の1段落目に用途と実行例を書き、この README の早見表と表に1行足す。
- テストは対象の隣の `tests/` に。合成DB（`合成DB/synth.py`）だけを使い、実DB に触らない。ファイル名は `tools/` 全体で重複させない。
