# 傾向スコアの点数化項目

状態: 実装済み（線引きは最初の値）　／　更新日: 2026-09-18

使い方:

```powershell
uv run python tools/傾向スコア/trend_score.py --date 2026-09-19 --venue 中山 --race 11 --condition 良 --pops "3:1,7:2" --html --open
uv run python tools/傾向スコア/trend_score.py --items          # この一覧を道具から出す
uv run python tools/傾向スコア/backtest.py --from 2026-08-01    # 点数の高い馬が来ているかを、終わったレースで確かめる
```

検索画面（`tools/検索画面/run.bat`）の「傾向スコア」タブでも同じことができる。項目の登録簿は `tools/共通/trend_items.py`、採点は `tools/共通/trend.py`。

## これは何か

当日のレースと条件が同じ過去レースから傾向を出し、出走馬を項目ごとに **+1 / −1** で採点して順位を付ける。
この文書は、その採点に使う項目の一覧である。

- プラス要素は 89 個、マイナス要素は 75 個ある。
- 「外枠」のような単独の項目と、「外枠×差し」のような掛け合わせの項目の両方を入れた。
- どの値が良いか・悪いかは、**人が決めない。コースごとの過去の成績が決める。** 表の「例」は見本であり、実際の傾向ではない。
- この文書には数字（勝率など）を書かない。数字は道具の出力（画面と `reports/trend-score/`）に出す。

## 採点のしかた

採点は次の5つの手順で行う。

1. **母集団を決める。** 狭い順に「同レース → 4つ一致 → 3つ以上一致 → 2つ以上一致」の4段を用意する。
2. **項目ごとに、母集団の成績を切り口の値ごとに出す。** 例: 枠帯×前後なら「内×前」「内×後」…「外×後」の6行。
3. **当日の馬が当たる値の行を見る。** その行の出走数が 20 以上ある、いちばん狭い段を使う。どの段でも 20 に届かなければ 0 点にする。
4. **良い・悪いを判定する。** 線引きは下の表のとおり。
5. **全項目の点を足して、高い順に並べる。**

| 判定 | 条件 | 点 |
|---|---|---|
| 良い（頭向き） | 勝率が基準値の 1.3 倍以上 | +1 |
| 良い（相手向き） | 勝率は 1.3 倍に届かないが、連対率か複勝率が基準値の 1.3 倍以上 | +1 |
| 悪い | 複勝率が基準値の 0.7 倍以下 | −1 |
| どちらでもない | 上のどれにも当たらない。または出走数が足りない | 0 |

- **偶然では起きにくい差だけを採る。** 上の倍率に加えて、基準値との隔たりが「出走数に見合うばらつき」の 1.64 倍以上あることを求める（偶然なら 20 回に 1 回しか起きない隔たり）。例: 基準の勝率 7% のとき、20 走で 2 勝（10%）は 1.3 倍を超えるが、偶然でもよく起きるので採らない。これを入れないと、出走数の少ない値に「良い」が付きすぎる。強さは `--min-z` で変えられる（0 で求めない）。

- 「頭向き」「相手向き」は、どちらも +1 である。ランキングには合計点のほかに、頭向きの数と相手向きの数を分けて出す。勝率は低いが連対・複勝で来る型を見分けるためである。
- 穴馬・人気馬が対象の項目は、基準値も穴馬だけ・人気馬だけの率にする。全馬と比べると、人気馬はいつも「良い」になってしまうためである。
- 出走数 20、1.3 倍・0.7 倍、強さ 1.64 は最初の値である。`tools/共通/trend.py` の定数（`MIN_RUNS` `GOOD_RATIO` `BAD_RATIO` `MIN_Z`）で、コマンドと画面からも変えられる。
- 「無条件」と書いた項目は、過去の成績を見ずに、当てはまれば加点・減点する。同レースは過去の開催が少なく（2016年からでも最大 10回あまり）、成績で判定するには出走数が足りないためである。

例（値は架空）: 母集団全体の複勝率が 21%。枠帯×前後の「外×後」は 40 走で複勝率 30%、勝率は並。30% は 21%×1.3 = 27.3% 以上なので「良い（相手向き）」。当日、外枠で推定脚質が差しの馬に P09 で +1 が付く。

出力の見本（値は架空）:

| 順位 | 馬番 | 馬名 | 合計 | プラス | マイナス | 頭向き | 相手向き | 当たった項目 |
|---|---|---|---|---|---|---|---|---|
| 1 | 7 | A馬 | +6 | 8 | 2 | 3 | 5 | P02 P09 P21 … M43 M48 |
| 2 | 3 | B馬 | +4 | 5 | 1 | 4 | 1 | P01 P07 P31 … M60 |

## 要る入力（表の「要る入力」の列）

空欄の項目は、木曜の出走馬名表の時点から採点できる。要る入力が無いとき、その項目は 0 点にして、出力の先頭に「未入力の材料」として出す。

| 記号 | 意味 | いつ分かるか |
|---|---|---|
| 枠 | 枠番・馬番 | 金・土に出馬表を jvdata-store で取得したあと |
| 馬場 | 当日の馬場状態 | 当日。手入力する。無ければ馬場状態を問わない母集団（3つ以上一致から）で採点する |
| 人気 | 当日の単勝人気 | 当日。手入力する |
| 体重 | 当日の馬体重と増減 | 当日の発表後。手入力する |

## いまは採点に使えない材料

次の材料は、発走前の DB に入らないので、当面は項目にしない。jvdata-store で速報を取得するようになったら足す。

- データマイニング予想の順位（タイム型・対戦型）と、人気との差
- 単勝オッズの帯（人気の手入力だけで足りるようにするため、オッズは使わない）
- 当日の天候

## 注意

- **過去のデータは、DB に入っている期間だけ。** 2026-09 時点は 2016年1月からで、同レースの過去は最大 10回あまり。DB の期間が短いと、同レースの段で判定が付く項目は少なく、点数は同条件の段で付くことが多い。同レースの傾向の表は参考として出す。
- **平場のレースには同レースが無い。** 同条件だけで採点する。
- **似た項目は同じ信号を重ねて数える。** 枠番・枠帯・馬番、前走の着順・着差・人気などである。内訳には項目のグループ（1〜9）ごとの小計も出す。グループごとに上限を付けるかは、過去のレースで確かめてから決める。
- **推定脚質は推定である。** 4分類をぴったり当てるのは難しい。掛け合わせの項目は、前・後の2分類を主に使う。
- **線引き（出走数 20、1.3 倍、0.7 倍、強さ 1.64）は最初の値である。** 変えたときは `tools/傾向スコア/backtest.py` で、終わったレースに同じ採点を当てて、点数の高い馬が本当に来ているかを確かめる。
- **点数は市場（人気）の代わりにはならない。** 終わったレースで確かめると、点数1位の馬は無作為に選ぶよりはっきり良く来るが、1番人気ほどは来ない。点数は「このコースの傾向に合う馬・合わない馬を一覧する道具」として使い、人気と見比べる。
