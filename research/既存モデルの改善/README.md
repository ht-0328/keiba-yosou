# 既存モデルの改善

既存の4つの予想（全頭の3着以内・穴馬の3着以内・人気馬の4着以下・レースの荒れ具合）を、計画
（`plans/既存モデルの修正計画.md`）に沿って直し、**直す前（現行）・直した後（変更版）・オッズだけの基準**を、同じ期間・同じ時点で比べる研究。
そのあと、直した予想を組み合わせた馬券の買い方を、過去のレースで確かめる。

- 予想そのものの直しは `src/yosou/`（予想のパッケージ）にある。この研究は、直した予想を**期間ごとに学習し直して比べる**道具と、**組み合わせた買い方の検証**を持つ。
- 数値（JV-Data 由来の成績・回収率）は Git 対象外の `reports/既存モデルの改善/` に出す。この README と `docs/` には数値を書かない。

## この文書で使う言葉の意味

この研究の文書とコードに出てくる言葉のうち、分かりにくいものの意味をまとめた。

| 言葉 | 意味 | この研究では（例） |
|---|---|---|
| 基準（オッズから作った基準の確率） | 単勝オッズだけから出した、目的変数が 1 になる確率。モデルはこれを出発点にして、近走や適性による上げ下げだけを学ぶ | オッズから見た3着以内率 0.40 の馬を、条件が合うので 0.48 と見積もる |
| オッズから見た3着以内率 | 単勝オッズの逆数をレース内で合計 1 にそろえた勝率から、Harville の式で出した3着以内に入る確率。レースで合計 3 | `src/yosou/shared/feature/odds/` |
| 区切り | 過去で学習して次の半年を予想する検証の1回分。学習・検証・テストの期間を持つ | 「2025年後半」= 学習は 2017年1月〜2024年12月、検証は 2025年1〜6月、テストは 2025年7〜12月 |
| 検証期間 | テスト期間の直前の半年。木を足すのを止める判断と、確率の調整・買う線・危険の線を決めるのに使う | |
| テスト期間 | 評価する半年。ここの結果は、どの線を決めるのにも使わない | 7つの区切りのテスト期間を合わせると 2023年1月〜2026年9月 |
| 作り方 | 比べるモデルの作り方（使う特徴量の列・基準を使うか・学習データを分けるか） | 現行・オッズだけ・変更版 |
| 区分 | 学習データを分けて別のモデルで学ぶときの、分け方の単位 | 穴馬の中穴・大穴、人気馬の 1番人気・2〜3番人気・4〜5番人気 |
| 危険度 | 人気馬の「4着以下になる確率 − オッズから見た4着以下の確率」。同じオッズの馬より、どれだけ負けやすいか | |
| 期待値 | 「当たる確率 × 見込みの払戻の倍率」。1 で元返し | 複勝的中の確率 0.25 × 見込みの倍率 4.6 = 1.15 |
| 見込みの倍率 | 複勝・ワイドで実際に受け取る払戻の倍率の見積もり（最低オッズ × 帯ごとの倍率） | |

## フォルダ構成

| 場所 | 中身 |
|---|---|
| `build_tables.py` | 入口①: 4つの予想の学習データを、予想のパッケージの `dataset_builder` で全期間（2017年〜）ぶん作って保存する |
| `walk_forward.py` | 入口②: 区切りごとに学習し、検証とテストの予測を残す（作り方ごと） |
| `upset_calc.py` | 入口③: 荒れ具合を、馬ごとの着順の確率と券種ごとの確定オッズから計算で出す |
| `compare.py` | 入口④: 現行・オッズだけ・変更版を比べる表を出す（`--only form_experiments` で、材料の実験を変更版と比べた採否の表） |
| `backtest.py` | 入口⑤: 直した予想から馬の期待値と役割を決め、券種で期待値を積んで買う買い方を、過去のレースで確かめる |
| `build_experiments.py` | 入口⑥: 材料を1つずつ足す実験の表を作る（能力指数・当日の馬場傾向 など） |
| `analysis/` | 部品（下の表） |
| `docs/` | 進め方（`01-進め方.md`）と結果の読み方（`02-結果の読み方.md`） |
| `tests/` | 部品のテスト（合成データだけ） |

`analysis/` の中:

| フォルダ | 仕事 |
|---|---|
| `tables/` | 学習データを作って保存・読み込み |
| `windows/` | 7つの区切り |
| `variants/` | 比べる作り方 |
| `walk_forward/` | 区切りごとに学習して予測を残す |
| `scores/` | 評価指標（ログ損失・人気別 AUC・回収率の推定幅 など） |
| `comparison/` | 予想ごとの比べ方の表 |
| `combined/` | 3つの予想を組み合わせて、レースの中の勝率を出す |
| `race_probability/` | 勝率から着順の並びの確率を出す（Stern の補正つき Harville の式） |
| `market/` | 券種ごとの確定オッズを、レースごとに引ける形にする |
| `upset/` | 荒れ具合を計算で出す |
| `horse_roles/` | 馬ごとの期待値と役割（消・軸・◎、人気か穴か） |
| `ticket_combos/` | 券種ごとの買い目の候補の作り方と、点数の上限・賭け金の決め方 |
| `betting/` | 買い方の検証（確率の補正・賭け金・券種で期待値を積む・勝負するレースを検証期間で決める） |
| `experiments/`・`repository/` | 材料を1つずつ足す実験（と、そのための元DB の読み出し） |

## 動かし方

リポジトリ直下で、上から順に実行する。元DB を開くのは ①・③・⑤・⑥ だけ。

```powershell
uv run python research/既存モデルの改善/build_tables.py                                   # ① 学習データ（数分）
uv run python research/既存モデルの改善/walk_forward.py --model form_aptitude_top3        # ② 全頭（40分ほど）
uv run python research/既存モデルの改善/walk_forward.py --model longshots_in_top3         # ② 穴馬
uv run python research/既存モデルの改善/walk_forward.py --model favorites_out_of_top3     # ② 人気馬
uv run python research/既存モデルの改善/walk_forward.py --model upset_level               # ② 荒れ具合（現行の作り方）
uv run python research/既存モデルの改善/upset_calc.py                                     # ③ 荒れ具合（計算）
uv run python research/既存モデルの改善/compare.py                                        # ④ 比べ方の表
uv run python research/既存モデルの改善/backtest.py                                       # ⑤ 組み合わせた買い方
uv run python research/既存モデルの改善/build_experiments.py                              # ⑥ 材料の実験の表
uv run python research/既存モデルの改善/walk_forward.py --model form_experiments          # ⑥ 材料の実験（2時間ほど）
uv run python research/既存モデルの改善/compare.py --only form_experiments                # ⑥ 材料の実験の採否の表
uv run python -m pytest -q research/既存モデルの改善                                       # 部品のテスト
```

出るもの（どれも `reports/既存モデルの改善/`）: `tables/`（学習データ）、`predictions/`（予測）、`compare/<予想>.md`（比べ方の表）、
`backtest/結果.md`（買い方の検証の表）と買い目の CSV。

## 注意

- **オッズは確定オッズで検証している。** 実際に買う時点では締め切り前のオッズしか分からないので、ここの成績は実運用より楽観側にぶれる。
  締め切り前の全券種オッズの保存は、計画の「別途」の項目（jvdata-store の取得）で、この研究の範囲の外。
- 確率の線・買い方・危険の線は、区切りごとに検証期間だけで決めている。テスト期間の結果を見て線を選び直してはいない。
