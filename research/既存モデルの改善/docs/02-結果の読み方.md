# 02 結果の読み方: どの表を見て、何が分かったか

`reports/既存モデルの改善/` に出る表の読み方と、そこから分かったことを書く。数値は `reports/` にあり、ここには書かない
（JV-Data 由来の数値を Git に載せないため）。ここでは、区切りの数え上げと言葉だけで書く。

## この文書で使う言葉の意味

この文書に出てくる言葉のうち、分かりにくいものの意味をまとめた（README の表にあるものは、そちらを見る）。

| 言葉 | 意味 | この研究では（例） |
|---|---|---|
| ログ損失 | 確率の誤差。当たった馬に低い確率、外れた馬に高い確率を付けるほど大きくなる。小さいほど良い | 3着以内に入った馬に 0.1 を付けると、0.6 を付けたときより大きく罰せられる |
| 人気別 AUC | 同じ単勝人気の馬どうしで、目的変数が 1 の馬に高い確率を付けられた割合。0.5 なら人気で説明できない部分を何も当てていない | 同じ3番人気の中で、3着以内に入る馬を見分けられているか |
| 回収率の 90% の幅 | 開催日を単位にしたブートストラップ（開催日を選び直して何度も計算する）で出した、回収率がばらつく範囲 | 幅が 100% をまたぐなら、「100% を超える」とも「超えない」とも言えない |
| 上げ下げ | 予想の確率のロジットから、基準（オッズから作った確率）のロジットを引いた値。予想が市場より高く見ているか低く見ているか | 正なら「市場の見立てより来る」と予想している |

## 3. 組み合わせた買い方で分かったこと

表は `backtest/結果.md`（今の買い方）。前の2つの買い方の結果は `backtest-全組み合わせから選ぶ版/` と `backtest-印のルール版/` にある。
買い方の作り方は `01-進め方.md` の 4。

- **今の買い方（危険な1番人気を消し、期待値の高い馬を買い、券種で期待値を積む）は、回収率が 100% を大きく下回った。**
  印のルールの買い方より悪く、全部の組み合わせから選ぶ買い方と同じくらいだった。
- **券種で期待値を積んだ結果、ほとんどのレースで1つの券種（単勝か馬単）だけを買った。** 馬連・ワイド・3連複・3連単は、
  どの区切りでも検証期間の回収率が 100% に届かず、買わなかった。
- **単勝の「期待値が高い馬」は、ほとんどが 5〜11番人気の穴馬だった。** 検証期間では回収率が 100% を超えていたが、
  テスト期間では大きく下回った。当たりが少ないので、検証期間の回収率が数回の当たりで決まっていた。
- **確率のずれは、補正でほぼ無くなった。** 補正後は、どの券種・どのオッズの帯でも「実際 ÷ 予想」が 1 に近い。
  それでも負けたのは、帯の平均では確率が合っていても、予想が「市場より来る」と見た馬が、実際には市場の見立てほどしか
  来ていないため。つまり、予想が市場より良く見分けられている部分が小さく、1頭ずつの期待値の差を信じて買うと負ける。
- **1番人気を消したレースは、消さなかったレースより大きく負けた。** 人気馬の予想の危険度で1番人気を消しても、
  その1番人気が負ける割合は、消して買った馬で儲けを出せるほどには高くなかった。
- **勝負するレースの数は、ほとんどの区切りで「全部」が選ばれ、絞れなかった。** 堅さの帯と1日3レースまでの上限を足して確かめた結果は 7。

## 4. 気をつけること

- **オッズは確定オッズで検証している。** 実際に買う時点では締め切り前のオッズしか分からないので、ここの成績は実運用より楽観側にぶれる。
- **2026-09-24 に、勝率の重みの学び方の不具合を直した。** 着順の無い馬（取消・除外など）の「1着か」が欠損のまま残り、重みの最適化が
  1歩も進まずに「市場の勝率そのまま」を返していた。直す前の `backtest/` の結果は、`backtest-重みが学べていなかった版/` に退避してある。
  直したあとは、3つの予想の上げ下げに重みが付き（「勝率の出し方」の表）、的中の数が大きく増えた。荒れ具合の計算も、直したあとで回した。
- 確率の線・買い方・危険の線は、区切りごとに検証期間だけで決めた。テスト期間の結果を見て選び直してはいない。

## 5. 材料の実験で分かったこと

表は `compare/form_experiments.md`。全頭の変更版（base）に、材料を1つずつ足した作り方と、条件で学習データを分けた作り方を、
base と比べた。採用の基準は、テスト期間のログ損失が base より小さい区切りが 7つのうち 5つ以上あり、全期間を合わせても小さいこと。
「base との差」の列は、差がごく小さいので 1000倍して出している。

| 作り方 | base より良かった区切り | 判断 |
|---|---|---|
| ＋ 券種ごとのオッズから見た支持 | 7つすべて。差もほかの作り方よりはっきり大きく、人気別 AUC も上がった | 採用の基準を満たす。ただし予想する時点で全券種の締め切り前のオッズが要り、まだ取れないので、src にはまだ移さない |
| ＋ 騎手・調教師・血統の市場に対する成績 | 6つ。ただし全期間の差はごく小さい（券種ごとのオッズの数十分の一） | 採用の基準は満たす。効き目がごく小さいので、src に移すかは利用者の確認待ち |
| ＋ 当日の馬場傾向 | 2つ | 採用しない |
| ＋ 能力指数（標準タイムと比べた速さ） | 3つ | 採用しない |
| ＋ 相手関係を考えた近走（市場に対する成績） | 3つ | 採用しない |
| 芝ダで分ける | 3つ | 採用しない |
| 競馬場（主場・ローカル）で分ける | 4つ | 採用しない |
| 距離帯で分ける | 1つ | 採用しない |
| 芝ダ×距離帯で分ける | 0 | 採用しない（細かく分けるほど悪くなった） |
| 頭数帯で分ける | 2つ | 採用しない |

  分けるとデータが減るぶん、かえって悪くなる。
- 馬の情報から作った材料（能力指数・相手関係・当日の馬場傾向）は、オッズから作った基準に上乗せできる情報がほとんど無かった。
  効き目がはっきりあったのは、ほかの券種のオッズ、つまり市場の別の見方だけだった。

## 6. 重賞の予想で分かったこと（2026-09-30）

表は `compare/stakes_tendency_top3.md`。確かめ方は `01-進め方.md` の 5（1年ずつの7つの区切り・2012年から学習・当日と木曜・前日）。

| 見たこと | 結果 |
|---|---|
| 既定がオッズだけより確率の誤差（ログ損失）が小さい区切り | 7つのうち 4つ。採用の基準（5つ以上）に届かなかった |
| 7つを合わせたログ損失 | 既定がオッズだけよりわずかに小さいが、差はごく小さい（小数第4位で同じ） |
| 重賞の傾向（まとまり K）を外したとき | 既定とほとんど変わらない。今の形の傾向は、オッズから作った基準に上乗せできる情報をほとんど持っていない |
| 各レースで確率がいちばん高い馬 | どの作り方も、1番人気を選んだときと 3着以内率・回収率がほぼ同じ |
| 複勝を期待値で買ったとき | 既定は、検証期間で買う線が決まったのが 7つのうち 1つだけで、判断できるほど買えなかった。オッズだけは 3つで線が決まり、合計の回収率は 100% に届かなかった |

時点を替えたとき（表の「重賞（木曜）」「重賞（前日）」）:

| 時点 | 比べた相手 | 結果 |
|---|---|---|
| 前日 | 前日のオッズだけのモデル | 当日とほぼ同じ。小さい区切りは 7つのうち 4つで、基準に届かない |
| 木曜 | 当日のオッズだけのモデル（締め切りの市場の見立て） | 7つすべてで誤差が大きい。人気馬の確率を低く、人気の無い馬の確率を高く見積もっている。複勝を期待値で買うと人気の無い馬ばかり買い、7つすべての区切りで回収率が 100% を下回った |

- 前日と当日は、どちらも確定オッズで検証している（締め切り前のオッズが DB に無いため）。前日の結果が当日とほぼ同じなのはそのためで、
  実際の前日のオッズで買うと、ここより悪くなる側にぶれる。
- 木曜も、重賞の傾向を外して結果がほとんど変わらないのは当日と同じ。木曜の本命（確率1位）は、1番人気より3着以内率が低い。

- **判断: 今の既定は、どの時点でも採用の基準を満たさない。時点によって判断は変わらない。** 重賞の予想は、オッズだけで学んだモデルより良いと言えるところまで来ていない。
  予想のコード自体は動くので残すが、買い方の判断材料にはオッズだけのモデルより上の扱いはできない。
- 複勝の線がほとんど決まらないのは、線を選ぶのに検証期間で 100点以上買えることを求めているため。重賞の1年では、期待値が 1 を超える馬が
  100頭に届かないことが多い。重賞で期待値の買い方を確かめるなら、線の選び方を重賞の数に合わせる（区切りをまたいで数える、点の下限を下げる）必要がある。
- 直すなら、傾向の特徴量の作り方（何を数えるか・縮め方）と、学習データの少なさ（2011年より前の重賞を足せるか）が先の課題。
  設計書 `docs/design/重賞の傾向と近走から3着以内を予想/15-decisions.md` の 8 に書いた。

## 7. 勝負するレースの選び方で分かったこと（2026-09-30）

表は `backtest-勝負レースの絞り込み/勝負するレースの選び方.md`。確かめ方は `01-進め方.md` の 6。
7つの区切りのうち 2024年後半と 2025年前半は、検証期間で回収率が 100% に届いた券種が無く、どの選び方でも1レースも買っていない。
比べたのは残りの 5つの区切り。

| 選び方 | 結果 |
|---|---|
| 今の買い方（上位 N、1番人気を消したレースを先に） | 比べる出発点。回収率は 100% を大きく下回った |
| 今の買い方を期待値の順に並べる | 合計の回収率は、比べた中でいちばん高かった。ただし 100% には届かない。勝負するレースは1日に十数レースと多い |
| 期待値の順＋堅さの帯 | 並べ方を替えただけのものより、少し悪くなった |
| 1日3レースまで（重賞は別枠） | 合計の回収率は今の買い方とほぼ同じ。買うレースと投資は半分ほどに減った |
| 1日3レースまで（重賞は別枠）＋堅さの帯 | 今の買い方より良い区切りは 3つあったが、合計の回収率は下がった |
| 1日3レースまで（重賞も枠に入れる）＋堅さの帯 | 重賞を別枠にしたときとほぼ同じ |

- **堅さの見分け自体は効いている。** 今の買い方で買ったレースを軸の3着以内の確率の帯で分けると、確率が高い（予想が迷わず1頭を選べている）
  レースほど回収率が高かった。研究「一番人気を疑う」の「◎が堅いレース」と同じ向きである。
- **ただし、帯を検証期間で選ばせると、テスト期間では良くならなかった。** 検証期間で選ばれる帯が、区切りごとに堅い側（0.8 以上）と
  迷う側（0.6 未満）の間で入れ替わった。検証期間の1年では、どの帯が良いかを安定して決められるほど当たりが無い。
- **1日3レースまでにしても、回収率は良くならなかった。** 期待値の高い順の上位3レースは、全部のレースより回収率が低かった。
  券種全体の期待値がいちばん高いレースほど、見積もりの誤差で高く出ただけのレースが多いと考えられ、上位ほど良いレースとは言えない。
  上限の良さは、負けているときに使うお金を半分ほどに抑えられることだけである。
- 重賞は、別枠でも枠に入れても、買った重賞の数は同じだった（期待値のある重賞は、1日3レースの枠の中でも先に入る）。
- **判断:**
  - 1日3レースまでの上限（利用者の決定、2026-09-30）は、この買い方に入れる（`backtest.py` の既定の選び方を `cap3` にした）。回収率は変わらず、
    使うお金が減るため。並べ方は、決めごと 3 のとおり期待値の順にする。
  - 重賞は上限の外（別枠）で扱う。期待値のある重賞は全部勝負する。利用者の「重賞はできれば勝負するレースに入れる」に合い、
    `docs/design/買うレースと買い目を決める/03-race-screening.md` の 3 とも同じ。枠に入れても成績は良くならなかった。
  - 堅さの帯は、勝負するレースを選ぶ条件には入れない。効き目の向きは見えたが、検証期間で帯を選ぶやり方ではテスト期間で良くならなかった。
    帯を固定して入れる（例: いつも 0.7 以上）なら、それを先に決めてから、新しい期間で確かめる必要がある（今のテスト期間の結果を見て決めると、テスト期間を使って選んだことになる）。
  - どの選び方でも回収率は 100% に届かない。勝負するレースの選び方では、この買い方の負けは直らない。直すべきは、3で書いた、予想が市場より
    見分けられている部分の小ささである。
- `backtest-勝負レースの絞り込み/結果.md` は、今の買い方（current）で出したもの。全頭の学習データの表が 2026-09-30 に作り直されていて、
  `backtest/結果.md`（2026-09-25）とは数が少し違う。選び方どうしの比べ方は、同じ1回の実行の中で比べているので影響しない。
