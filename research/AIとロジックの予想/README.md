# AIとロジックの予想

今の予想（AI だけの予想。全頭の予想のモデルが付けた印と、全レースの印の買い目）で負けたレースを負け方で分け、
AI が材料にしていないこと（展開・その日の馬場の偏り・3連単の売れ方・消の強さ・買い目の形）をロジックにして、
「AI＋ロジック予想」として AI だけの予想と並べて出せるかを確かめる。

結論: **展開のロジック（逃げ・先行の馬が頭数の 20% 以下で、◎ が差し・追込なら、全レースの印の買い目を見送る）** が、
作る期間・確かめる期間のどちらでも、回収率 100% 超え・回収率が上がる・的中率が上がるの3つを満たした。参考の2つの期間でも同じ向きに上がった。
続けて、**クラスのロジック（オープン以上のレース（オープン・L・G3・G2・G1）は、全レースの印の買い目を見送る）** を足した。4つの期間すべてで、展開のロジックだけのときより回収率と的中率が上がった。
さらに、**消のロジック（1着の予想が市場の見立て以上の馬は、消を取り消す）** を足した。残る消の勝率が4つの期間とも下がった。印と買い目は変えない（取り消した馬に印を付け直す形は、確かめる期間で回収率が下がった）。
発走前の通知（中央）で、AI だけの予想の投稿のあとに「AI＋ロジック予想」として別に投稿する（設計書「買うレースと買い目を決める」08 の 2・09 の 31）。

## 入口

数値は Git の対象外の `reports/AIとロジックの予想/`。DB を開くのは `logic_features.py` と `race_materials.py` だけで、元DB は読むだけ。
買い目の候補は研究「裏目を買うかの予想」の `candidates.py` が書いた `reports/裏目を買うかの予想/candidates_<start>_<end>.pkl` と、印の表 `marked.pkl` を使う。

| 入口 | 何をするか |
|---|---|
| `analysis/race_outcomes.py` | 今の本番の全レースの印の買い目を、本番と同じ配り方で1レースずつ再現し、印の付いた馬の着順を付ける（負け方を分ける） |
| `analysis/logic_features.py` | AI が材料にしていないこと（その日の馬場の偏り・推定脚質・逃げ先行の数）を1レースごとに作る |
| `analysis/race_table.py` | 1レースごとの、レースの前に分かる材料の表（AI の印の材料とロジックの材料）を期間ごとに書く |
| `analysis/logic_eval.py` | 期間（買い目の候補と材料）を読み、決まりを渡すと本番と同じ配り方で数える部品 |
| `analysis/logic_rules.py` | ロジックの決まりごとに、期間ごとの回収率・的中率・1日の儲けを出す |
| `analysis/race_materials.py` | 期間ごとのレースの表に、レースと ◎ の馬の材料（クラス・距離・前走・乗り替わりなど）を足す |
| `analysis/logic_scan.py` | 材料の値ごとに、探す3つの期間とも回収率・的中率が低い（高い）ものを洗い出す |
| `analysis/logic_candidates.py` | 展開のロジックの上に足す見送りの候補ごとに、期間ごとの成績を出す（`--verify` で確かめる期間） |
| `analysis/danger_cancel.py` | 消のロジックで残る消・取り消す消の成績を期間ごとに出す（`--flags` で道具「印の成績」に渡す消の表を書く） |
| `analysis/danger_tickets.py` | 消を取り消して印を付け直したときの買い目の成績を、今の消のときと期間ごとに比べる |

本番の部品は `tools/今週の予想/slow_pace_logic.py`（展開のロジック）・`open_class_logic.py`（クラスのロジック）・`danger_cancel_logic.py`（消のロジック）・`logic_forecast.py`（AI＋ロジック予想の1行）。
推定脚質は発走前の通知の `RaceStyles`（直近3走の脚質の中央。事実表の `style_before` と同じ決まり）。
