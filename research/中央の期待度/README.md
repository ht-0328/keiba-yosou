# 中央の期待度

**何をする研究か。** 中央の予想に添える「期待度」（レースに添える1つだけの目安。S・A・B・C）の式と線を、中央の未見の予測で決め直す。
目標は「S でも C でも ◎ の単勝回収率が 100% を超え、S のほうが的中率も回収率も高い」。結論は、◎ の単勝の期待値 0.90 未満を見送りにし、残りを重み 1.25 の点数で分けると、全等級で 100% を超え、的中率は S が一番になる（回収率の順は偶然のぶれに埋もれて約束できない）。

**なぜ始めたか。** 期待度を中央にも出すようにしたあと（設計書「買うレースと買い目を決める」の 09 の 22）、当日の予測で等級ごとの ◎ の成績を見ると、
的中率は等級の順に上がるが、単勝回収率は S が A・B より低かった。利用者から「S が一番単勝回収率と的中率がともに高いようにしてほしい」「S でも C でも 100% を超える予想を、条件を変えて見つかるまで探して」と言われた（2026-11-14）。

結論は [docs/01-重みと線の決め方.md](docs/01-重みと線の決め方.md)。本番の決まりは設計書「買うレースと買い目を決める」の [03 の 5](../../docs/design/買うレースと買い目を決める/03-race-screening.md#5-レースごとの目安期待度)。
数値（JV-Data 由来の成績・回収率）は Git 対象外の `reports/中央の期待度/` に出し、この README と docs には書かない。

## この文書で使う言葉の意味

| 言葉 | 意味 | この研究では（架空の例） |
|---|---|---|
| ◎ | 道具「印の成績」と同じ決め方で付けた本命。危険な人気馬を消にしてから、単勝 30倍以下の馬の中で単勝の期待値（1着になる確率 × 単勝オッズ）が1位の馬 | 1着の確率 0.28・単勝 4.0倍 の馬 |
| 点数 | ◎ の1着の確率 ＋ 重み ×（単勝の期待値 − 1）。重み 1 が前の本番の式 | 重み 3 なら 0.28 + 3 × 0.12 = 0.64 |
| 等級 | 点数を S・A・B・C にしたもの。線は下の値を含む | 0.64 → S |
| 決める期間・確かめる期間 | 線は 2023〜2024年の点数の分位（上から 20%・30%・30%・20%）で決め、重みも 2023〜2024年の成績だけで選ぶ。2025〜2026年で1回だけ確かめる | |
| 順に上がった | C → B → A → S の順に、率（勝率・複勝率・単勝回収率・複勝回収率）が真に上がったこと | |

## 最初の重みの選び方（手順 1。結果を見る前に決めた決まり。満たす重みは無かった）

1. 重み 1・1.5・2・2.5・3・4・5 のそれぞれで、決める期間の点数の分位から線を決める。
2. 決める期間をまとめて、4つの率が全部順に上がる重みだけを残す。
3. その中で、決める期間の年ごと（2023年・2024年）に順に上がった率の数がいちばん多い重みを選ぶ。同じなら重みの小さいもの（前の式に近いもの）。
4. 選んだ重みと線で、確かめる期間（2025〜2026年）をまとめて4つの率が全部順に上がるかを見る。上がれば本番の式と線を替える。上がらなければ替えない。

## フォルダの中身

| 場所 | 何があるか |
|---|---|
| `expectation.py` | 入口。◎ の行と全頭の行を読み（無ければ元DB から作り）、重みの候補ごとに期間 × 等級の ◎ の単勝・複勝の成績とまとめの表を Markdown に書く（docs/01 の手順 1） |
| `analysis/jra_top_picks.py` | 研究「既存モデルの改善」の当日の予測（7つの区切りのテスト期間）に、印の成績と同じ決め方で印を付け、◎ の行（確率・期待値・結果・払戻）だけを残して pickle にとっておく（`JraTopPicks`） |
| `analysis/weight_candidates.py` | 重みの候補（`WEIGHTS`・`CANDIDATES`。結果を見る前に決めた一覧） |
| `analysis/grade_period_table.py` | 期間 × 等級の ◎ の成績の表と、順に上がったかの判定（`GradePeriodTable`） |
| `analysis/weight_study.py` | 流れ（候補ごとに線を決め、決まりで重みを選び、表を書く。`WeightStudy`） |
| `rules.py`・`analysis/top_rules.py`・`analysis/rule_study.py` | ◎ の選び方 9 通り × 重みを比べる（docs/01 の手順 2） |
| `search.py`・`analysis/rule_search.py` | ◎ の選び方を約 2,000 通りに広げて比べる（手順 3） |
| `value_cut.py`・`analysis/value_cut_study.py` | 見送りの線 × 重み × 等級の割合を比べ、本番の決まりの期間・年ごとの成績を出す（手順 5） |
| `tests/` | 架空の値で、候補の式・順に上がったかの判定・選び方・表の書き出しを確かめる |

線の決め方（`GradeLines`）と点数の候補の形（`ScoreCandidate`）は、研究「地方の期待度」の部品をそのまま使う。

## 動かし方

```powershell
uv run python research/中央の期待度/expectation.py             # 当日の予測。2023〜2024年で決め、2025〜2026年で確かめる
uv run python research/中央の期待度/expectation.py --rebuild   # ◎ の行を元DB から作り直す
uv run python -m pytest -q research/中央の期待度/tests          # テスト
```

最初の1回は元DB から全レースの成績を読む（数分）。開催日のレースの時間（発走前の通知が動いている間）には動かさない。
出るもの: `reports/中央の期待度/重みの候補-当日.md`・`◎の選び方-当日.md`・`全レースの選び方-当日.md`・`見送りの線-当日.md`、◎ と全頭の行は `reports/中央の期待度/cache/`。
