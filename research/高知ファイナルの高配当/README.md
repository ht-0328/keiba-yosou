# 高知ファイナルの高配当

**何をする研究か。** 高知競馬の最終レース「ファイナルレース」を、荒れる前提で予想するための材料を探す。
荒れたレースを1つずつ見て「どういう馬が人気のわりに来るか／来ないか」の理論を立て（段1）、全部のファイナルレースで同じ人気の馬と比べて確かめる（段2）。

**なぜ始めたか。** ファイナルレースは高知のほかのレースよりはっきり荒れる。ただし、荒れることは単勝オッズに入っていて、どの人気の馬を全部買っても回収率は 100% を割る。
「荒れるから買う」では勝てないので、荒れる前提で「どの馬が来るか」を当てる専用の予想を作る。その予想の材料を決めるのがこの研究である。

進め方は [docs/01-事例.md](docs/01-事例.md)（段1）と [docs/02-理論.md](docs/02-理論.md)（段2）に書く。
数値（地方競馬DATA 由来の成績・配当・回収率）は Git 対象外の `reports/高知ファイナルの高配当/` に出し、この README と docs には書かない。

## この文書で使う言葉の意味

| 言葉 | 意味 | この研究では（架空の例） |
|---|---|---|
| ファイナルレース | 高知で、その日の最大のレース番号のレースのうち、競走名に「ファイナルレース」を含むもの（`FinalRace`） | 12レースの日の 12レース |
| 人気馬・中穴・大穴 | 単勝人気で分けた3つの帯。人気馬 1〜3番人気、中穴 4〜7番人気、大穴 8番人気以下（`PopularityBand`） | 5番人気は中穴 |
| 決着の型 | 1〜3着が、どの帯から何頭来たか。「人1中1大1」（順不同）と「人中大」（1着→3着の順）の2つの書き方 | 1着 2番人気・2着 6番人気・3着 9番人気 → 人中大 |
| 配当の帯 | 3連単の払戻（100円あたり）で分けた4つ。固い・中荒れ（万馬券）・大荒れ（10万馬券）・超荒れ（`PayoutBand`） | 払戻 18万円 → 大荒れ |
| 相対位置 | コーナーの順位を頭数でならした値。0 が先頭、1 が最後方（`RelativePosition`） | 11頭の6番手 → 0.5 |
| 倍率 | 実際に来た頭数 ÷ 同じ人気の馬と同じ率で来たときの頭数。1 より大きければ人気のわりに来る、小さければ買われすぎ（`SamePopularityRates`） | 見込み 10頭のところ 12頭来た → 1.2 |
| 理論 | 「こういう馬は同じ人気の馬より来る／来ない」という見立て。条件は `analysis/theory_catalog.py` | 前に行ける大穴は来る |

## フォルダの中身

| 場所 | 何があるか |
|---|---|
| `cases.py` | 入口（段1）。配当の帯ごとのレース数・決着の型と、荒れたレースの事例（出走馬ごとの人気・オッズ・着順・近走）を書く |
| `theories.py` | 入口（段2）。理論と材料を、全部のファイナルレースで同じ人気の馬と比べる |
| `analysis/case_study.py` `theory_study.py` | 段1・段2 の流れ |
| `analysis/runner_tables.py` | 出走の表を作る流れ（高知の出走を読む → 材料を付ける → ファイナルレースの出走馬を取り出す） |
| `analysis/kochi_run_features.py` | 高知の出走の行に材料を付ける。部品は `final_race.py`（ファイナルレースの見分け）・`relative_position.py`（相対位置）・`past_runs.py`（近走）・`final_history.py`（ファイナルの出走歴）・`distance_history.py`（同じ距離の出走歴）・`jockey_form.py`（騎手の直近 365日の成績）・`day_trend.py`（その日の傾向） |
| `analysis/final_runners.py` | ファイナルレースの出走馬の表（レースの中での順位・人気の帯・回収率の列） |
| `analysis/theory.py` `theory_catalog.py` | 理論と、その一覧（理論①〜⑤・差が無かった材料・そのほかに確かめた材料） |
| `analysis/same_popularity_rates.py` `period_split.py` `theory_check_table.py` | 同じ人気の馬の成績・期間の分け方・理論の検証の表 |
| `analysis/payout_band_table.py` `recent_runs_text.py` `case_list_table.py` | 事例の表（配当の帯・近走の文・1レースずつの一覧） |
| `analysis/popularity_band.py` | 人気の帯（本番の道具 `tools/地方の推奨買目` のものを使う） |
| `analysis/repository/` | 元DB を読むリポジトリ（1 SQL につき 1 クラス。高知の出走）。3連単の払戻は研究「地方の万馬券」のリポジトリを使う |
| `docs/` | 進め方と結果の読み方（01 事例・02 理論） |
| `tests/` | 架空の値と地方の合成DB で部品と流れを確かめるテスト（実DB は要らない） |
| `reports/高知ファイナルの高配当/`（Git 対象外） | `事例.md`・`理論の検証.md`・`理論の検証.csv` |

配当の帯・決着の型の表・報告の書き出しは、研究「地方の万馬券」（`research/地方の万馬券/analysis/`）の部品をそのまま使う。

## 動かし方

リポジトリ直下（`keiba-yosou/`）から実行する。元DB は nvdata-store の `nvdata.duckdb`（読むだけ）。
開催日のレースの時間は元DB を発走前の通知が使っているので、DB の写しを `--db` で渡す。

```bash
uv run python research/高知ファイナルの高配当/cases.py                 # 段1: 事例の表（数分。事実表づくりに約1分）
uv run python research/高知ファイナルの高配当/cases.py --list-from 2022-01-01 --limit 40   # 並べる事例の期間と数を変える
uv run python research/高知ファイナルの高配当/theories.py              # 段2: 理論の検証（数分）
uv run python research/高知ファイナルの高配当/theories.py --db <DB の写し>   # 写しを読む
uv run python -m pytest research/高知ファイナルの高配当 -q            # 部品のテスト
```
