# 一番人気を疑う

**何をする研究か。** 予想の◎（3着以内に来る確率がいちばん高い馬）が、1番人気より多く3着以内に来るようにできるかを調べる。
競馬予想でよく言われる「まず1番人気を疑え」（人気は人が作るもので、強さの順ではない）を、データで確かめる。

**なぜ始めたか。** 利用者から「予想AIの選ぶ◎が、1番人気より多く3着以内に来るように、予想を直せるなら直して」と頼まれた（2026-09-29）。
今の予想（`src/yosou/form_aptitude_top3`、設計書 `docs/design/近走と適性から3着以内を予想/`）の◎は、
単勝オッズを材料にする版ではほとんどのレースで1番人気と同じ馬で、1番人気とほぼ同じ割合でしか来ていなかった。
オッズを使わない版（木曜版）の◎は、1番人気よりはっきり少なくしか来ていなかった。

**結論（2026-09-29）。** [docs/02-結果.md](docs/02-結果.md) にまとめた。数値は Git の対象外の `reports/一番人気を疑う/` にある。

## この文書で使う言葉の意味

この文書と docs に出てくる言葉のうち、分かりにくいものの意味をまとめた。

| 言葉 | 意味 | この研究では（架空の例） |
|---|---|---|
| ◎（本命） | 1レースで、予想の「3着以内に来る確率」がいちばん高い馬 | 3番の馬が 0.62 で最も高ければ、3番が◎ |
| 1番人気 | 確定の単勝オッズがいちばん低い馬 | 単勝 2.4倍の馬 |
| ◎の3着以内率 | ◎が3着以内に来たレースの割合 | 100レース中 62レースなら 62% |
| 疑った | ◎が1番人気でないこと。予想が1番人気を疑って、別の馬を◎にした | 1番人気は5番だが、◎は3番 |
| 疑ったレースの◎・1番人気 | 疑ったレースだけで数えた、◎の3着以内率と、疑われた1番人気の3着以内率 | ◎ 50%・1番人気 56% なら、疑うと外れやすい |
| 区切り | 過去で学習して次の半年を予想する検証の、1回ぶんの期間。研究「既存モデルの改善」と同じ7つ | 2023年前半（学習は 2022年6月まで、検証は 2022年7〜12月、テストは 2023年1〜6月） |
| オッズを使わない材料 | 単勝オッズ・人気・券種のオッズを入れない材料。近走・適性・スピード指数・調教・人・血統など | 研究「馬の力と展開でオッズに勝つ」の197個の材料 |
| 券種ごとのオッズから見た支持 | 3連単・馬連などのオッズから取り出した、その馬の勝つ（3着以内に来る）確率と、単勝オッズから見た確率の比 | 単勝では3着以内率 0.20 の馬が、3連複では 0.26 なら、3連複の人のほうが高く見ている |
| 締め切り前の断面 | 発走の前に発表されたオッズ。過去のものは単勝・複勝・枠連と馬連だけがある（発走の11分前・6分前・1分前） | 発走の11分前の単勝オッズ |

## フォルダの中身

| 場所 | 何があるか |
|---|---|
| `extract_sales.py` | 入口①。元DB からセリの取引価格を読んで中間データにする |
| `run_experiments.py` | 入口②。作り方ごとに7つの区切りで学習し、予測を保存する |
| `summarize.py` | 入口③。保存した予測から、◎と1番人気を比べた表を書く |
| `pre_deadline_check.py` | 入口④。券種のオッズの材料が、締め切り前のオッズでも効くかを確かめる |
| `port_check.py` | 入口⑤。良かった2つの直し方を予想「近走と適性から3着以内を予想」に移したあと、7つの区切りで今の予想と比べる |
| `analysis/experiments.py` | 試した作り方の一覧 |
| `analysis/source/` | 既存の研究が保存した学習データの表を読む部品 |
| `analysis/feature/` | 材料を足す部品（レース内の比較・セリの価格・締め切り前のオッズ） |
| `analysis/repository/` | 元DB から読む部品 |
| `analysis/model/` | 7つの区切りで学習して予測する部品 |
| `analysis/evaluation/` | ◎と1番人気を比べる部品 |
| `analysis/port/` | 予想に移したあとの確かめの部品（表・比べる作り方・採否の決め方） |
| `docs/` | 進め方と結果 |
| `prompts/` | 結果の表の見方 |
| `tests/` | 架空の値で部品を確かめるテスト |
| `reports/一番人気を疑う/`（Git 対象外） | 予測と、結果の表。移したあとの確かめは `移したあとの確かめ/` |

## 動かし方

リポジトリ直下から。研究「既存モデルの改善」の表（`build_tables.py`）と、研究「馬の力と展開でオッズに勝つ」の表
（`extract.py`・`extract_extra.py`・`experiment.py --rebuild`）が先に要る。

```bash
uv run python research/一番人気を疑う/extract_sales.py        # セリの取引価格を中間データにする（数秒）
uv run python research/一番人気を疑う/run_experiments.py      # 作り方ごとに学習して予測を保存する（全部で数時間。済んだものは飛ばす）
uv run python research/一番人気を疑う/summarize.py           # 結果の表を書く
uv run python research/一番人気を疑う/pre_deadline_check.py  # 締め切り前のオッズで確かめる（十数分）
uv run python research/一番人気を疑う/port_check.py tables   # 予想に移したあとの学習データの表を作る（数十分）
uv run python research/一番人気を疑う/port_check.py run      # 時点ごとに今の予想と移した作り方を7つの区切りで学習する（数時間）
uv run python research/一番人気を疑う/port_check.py summary  # 時点ごとの採否と、◎と1番人気の表を書く
uv run python -m pytest -q research/一番人気を疑う          # 部品のテスト（架空の値だけ）
```
