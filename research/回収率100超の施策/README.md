# 回収率100超の施策

**何をする研究か。** 印のルールの買い目（設計書「買うレースと買い目を決める」08 の 2）の回収率を 100% より上にするために、
前のチャットで挙げた5つの施策を、7つの区切り（研究「既存モデルの改善」の区切り。テスト期間 2023年1月〜2026年9月）で確かめる。

**なぜ始めたか。** 予想モデル（近走と適性から3着以内を予想）の市場に対する上乗せは、控除率と同じくらいまで来ている。
◎（単勝の期待値が1位）の単勝は、期待度「高」のレースで回収率 100% を超えるが、90% の幅が 100% をまたぎ、採用の基準を満たさない。
100% を自信を持って超えるには、もう一段の上乗せか、上乗せの大きいレースだけを選ぶ仕組みが要る（設計書「近走と適性から3着以内を予想」の 16 の 6）。

**5つの施策（見込みの高い順）。** 進め方と採用の基準は [docs/01-進め方.md](docs/01-進め方.md)、結果は [docs/02-結果.md](docs/02-結果.md)。

| 番 | 施策 | どこで確かめるか |
|---|---|---|
| 1 | 券種どうしのずれ（3連単から見た勝率と単勝から見た勝率の食い違い）を単勝に使う | 道具「印の成績」の絞り込み（A）と、1着のモデルの出発点を3連単から見た勝率に替える作り方（B。この研究の `pool_baseline_check.py`） |
| 2 | LightGBM と CatBoost の2つがそろって「市場より上」と見たときだけ買う | 道具「印の成績」の絞り込みと買い方の行 |
| 3 | 1着を当てる専用の材料（勝ち切る力）を1着のモデルに足す | この研究の `finish_check.py`（7つの区切りで今の1着のモデルと比べる）。**当日の1着のモデルに採用し、予想のパッケージに移した**（設計書 15 の 15） |
| 4 | 市場が効率的でない場面（クラス・競馬場・頭数・売上）で上乗せが大きいかを測る | 道具「印の成績」の表10 |
| 5 | 前日夜 → 当日朝の単勝オッズの動きを材料にする | 道具「印の成績」の表11（時系列オッズのある 1年ぶんのレースだけ） |

## この文書で使う言葉の意味

| 言葉 | 意味 | この研究では |
|---|---|---|
| 上乗せ | モデルの確率が、オッズから見た確率（市場の見立て）よりどれだけ正しいか。確率の誤差（ログ損失）の差で測る | 上乗せが控除率を超えて初めて、買って儲かる |
| 2モデル一致 | LightGBM と CatBoost のそれぞれの確率で出した期待値が、どちらも線（単勝 1.00・複勝 1.25・組 1.0）以上であること | 平均の期待値だけでなく、2つの見立てがそろった買い目だけを買う |
| 3連単の支持 | 3連単のオッズから取り出した勝率（売上の大きいプールの見立て）が、単勝オッズから見た勝率以上であること | ◎ がこの条件を満たすレースだけを買う |
| 勝ち切る材料 | 3着以内ではなく1着に直接効くと考えた材料。馬の勝ち切り率（1着 ÷ 連対）・2着止まりの数・勝ったときの着差・惜敗の数、騎手と調教師の勝ち切り率 | 1着のモデルにだけ足す |
| 場面 | レースの条件の分け方。クラス・競馬場（主場・ローカル）・頭数・単勝の売上（票数）の帯 | 上乗せが場面でどう違うかを測る。場面で絞る決まりは、この研究では作らない |
| オッズの動き | 前日夜の最後の断面から当日朝（9時半まで）の最後の断面への、単勝オッズの対数の差。負なら売れた（人気が上がった） | 時系列オッズは JV-Data の提供が1年ぶんなので、確かめられるレースは限られる |

## フォルダの中身

| 場所 | 何があるか |
|---|---|
| `docs/01-進め方.md` | 施策ごとの手順・成果物・採用の基準（結果を見る前に決めた） |
| `docs/02-結果.md` | 何が分かったか（数値は書かない） |
| `pool_baseline_check.py` | 入口①（施策1-B）。1着のモデルの出発点を「3連単から見た勝率」に替えて、当日の7つの区切りで今の1着のモデルと比べる |
| `finish_check.py` | 入口②（施策3）。勝ち切る材料（予想のパッケージの `FinishRecordsLoader` で読む）を元の表に足し、1着のモデルを時点ごとに7つの区切りで学んで、今の1着のモデルと比べる。3着以内のモデルに足した作り方と、1-B と重ねた作り方も学ぶ |
| `analysis/` | 部品（勝ち切る材料を表に足す・3連単の出発点・作り方。材料を読む SQL は採用して予想のパッケージに移した） |
| `tests/` | 架空の値で部品を確かめるテスト |
| `reports/回収率100超の施策/`（Git 対象外） | 比べ方の表。買い目の回収率は道具「印の成績」の `reports/印の成績/` |

施策 1-A・2・4・5 は道具「印の成績」（`tools/印の成績/mark_stats.py`）に組み込んだ。モデルを作ったり直したりしたら、同じ道具を回せば
絞り込みごとの全券種の回収率と、場面・オッズの動きの表が出る。

## 動かし方

リポジトリ直下から。学習データの表（`reports/既存モデルの改善/tables/h2h_ability`・`h2h_pool_ability`）と、今の1着のモデルの予測
（`win_check.py run`）が先に要る。

```bash
uv run python research/回収率100超の施策/pool_baseline_check.py run        # 施策1-B: 3連単の出発点の1着のモデルを当日の7つの区切りで学ぶ（30〜60分）
uv run python research/回収率100超の施策/pool_baseline_check.py summary    # 今の1着のモデルと比べた表を書く
uv run python research/回収率100超の施策/finish_check.py tables            # 施策3: 元の表に勝ち切る材料を足す（元DB を開く）
uv run python research/回収率100超の施策/finish_check.py run               # 時点ごとに7つの区切りで学ぶ（1つ 30〜60分）
uv run python research/回収率100超の施策/finish_check.py summary           # 今の1着のモデルと比べた表を書く
uv run python tools/印の成績/mark_stats.py --form h2h_pool_ability/h2h-race_day --win reports/回収率100超の施策/predictions/finish_pool_ability/finish-win-race_day.pkl --timing 当日 --out-dir reports/回収率100超の施策/印の成績-勝ち切る材料   # 新しい1着の予測で、印と買い目の回収率を出す
uv run python -m pytest -q research/回収率100超の施策                       # 部品のテスト（架空の値だけ）
```
