# 01 進め方

**この文書は、5つの施策を何の順で、どう確かめ、何をもって採用するかを書く。** 採用の基準は、結果を見る前に決めた。
言葉の意味は [../README.md](../README.md) の表を参照。

## 1. 共通の決まり

| 項目 | 中身 |
|---|---|
| 期間 | 研究「既存モデルの改善」の7つの区切りのテスト期間（2023年1月〜2026年9月）。学習にも線にも使っていない期間 |
| 予測 | 今の本番と同じ作りの予測（前日 `h2h_ability/h2h-day_before`・`win-day_before`、当日 `h2h_pool_ability/h2h-race_day`・`win-race_day`） |
| オッズ | 確定オッズ。実際に買うときより良く出る（どの表にも書き添える） |
| 買い目 | 設計書「買うレースと買い目を決める」08 の 2 の印のルール。道具「印の成績」の表7 で全券種を出す |
| 回収率の幅 | 開催日を単位にしたブートストラップの 90% の幅 |
| 線 | 既存の線（単勝の期待度 1.00・複勝 1.25・組の期待値 1.0）を動かさない。新しい線（3連単の支持の比 1.0）も固定 |

## 2. 施策ごとの手順と採用の基準

### 施策2: 2モデル一致（手間が小さいので先に）

| 項目 | 中身 |
|---|---|
| すること | 7つの区切りの予測には LightGBM と CatBoost の確率が別々に残っている。それぞれの確率で単勝・複勝・組の期待値を出し、「平均の期待値が線以上」に「2つとも線以上」を足した絞り込みを作る |
| 直すもの | `tools/印の成績/`: 予測の読み込みにモデルごとの確率を残す、◎ の単勝の期待値をモデルごとに付ける、レースの絞り込み「期待度 高・2モデル一致」を表6・表7・表8 に足す、買い方に「複勝（2モデル一致）」「3連複・3連単（期待値 1.0 以上・2モデル一致）」の行を足す |
| 採用の基準 | 絞り込んだ「高」の ◎ の単勝回収率が 100% を超え、90% の幅の下の端も 100% を超えること（設計書 16 の 6 と同じ）。買い方の行も同じ基準で、行ごとに見る |
| 満たしたら | 今週の予想の印とレースの期待度に「2モデル一致」を出し、設計書 07 の 5・08 の 2 に書く |
| 満たさなければ | 道具の表には残す（モデルを直すたびに同じ表で見る）。本番の印は変えない |

### 施策1: 券種どうしのずれを単勝に使う

| 項目 | 中身 |
|---|---|
| A. 絞り込み | 3連単のオッズから取り出した勝率（`FirstHorsePoolRepository`。当日のモデルの材料 N と同じ計算）を ◎ に付け、「3連単から見た勝率 ÷ 単勝から見た勝率」が 1.0 以上の ◎ だけに絞る。道具「印の成績」の絞り込み「期待度 高・3連単の支持あり」（2モデル一致との重ねも） |
| B. 出発点を替える | 1着のモデルの出発点（基準）を「オッズから見た勝率」から「3連単から見た勝率」に替えて、当日の表（`h2h_pool_ability`）で7つの区切りで学ぶ（`pool_baseline_check.py`）。材料は今の1着のモデルと同じ |
| A の採用の基準 | 施策2 と同じ（絞り込んだ「高」の ◎ の単勝回収率と幅の下の端が 100% 超え） |
| B の採用の基準 | テスト期間のログ損失が今の1着のモデル（`win-race_day`）より小さい区切りが 7つのうち 5つ以上あり、全期間でも小さいこと（研究「既存モデルの改善」の材料の実験と同じ）。満たしたら、その予測で道具「印の成績」を回し、◎ の単勝回収率も見る |
| 気をつけること | 3連単のオッズは当日にしかそろわないので、前日のモデルには使えない。確定の3連単オッズでの確かめなので、締め切り前のオッズではこれより悪く出る |

### 施策4: 場面ごとの上乗せを測る

| 項目 | 中身 |
|---|---|
| すること | テスト期間のレースを、クラス帯・競馬場（主場・ローカル）・頭数帯・単勝の売上（票数）の帯・芝ダで分け、場面ごとに ◎ の単勝回収率（全体と期待度「高」）、複勝（期待値 1.25 以上）の回収率、上乗せ（3着以内と1着の、モデルと市場のログ損失の差）を出す。道具「印の成績」の表10 |
| 直すもの | `tools/印の成績/`: レースの場面を事実表から読む、単勝の票数合計を読む、表10 |
| 採用の基準 | **採用する決まりは作らない。** 測るだけ。場面で絞る決まりをテスト期間の結果から選ぶと、結果に合わせた選び方になるため（利用者の決定「場面の絞り込みが先に来ないよう、モデルの改善とセットで」） |
| 使い方 | 上乗せの大きい場面が見つかれば、「その場面の材料をモデルに足す」案の候補として 02-結果 に書く |

### 施策5: 前日夜 → 当日朝のオッズの動き

| 項目 | 中身 |
|---|---|
| すること | 時系列オッズ（`o1` のデータ区分 1）から、前日の最後の断面と当日 9時30分までの最後の断面の単勝オッズを馬ごとに読み、動き（対数の差）を付ける。◎ の動きの帯ごとに単勝の成績を出す。道具「印の成績」の表11 |
| 制約 | 時系列オッズは JV-Data の提供が1年ぶんなので、確かめられるのはテスト期間の終わりの約1年のレースだけ。表には対象のレース数と割合を書く |
| 採用の基準 | 施策2 と同じ基準を、動きの帯に当てる。ただしレース数が少ないので、満たしても「届いたが数が少ない」と書き、本番の印には入れない。モデルの材料にするのは、時系列オッズが学習の全期間ぶんそろわないので、できない |

### 施策3: 勝ち切る材料を1着のモデルに足す（手間が大きいので最後）

| 項目 | 中身 |
|---|---|
| 材料 | 馬: 近10走の1着数・2着数・勝ち切り率（1着 ÷ 連対。連対が無ければ欠損）・惜敗の数（0.2秒以内の負け）・勝ったときの平均着差・1番人気以内で負けた数。騎手・調教師: 近1年の勝ち切り率（1着 ÷ 連対）と、1番人気のときの勝率。全部、開催日の前日までの記録だけで作る |
| すること | 元の表（`h2h_ability`・`h2h_pool_ability`）に材料を足し（`finish_check.py tables`）、1着のモデルを時点ごと（前日・当日。木曜は期待値が出ないので比べない）に7つの区切りで学ぶ（`run`）。比べる相手は今の1着のモデル（`win-day_before`・`win-race_day`） |
| 採用の基準 | 施策1-B と同じ（ログ損失が小さい区切りが 5つ以上、全期間でも小さい）。満たした時点だけ、その予測で道具「印の成績」を回し、◎ の単勝回収率と全券種の回収率を見る |
| 満たしたら | 材料を予想のパッケージ（`src/yosou/shared/feature/`）に移し、1着のモデルにだけ渡す。設計書 09・15・16 に書く |

## 3. 順

1. 道具「印の成績」に施策 2・1-A・4・5 を足し、前日と当日の予測で回す（1回 10〜15分）。
2. 結果を 02-結果 に書く。**ここで一度報告する。**
3. 施策 1-B と 3 の学習を回す（合わせて数時間）。結果を 02-結果 に足す。
4. 採用の基準を満たした施策を本番（今週の予想・設計書）に入れる。満たさなかった施策は、道具の表に残して終える。

## 4. 気をつけること

- 絞り込みを増やすほど、たまたま良く見える絞り込みが出る。採用の基準（幅の下の端が 100% 超え）を全部に同じに当て、基準に届かない絞り込みを「惜しい」と扱わない。
- 2026年は既存の研究で何度も見ているので、手つかずのデータではない。採用した施策も、これからのレースの確定成績で確かめ直す。
- 数値（JV-Data 由来）はこの文書に書かない。`reports/` に出す。
