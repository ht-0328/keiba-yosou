# 事例の分析（サブエージェントへの指示文）

研究「展開の理論の検証」の手順1で、1つの型の事例のレースを1つずつ読み、なぜそうなったかを書き出す。
型は `analysis/cases/case_patterns.py` にあり、事例の一覧は `collect_cases.py` が `reports/展開の理論の検証/cases/一覧.md` に書く。

## この指示文で使う言葉の意味

この指示文に出てくる言葉のうち、分かりにくいものの意味をまとめた。

| 言葉 | 意味 | この研究では（架空の例） |
|---|---|---|
| ペース | 前半 600m のタイム（前3ハロン。距離が 200m で割り切れないレースは 500m か 550m）が、同じ競馬場・コース・距離・クラスの基準より速いか遅いか。基準は開催日の前日までの3年の平均 | 基準 35.1秒で前半 34.6秒なら、速い方に外れているので「ハイ」 |
| 前半の速さ（z） | （基準 − 前半タイム）÷ 基準の標準偏差。0.5 より大きければハイ、−0.5 より小さければスロー、そのあいだはミドル | z = 0.83 はハイ |
| 脚質 | 逃げ（先頭）・先行（前の方）・差し（中ほど）・追込（後ろ）。JV-Data がレース後に付けた判定 | 勝ち馬の脚質 = 差し |
| 推定脚質 | 今回より前の直近3走の脚質の真ん中。レース前に分かる脚質 | 前3走が 逃げ・先行・先行 なら 先行 |
| 逃げそうな馬 | そのレースで推定脚質が逃げの馬の数 | 2頭 |
| 理論 | 調べている展開の理論。**発生条件**: 逃げたい馬が1頭（か0頭）ならスロー、複数ならハイになりやすい。**有利な脚質**: スローなら逃げ・先行、ハイなら差し・追込が有利。ミドルなら有利不利が少ない | |

## 頼むこと

型 `{型}`（{型の中身}、{理論との関係}）の事例の一覧にある 20 レースを、1レースずつ読む。

1. `reports/展開の理論の検証/cases/一覧.md` から、型 `{型}` の表を読む。
2. 各レースについて、作業フォルダ `C:\Users\ht-03\workspace\keiba-yosou-worktree-pace-theory` で次を実行して詳細を読む。
   `uv run python tools/レース詳細/race.py <rid>`（出走表と結果・ラップ・通過順・払戻が出る）
3. 各レースで、次を見る。
   - **ラップ（200m ごとの秒）**: 前半・中盤・後半のどこが速く、どこで緩んだか。前半だけ速くて中盤で大きく緩んだ、のような形。
   - **通過順**: 最初のコーナーで先頭を争った馬は何頭か。隊列は縦長か、固まっていたか。勝ち馬と 2・3着の馬は、どのコーナーでどこにいたか。
   - **1〜3着の脚質・人気・上がり3ハロン**: 勝った馬は人気で、力が抜けていたのか。後ろから来た馬の上がりは速かったか。
   - **条件**: 頭数、芝かダートか、距離、馬場状態、コースの形（直線の長さ・小回りか）。
4. レースごとに、**なぜこの型になったのか**を 2〜4 文で書く。理論どおりの型なら「理論の説明どおりか、別の理由か」、理論に反する型なら「理論が外れた理由」を書く。
5. 20 レースを読み終えたら、**よく出てくる理由**を、何レースで見られたかの数と一緒にまとめる。
   例: 「スローなのに差しが勝った 20 レースのうち 8 レースは、勝ち馬が1番人気で力が抜けていた」。

## 書く場所と書き方

- 結果は `reports/展開の理論の検証/cases/{型}.md` に書く（Git の対象外。馬名を書いてよい）。
- 形: 先頭に `# {型}: {型の中身}（{理論との関係}）`。次に「よく出てくる理由」の表（理由 | レース数 | 例の rid）。そのあとに、レースごとに `## <rid> <開催日> <競馬場> <コース><距離>m <馬場> <クラス> <頭数>頭` の見出しと、見たこと（ラップの形・隊列・1〜3着）と理由。
- 推測で埋めない。出力に無いこと（騎手の意図・出遅れの理由など）は「分からない」と書く。

## 返すもの

主担当には、次の2つだけを短く返す。馬名・騎手名・オッズの値は返さない（馬番と人気の順位は返してよい）。

- よく出てくる理由の表（理由 | レース数）
- 理論について、この型から言えそうなこと（3文以内）
