# 03 通知の時刻での確かめ（推奨買目の期待の儲けは、通知の目安に使えない）

**この文書で決めること:** [02](02-推奨買目の見込みで付ける期待度.md) で決めた点数（推奨買目の期待の儲け）を、発走前の通知の期待度として使い続けるか。
数値（割合・回収率・儲け）は `reports/地方の期待度/通知のときの期待の儲け.md`（Git 対象外）にあり、ここには載せない。

**結論: 使わない。** 通知の時刻のオッズで作った推奨買目では、期待の儲けの点数が膨らんで大半のレースが S になり、点数の高いレースほど実際の回収率が低い。
通知の期待度は、買い目を決める時刻に分かることだけで学んだ直前の買い目（設計書「買うレースと買い目を決める」の [13](../../../docs/design/買うレースと買い目を決める/13-local-late-tickets.md)）の線への近さに替えた（設計書の [11](../../../docs/design/買うレースと買い目を決める/11-local-expectation.md)）。
期待の儲けの点数と線は、確定オッズで作り直した推奨買目を分ける研究の物差し（`LocalBetProfitScale`）として残す。

## 1. なぜ始めたか

利用者から「期待度が S 多すぎ」と言われた。02 で線を決めたときは S が全レースの 2割ほどになるはずだった。

## 2. 仮定（何が成り立てば、02 の点数を使い続けられるか）

- 通知のときの推奨買目でも、等級の割合が 02 と同じくらいになる（S が 2割ほど）。
- 通知のときの推奨買目でも、点数が高いレースほど実際の回収率・儲けが高い。

02 は、オッズに確定の値を使い「確定のオッズ ≒ 通知のときのオッズ」を前提にしていた。この前提が地方で成り立つかを、ここで確かめる。

## 3. 進め方

| 段 | 内容 |
|---|---|
| 通知のときの推奨買目を作り直す | 発走前の通知が保存した当日の時点の予想（`reports/発走前の通知/地方/<開催日>/<rid>.json`）と、通知が発走前に取り込んだ途中のオッズ（元DB に残る。確定の断面は発表月日時分が 0 なので、推奨買目が読む「最新の発表」は途中の断面のまま）で、本番と同じ `Recommender` を動かす（`NotifiedBets`）。3連複の荒れ具合の条件も、通知が保存した確率を読む |
| 数えないレース | 締め切り後に取り込んだ断面のあるレース（通知のときのオッズが再現できない。`LateSnapshotRepository`）、結果のまだ無いレース、推奨買目を出せなかったレース |
| 払戻 | 確定の払戻（`NotifiedPayoutRepository`）。1点 100円 |
| 分け方 | 02 の線の等級（S・A・B・C）と、点数の低い順に頭数を等しく分けた 5組（`NotifiedGradeTable`） |
| 判定 | 等級の割合が 02 と同じくらいか。等級が高い・点数が高い組ほど回収率と1レースの儲けが高いか |

## 4. 分かったこと

- **割合。** 通知のときは S が 7〜8割で、B と C は合わせて 1割に満たない。点数の中央値が S の線の倍を超える。1レースの推奨買目の点数も、確定オッズで作り直したときの倍ほどになる。
- **向き。** 全体の回収率は 100% を大きく割る。S の回収率は全体より低く、点数の低い順の 5組では、点数がいちばん低い組だけが 100% を超え、点数が高い組ほど回収率が低く1レースの負けが大きい。
- **理由。** 地方は、通知のとき（締め切りの約10分前）のオッズが確定のオッズと大きく違う。推奨買目の期待値は「予想の確率 × そのときのオッズ」なので、あとで下がるオッズの組ほど期待値が高く出て選ばれる。
  期待値の高い組が多いレースほど点数が高くなるので、点数は「見込みの高さ」でなく「オッズがこれから動く大きさ」を拾っている。

2つの仮定はどちらも成り立たない。線を引き直しても向きが逆なので、目安にならない。

## 5. 決めたこと

- 通知の期待度の点数を、直前の買い目の線への近さに替える（設計書の 11・09 の 29）。直前の買い目は、取り直した時系列オッズの「買い目を決める時刻の断面」で学び、同じ断面で確かめた買い方なので、通知の時刻のオッズでも見込みが膨らまない。
- 期待の儲けの点数と線（02）は、確定オッズで作り直した推奨買目を分ける物差しとして研究に残す。通知には出さない。

## 6. 割り引いて見るところ

- 数えたのは通知を始めてからの 10日ほど・数百レースで、等級ごとの回収率の振れは大きい（A だけ 100% を超えたのは、この少ない回数での振れと見る）。向き（S と点数の高い組が低い）は、等級でも 5組でも同じに出た。
- 通知のときの予想そのもの（全頭の確率）は作り直していない。保存した予想をそのまま使った。
