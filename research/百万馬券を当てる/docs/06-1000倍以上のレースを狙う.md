# 06 1,000倍以上のレースを狙う（レース選びの精度と、選んだレースでの的中率）

**この文書で示すこと:** 利用者の指示「1,000倍以上のレースと判断したら1日何レースでも参加する。まず、どれだけそういうレースを選べているかを示し、選ぶ精度を上げる。次に、選んだレースでの的中率を上げる」に対して、何を試し、何を採ったか。数値は `reports/百万馬券を当てる/`（Git 対象外）の `レース選びの精度.md`・`一律の買い目の結果.md` にある。この文書には、判定と言葉でまとめたことだけを書く。

**結論:**

| 段 | 試したこと | 判定 |
|---|---|---|
| レース選び | 専用の二値モデル、馬の予想から作る材料、オッズ板の材料、市場との差、予想が見た確率、「買い目が当たるか」のモデル | **荒れ具合の予想の「大荒れ＋超荒れ」の確率と、予想が見た 1,000倍以上になる確率の平均**を採る。同じレース数で精度が上がり、的中率と回収率を保てる。オッズ板の材料は精度は上がるが的中率と回収率が下がるので採らない。ほかは上がらない |
| 選んだレースの的中 | 組の確率の2着・3着の重みを、1着の確率から3着以内の確率に替える。今の予想を混ぜる | **1着は荒れる前提の1着の確率、2着・3着は今の予想と荒れる前提の予想の3着以内の確率の平均**を採る。100円・300円・500円のどれでも元の式より当て、2つの期間のどちらでも回収率が 100% を超えた |

## 1. 採用の基準（結果を見る前に決めた）

- レース選び: 点数の高い順に**同じレース数**（1開催日あたり 8・5・2.5・1レース）を選んだとき、実際に 1,000倍以上で決まった割合が今の点数より高いこと。2021〜2026年の11の区切り（それぞれ前の期間だけで学ぶ）で数え、2021〜2022年と 2023〜2026年のどちらでも高いこと。利用者の指示で、同じ選び方で一律の買い目を買ったときの的中率を下げず、回収率も下げないことも条件にした。
- 選んだレースの的中: 線以上のレースを全部買い、1,000倍以上の組を組の確率の高い順に一律の金額（100円・300円・500円）で買ったとき、**1,000倍以上で決まったレースのうち当てた割合**が元の式より高いこと。回収率は参考（数回の大きい当たりで動くため）。こちらも2つの期間に分けて見る。

## 2. レース選びの精度

全レースのおよそ 2割が 1,000倍以上で決まる。点数の高い順に選ぶと、選ぶ数を絞るほど実際に 1,000倍以上だった割合は上がる（1開催日あたり 8レースで 3割台、2〜3レースで 4割台、1レースで 5割ほど）。

| 点数 | 結果 |
|---|---|
| **荒れ具合の予想の3連単の大荒れ＋超荒れの確率（採用）** | 超荒れだけの確率より、どのレース数でも当たる割合が高い（目的変数「1,000倍以上」と線がそろうため） |
| 荒れ具合の予想の3連単の超荒れだけの確率（最初の本番） | 上より低い。50万円以上を当てる確率なので、10万〜50万円のレースを拾いにくい |
| 専用の二値モデル（`walk.py big`。荒れ具合の予想と同じレース単位の材料 49個で「1,000倍以上か」を当てる） | 上とほぼ同じ（割合の差は ±0.01、AUC も同じ）。材料が同じなので、目的変数を変えても上がらない |
| 専用モデルの材料に、馬の予想から作るレース単位の材料（今の予想・荒れる前提の予想の1着・3着以内の確率の、1番人気の値・人気薄の合計・エントロピー など）を足したモデル | 2022〜2026年の区切りで上と同じ。材料が 2020年後半からしか無い（馬の予想の区切りごとの予測が要る）割に上がらない。手元の確かめだけで、研究のコードには残していない |
| 帯になる確率のモデル・条件のルール（docs/04） | 上より低い |
| **3連単のオッズ板から作る材料**（市場が見た 1,000倍以上になる確率 = 1,000倍以上の組の 1/オッズ の合計、1番人気の組のオッズ、上位10組の割合、エントロピー など 8個）を専用モデルの材料に足す。3連複・馬連の板も足す | 同じレース数で割合が数ポイント上がり、2023年以降ではっきりする（3券種にしても3連単だけと同じ）。**しかし、同じ選び方で一律の買い目を買うと的中率と回収率が下がる。** 市場が「荒れそう」と見るレースは 1,000倍以上の組が多く（3,000通り近く）、100点では覆えないため。採らない。手元の確かめだけで、研究のコードには残していない |
| 大荒れ＋超荒れの確率 − 市場が見た確率（市場より自分の予想が荒れると見るレース） | 回収率は上がるが、割合は大きく下がる。採らない |
| **予想が見た 1,000倍以上になる確率**（今の予想の全頭の1着の確率から Harville の式で全部の3連単の組の確率を出し、1,000倍以上の組の確率を合計。本番の `BigPayoutChance`） | 単独で大荒れ＋超荒れと同じ程度の精度で、材料が違うので平均すると上がる。**大荒れ＋超荒れとの平均（採用）** は、同じレース数で割合が上がり、的中率は同じ、回収率は 1開催日あたり 1〜1.5レースに絞ると上がり、2.5レース以上選ぶと少し下がる |
| 「一律の買い目が当たるか」を直接当てるモデル（材料: 大荒れ＋超荒れ・市場が見た確率・1,000倍以上の組の数・買い目の見込み） | 学べるレースが 2021年からしか無く、上がらない |

**まとめ。** レース選びの精度は、どの方法でも数ポイントしか上がらない。市場（オッズ板）そのものでも同じ程度で、残りは運の部分が大きい。精度を上げる方法の多くは的中率・回収率と引き換えになる中で、大荒れ＋超荒れと予想が見た確率の平均だけが、精度を上げつつ的中率と回収率を保てた。線を上げて選ぶ数を絞るほど3つとも上がり、どこで切るかは利用者が決める（本番の既定は 0.40。平均の点数では 1開催日あたり 1〜2レース）。

## 3. 選んだレースでの的中率

線以上のレースを全部買い、1,000倍以上の3連単の組を組の確率の高い順に一律の金額で買った。組の確率は Harville の式で、1着の確率と2着・3着の重みの組み合わせを変えて比べた。

| 組の確率 | 結果 |
|---|---|
| **1着は荒れる前提の1着の確率、2着・3着は今の予想と荒れる前提の予想の3着以内の確率の平均（採用）** | 100円・300円・500円のどれでも、1,000倍以上で決まったレースのうち当てた割合が元の式より高い（1.3〜1.5倍）。2021〜2022年・2023〜2026年のどちらでも回収率が 100% を超えた |
| 元の Harville の式（2着・3着も荒れる前提の1着の確率の比。最初の本番） | 荒れる前提の1着の確率は人気薄に寄るので、2着・3着まで人気薄で固めた組に寄る。当てた割合がいちばん低い |
| 2着・3着を今の予想の3着以内の確率だけにする | 300円・500円では採用と同じくらい当て、回収率は採用より高い。100円では採用より当てる割合が低い。1つの式にそろえるため採らない |
| 1着も今の予想と平均する・今の予想だけにする | 100円では採用と同じくらい当てるが、300円・500円で下がる。利用者の「荒れる前提の予想を使う」にも合わない |
| 2着・3着を荒れる前提の3着以内の確率だけにする。1着の確率を弱める（0.5乗・0.7乗） | 元の式とほぼ同じで、上がらない |

- 1,000倍以上で決まったレースは「人気薄が勝ち、2着・3着に人気馬や中位の馬が入る」形が多い。1着を荒れる前提の予想で、2着・3着を今の予想も混ぜた重みで決めると、この形に合う。
- 1点の金額を上げると点数が減り、当てる割合は下がる（100円の 100点で 6回に1回ほど、500円の 20点で 20回に1回ほど）が、当たり1回の払戻と回収率は上がる。どれにするかは利用者が決める（本番の既定は 100円）。
- 100円では、回収率の 90% の幅の下の端が 100% を下回る。300円・500円では 2021〜2026年の全体で下の端も 100% を超えたが、2023〜2026年だけでは下回る。順位の付け方は 2021〜2026年の結果を見て選んだので、まだ見ていない期間での確かめにはなっていない。勝負用の財布で買うかは、別の期間で確かめてから決める。それまで買い目は参考のまま。

## 5. 動かし方

```bash
uv run python research/百万馬券を当てる/walk.py big           # 専用の二値モデルを 11の区切りで学ぶ（3時点。30分ほど）
uv run python research/百万馬券を当てる/backtest.py select    # 2. の表（レース選びの精度。初回は元DB から予想が見た確率を出す。数分）
uv run python research/百万馬券を当てる/backtest.py flat      # 3. の表（一律の買い目の結果。本番と同じ平均の点数で選ぶ。初回は元DB から 1,000倍以上の組のオッズを読む）
uv run python research/百万馬券を当てる/backtest.py flat --score 大荒れ＋超荒れ --line 0.35   # 点数と線を替えて数える
```
