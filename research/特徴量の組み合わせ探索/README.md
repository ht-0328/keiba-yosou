# 特徴量の組み合わせ探索

**何をする研究か。** `custom_binary`（特徴量と条件を YAML で選ぶ予想モデル。利用手順は [docs/custom_binary.md](../../docs/custom_binary.md)）を使い、
「短距離のレースなら馬体重が N kg 以下の馬が有利」「ある競馬場なら外枠が有利」のような
**特徴量の組み合わせで、回収率 100% を超える買い方があるか**を探す。

**やり方は2通り。**

1. **ルールで探す（入口②）** — レースの区分 × 馬の条件（1つの特徴量の値の範囲）× 人気帯 の組み合わせごとに、
   当てはまる馬を全部買ったときの単勝・複勝の回収率を数える。モデルは使わない。
2. **モデルで探す（入口③）** — レースの区分ごとに `custom_binary` のモデルを学習し、
   「各レースで確率1位」「期待値がいくつ以上」などの買い方の回収率を見る。

どちらも、見つかった組み合わせは `custom_binary` の YAML（`conditions:` と `popularity:`）にそのまま書ける形で出す。

## この文書で使う言葉の意味

この文書に出てくる言葉のうち、分かりにくいものの意味をまとめた。

| 用語 | 意味 | この研究では |
|---|---|---|
| 回収率 | 払戻の合計 ÷ 買った金額。1点100円で数える | 何も考えずに買うと、控除率のぶん 70〜80% になる |
| レースの区分 | レースを条件で分けたもの | 芝ダ、芝ダ×距離帯、芝ダ×馬場状態、競馬場×芝ダ、競馬場×芝ダ×距離帯 |
| 距離帯 | 距離を4つに分けたもの | 短距離 〜1400m、マイル 1401〜1800m、中距離 1801〜2200m、長距離 2201m〜 |
| 馬の条件 | 1つの特徴量の値の範囲 | 数値の特徴量は、見つける期間の分布で5等分（下位20%ずつ）。カテゴリの特徴量は、出走の多い値30個まで |
| 人気帯 | 確定の単勝人気の範囲 | 全人気、1〜3番人気、4〜6番人気、7〜9番人気、10番人気以下 |
| 見つける期間 | 候補を探す（モデルなら学習する）期間 | 2017年1月〜2022年12月 |
| 確かめる期間 | 見つけた候補が続くかを確かめる期間。モデルでは早期終了と買い方の選択にも使う | 2023年1月〜2024年12月 |
| テスト期間 | 採否を決めたあとに1回だけ見る期間 | 2025年1月〜（DB の最後の日まで） |
| 期待値 | 確率 × オッズ。1 を超えれば長い目で見て儲かる | 勝利モデルは確率×単勝オッズ、馬券内モデルは確率×複勝オッズ（最低） |
| z | （回収率 − 1）÷ 回収率の標準誤差 | 2 を超えなければ、100% との差は偶然の範囲 |
| 多重比較 | たくさん試すと、偶然だけで良い結果が出るものが必ず混ざること | 約22万通り試すので、1つの期間だけ良いルールはほぼ偶然。だから期間を3つに分ける |

## 採否の基準（結果を見る前に決めた）

`analysis/rule_selection.py` に書いたとおり。

- 見つける期間で、点数 300 以上・回収率 110% 以上なら候補。
- 確かめる期間でも、点数 100 以上・回収率 100% 以上なら採用。
- テスト期間は採否に使わない。採用したルールが続いたかを1回だけ見る。

モデルは、確かめる期間で点数 100 以上の買い方のうち回収率がいちばん高いものを選び、テスト期間でその買い方の回収率を見る。

### 年ごとのウォークフォワードの採用基準（結果を見る前に決めた）

テスト期間（2025年1月〜）だけでは点数が足りず、券種オッズ入りの設定の採否を決められなかった。
そこで、2019年から1年ずつ「その年より前で学習し直して、その年を予測する」をくり返す（入口⑤）。

- 学習は 2017年からその年の前々年まで。直前の1年は、早期終了と、買う期待値の線の選択だけに使う。
  線の選び方は元の探索と同じ（期待値 1.0〜1.5 の線のうち、直前の1年で点数 100 以上・複勝の回収率がいちばん高いもの）。
  確かめる年の結果は、線を選ぶのに使わない。
- 採用するのは、次の4つを全部満たすとき（`analysis/walk_forward_verdict.py`）。
  1. 年を合わせて、点数 300 以上。
  2. 年を合わせて、複勝の回収率 100% 以上。
  3. 年を合わせて、開催日単位の 90% の幅の下限が 100% 以上。
  4. 回収率 100% 以上の年が、買った年の半分を超える（1〜2年の大当たりだけで合計が 100% を超えていない）。
- 参考に、当日の予想（`tools/当日の予想`）と同じ線 1.2 に固定した結果も出す。

## フォルダの中身

| 場所 | 何があるか |
|---|---|
| `extract.py` | 入口①。元DB から全頭・全特徴量の表を作る（2分ほど） |
| `rule_scan.py` | 入口②。ルールで探す（3分ほど） |
| `model_search.py` | 入口③。モデルで探す（54設定で1時間半ほど。済んだ設定は飛ばす） |
| `summarize.py` | 入口④。入口②・③の結果を `reports/特徴量の組み合わせ探索/結果.md` にまとめる |
| `walk_forward.py` | 入口⑤。券種オッズ入りの設定を、年ごとのウォークフォワードで確かめる（1設定20分ほど。済んだ年は飛ばす） |
| `analysis/feature_table.py` | 全頭・全特徴量の表。`custom_binary` の特徴量の登録をそのまま使う |
| `analysis/search_periods.py` | 3つの期間の区切り |
| `analysis/race_segments.py` | レースの区分 |
| `analysis/popularity_bands.py` | 人気帯 |
| `analysis/condition_bins.py` | 馬の条件の候補 |
| `analysis/roi_scan.py` | 組み合わせごとの点数と払戻の集計 |
| `analysis/rule_selection.py` | ルールの採否の基準 |
| `analysis/model_config.py`・`model_configs.py` | モデルで探す設定（目的 × 特徴量の組 × 区分） |
| `analysis/model_trial.py` | 1つの設定で学習して、買い方を選んで、テスト期間で確かめる |
| `analysis/walk_forward_years.py` | ウォークフォワードの年ごとの期間の区切り |
| `analysis/walk_forward_trial.py` | 1つの設定の1年ぶん（学習し直し → 直前の1年で線を選ぶ → その年の買い目の候補） |
| `analysis/yearly_payback.py` | 年ごとと年を合わせた、複勝の点数・回収率・開催日単位の下限 |
| `analysis/walk_forward_verdict.py` | ウォークフォワードの採用の基準 |
| `tests/` | 架空の値で部品を確かめるテスト |
| `reports/特徴量の組み合わせ探索/`（Git 対象外） | 実測の数値。JV-Data 由来の値はここにだけ置く |

## 動かし方

リポジトリ直下から実行する。

```powershell
uv run python research/特徴量の組み合わせ探索/extract.py        # 元DB から全特徴量の表を作る
uv run python research/特徴量の組み合わせ探索/rule_scan.py      # ルールで探す
uv run python research/特徴量の組み合わせ探索/model_search.py   # モデルで探す
uv run python research/特徴量の組み合わせ探索/walk_forward.py   # 券種オッズ入りの設定を、年ごとのウォークフォワードで確かめる
uv run python -m pytest -q research/特徴量の組み合わせ探索       # 部品のテスト（架空の値だけ）
```

`extract.py` だけが元DB を読む。ほかは `reports/特徴量の組み合わせ探索/cache/` の表だけを使う。

## 結果

[docs/結果.md](docs/結果.md)。数値は `reports/特徴量の組み合わせ探索/結果.md` と `walk_forward/結果.md`（Git 対象外）。

**年ごとのウォークフォワードの結論: 今の当日の予想（「馬体重あり」のモデル・期待値 1.2 以上を買う）は、年ごとに見ると採用基準を満たさない。**
年を合わせた下限がわずかに 100% に届かず、100% を超えた年は半分だけだった。同じモデルで線を毎年直前の1年で選び直すと基準は満たしたが、
下限はちょうど境目で、確定オッズで数えた値である。
