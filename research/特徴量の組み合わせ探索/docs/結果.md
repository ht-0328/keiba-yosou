# 結果

**結論: 馬柱の特徴量の組み合わせでは、回収率 100% を安定して超えるものは見つからなかった。
券種オッズの特徴量を足すと、テスト期間で複勝の回収率が 100% を超えた（ただし点数が少なく、事前の採用基準は満たしていない）。
年ごとのウォークフォワード（2019年〜）で確かめると、今の当日の予想（「馬体重あり」のモデル・期待値 1.2 以上を買う）は、
年ごとに見ると採用基準を満たさなかった。**
数値は `reports/特徴量の組み合わせ探索/結果.md` と `reports/特徴量の組み合わせ探索/walk_forward/結果.md`（どちらも Git 対象外）にある。

## ルールで探した結果

- レースの区分 × 馬の条件 × 人気帯で、約22万通りを数えた。
- 見つける期間で 110% を超え、確かめる期間でも 100% を超えたルール（採用）は、単勝で数百、複勝で十数あった。
- しかし採用したルールは、**テスト期間では、何も絞らずに同じ人気帯を買ったときと同じか、それより悪かった**。
  「東京の芝の短距離で、10番人気以下の、前走の上がりが遅い馬」のような、もっともらしいルールも含めてである。
- 3つの期間すべてで 100% を超えたルールもあったが、数は偶然で出る数と同じくらいで、
  どれも z（100% との差 ÷ 標準誤差）が 2 に届かなかった。単勝の 10番人気以下は払戻のばらつきが大きく、
  数百点では 1〜2回の大穴で回収率が 100% を上下する。

**なぜか。** 1つの特徴量で分かる程度の有利・不利（外枠、馬体重、前走の上がりなど）は、オッズにすでに織り込まれている。
その馬が有利なら人気になり、払戻が下がる。22万通りも試すと、偶然だけで良く見えるものが必ず混ざる（多重比較）。

## モデルで探した結果

`custom_binary` のモデルを、目的（勝利・馬券内）× 特徴量の組 × レースの区分（全体・芝ダ×距離帯）の 54通りで学んだ。

| 特徴量の組 | 中身 | 分かったこと |
|---|---|---|
| 馬柱だけ（form） | 今回のオッズ・人気を使わない | 各レースで確率1位を買うと、1番人気を買うのとほぼ同じ回収率。期待値で買うと大きく負ける（下） |
| 馬柱＋オッズ（form_odds） | オッズ・人気も特徴量にする | 確率の当たり具合（AUC）は上がるが、回収率は市場並み |
| 馬柱＋オッズを出発点（form_base） | `odds_baseline: true` | 期待値で買う点数がまともになった。確かめる期間で 100% を超えた買い方もあったが、テスト期間では続かなかった |

**`custom_binary` の問題が1つ見つかった。** オッズを出発点にしないモデルは、大穴にも数%の確率を付ける。
オッズ100倍の馬に 2% を付けると期待値が 2 になるので、「期待値1以上を買う」が全出走馬の半分以上を買う買い方になり、
回収率が大きく下がった。これを直すため、`custom_binary` に `odds_baseline` を足した（[docs/custom_binary.md](../../../docs/custom_binary.md)）。
直したあとは、期待値1以上の点数が数十分の一になり、確率として使える値になった。それでも市場を上回るまでには届かなかった。

## 券種オッズの特徴量を足した結果（2回目の探索）

計画「券種オッズの特徴量で、custom_binary を回収率 100% 超にする計画」に沿って、
`custom_binary` に券種オッズの特徴量12個（3連単・3連複などから見た確率と、単勝との差）を足し、
馬券内モデル（`odds_baseline: true`）で複勝を期待値で買った。

- **券種オッズを足すと、確率の当たり具合（ログ損失）が良くなった**（計画の前提2）。
- **全レースのモデルでは、テスト期間で複勝の回収率が 100% を超えた。** 期待値の線を上げるほど回収率が上がり、
  研究「回収率100超」と同じ形になった（前提4）。券種オッズだけのモデルでも、線 1.0〜1.3 のどれでも 100% を超えた。
- ただし、**事前に決めた採用の基準（点数 300 以上・開催日単位の下限 100% 以上）を全部満たした設定は無かった。**
  線 1.2 の買い方は、テスト期間（2025年1月〜2026年9月）で点数が 200点台しかなく、下限が 100% に届くものと届かないものがあった。
- 券種オッズを足さないモデル（比べる相手）は、同じ買い方でテスト期間 100% に届かなかった。上乗せは券種オッズから来ている。
- 区分ごと（芝ダ×距離帯・人気帯）の結果は多重比較なので参考に留める。

## 年ごとのウォークフォワードで確かめた結果（3回目）

テスト期間だけでは点数が足りなかったので、入口⑤（`walk_forward.py`）で、2019年から1年ずつ
「その年より前で学習し直して、その年を予測する」をくり返した。直前の1年は早期終了と線の選択だけに使い、
採用の基準は結果を見る前に README に書いた（年を合わせて点数 300 以上・回収率 100% 以上・開催日単位の下限 100% 以上、
かつ 100% 以上の年が半分を超える）。確かめたのは、当日の予想の「馬体重あり」と同じ設定（`pool_main_all`）と、
券種オッズを足さない比べる相手（`pool_ref_form_all`）。券種オッズの特徴量は、2017年からどの年も元DB の確定オッズで作れた。

| 買い方 | 判定 | 分かったこと |
|---|---|---|
| 今の当日の予想と同じ（期待値 1.2 以上で固定） | **不採用** | 年を合わせた回収率は 100% を超えたが、下限がわずかに 100% に届かず、100% を超えた年は8年のうち半分だけ。1年あたりの点数が100点前後と少なく、年ごとの上下が大きい |
| 同じモデルで、線を毎年、直前の1年の成績で選び直す | 採用（境目） | 4つの基準を満たしたが、下限はちょうど 100% の境目で、余裕は無い。選ばれた線は年によって 1.0〜1.2 と動いた |
| 券種オッズを足さない比べる相手 | 不採用 | どの年もほぼ 100% に届かない。上乗せは券種オッズから来ている（2回目と同じ） |

**結論: 今の当日の予想は、年ごとに見ると採用基準を満たさない。** 券種オッズの上乗せは年をまたいでも見えるが、
線 1.2 では点数が少なく、100% を超えるかどうかは年の当たり外れに左右される。
線を毎年選び直す買い方は基準を満たしたが、境目ぎりぎりで、確定オッズで数えた値である。
どちらも「実際のお金で買ってよい」と言える強さではない。

## ここから何をすればよいか

- 当日の予想を実際のお金で使う前に、締め切り前のオッズで、年ごとのウォークフォワードと同じ数え方をし直す
  （確定オッズでも境目なので、買う時点のオッズで下限が 100% を割るなら使わない）。
- 当日の予想の線 1.2 は、点数が少なすぎて年ごとの上下が大きい。線を下げて点数を増やすか、
  毎年直前の1年で選び直す形にするかを、上の締め切り前のオッズの結果を見てから決める。
- 確定オッズで検証しているので、買う時点のオッズで同じ結果になるかは別に確かめる必要がある。
  発売中の全券種オッズは、jvdata-store の `jvstore realtime` で取り込める。当日の予想は `tools/当日の予想/run.bat` で出せる。
