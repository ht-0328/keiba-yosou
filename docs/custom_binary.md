# 特徴量を選んで予想する

`custom_binary` は特徴量テキストとYAMLで条件を決める独立モデルです。既存の予想モデルを変更せずに使えます。

## 使い方

リポジトリ直下で実行します。初回は `uv sync` でPyYAMLを含む依存パッケージを入れてください。

```powershell
uv run python -m yosou.custom_binary features
uv run python -m yosou.custom_binary train --config examples/custom_binary/model.yml
uv run python -m yosou.custom_binary predict <レースID> --models reports/custom_binary/top3_pop6_10
uv run python -m yosou.custom_binary evaluate --models reports/custom_binary/top3_pop6_10
```

`<レースID>` は実際の16桁のIDに置き換えます。`--db` で元DBを指定できます。省略時は `YOSOU_DB` または隣の `jvdata-store/jvdata.duckdb` を使います。元DBは読取専用で開き、学習前に接続を閉じます。

出力形式は `--format markdown|csv|json`、保存先は `--out ファイル名` で指定します。元データ由来の出力はGit対象外の `reports/` に保存してください。

## 条件を変更する

`examples/custom_binary/model.yml` と `features.txt` をコピーして編集します。

```yaml
name: win_pop1_3
features_file: features.txt
target: 勝利
timing: 前日
popularity:
  min: 1
  max: 3
```

| 設定 | 意味 |
|---|---|
| `name` | 保存先 `reports/custom_binary/<name>`。既存の名前は上書きできない |
| `features_file` | YAMLからの相対パス、または絶対パス |
| `target` | `馬券内`は1〜3着、`馬券外`は4着以下と中止・失格、`勝利`は1着。同着は確定着順に従う |
| `timing` | `木曜`・`前日`・`当日`。1設定につき1時点 |
| `popularity.min/max` | 両端を含む人気範囲。学習・検証・テスト・予想すべてに適用 |
| `conditions` | 特徴量の値で対象の馬を絞る条件（下の「対象を条件で絞る」）。学習・検証・テスト・予想すべてに適用 |
| `odds_baseline` | `true` にすると、オッズから見た確率をモデルの出発点にする（下の「オッズを出発点にする」）。省略時は `false` |
| `training` | `warmup_from`・`train_from`・`valid_from`・`test_from` を日付で指定 |
| `lightgbm/catboost` | 既存モデルと同じ `early_stopping_rounds` と `params`。LightGBMの `min_category_count` も指定可 |

人気範囲を省略すると全人気です。`min: 6` だけなら6番人気・7番人気…（6番人気より人気のない馬）、`max: 3` だけなら1〜3番人気が対象です。`null`は使わずキーを省略してください。学習・検証の対象が空、または正解が一方のクラスだけの場合は停止します。

学習期間の既定値はウォームアップ2020-01-01、学習2021-08-01、検証2025-07-01、テスト2026-01-01です。`train_from`を変更して `warmup_from` を省略した場合は、学習開始日の前年1月1日がウォームアップ開始になります。検証開始より前で学習、検証開始からテスト開始より前で早期終了を判定し、テストは学習から分離します。

特徴量は正式名称を1行ずつ書きます。UTF-8（BOM付き可）で保存してください。空行と `#` から始まる行は数えません。重複・誤記・時点に合わない項目は行番号付きでエラーになります。10項目を指定したらモデル入力も10列です。

人気順位は絞り込みに使いますが、特徴量として指定しない限り入力しません。オッズによる基準確率は `odds_baseline: true` のときだけ使います。予想はLightGBMとCatBoostの確率の単純平均です。確率は0〜1で表示し、0.25は25%を表します。馬券外モデルの高い確率は「来やすい」ではなく「馬券外になりやすい」を意味します。

## 対象を条件で絞る

`conditions` に「特徴量の名前: 条件」を並べると、すべてに当てはまる馬だけで学習・評価・予想します。
「短距離のレースで、馬体重が 440kg 以下の馬」のような対象を、そのままモデルにできます。

```yaml
conditions:
  芝ダ: 芝                 # カテゴリの特徴量は値を1つ、または [東京, 中山] のようにリストで
  距離: {max: 1400}        # 数値の特徴量は min・max（両端を含む）。片方だけでもよい
  馬体重: {max: 440}
```

- 名前は `features` コマンドで出る正式名称です。特徴量テキストに書いていない特徴量も条件に使えます（モデルの入力にはなりません）。
- `timing` の時点で分からない特徴量は使えません（例: 木曜に `馬体重`）。
- 値が欠けている馬は、条件に当てはまらないものとして除きます。
- レース内の比較（`斤量とレースの平均との差` など）は、絞る前の全頭で計算した値で判定します。

## オッズを出発点にする

`odds_baseline: true` にすると、モデルはオッズから見た確率（勝利なら勝率、馬券内なら3着以内率）を出発点にして、
特徴量から「同じオッズの馬より来やすいか・来にくいか」の上げ下げだけを学びます。
既存の予想モデル（`form_aptitude_top3` など）と同じ仕組みです（LightGBM の `init_score`、CatBoost の `baseline`）。

- **期待値（確率×オッズ）で買うなら `true` にしてください。** `false` のモデルは大穴にも数%の確率を付けやすく、
  オッズ100倍の馬が期待値2以上に見えて、期待値で買うと大穴ばかり買ってしまいます。
- オッズが分かる `前日`・`当日` だけで使えます。予想するときは全頭の単勝オッズが必要です（DB の速報か `--odds`）。
- 特徴量テキストに `単勝オッズ` を書く必要はありません（書いても動きます）。

## 券種オッズの特徴量

3連単・馬単・3連複・馬連・ワイド・複勝のオッズから、馬ごとの確率を出した特徴量があります（当日から使えます）。

| 特徴量 | 意味 |
|---|---|
| `3連単から見た勝率`・`馬単から見た勝率` | その券種で、この馬が1着の買い目の確率（1/オッズ をレース内で合計1にそろえた値）を足したもの |
| `3連複から見た3着以内率`・`ワイドから見た3着以内率`・`複勝から見た3着以内率` | この馬が入った買い目の確率を足したもの。レース内の合計が3になる |
| `馬連から見た2着以内率` | 同上。レース内の合計が2になる |
| `〜と単勝の差`（6個） | log（上の確率）− log（単勝オッズから見た同じ意味の確率）。プラスなら、その券種は単勝より高く見ている |

売上の大きい券種（3連単・3連複）のオッズには、単勝より多くの人の判断が入っています。
単勝との差は「単勝・複勝が見誤っている向き」の手がかりになります。`odds_baseline: true` と組み合わせて使ってください。

- 元DB の券種オッズを読むのは、これらの特徴量（または条件）を選んだときだけです。
- **発売中のレースでは予想できません。** jvdata-store が締め切り前の券種オッズ（全賭式）をまだ取っていないためです。選んだモデルで `predict` すると「券種オッズが未取得」と出して止まります。

## 予想に必要な情報

発売前の想定人気や、DBにない人気・オッズは手入力できます。

```powershell
uv run python -m yosou.custom_binary predict <レースID> --models reports/custom_binary/top3_pop6_10 --pops 1:3 2:1 3:2
```

上記は書式の例です。実際には全出走馬分を指定してください。木曜で馬番が決まっていない場合は `馬名:人気` を使います。人気の優先順は手入力の人気、手入力のオッズ順、DBの直近速報オッズ順、出走行の人気です。想定人気は発売後の実際の人気を保証しません。

`--odds 馬番:倍率` で単勝オッズを指定できます。選択した項目とその依存項目に必要な馬体重・枠番・馬場・オッズ等が未取得なら停止します。過去走のない馬の履歴欠損は既存の欠損処理で扱います。人気範囲に該当馬がなければ「対象なし」です。

学習した条件は `model.json` に保存します。予想時には元のYAMLやテキストを読みません。条件を変えたら新しい `name` で学習してください。特徴量の名称・順序・型・依存関係、期間、学習パラメータ、コードの版情報を保存します。登録された特徴量の型や依存関係が保存時と違えば再学習を案内します。計算式を変更した場合も再学習してください。

保存中に失敗すると `model.json` のない未完了フォルダが残る場合があります。このフォルダは読み込まず、再実行は別の `name` で行います。

## 特徴量を追加する

1. `feature/` にクラスを追加し、`FeatureDefinition` の共通インターフェースを実装します。元DB から新しいデータを読む必要があるなら、`extra_data/` に読むクラスを作って `SOURCES` に登録し、特徴量に `sources = ("その名前",)` を書きます（例: `feature/pool_probability.py`）。
2. `feature/registrations.py` でそのクラスをimportし、`ADDITIONAL_FEATURES` に `NewFeature(),` を1行追加します。
3. `features` コマンドで確認し、特徴量テキストにその名前を書いて再学習します。

実装例は `examples/custom_binary/carried_difference.py` にあります。`name`・`description`・`kind`・`known_from`・`dependencies` と `compute(records, dependencies)` を定義します。`compute` は `records.entries` と同じインデックス・行順の `pandas.Series` を返してください。引数の記録や依存列は変更しないでください。

依存項目は名前で宣言します。依存順で一度ずつ計算されますが、テキストに指定していない依存項目はモデルには渡りません。レース内比較は人気で絞る前の全頭で行います。重複登録・依存先の誤記・循環・時点不適合・行順の不一致は検出します。

学習時は各対象レースより前に分かるデータだけを使ってください。過去走には他の対象日のデータも入るため、対象日で区切る必要があります。`known_from` は項目の利用可能時点であり、計算処理そのものの未来情報混入を防ぐ仕組みではありません。

既存項目は元のグループ計算に接続し、1回の生成内でグループごとにキャッシュします。新しい元データが必要なら、共通の取得処理と `EntryRecords` の拡張・対応する合成テストも必要です。

## 評価の読み方

学習時に `validation.json`、`evaluate` 実行時に `test_evaluation.json` を保存します。評価は2つの表です。

- **成績**: 件数・正例率・ログ損失・Brierスコア・AUCと人気別成績。正例または負例しかない人気区分ではAUCを空欄にし、理由を表示します。対象がゼロなら対象なしと表示します。
- **回収率**: 1点100円で、次の買い方をしたときの単勝・複勝の的中率と回収率。
  - 対象の全頭（モデルなし）: 人気範囲と条件に当てはまる馬を全部買う。条件そのものの良し悪しが分かります。
  - 各レースで確率1位: 対象の馬のうち、モデルの確率がいちばん高い馬を1頭買う。
  - 期待値1.0以上・1.1以上・1.2以上・1.3以上・1.5以上・2以上: 期待値がその値以上の馬を買う。
    - 勝利モデルの期待値は、確率×単勝オッズ。
    - 馬券内モデルの期待値は、3着以内の確率×複勝の想定払戻倍率。想定払戻倍率は、複勝の最低オッズに、オッズの帯ごとの倍率（学習期間の実際の払戻 ÷ 最低オッズの平均）を掛けた値です。最低オッズのままだと、期待値を低く見積もりすぎるためです。
    - 馬券外モデルは、（1−確率）を3着以内の確率として同じように計算します。
    - 3着以内の確率は、同じレースの全頭がそろっているとき（人気範囲や馬の条件で一部の馬を除いていないとき）だけ、合計が3（7頭以下は2）になるようにそろえ直します。
  - 回収率の下限: 開催日を丸ごと取り直して回収率を1000回計算した、90%の幅の下側の値。**これが100%を超えて初めて、偶然ではなく100%を超えたと言えます。**

検証期間は早期終了の判定にも使っているため、検証期間の成績はやや良く出ます。モデルや買い方の良し悪しは、`evaluate`（テスト期間）で判断してください。

履歴の評価には確定人気・確定オッズを使用します。木曜・前日・当日の設定は入力項目を制限するもので、当時の発表時刻・購入時刻を再現した検証ではありません。評価での人気範囲と、実運用時の想定人気・速報人気による範囲は一致しない場合があります。

回収率は確定オッズ・確定払戻で計算した参考値です。買う時点のオッズは確定オッズと違うため、実際の回収率はこれより下がりえます。
複勝の発売条件（7頭以下は2着まで）は、実際の払戻で計算しているので反映されています。
