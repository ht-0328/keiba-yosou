# 16 当たり具合の測り方と採用の基準

**この文書で決めること:** 学習に使っていないデータで、3つの予想の当たり具合をどう測るか。学習・検証・テストの期間をどう分けるか。何と比べれば「当たっている」と言えるか。どうなれば使ってよいと判断するか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 時期で分ける。既定は 学習 2017年1月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜（ウォームアップは 2016年）。先頭の予想だけ、検証を前半（早期終了）と後半（温度）に分ける |
| 2. 評価指標 | 予想ごとに、いちばん大事な指標を1つ決める。①はレースごとのログ損失、②③の区分は多クラスのログ損失、③の秒数は MAE。ほかの指標は補助に出す |
| 3. 比べる基準 | モデルによらない簡単な予想（全馬に同じ確率、先頭率をそろえただけのもの、今ある推定脚質、学習データの割合、基準の秒数だけ）と並べる。基準と同じなら、モデルは何も学んでいない |
| 4. 正解を作らなかったレースの確かめ | 先頭が決まらないレースなどの割合を条件ごとに出し、一部を元の記録と照らし合わせる |
| 5. 採用の基準 | 結果を見る前に決めておく（[15-decisions.md の 10](15-decisions.md#10-採用の基準)） |
| 6. 期間をずらした確かめ | 検証期間を半年ずつずらした6つの期間で、同じ向きの差が出るかを見る |

用語の意味は [02-glossary.md](02-glossary.md) を参照。当たり具合を測るクラスは [04-classes.md の「evaluation/」](04-classes.md#evaluation--当たり具合と比べる基準) を参照。

## 1. 期間の分け方

| 区分 | 何に使うか | 既定 |
|---|---|---|
| ウォームアップ | 序盤の履歴と基準を計算するためだけに読む。サンプルにしない | 2016年1月〜12月 |
| 学習 | モデルの `fit` に渡す | 2017年1月〜2025年6月 |
| 検証 | 早期終了と、下の指標で当たり具合を見る。特徴量やハイパーパラメータを直すときは、ここで比べる | 2025年7〜12月 |
| 　検証の前半（①だけ） | ①の早期終了 | 2025年7〜9月（検証の開催日の真ん中で切る） |
| 　検証の後半（①だけ） | ①の温度を決める | 2025年10〜12月 |
| テスト | 候補を1つに決めたあと、最後に1回だけ確かめる。直す判断には使わない | 2026年1月〜 |

- 時期で分ける（レースを混ぜてくじで分けない）。同じ開催日のレースや、同じ馬の前後の走が学習と検証に散らばると、実際より当たって見えるためである（手本と同じ）。
- ①だけ検証を2つに分けるのは、木の数と温度を別のデータで決めるためである（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 10）。②③は温度を使わないので、検証データ全体で早期終了する。
- ①の検証データの指標は、温度を決めた後半も含むので、少し良く出る。採用は、6. の期間をずらした確かめと、テストデータで決める。
- 区切りの日は `train` の引数で変えられる（[08-training-data.md の 4.](08-training-data.md#4-期間の指定)）。

## 2. 評価指標

学習の報告（`train` の出力）に、予想ごと・時点ごとに出す。どれも検証データで測る。**太字がいちばん大事な指標**で、採用の判断はこれで行う。

| 予想 | 指標 | 意味 | 良い向き |
|---|---|---|---|
| ① 先頭 | **レースごとのログ損失** | 各レースで、実際に先頭になった馬に付けた確率 p の `−log(p)` を、レースで平均した値 | 小さいほど良い |
| ① 先頭 | 確率1位の的中率 | 確率がいちばん高い馬が先頭だったレースの割合 | 大きいほど良い |
| ① 先頭 | 上位3頭の的中率 | 確率の高い3頭の中に先頭がいたレースの割合 | 大きいほど良い |
| ① 先頭 | 確率の帯ごとの実際の割合 | 「先頭の確率 0.2〜0.3」と出した馬が、実際に何割先頭だったか。頭数（〜10頭・11〜14頭・15頭〜）別にも出す | 出した確率に近いほど良い |
| ②・③の区分 | **多クラスのログ損失** | 3つの確率が正解から外れた大きさ（1行ずつの平均） | 小さいほど良い |
| ②・③の区分 | 正解率・マクロ F1・混同行列・クラスのずれの平均 | 共通の `ClassModelEvaluator` がそのまま出す（[荒れ具合の 16 の「2. 評価指標」](../レースの荒れ具合を4段階で予想/16-evaluation.md#2-評価指標)） | ― |
| ③ 前半タイム | **MAE** | 予測の真ん中の値（50% の分位点）と、実際の前半タイムの差の絶対値の平均（秒） | 小さいほど良い |
| ③ 前半タイム | 分位点の損失 | 10%・50%・90% の分位点の当たり具合（scikit-learn の `mean_pinball_loss`）の平均 | 小さいほど良い |
| ③ 前半タイム | 80% の予測区間の包含率と平均の幅 | 実際の前半タイムが 10%〜90% の幅に入った割合と、その幅の平均（秒）。測る区間（500・550・600m）別にも出す | 包含率は 80% に近く、幅は狭いほど良い。幅を広げて包含率だけを上げても良いとはしない |

- **時点ごとに出す。** 木曜は枠が分からないので、前日・当日より当たりにくいはずである。その差の大きさも見る。
- **条件ごとにも出す。** 芝ダ・距離帯・頭数・新馬戦かどうか・基準の段（同じクラス／クラスをまとめた）ごとに出し、`reports/race_development/` に置く。件数が少ない条件は「確かめきれない」として扱い、一部の条件だけの良さを全体に広げない。
- **今ある見立てとの比べ方。** ①は、推定脚質が「逃げ」の馬を先頭とみなす今ある見立て（下の 3.）と比べる。

## 3. 比べる基準

モデルによらない簡単な予想を、同じ検証データ・同じ指標で出して並べる（`DevelopmentBaselines`）。**いちばん強い基準と同じなら、モデルは何も学んでいない。** 基準の割合は、すべて学習データだけで数える。

| 予想 | 基準 | 何を出すか |
|---|---|---|
| ① 先頭 | 全馬に同じ確率 | 1 ÷ 頭数 |
| ① 先頭 | 先頭率をそろえただけ | K の先頭率（平滑化したもの）を、レースの中で合計 1 に割り直したもの。モデルが「過去の先頭率」以上のことを学べているか |
| ① 先頭 | 推定脚質 | 推定脚質が逃げの馬に、確率を等分する。逃げの馬がいなければ全馬に等分する。今ある見立て（事実表の `style_before`） |
| ② 序盤の位置 | 学習データの割合 | 先団・中団・後方の割合を、全馬に同じ確率として出す |
| ② 序盤の位置 | 前走の区分からの割合 | 前走の序盤の区分ごとに、今回の区分の割合を学習データで数えた表。前走が無ければ全体の割合 |
| ③ ペースの区分 | 学習データの割合 | ハイ・平均・スローの割合 |
| ③ ペースの区分 | 逃げそうな馬の数からの割合 | 逃げそうな馬の数（0・1・2・3以上）ごとの、ペースの区分の割合を学習データで数えた表。今ある見立て |
| ③ 前半タイム | 基準だけ | 基準との差を 0 と予測する（前半タイム = 基準）。予測区間は、学習データの基準との差の 10%・90% の分位点を、どのレースにも足す |

## 4. 正解を作らなかったレースの確かめ

正解を作れるレースだけで学習・評価すると、「作れるレース」だけで当たりが良く見えることがある（[10-target.md の 2.](10-target.md#2-先頭の馬の目的変数)）。そのため、学習のたびに次を出す。

| 確かめること | 出し方 |
|---|---|
| 正解を作らなかったレースの割合 | 理由（先頭が決まらない・コーナーを5回以上通る・直線・記録なし・基準なし）ごとに、頭数・競馬場・ペースの区分別の割合を表にする |
| 先頭が決まらないレースの中身 | 検証期間から 20 レースを抜き出し、`tools/レース詳細/race.py` の通過順と照らし合わせて、決まらない理由が「並んで先頭」だけかを目で見る |
| 数え方の元の記録との一致 | 事実表に足した列（最初のコーナーの番号・先頭の馬番）を、同じ 20 レースで元の `ra__コーナー通過順位` の文字列と照らし合わせる |

## 5. 採用の基準

**結果を見る前に決めておく。** 結果を見てから基準を決めると、都合のよい基準を選んでしまうためである。予想ごとに判断し、4つのうち基準を満たしたものだけを使う。

| 判断すること | 使ってよい条件（おすすめ。[15-decisions.md の 10](15-decisions.md#10-採用の基準) で決める） |
|---|---|
| 検証データ | いちばん大事な指標が、いちばん強い基準より 1% 以上良い |
| 期間をずらした確かめ（6.） | 6つの期間のうち 5つ以上で、いちばん強い基準より良い |
| テストデータ | 候補を1つに決めてから1回だけ測り、いちばん強い基準より悪くない。悪ければ、テストデータに合わせて直すことはせず、採用しない |
| 確率・幅の当てはまり | ①の確率の帯ごとの実際の割合が、帯から大きく外れていない。③の 80% の予測区間の包含率が 70〜90% に入っている |

- 1% は、差が偶然でないと言うための目安で、この値なら当たるという保証ではない。
- 基準を満たさなかった予想も、結果と理由を `reports/race_development/` に残す。表示用・研究用としては使える。
- 既存の予想（3着以内など）に渡してよいかは、この基準とは別に、渡したときに既存の予想が良くなるかで決める（[15-decisions.md の 11](15-decisions.md#11-既存の予想に渡すか)）。

## 6. 期間をずらした確かめ

検証期間を半年ずつずらして6回学習し、いちばん大事な指標を基準と比べる。1つの検証期間の結果は、その期間の偶然に左右されるためである。

| 回 | 学習 | 検証 |
|---|---|---|
| 1 | 2017年1月〜2022年12月 | 2023年1〜6月 |
| 2 | 2017年1月〜2023年6月 | 2023年7〜12月 |
| 3 | 2017年1月〜2023年12月 | 2024年1〜6月 |
| 4 | 2017年1月〜2024年6月 | 2024年7〜12月 |
| 5 | 2017年1月〜2024年12月 | 2025年1〜6月 |
| 6 | 2017年1月〜2025年6月 | 2025年7〜12月（既定と同じ） |

```powershell
uv run python -m yosou.race_development train --valid-from 2023-01-01 --test-from 2023-07-01 --models reports/race_development/periods/2023H1
```

（1回目を学習するコマンド。検証を 2023年1〜6月にし、モデルを期間ごとのフォルダに保存する。2回目からは日付を半年ずつずらす。テストデータ（2026年1月〜）は、どの回でも使わない）

- 6つの期間は、特徴量や設定を直すたびに同じものを使う。直すたびに期間を選び直すと、たまたま良い期間を選んでしまう。
- 6回の結果を見ながら直しを重ねると、6つの期間にも合わせてしまう。**6つの期間は「独立した6回のテスト」ではない。** 最後の判断はテストデータで行う。
