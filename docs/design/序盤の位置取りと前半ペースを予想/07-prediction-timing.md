# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使える情報が変わる。

**結論: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする（利用者が 2026-09-26 に決めた）。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（4つの予想 × 3つの時点 × LightGBM と CatBoost）。木曜は枠番・馬番が分からないので、内側・外側の相手を見る特徴量を使わない。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。時点ごとに分かること（木曜・前日・当日）と、時点ごとにモデルを分ける理由は手本と同じで、[手本の 07](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに分かること) を参照。

## この予想で時点が効くところ

| 時点 | 分かること（この予想に効くもの） | まだ分からないこと |
|---|---|---|
| 木曜（出走馬名表） | 出走予定の馬、騎手、過去走（序盤の位置取りの履歴）、コース | 枠番・馬番、馬場状態、馬体重 |
| 前日（出馬表） | 上に加えて枠番・馬番、前日発表の馬場状態 | 馬体重、当日の馬場状態 |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態 | 結果 |

**枠番・馬番は、位置取りにいちばん効くと考えられる材料である。** 内枠の馬は短い距離で前に行きやすく、外枠の馬は前に行くのに脚を使う。木曜はこれが分からないので、木曜の予測は前日・当日より当たりにくいと見込む。どれだけ違うかは、時点ごとの当たり具合で確かめる（[16-evaluation.md](16-evaluation.md#2-評価指標)）。

オッズは、どの時点でも使わない（[09-features.md の「使わない特徴量」](09-features.md#使わない特徴量)）。

## 時点ごとに使う特徴量

### 1頭ごと（予想①②）

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 98個のうち） | 特徴量の数 |
|---|---|---|
| 木曜（出走馬名表） | 手本と同じ9個（枠番、馬番、馬体重、馬体重の増減、馬場状態、同じ芝ダ・馬場状態での通算の出走数・3着以内の数、持ち時計のレース内順位2つ）と、L の3個（自分より内の馬の先頭率の合計、自分より外の馬の先頭率の合計、相対馬番） | 86 |
| 前日（出馬表） | 馬体重、馬体重の増減 | 96 |
| 当日（馬体重の発表のあと） | なし | 98 |

### 1レースごと（予想③）

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 27個のうち） | 特徴量の数 |
|---|---|---|
| 木曜（出走馬名表） | 馬場状態（R）、先頭率の1位の馬の相対馬番（P） | 25 |
| 前日（出馬表） | なし | 27 |
| 当日（馬体重の発表のあと） | なし | 27 |

- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書く。手本と同じ仕組みである。
- 前半タイムの基準は、馬場状態を使わずに作るので、どの時点でも同じ値になる（[10-target.md の 5.](10-target.md#5-前半タイムの基準の作り方)）。馬場状態は、前日と当日に特徴量として入る。
- 前日の馬場状態は前日発表の値、当日は当日の発表の値を使う。学習データの馬場状態は確定の値なので、当日に馬場が変わると少しずれる（手本と同じ扱い）。

## 取消が出たときの扱い

| 時点 | 相手の数え方 |
|---|---|
| 木曜 | 出走馬名表の全馬で、L（同じレースの馬との比較）と P（ペースの材料）を作る。あとで取消が出ると、実際の相手と変わる |
| 前日・当日 | 速報の取消・除外を反映したあとの馬で作る |

- 取消が出たら、同じ時点でも出し直す。1頭が抜けると、ほかの全頭の先頭の確率と、ペースの確率が変わるためである。
- 学習データは、確定した出走馬（実際に走った馬）で作る。木曜・前日の予測では、あとで取消になる馬が相手に入ることがあり、学習のときとは少し条件が違う。今の元DB は出馬表を新しい版で上書きするので、過去の木曜・前日の出走予定の馬を作り直せないためである（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 9）。

## 予測のコマンド

```powershell
uv run python -m yosou.race_development predict 2026100404050311 --timing 前日
uv run python -m yosou.race_development predict 2025102605050211 --timing 当日
```

（1行目は、これから走るレースの展開を、前日の時点で予測するコマンド。2行目は、終わったレースを当日の時点で予測し直すコマンド。どちらも、1頭ごとの表と、レースの1行の表を出し、`reports/race_development/predictions/` に記録を書き足す）

- 前日・当日の予測の前に、jvdata-store で `uv run jvstore realtime --date <開催日>` を実行して、速報の馬場状態・取消・馬体重を取り込んでおく（手本と同じ）。
- `--odds` は無い。オッズを使わないためである。
