# 16 当たり具合の測り方と「買い」の線引き

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。予測確率から、どの穴馬を「買い」とするか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 学習データの始まりから検証データの始まりの前日までが学習、そこからテストデータの始まりの前日までが検証、それ以降がテスト。既定は 学習 2021年8月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜。`train` の引数で変えられる |
| 2. 評価指標 | 一般的な3つ（ログ損失・AUC・Brier）に加えて、**人気順をなぞるだけになっていないか**を見る4つ（確率1位の穴馬の3着以内率と複勝回収率、人気最上位の穴馬の同じ値（基準）、人気の中での AUC）。どの予想でも同じ指標を使う |
| 3. 「買い」の線引き | 予測確率がしきい値以上の穴馬を買う。しきい値は、検証データの複勝回収率と頭数を見て決める。設計書には数字を入れず、結果は `reports/穴馬が3着以内に入るかを予想/` に置く |
| 4. 半年ずつずらした確かめ | 予想を直すときは、手本と同じ7つの半年の区切りで学習し直す。大穴でも、直す前・大穴を全部買う・人気最上位の大穴を選ぶより良いかを見る（2026-09-28 に足した） |

用語の意味は [02-glossary.md](02-glossary.md) を参照。指標を計算するクラス（`MetricCalculator`）と学習の結果の表（`TrainingReportTables`）は共通の部品で、[04-classes.md](04-classes.md#1-共通の部品とこの予想だけの部品の分け方) の `evaluation/`・`command/` にある。

## 1. 期間の分け方

| 区分 | 何に使うか | 既定 |
|---|---|---|
| ウォームアップ | 過去走の特徴量を計算するためだけに読む。サンプルにしない | 2020年1月〜2021年7月 |
| 学習 | モデルの `fit` に渡す | 2021年8月〜2025年6月 |
| 検証 | 早期終了の判断と、下の指標で当たり具合を見る。特徴量やハイパーパラメータを直すときは、ここで比べる | 2025年7〜12月 |
| テスト | 最後に1回だけ確かめる。直す判断には使わない（使うと、テストの結果に合わせて直してしまう） | 2026年1月〜 |

- 時期で分ける（レースを混ぜてくじで分けない）。同じ開催日の別のレースや、同じ馬の前後の走が学習と検証に散らばると、実際より当たって見えるためである。
- 区切りの日は `train` の引数（`--train-from` `--valid-from` `--test-from`）で変えられる（[08-training-data.md](08-training-data.md#4-期間の指定)）。

## 2. 評価指標

学習の報告（`train` の出力）に出す。どれも検証データで測る。

| 指標 | 意味 | 良い向き | 何が分かるか |
|---|---|---|---|
| ログ損失 | 確率が正解から外れた大きさ | 小さいほど良い | 確率として使えるか |
| AUC | 3着以内に入った馬に、入らなかった馬より高い確率を付けられた割合 | 大きいほど良い（0.5 はでたらめ） | 並べ方の当たり具合 |
| Brier | 確率と正解（0 か 1）の差の2乗の平均 | 小さいほど良い | 確率の大きさが合っているか |
| 確率1位の穴馬の3着以内率 | 各レースで確率がいちばん高い穴馬を1頭選んだとき、3着以内に入った割合 | 大きいほど良い | 1頭選ぶ使い方での的中率 |
| 確率1位の穴馬の複勝回収率 | その1頭の複勝を 100円ずつ買ったときの、払戻の合計 ÷ 買った金額 | 大きいほど良い（1 で元返し） | 1頭選ぶ使い方で儲かるか |
| 人気最上位の穴馬の3着以内率・複勝回収率 | 各レースで人気がいちばん上の穴馬（13頭以下なら 4番人気、14頭以上なら 6番人気）を選んだときの同じ値。モデルによらない**基準** | ― | 上の2つと同じなら、モデルは人気順をなぞっているだけ |
| 人気の中での AUC | 同じ確定単勝人気の穴馬どうしで比べた AUC を、頭数で重み付けして平均したもの | 大きいほど良い（0.5 なら何も当てていない） | 人気で説明できないところを、どれだけ当てているか |

**人気の基準と比べる理由。** 穴馬の3着以内率は、人気で大きく違う（4番人気と 12番人気では何倍も違う）。そのため、各レースで確率がいちばん高い穴馬は、ほとんどの場合、人気がいちばん上の穴馬になる。AUC が高くても、それは「人気順に並べただけ」で得られる分を含んでいる。モデルが人気以上のことを見つけているかは、人気の基準と並べるか、同じ人気の中で比べないと分からない。

**2026-09-24 からは、表が区分ごとに出る。** 中穴と大穴で別のモデルを学習するようになったため（[15-decisions.md の 12](15-decisions.md#12-既存モデルの修正計画での直し)）、`train` の出力は「中穴: 検証データでの当たり具合」のように区分ごとになる。そのとき「人気最上位の穴馬」は、各レースのその区分の中で人気がいちばん上の馬（中穴の表なら 4番人気か 6番人気、大穴の表なら 7番人気か 10番人気）である。

**最初に学習したときの結果（2026-09-23）。** 確率1位の穴馬の3着以内率と複勝回収率は、人気最上位の穴馬とほぼ同じだった。つまり、1頭選ぶ使い方では人気順をなぞっているだけである。ただし、人気の中での AUC は 0.5 より大きく（0.6 弱）、人気以外の手がかりも少しは効いている。予測確率で絞る使い方（下の 3）では、しきい値を上げるほど3着以内率と複勝回収率が上がるが、複勝回収率が 1 を超えるのは頭数がごく少ない範囲だけだった。数値は `reports/穴馬が3着以内に入るかを予想/`（Git 対象外）にある。

## 3. 「買い」の線引き

**予測確率がしきい値以上の穴馬を買う。** 1レースに何頭でもよく、1頭もいないレースは買わない。

- 1頭選ぶ使い方（確率1位）は、人気最上位の穴馬を選ぶのとほぼ同じになるので、線引きに使わない。
- しきい値は、検証データで「しきい値ごとの頭数・3着以内率・複勝回収率」を並べて決める。複勝回収率が高くても、頭数が少なすぎる（半年で数十頭）しきい値は、偶然の幅が大きいので採らない。
- 決めたしきい値は設計書に書かず、`reports/穴馬が3着以内に入るかを予想/` に置く。値は学習し直すたびに変わるためである。
- 区分（中穴・大穴）で絞るのは、しきい値と組み合わせて使える（`--zone`。[07-prediction-timing.md](07-prediction-timing.md#予測のときの人気の与え方)）。

## 4. 半年ずつずらした確かめ

予想を直すときの確かめ方（7つの半年の区切りで学習し直す、区切りの日、動かし方）と、ハイパーパラメータの調整のやり方は、[手本の 16 の「4.」「5.」](../近走と適性から3着以内を予想/16-evaluation.md#4-半年ずつずらした確かめ) と同じである。`walk_forward.py` の `--model` に `longshots_in_top3` を渡し、表は `reports/既存モデルの改善/compare/longshots_in_top3.md` に出る。

| 項目 | この予想では |
|---|---|
| 比べる作り方 | 直す前（現行）・オッズだけで学習したモデル・基準＋補正（区分で分けない）・直した後（中穴と大穴で分ける）の4つ |
| 採用の基準 | 中穴・大穴それぞれで、テスト期間のログ損失がオッズだけのモデルより小さいこと。そのうえで、大穴を期待値で買う方法が、直す前の選び方・大穴を全部買う方法・人気最上位の大穴を選ぶ方法より回収率が高いこと。回収率には、開催日を単位にしたブートストラップの 90% の幅を添える |

2026-09-24 に、この確かめで直した後の予想を採用した。結果は [15-decisions.md の 12](15-decisions.md#12-既存モデルの修正計画での直し) を参照。
