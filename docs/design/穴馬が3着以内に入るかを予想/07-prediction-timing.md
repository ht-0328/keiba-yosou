# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。予測のときに、人気をどうやって渡すか。

**結論: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする（利用者の指示。[15-decisions.md](15-decisions.md#8-木曜の人気の渡し方)）。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（LightGBM と CatBoost に3つずつ、計6つ）。人気は、利用者が `--pops` で全頭ぶん渡す（木曜は馬名で、前日・当日は馬番で）。前日・当日は、元DB の締め切り前のオッズからも作れる。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと | 人気の元 |
|---|---|---|---|
| 木曜（出走馬名表） | 出走馬、騎手、斤量、過去走、出走別着度数（20時ごろ）、それまでの調教 | 枠番・馬番、**人気**（前売りも始まっていない）、馬体重、馬場状態 | 利用者の見立て |
| 前日（出馬表） | 上に加えて枠番・馬番、前日発表の馬場状態、前日発売の単勝オッズ（JRA の発表） | 馬体重、当日の馬場状態、締め切り前のオッズ | 利用者が見た人気、または元DB のオッズ |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前のオッズ | 確定オッズ、結果 | 同上 |

**木曜にも出す理由と、その代わりに引き受けること。** 危険な人気馬の予想は、木曜は馬番も人気も決まっていないので出さない（[人気馬の 07](../人気馬が4着以下になるかを予想/07-prediction-timing.md#時点ごとに分かること)）。この予想は、利用者の指示で木曜も出す。木曜は人気が無いので、利用者が「何番人気になりそうか」を自分で見立てて渡す。見立てが確定の人気とずれると、穴馬の範囲に入る馬も、中穴か大穴かも変わる。前日・当日に出し直して、ずれを小さくする。

## 予測のときの人気の与え方

人気は、レースの前には確定しない（確定単勝人気は、発売の締め切り後に決まる）。そのため、予測のときは、次の順で人気を決める。判断の手順は [06-flowchart.md](06-flowchart.md#図2-予測用データに人気を当てる) を参照。

| 順 | 人気の元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--pops` で渡した人気。木曜は `馬名:人気`、前日・当日は `馬番:人気`。**全頭ぶん渡す** | 3つの時点すべて。木曜は、これしか使えない |
| 2 | 利用者が `--odds 馬番:オッズ` で全頭ぶん渡した単勝オッズ（小さい順に人気を付ける） | 前日・当日。2026-09-24 に足した（[15-decisions.md の 12](15-decisions.md#12-既存モデルの修正計画での直し)） |
| 3 | 元DB の締め切り前の単勝オッズ（小さい順に人気を付ける） | 前日の夜（前日発売のあと）と当日。予測の前に jvdata-store で `uv run jvstore realtime --date <開催日>` を実行して、速報オッズ（`0B31`）を `o1` に取り込んでおく。今の元DB には断面がごく少数しか無く、取り込んでいないレースでは使えない |
| 4 | 元DB の出走の行に入っている単勝人気 | **終わったレースだけ**（確定単勝人気）。これから走るレースでは空なので、止めて `--pops` を案内する |

前日・当日は、オッズから作った基準とまとまり K に、人気とは別に単勝オッズが要る。オッズは、手本と同じ順（`--odds` → 締め切り前のオッズ → 確定オッズ）で決める（[手本の 07 の「予測のときのオッズの与え方」](../近走と適性から3着以内を予想/07-prediction-timing.md#予測のときのオッズの与え方)）。2番目は、そのオッズを人気にも使うものである（`PopularityApplier`）。

4番目は、**終わったレースで「この予想が当たっていたか」を確かめるためにある。** 走る前の予測では、1〜3 でしか人気が分からない。

```powershell
uv run python -m yosou.longshots_in_top3 predict 架空レースA --timing 木曜 --pops 架空馬イ:1 架空馬ロ:2 架空馬ハ:3 …（16頭ぶん）
uv run python -m yosou.longshots_in_top3 predict 架空レースA --timing 前日 --pops 3:1 7:2 11:3 …（16頭ぶん）
uv run python -m yosou.longshots_in_top3 predict 架空レースA --timing 当日 --zone 中穴
uv run python -m yosou.longshots_in_top3 predict 終わった架空レースB --timing 当日
```

（1行目は、木曜に、利用者が見立てた人気を馬名で渡して、穴馬の 3着以内に入る確率を出すコマンド。2行目は、前日に、JRA の発表で見た人気を馬番で渡すコマンド。`--pops` は「馬名:人気」か「馬番:人気」の組を並べる。コンマ区切りで `--pops 3:1,7:2` とも書ける。3行目は、当日に、取り込んだ締め切り前のオッズから人気を作り、中穴だけを出すコマンド。4行目は、終わったレースを確定単勝人気で予測し直すコマンド）

- **全頭ぶん渡す理由。** 穴馬は出走馬の大半である。渡されなかった馬の人気が分からないと、その馬が穴馬かどうかも、ほかの馬の順位が合っているかも決められない。人気の分からない馬が1頭でもいれば、止めて、足りない馬の人気を渡すよう案内する（[06-flowchart.md](06-flowchart.md#図2-予測用データに人気を当てる)）。
- 木曜の馬名は、出走馬名表の馬名とそのまま一致させる。一致しない馬名があれば、止めてその馬名を示す。
- 渡した人気と、締め切り後に確定する人気は、ずれることがある。確定人気で選ばれる馬と、予測した馬が違うこともある。当日の締め切り直前に出し直すと、ずれは小さくなる。
- 学習データでは、確定単勝人気で穴馬を選ぶ。このずれの扱いは [11-leak-prevention.md](11-leak-prevention.md#決まり) の 5 と 8 を参照。
- `--zone` は、出力を絞るだけである。付けなければ、穴馬すべてを出す（[01-overview.md](01-overview.md)）。

## 時点ごとに使う特徴量

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 86個のうち） | 特徴量の数 |
|---|---|---|
| 木曜（出走馬名表） | 手本の木曜と同じ9個（枠番、馬番、馬体重、馬体重の増減、馬場状態、同じ芝ダ・馬場状態での通算の出走数・3着以内の数、持ち時計のレース内順位（コース単位・距離単位）。[手本の 07 の「時点ごとに使う特徴量」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量)）と、まとまり K の3個（単勝オッズ、オッズから見た勝率、オッズから見た3着以内率）と、まとまり M の4個（複勝の最低オッズ、複勝の最高オッズ、複勝オッズから見た3着以内率、複勝と単勝の3着以内率の比） | 70 |
| 前日（出馬表） | 馬体重、馬体重の増減 | 84 |
| 当日（馬体重の発表のあと） | なし | 86 |

- まとまり J（人気と人気の履歴）は、3つの時点とも使う。どの時点も、上の「予測のときの人気の与え方」で人気が決まっているためである。
- まとまり K（単勝オッズから見た評価）は、前日と当日だけ使う。木曜は前売りがまだ始まっていない。
- まとまり M（複勝オッズから見た評価。2026-10-01）も、前日と当日だけ使う。複勝オッズは単勝オッズと同じオッズ1（単複枠）に入るので、分かる時点も同じである。予測のとき DB に複勝オッズが無ければ、`jvstore realtime` で取り込むよう案内して止まる（単勝オッズと違って `--odds` のような手で渡す引数は無い）。
- まとまり L（騎手・調教師・血統の市場に対する成績）は、木曜から全部の時点で使う。数えるのに使うのは、開催日の前日までの過去のレースの確定オッズだけで、そのレースのオッズは使わないため（[手本の 09 の L](../近走と適性から3着以内を予想/09-features.md#l-騎手調教師血統の市場に対する成績4個)）。
- 木曜の出走頭数は、出走馬名表の頭数である。あとで取消が出ると頭数が変わり、穴馬の範囲（13頭以下か 14頭以上か）と区分も変わることがある（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 7）。
- 木曜は馬場状態が分からないので、馬場状態を条件にして数える特徴量も使わない。前日の馬場状態は、前日発表の値を使う。理由は [手本の 07](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量) と同じである。

## 時点ごとにモデルを分ける理由

手本と同じ理由である。[手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由) を参照。1つのモデルで済ませると、木曜の予測では、学習のときに値が入っていた「馬番」や「馬体重」を欠損値で渡すことになり、学習と予測でデータの様子がずれる。

学習データは3つの時点で同じものを使い、モデルに渡す列だけを変える（[08-training-data.md](08-training-data.md#2-列の種類)）。
