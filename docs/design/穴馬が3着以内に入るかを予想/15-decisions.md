## 1. 少頭数の穴馬を4番人気からにするか

| 選び方 | 変わること |
|---|---|
| **13頭以下は 4番人気以下、14頭以上は 6番人気以下（決定）** | 危険な人気馬の予想の「人気馬」（13頭以下 1〜3番、14頭以上 1〜5番）の裏返しになる。2つの予想を合わせると、出走馬をもれなく・重なりなく分ける |
| どの頭数でも 6番人気以下 | keiba-yosou の道具（傾向スコア）の穴馬と同じ範囲になる。13頭以下のレースで 4・5番人気が、どちらの予想の対象にもならない |
| 出走馬の割合で決める（下位の 7割など） | 頭数に対する範囲がいちばんそろう。頭数ごとに「何番人気から」を計算することになり、利用者が範囲を暗算できない |
| 3段階にする（10頭以下は 4番から、11〜13頭は 5番から、14頭以上は 6番から） | 割合がそろうが、決まりが1つ増える。危険な人気馬の予想の線引き（2段階）ともずれる |

**人気馬の裏返しにした理由。**

- 穴馬に、決まった定義は無い。調べたところ「6番人気以下」「単勝 10倍以上」「単勝 15倍以上」など、資料によって違った。頭数で変える資料は無いが、「18頭立ての 10倍と 5頭立ての 10倍では価値が違う」と、頭数で相対化する考え方は一般的だった。
- 危険な人気馬の予想は、人気馬を「出走馬の 2〜4割」と決め、13頭以下は 1〜3番人気、14頭以上は 1〜5番人気とした（[人気馬の 15 の「1. 多頭数を何頭からにするか」](../人気馬が4着以下になるかを予想/15-decisions.md#1-多頭数を何頭からにするか)）。その次の人気からを穴馬とすれば、2つの予想が同じ線引きを使い、頭数の境（14頭）も1か所で持てる。
- 14頭以上で 6番人気からにするのは、一般的な「6番人気以下が穴馬」とも一致する。

関連する資料: 穴馬の範囲は [08-training-data.md の「3. どのサンプルを入れるか」](08-training-data.md#3-どのサンプルを入れるか)。用語は [02-glossary.md の「この予想で増える用語」](02-glossary.md#この予想で増える用語)。

## 2. 中穴と大穴の線引き

| 選び方 | 変わること |
|---|---|
| **13頭以下は 4〜6番人気が中穴・7番人気以下が大穴、14頭以上は 6〜9番人気が中穴・10番人気以下が大穴（決定）** | 中穴は、どの頭数でも出走馬の 2〜4割になる。多頭数では、大穴がちょうど二桁人気になる |
| どの頭数でも 6〜9番人気が中穴、10番人気以下が大穴 | 一般的な相場観そのままで分かりやすい。13頭以下では、4・5番人気が穴馬なのにどちらの区分にも入らず、中穴が 6番人気の1頭だけになる |
| 単勝オッズで分ける（10〜30倍が中穴、30倍以上が大穴など） | 人気の差の大きさまで区分に反映できる。学習は確定オッズ、予測は締め切り前のオッズになり、値がずれる。木曜はオッズが無く、区分を決められない |
| 3つに分ける（中穴・大穴・超大穴） | 大穴の中を、さらに来やすい側と来にくい側に分けられる。出力を絞る選び方が増え、超大穴は 1 のサンプルがごく少なくなる |

**この線引きにした理由。**

- 調べたところ、一般的な相場観は「本命サイドは 1〜3番人気、中穴は 4〜9番人気あたり（資料により 4〜5・5〜8・6〜9）、大穴は二桁人気で単勝 50〜100倍以上」だった。14頭以上の「6〜9番人気が中穴、10番人気以下が大穴」は、これと一致する。
- 13頭以下は、穴馬が 4番人気から始まるので、同じ「出走馬の 2〜4割」の幅で 4〜6番人気を中穴にした。13頭で3頭（23%）、8頭で3頭（38%）である。
- 区分は出力を絞るためだけのもので、モデルには渡さない（5）。線引きを変えても学習し直しは要らないので、使ってみて合わなければ変えればよい。

関連する資料: 線引きの表は [08-training-data.md の「3. どのサンプルを入れるか」](08-training-data.md#3-どのサンプルを入れるか)。区分の列の扱いは [08-training-data.md の「2. 列の種類」](08-training-data.md#2-列の種類)。

## 7. 1着の列も学習データに置くか

「1着の列」とは、「その馬が1着なら 1、それ以外なら 0」という答えの列である。手本の予想は、実際に当てさせる「3着以内なら 1」の列のほかに、この列も学習データに置いている（モデルには渡さない）。

| 選び方 | 変わること |
|---|---|
| **置く（決定）** | あとで穴馬の単勝用のモデルを作るとき、学習データを作り直さずに済む。穴馬は単勝の配当が大きいので、単勝用を作りたくなる可能性が高い。手本の目的変数を付ける部品をそのまま使える |
| 置かない | 学習データの列が1つ減るだけ。単勝用を作るときに、学習データを作り直す |

関連する資料: 作り方は [10-target.md の「作り方」](10-target.md#作り方)、列の種類は [08-training-data.md の「2. 列の種類」](08-training-data.md#2-列の種類)。

## 8. 木曜の人気の渡し方

**木曜にも予測を出すことは、利用者が決めた（2026-09-23）。** 木曜は馬番も前売りも無いので、人気をどう渡すかを決める。

| 選び方 | 変わること |
|---|---|
| **利用者が見立てた人気を `--pops 馬名:人気` で全頭ぶん渡す。無ければ止める（決定）** | 前日・当日と同じ `--pops` で渡せる。馬名は出走馬名表とそのまま一致させる。見立てが確定の人気とずれると、穴馬の範囲と区分も変わるので、前日・当日に出し直す |
| 馬ID（血統登録番号）で渡す | 馬名の打ち間違いが起きない。利用者が馬IDを調べる手間がかかる |
| 前走までの成績から人気を推し量って作る | 利用者の入力が要らない。当たるかどうか分からない値で穴馬を選ぶことになり、見立てより外れやすい |
| 木曜は人気を使わず、全頭に確率を出す | 入力は要らない。人気を使わないので、手本の木曜の予想と同じものになり、穴馬の予想にならない |
| 木曜は出さない（危険な人気馬の予想と同じ） | 人気が決まってから予測するので、見立てのずれが無い。利用者が木曜も出すと決めたので、選ばない |

関連する資料: 渡し方は [07-prediction-timing.md の「予測のときの人気の与え方」](07-prediction-timing.md#予測のときの人気の与え方)、判断の手順は [06-flowchart.md の「図2. 予測用データに人気を当てる」](06-flowchart.md#図2-予測用データに人気を当てる)、見立てのずれの扱いは [11-leak-prevention.md の「決まり」](11-leak-prevention.md#決まり) の 8。

| **入れない（決定）** | 予測の表は、3着以内に入る確率の高い順に、人気順位と区分の列を付けて並べるだけにする。線引き（何%以上を「買い」とするか）は、評価指標と一緒に [16-evaluation.md](16-evaluation.md#3-買いの線引き) で決めた（しきい値の値そのものは設計書に書かない） |
| 確率か、オッズとの比較で印を付ける | 出力は読みやすくなる。値を決める根拠が無いまま、設計書に数字が入る |
| 1レースで挙げる頭数に上限を付ける | 出力が短くなる。3着以内は3頭までだが、どの穴馬が来るかは分からないので、上限を決める根拠が無い |

**1レースで、複数の穴馬を挙げられる。** 穴馬1頭ずつに別々の確率を出すので、「1レースで1頭まで」のような決まりは設けない。

関連する資料: 予測の出力は [05-sequence.md の「図2. 予測」](05-sequence.md#図2-予測)、これから決めることは [05-sequence.md の「今は無く、これから作るところ」](05-sequence.md#今は無くこれから作るところ)。

## 12. 既存モデルの修正計画での直し

2026-09-24 に、ワークスペースの `plans/既存モデルの修正計画.md` に沿って直した。直し方と確かめ方は研究「既存モデルの改善」の
[01-進め方.md](../../../research/既存モデルの改善/docs/01-進め方.md) にある。数値は Git の対象外の `reports/既存モデルの改善/compare/longshots_in_top3.md` にある。

| 直したこと | 直す前 | 直した後 | 理由 |
|---|---|---|---|
| オッズの使い方 | 人気順位だけを特徴量に使った | 単勝オッズから Harville の式で出した「オッズから見た3着以内率」を基準にし、モデルは基準からの上げ下げだけを学ぶ（LightGBM の `init_score`、CatBoost の `baseline`。木曜はオッズが無いので基準なしで学ぶ）。単勝オッズ・オッズから見た勝率・オッズから見た3着以内率（まとまり K）も特徴量に足した | オッズで説明できる部分と、馬の情報で新しく説明できる部分を分けるため |
| 区分（3 を決め直した） | 穴馬すべてで1つのモデル | 中穴と大穴で別のモデル（時点ごと） | 全体では良くても、大穴を見分けられているとは限らないため |
| 買う候補 | 確率の高い順に並べるだけ | 並べ方は同じ。予測の表に「複勝的中の確率」と「複勝の期待値」（複勝的中の確率 × 見込みの払戻の倍率）を足した。見込みの倍率は学習のときに保存する | 「来やすい」と「払戻まで考えて買う価値がある」は違うため |
| 前日・当日のオッズの渡し方 | `--pops` だけ | `--odds 馬番:オッズ` も受け取る。`--pops` を省くと、オッズの小さい順を人気にする | 基準とまとまり K にオッズが要るため |

**確かめた結果。** 7つの区切り（2023年前半〜2026年）のテスト期間で、直した後の確率の誤差（ログ損失）は、中穴・大穴とも
7つすべての区切りで、直す前とオッズだけの基準より小さかった。大穴を期待値で買う方法は、直す前の期待値の選び方・
人気がいちばん上の大穴を選ぶ方法・大穴を全部買う方法のどれよりも回収率が高かった（ただし 100% には届かなかった）。
分ける・分けないの差はごく小さかったが、計画どおり分けて採用した。

## 13. アンサンブルの平均のしかた

プログラムは、はじめから単純な平均で作ってあったが、設計書では「手本と同じく、次の設計書で決める」のままだった（仮の作り）。2026-09-28 に、手本と一緒に、今の作りのまま決めた。利用者の「任せる」による。

| 選び方 | 変わること |
|---|---|
| **重みを付けない単純な平均（決定）** | 手本と同じ部品（`EnsembleModel`）をそのまま使う |
| 区分ごとに、検証データで重みを選ぶ | 重みが 2つの区分 × 3つの時点ぶんに増え、学習し直すたびに変わる |

**決めた理由。** 手本の [15 の 8](../近走と適性から3着以内を予想/15-decisions.md#8-アンサンブルの平均のしかた) と同じ比べ方で、7つの区切り × 2つの区分（中穴・大穴）の 14 通りを確かめた（2026-09-28）。

- 平均のログ損失は、14 のうち 12 で、2つのモデルのどちらよりも小さかった。
- 検証期間で重みを選んでテスト期間で使うと、単純な平均より良くなったのは 14 のうち 4 で、全体では単純な平均のほうがわずかに良かった。
- どちらのモデルが良いかは、ほぼ半々で入れ替わった（LightGBM が良かったのは 14 のうち 6）。

**複勝の期待値も、この平均の確率から出す**（[15 の 12](#12-既存モデルの修正計画での直し)）。

関連する資料: [手本の 03 の 6.](../近走と適性から3着以内を予想/03-library-basics.md#6-2つの予測確率を合わせる)。

## 15. 確率を較正するか

**2026-09-28 に決めた（issue #31）。** 研究「馬券の買い方の検証」（2026-09-23）は、「穴馬の予想の確率は実際より高く出るので、
確率 × オッズの期待値の計算には使えない」と結論した。ただし、それは 12 で直す前のモデルでの結論だった。そこで、今のモデルで
確率のずれを測り直してから決めた。測り方と結果は [16-evaluation.md の 5](16-evaluation.md#5-確率のずれの確かめ方) にある。

| 選び方 | 変わること |
|---|---|
| **較正は足さない。確率のずれを確かめる道具を残す（決定）** | 予測の表の確率と複勝の期待値は、今までどおり2つのモデルの確率の平均から出す。学習し直したら `calibration` コマンドでずれを確かめ、ずれが出ていたら、そのとき較正を足す |
| Platt scaling を学習の後段に足す（検証期間で学ぶ） | 確率の平均が実際の割合にぴったり合う（7つの区切りのモデルは大穴を 4% ほど低めに出していたので、確率が全体に少し上がる）。ログ損失の差は小数第3位にも出ないほど小さい。期待値 1 以上の馬が 1〜4割増え、その回収率は 4つの組（前日・当日 × 中穴・大穴）すべてで下がった |
| isotonic regression を学習の後段に足す | 曲がったずれも直せるが、確率の高い端で階段が振れて、テスト期間のログ損失はかえって悪くなった（7つの区切りのうち、良くなったのは 0〜1）。期待値 1 以上の馬は 5〜8割増え、回収率は 4つの組のうち 3つで下がった |
| 複勝オッズも入れて較正する（確率と複勝オッズの2つから、実際の割合を当てる） | 当日で試しに比べた（道具には入れていない）。期待値の高い馬の選び方が変わり、大穴で回収率が上がる線もあったが、係数が区切りごとに大きく振れた。較正というより、特徴量（複勝オッズ）を足す直しになる |

**較正を足さない理由。**

- **今のモデルの確率は、すでに実際の割合とそろっている。** 3つの時点・中穴と大穴のどれでも、予想の平均と実際の割合がそろっていて、確率の帯ごと・人気ごとに見ても、人気薄ほど高めに出るような偏りは無かった（測った値は [16-evaluation.md の 5](16-evaluation.md#5-確率のずれの確かめ方)）。12 で、オッズから見た3着以内率を出発点にして学ぶ形にしたことで、ずれがほぼ直っていた。
- **較正を足しても、確率も期待値の当たり具合も良くならなかった。** 7つの区切りで、検証期間で較正を学んでテスト期間に当てたところ、ログ損失はほとんど変わらず（isotonic regression は悪くなった）、期待値 1 以上の馬を買ったときの回収率は、ほとんどの組で較正なしより下がった（上がった1組も 1ポイント未満）。
- **期待値の高い馬で、実際の的中率が予想より少し低いずれは残る。** これは確率の帯で直す較正では消えない。期待値で馬を選ぶと、モデルがたまたま高めに見積もった馬が集まりやすい（選んだことで起きる偏り）ためで、当日で試したところ、テスト期間そのもので較正を学ばせても（答えを見ても）消えなかった。見込みの倍率（払戻）も、期待値の高い馬では 5% ほど高めに出ていた。
  そのため、期待値 1 を「超えたら必ず儲かる線」とは読まない。買う線は、確率の線と同じく、検証期間の回収率を見て決める（[16-evaluation.md の 3](16-evaluation.md#3-買いの線引き)）。
- **穴馬を選べなくなることは無い。** どの方法でも、期待値 1 以上で選んだ大穴の 8割ほどが 10番人気以下だった（較正なしと同じ程度）。

関連する資料: 道具は [04-classes.md の command/](04-classes.md#command--コマンド)。7つの区切りでの比べ方は、研究「既存モデルの改善」の
入口⑦（[README](../../../research/既存モデルの改善/README.md)）。数値は Git の対象外の `reports/穴馬が3着以内に入るかを予想/` の
`calibration.md`（本番のモデル）と `calibration-walk-forward.md`（7つの区切り）にある。
