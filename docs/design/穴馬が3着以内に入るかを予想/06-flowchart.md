# 06 判断の手順（フローチャート）

**この文書で示すこと:** 学習データを作るときと、予測のときの人気を決めるときの、条件によって分かれる判断の手順。

**結論: 条件によって分かれる判断は2つある。「学習データに入れる行の選び方」（穴馬かどうか、中穴か大穴かの判断を含む）と、「予測用データに人気を当てる手順」（全頭の人気がそろっているかの判断を含む）である。**

- この文書は、1つの public メソッドの中で、条件で分かれる判断の手順を示す。クラスどうしのやりとりは [05-sequence.md](05-sequence.md) を参照。2種類の図の使い分けは [01-overview.md](01-overview.md#図の使い分け) を参照。
- 図の読み方（凡例）は [手本の 06 の「図の読み方」](../近走と適性から3着以内を予想/06-flowchart.md#図の読み方) を参照。四角が作業、ひし形が if 文1つ、平行四辺形ができあがるものである。
- モデルごとの判断の手順（カテゴリ特徴量の値の変え方）は、手本と同じで、[手本の 12 の 3.](../近走と適性から3着以内を予想/12-lightgbm.md#3-カテゴリ特徴量の値の変え方フローチャート)・[手本の 13 の 3.](../近走と適性から3着以内を予想/13-catboost.md#3-カテゴリ特徴量の値の変え方フローチャート) を参照。
- 用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 図1. 学習データに入れる行の選び方

`LongshotSelector.training_samples()` と `LongshotSelector.keep_samples()`（どちらも `DatasetBuilder.build_training_data()` から呼ばれる）の中で行う判断と、その間の段。事実表の1行（1レースの1頭）が、学習データの1行になるまで。

```mermaid
flowchart TD
    S["事実表の1行<br>1レースの1頭"] --> Q1{"障害レースか"}
    Q1 -->|はい| X["学習データに入れない"]
    Q1 -->|いいえ| Q2{"出走したか<br>取消・除外ではないか"}
    Q2 -->|いいえ| X
    Q2 -->|はい| Q3{"学習データの始まり以降か<br>既定は 2021年8月1日"}
    Q3 -->|いいえ| WU["ウォームアップ期間<br>ほかの行の過去走の計算にだけ使う"]
    Q3 -->|はい| Q4{"穴馬か<br>13頭以下なら 4番人気以下<br>14頭以上なら 6番人気以下"}
    Q4 -->|いいえ| N["「穴馬か = いいえ」を足す"]
    Q4 -->|はい| Q5{"中穴か大穴か<br>13頭以下は 6番人気まで<br>14頭以上は 9番人気までが中穴"}
    Q5 -->|中穴| YM["「穴馬か = はい」<br>「区分 = 中穴」を足す"]
    Q5 -->|大穴| YB["「穴馬か = はい」<br>「区分 = 大穴」を足す"]
    N --> F["特徴量 75個を作る<br>レース内順位は、レースの全出走馬から計算"]
    YM --> F
    YB --> F
    F --> Q6{"穴馬か<br>keep_samples"}
    Q6 -->|いいえ| X
    Q6 -->|はい| T["目的変数を付ける<br>3着以内なら 1、それ以外は 0<br>（1着の列も付ける）"]
    T --> R[/"学習データの1行"/]
```

**説明。** 手本の予想との違いは、4つ目から6つ目の問いである。穴馬でない行も、いったんは残して特徴量を作る。まとまり G のレース内順位（近5走の平均着差の順位など）を、そのレースの全出走馬から計算するためである（理由は [08-training-data.md](08-training-data.md#3-どのサンプルを入れるか)）。特徴量ができたあと、6つ目の問い（`keep_samples()`）で穴馬の行だけを残す。

5つ目の問い（中穴か大穴か）で足す「区分」の列は、出力の表と区分ごとの評価に使うもので、**モデルには渡さない**（[08-training-data.md](08-training-data.md#2-列の種類)、[15-decisions.md](15-decisions.md#5-穴馬の区分を特徴量に入れるか)）。

- 穴馬の範囲と区分を決める規則は [08-training-data.md](08-training-data.md#3-どのサンプルを入れるか)、特徴量は [09-features.md](09-features.md)、目的変数は [10-target.md](10-target.md) を参照。
- 「穴馬か」「中穴か大穴か」の判断に使う人気は、学習では確定単勝人気、予測では図2で決めた人気である（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 5）。頭数は、学習では実際に走った頭数、予測ではその時点で取消・除外になっていない頭数（木曜は出走馬名表の頭数）である。
- 3つ目の問いの日は、`train` の引数 `--train-from` で変えられる（[手本の 08 の「4. 期間の指定」](../近走と適性から3着以内を予想/08-training-data.md#4-期間の指定)）。
- 予測用データを作るときも同じ手順を通る。ただし、これから走るレースなので3つ目の問いは常に「はい」になり、目的変数を付ける段は無い。作る特徴量は、その時点で使うものだけである（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。

## 図2. 予測用データに人気を当てる

予測に使う人気を決める判断。前半（1つ目から3つ目の問い）は `PopularityApplier.resolve()`、後半（4つ目の問い）は `LongshotSelector.prediction_runners()` の中にある。どちらも `PredictionWorkflow.run()` から呼ばれる。

```mermaid
flowchart TD
    S["予測する1レース"] --> Q1{"利用者が --pops で<br>人気を渡したか"}
    Q1 -->|はい| U["渡された人気を、その馬番に当てる<br>木曜は馬名に当てる"]
    Q1 -->|いいえ| Q2{"元DB に、このレースの<br>締め切り前のオッズがあるか"}
    Q2 -->|はい| O["オッズの小さい順に<br>人気を付けて当てる"]
    Q2 -->|いいえ| N["人気を当てない"]
    N --> Q3{"元DB の出走の行に<br>単勝人気が入っているか"}
    Q3 -->|はい| D["その人気を使う<br>終わったレースの確定単勝人気"]
    Q3 -->|いいえ| E["止めて、--pops で全頭の人気を<br>渡すよう案内する"]
    U --> Q4{"人気の分からない馬が<br>1頭でもいるか"}
    O --> Q4
    D --> Q4
    Q4 -->|はい| E2["止めて、足りない馬の人気を<br>渡すよう案内する"]
    Q4 -->|いいえ| R[/"全頭に人気の付いた出走の行"/]
```

**説明。** 人気は、レースの前には確定しない。そのため、予測のときは利用者が見た（木曜は見立てた）人気を渡してもらう。前日・当日は、元DB に締め切り前のオッズが入っていれば、そこから人気を作れる。

**木曜は、1つ目の問いで渡すしかない。** 木曜は馬番も締め切り前のオッズも無いので、渡さなければ2つ目・3つ目の問いはどちらも「いいえ」になり、止まる。木曜の `--pops` は、馬番の代わりに馬名で渡す（[07-prediction-timing.md](07-prediction-timing.md#予測のときの人気の与え方)）。

**3つ目の問いは、終わったレースの答え合わせのためにある。** すでに走ったレースなら、元DB の出走の行に確定単勝人気が入っている。そこで、渡された人気もオッズも無いときは、何も当てずにその値を使う。これから走るレースでは、その値が空なので、案内を出して止める。

**4つ目の問いは、危険な人気馬の予想には無い。** 危険な人気馬の予想は、人気を渡されなかった馬を「人気馬ではない」とみなして進む。この予想では、穴馬が出走馬の大半なので、人気の分からない馬を黙って落とすと、出力から穴馬が欠ける。そのため、人気の分からない馬が1頭でもいれば止める。渡す人気は、1 から頭数までの順位を全頭ぶんである。

- 人気の与え方は [07-prediction-timing.md](07-prediction-timing.md#予測のときの人気の与え方) を参照。
- 元DB のオッズの状態は [人気馬の 09 の「使うデータの期間」](../人気馬が4着以下になるかを予想/09-features.md#使うデータの期間) を参照。
