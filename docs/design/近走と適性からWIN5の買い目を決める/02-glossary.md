# 02 用語の意味

**この文書の目的:** この設計書に出てくる用語のうち、手本の予想に出てこないものの意味をまとめる。

**この文書で示すこと:** 機械学習の用語（特徴量・目的変数・リークなど）と、競馬とこの設計の用語（確定オッズ・締め切り前のオッズ・オッズから見た勝率・1着になる確率・単勝の期待値など）は、手本と同じものをそのまま使う。この予想で増えるのは、「今のモデル」と、WIN5 のルールの用語と、組の確率・配当の見積もり・買い目の組み方の用語である。

- 機械学習の用語は [手本の 02 の「機械学習の用語」](../近走と適性から3着以内を予想/02-glossary.md#機械学習の用語) を参照。
- 競馬とこの設計の用語は [手本の 02 の「競馬とこの設計の用語」](../近走と適性から3着以内を予想/02-glossary.md#競馬とこの設計の用語) を参照。
- 下の表は、それに足すものである。

## この予想で増える用語

### 今のモデルの用語

| 用語 | 意味 | この設計では |
|---|---|---|
| 今のモデル（今毎週の予想に使っているモデル） | 設計書「近走と適性から3着以内を予想」（この設計書の手本）の学習済みのモデル。週末の予想（道具「今週の予想」）・次のレースの予想・発走前の通知が、全頭の「3着以内に入る確率」と「1着になる確率」を出すのに使っている。学習済みのモデルは Git の対象外の `reports/近走と適性から3着以内を予想/models/` にある | この予想は、そのうち「1着になる確率」（2つのモデルの平均。道具「今週の予想」の結果の `win_probability` と同じ値）を借りる。新しくモデルを学ばない（[15-decisions.md の 1](15-decisions.md#1-1着の確率をこの予想で学ぶか)） |
| 今のモデルの時点 | 今のモデルは、木曜・前日・当日の時点ごとに別のモデルを持つ（当日は、券種のオッズが無いレース用のモデルも持つ） | この予想は、対象レースごとに前日か当日の1着の確率を使う（[07-prediction-timing.md](07-prediction-timing.md#対象レースごとの確率の選び方)） |
| 区切りごとの予測 | 半年ごとの区切りについて、その半年より前のデータだけで今のモデルと同じ作りのモデルを学び直し、その半年のレースを予測したもの。学習に使っていない年の1着の確率になる | 過去の WIN5 で確かめるときの1着の確率（[16-evaluation.md の 1.](16-evaluation.md#1-期間の分け方)、[11-leak-prevention.md の 10](11-leak-prevention.md#決まり)） |

### WIN5 のルールの用語

| 用語 | 意味 | この設計では |
|---|---|---|
| WIN5（重勝式） | JRA が日ごとに決めた5つのレースの1着の馬を、全部当てる馬券。1点 100円。JV-Data では「重勝式」と呼び、元DB の表 `wf` に入る | 予想の対象。表の読み方は [08-training-data.md の 5.](08-training-data.md#2-配当の見積もりに使うデータ) |
| 対象レース | その日の WIN5 の5つのレース。発売の順に1レース目〜5レース目と呼ぶ | 1着の確率を出すレース。どのレースが対象かは、jvdata-store が速報で取り込む（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに分かること)） |
| 組 | 5つの対象レースの1着の馬を1頭ずつ並べたもの。例: (3, 5, 1, 4, 6) は1レース目 3番 … 5レース目 6番 | 1点 = 1組。当たる確率と配当の見積もりは組ごとに出す |
| フォーメーション | 対象レースごとに馬を何頭か選び、その全部の組み合わせを買う買い方。点数は各レースの頭数のかけ算（2頭 × 5頭 × 2頭 × 1頭 × 5頭 = 100点） | この予想が出す買い目の形（[16-evaluation.md の 4.](16-evaluation.md#4-買い目の組み方と買う日の線)） |
| 払戻率 | 売上のうち払戻に回る割合。WIN5 は 70% | 配当の見積もりの元（[10-target.md の 2.](10-target.md#2-配当の見積もりで当てるもの)） |
| 発売票数 | その日の WIN5 が売れた点数。発売金額 = 発売票数 × 100円 | 締め切り前には分からないので、過去の WIN5 から見積もる（[09-features.md の 2.](09-features.md#2-配当の見積もりに使う値)） |
| キャリーオーバー | 当たりが出なかった回などの払戻の残りが、次の回の払戻に足されるお金。その日の初めの額（キャリーオーバー金額初期）は、発売の前に分かる | 払戻に回るお金に足す（[10-target.md の 2.](10-target.md#2-配当の見積もりで当てるもの)） |
| 払戻の上限 | 100円あたりの払戻の上限。上限を超える分はキャリーオーバーになる。値はルール集の [10-win5.md の「券種の特徴」](../../rules/馬券の買い方/10-win5.md#券種の特徴) | 見積もりの配当を、この値で頭打ちにする（[06-flowchart.md の図2](06-flowchart.md#図2-組1つの配当の見積もり)） |
| 的中無 | その回に当たりが1票も無かったこと。元DB の `的中無フラグ` が 1 | 払戻の値が無いので、配当の見積もりの式を作るのには入れない（[08-training-data.md の 5.](08-training-data.md#2-配当の見積もりに使うデータ)） |
| 返還 | 買った組の馬が出走取消・競走除外になったときなどに、その組の代金が戻ること。元DB の `返還フラグ` が 1 の回がある | 過去の WIN5 での確かめでは、返った代金を払戻に数える（[16-evaluation.md の 1.](16-evaluation.md#1-期間の分け方)） |

### 組の確率と配当の見積もりの用語

| 用語 | 意味 | この設計では |
|---|---|---|
| そろえた1着の確率 | 今のモデルの1着の確率（2つのモデルの平均）を、同じレースの全頭で合計が 1 になるように割り算でそろえたもの。例: 0.30・0.20・0.10 の3頭なら 0.50・0.33・0.17 | 組の当たる確率のもと（[16-evaluation.md の 3.](16-evaluation.md#3-組の当たる確率と期待値)） |
| 上乗せ | そろえた1着の確率 ÷ オッズから見た勝率。1 より大きいほど、今のモデルが市場より高く見ている | 買い目に入れる馬の並べ方の候補（[16-evaluation.md の 4.](16-evaluation.md#4-買い目の組み方と買う日の線)） |
| 組の当たる確率 | 組の5頭の、そろえた1着の確率のかけ算。5つのレースは別々に決まるとみなす | [16-evaluation.md の 3.](16-evaluation.md#3-組の当たる確率と期待値) |
| 市場の組の確率 | 組の5頭の、オッズから見た勝率のかけ算。市場（馬券を買う人たち全体）がその組をどれだけ買っていそうかの目安 | 配当の見積もりの式の材料（[09-features.md の 2.](09-features.md#2-配当の見積もりに使う値)） |
| 配当の見積もりの式 | 過去の WIN5 の当たり組の払戻を、市場の組の確率とキャリーオーバーの比から当てる式（対数をとった1次式） | 学習のときに作って保存する（[10-target.md の 2.](10-target.md#2-配当の見積もりで当てるもの)） |
| 見積もりの配当 | 組1つが当たったときの、100円あたりの払戻の見込み。式の値に、上限と自分の1票の分を当てたもの | [06-flowchart.md の図2](06-flowchart.md#図2-組1つの配当の見積もり) |
| 自分の1票 | 自分が買った票も、当たれば当たり票の1つに数えられること。ほかに当たる人がほとんどいない組では、払戻を自分の票と分け合う形になり、式の値より配当が小さくなる | 見積もりの配当に入れる（[06-flowchart.md の図2](06-flowchart.md#図2-組1つの配当の見積もり)） |
| 日の期待値 | 買い目の全部の組の「当たる確率 × 見積もりの配当」の合計 ÷ 買い目の代金。1 で元返し | 買う日を決める値（[16-evaluation.md の 3.](16-evaluation.md#3-組の当たる確率と期待値)） |
| 買う日の線 | 日の期待値がこの値以上の日だけ買う、という境目 | 値は過去の WIN5 で決める（[16-evaluation.md の 4.](16-evaluation.md#4-買い目の組み方と買う日の線)） |
| 予算（点数） | 1回の WIN5 で買う点数の上限 | 候補は [16-evaluation.md の 4.](16-evaluation.md#4-買い目の組み方と買う日の線)。実際に買う予算は段階の予算で決める |
| 判断用の買い目 | 買う日かどうかを決めるためだけに組む買い目（1着の確率の順・50点）。その日の期待値が買う日の線以上なら買う日。この買い目そのものは買わない | 買う日の判断（[15-decisions.md の 13](15-decisions.md#13-1回の予算段階の予算)、[06-flowchart.md の図3](06-flowchart.md#図3-買い目の組み方と買う日の判断)） |
| 本命の確率の積 | 対象5レースそれぞれの本命（そろえた1着の確率が最大の馬）の確率を5つかけた値。買い目に依らない、その日の値。5レースの本命が全部勝つ組の当たる確率と同じ | 多く買う日か少なく買う日かを決める値（[15-decisions.md の 13](15-decisions.md#13-1回の予算段階の予算)） |
| 多く買う日・少なく買う日 | 買う日のうち、本命の確率の積が多く買う日の線（0.0025）以上の日が多く買う日（100点・1万円）、未満の日が少なく買う日（30点・3,000円）。見送りの日も少なく買う日の予算の買い目を参考に出す | 段階の予算（[15-decisions.md の 13](15-decisions.md#13-1回の予算段階の予算)） |
| 段階の予算 | 判断用の買い目の予算・少なく買う日の予算・多く買う日の予算・多く買う日の線の4つの値。利用者の決めた範囲（3,000〜10,000円）の中で、日によって予算を変える決まり | 値は `formation/buying_defaults.py`（[15-decisions.md の 13](15-decisions.md#13-1回の予算段階の予算)、[16-evaluation.md の「段階の予算の確かめ」](16-evaluation.md#段階の予算の確かめ)） |
| レースの中のログ損失 | 各レースの勝ち馬に付けた、そろえた1着の確率の対数に −1 を掛けて、レースで平均したもの。小さいほど良い | 1着の確率の当たり具合の指標の1つ（[16-evaluation.md の 2.](16-evaluation.md#2-評価指標)） |
| 探索期間・確認期間 | 買い方（並べ方・予算・線）を選ぶのに使う期間と、選んだ買い方を1回だけ確かめる期間 | [16-evaluation.md の 1.](16-evaluation.md#1-期間の分け方) |
