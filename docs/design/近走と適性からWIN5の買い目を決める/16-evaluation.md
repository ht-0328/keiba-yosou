# 16 当たり具合の測り方

**この文書で決めること:** WIN5 の買い方の成績を、過去の WIN5 でどう測るか。組の期待値と買い目をどう決めるか。何と比べ、どうなれば採用するか（**採用の基準は、結果を見る前にここで固定する**）。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 1着の確率は、今のモデル（今毎週の予想に使っているモデル）の区切りごとの予測（その年を学習に使っていない予測）を使う。前日と当日の両方がそろう 2019年から確かめ、2019〜2024年を**探索期間**（買い方を選ぶ）、2025年から DB の最後までを**確認期間**（選んだ買い方を1回だけ確かめる）にする |
| 2. 評価指標 | WIN5 は、買った日数・投資・払戻・回収率・的中率と、開催日を単位にした 90% の幅。1着の確率は、対象レースでのレースの中のログ損失と確率の帯ごとの実際の勝率を参考に出す（採否には使わない） |
| 3. 組の当たる確率と期待値 | 組の当たる確率 = 5レースのそろえた1着の確率のかけ算。日の期待値 = 買い目の全部の組の「当たる確率 × 見積もりの配当」の合計 ÷ 代金 |
| 4. 買い目の組み方と買う日の線 | フォーメーション1枚。並べ方（2つ）× 予算（5つ）× 線（4つ）の 40 通りから、探索期間で決まりどおりに1つ選ぶ。予算ごとの成績の表も出して提案する |
| 5. 比べる相手 | (1) ルール集の WIN5 のルール（240点）、(2) 人気だけで選ぶ買い方 |
| 6. 採用の基準 | 確認期間で、回収率と 90% の幅の下の端が 100% を超え、(1)・(2) の回収率を上回る |
| 7. 道具と全券種の回収率 | 道具「印の成績」に WIN5 の表（`--win5`）を足し、回せば全部の表が出る形にする。この予想は今のモデルを変えないので、ほかの券種の買い目は変わらない |
| 8. 配当の見積もりの確かめ | 確認期間の当たり組で、見積もりの配当と実際の払戻を比べる |

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 期間の分け方

**1着の確率は、区切りごとの予測を使う。** 今の学習済みのモデルは、確かめたい年の多くを学習に使っているので、過去の WIN5 の確かめには使えない（[11-leak-prevention.md の 10](11-leak-prevention.md#決まり)）。代わりに、半年ごとに、その半年より前のデータだけで今のモデルと同じ作りのモデルを学び直し、その半年のレースを予測した「区切りごとの予測」を使う。これは、手本の確かめ（[手本の 16 の 4.](../近走と適性から3着以内を予想/16-evaluation.md#4-半年ずつずらした確かめ)）と道具「印の成績」が、過去の年の印の成績を出すときと同じやり方で、次の研究がすでに作っている（Git の対象外の `reports/` にある）。

| 今のモデルの時点 | 区切りごとの予測のある期間 | 作った研究・入口 | 置き場所 |
|---|---|---|---|
| 当日の1着 | 2015年前半〜2026年の半年ごと | 研究「既存モデルの改善」の入口⑪（`win_check.py`。2023年〜）と、研究「複勝以外の回収率100超」の入口③（`early_years.py`。2015〜2022年）を合わせたもの | `reports/複勝以外の回収率100超/predictions-2015から/` の当日の1着の予測 |
| 前日の1着 | 2019年前半〜2026年の半年ごと | 同上（`early_years.py` は 2019〜2022年） | `reports/複勝以外の回収率100超/predictions-2019から/` の前日の1着の予測 |

- WIN5 の後ろのほうのレースは前日の確率を使う（[07-prediction-timing.md の「過去のレースで確かめるときの時点のまね方」](07-prediction-timing.md#過去のレースで確かめるときの時点のまね方)）ので、**前日と当日の両方がそろう 2019年から** 確かめる。
- 区切りごとの予測は、作ったときの今のモデルの作り（特徴量など）で学んでいる。今のモデルの作りが変わっていたら、同じ仕組み（上の2つの入口）で作り直してから確かめる。確定の券種オッズがあるので、過去の確かめでは券種オッズなしのモデルは使わない。

| 期間 | テスト期間 | 区切りの数 | 使い方 |
|---|---|---|---|
| 探索期間 | 2019年1月〜2024年12月 | 12 | 買い方（並べ方・予算・線）を選ぶ（下の「4.」） |
| 確認期間 | 2025年1月〜DB にある最後の日 | 3 | 探索期間で選んだ買い方を、**1回だけ**確かめる（下の「6.」）。結果を見て買い方を選び直さない |

- それぞれの期間の WIN5 の回数は [08-training-data.md の 2.](08-training-data.md#2-配当の見積もりに使うデータ) の「回数の数え上げ」を参照（探索期間は 2019〜2024年、確認期間は 2025年からの行）。
- 配当の見積もりの式は、区切りごとに、そのテスト期間の始まりより前の WIN5 だけで作る（[11-leak-prevention.md の 8](11-leak-prevention.md#決まり)）。
- オッズは確定オッズで代え、馬体重は予測する時点で出ていたかを線でまねる（[07-prediction-timing.md の「過去のレースで確かめるときの時点のまね方」](07-prediction-timing.md#過去のレースで確かめるときの時点のまね方)）。
- 精算は元DB の当たり組で行い、返還のあった組の代金は払戻に数える（`Win5Settlement`）。
- 区切りごとの予測が無い平地のレースが1つでもある日（予測を作った最後の日より後の日など）は、その日の期待値を出せないので確かめから除く。比べる相手も同じ日だけで数え、除いた日と理由は道具の表に出す。障害のレースは、予測が無くてもオッズから見た勝率で代える（[15-decisions.md の 3](15-decisions.md#3-障害のレースが対象に入った日の扱い)）。
- **確認期間を、手つかずのまま残す。** 確認期間の結果は、買い方を選ぶのにも、配当の見積もりの式を直すのにも使わない。確認期間を見たあとで買い方を直したくなったら、それは新しい買い方として、次に増える WIN5 の回（これからの開催）で確かめる。

## 2. 評価指標

### WIN5 の買い方

| 指標 | 中身 |
|---|---|
| 買った日数 | 日の期待値が線以上で「買う」になった日の数（比べる相手は毎回買う） |
| 投資・払戻 | 1点 100円。払戻には返還の代金を含む |
| 回収率 | 払戻 ÷ 投資 |
| 的中率 | 当たった日 ÷ 買った日 |
| 90% の幅 | 回収率の 90% の幅。WIN5 の日を単位にしたブートストラップ（日を選び直して数え直すのを何度もくり返し、回収率の散らばりを見る）で出す（手本の確かめと同じ出し方） |
| 年ごとの回収率 | 1回の大きな当たりで回収率が決まっていないかを見る |
| キャリーオーバーの日だけの成績 | キャリーオーバーの日は、探索期間にも確認期間にも数回しか無い。参考に並べるだけにする |

### 1着の確率（参考）

1着の確率は今のモデルのもので、この予想では直さない。WIN5 の組の確率が合っているかの手がかりとして、区切りごとの予測で次を出す（採用の基準には使わない）。

| 指標 | 何を見るか |
|---|---|
| レースの中のログ損失 | そろえた1着の確率で、各レースの勝ち馬に付けた確率の対数の平均（−1 を掛けたもの）。WIN5 の組の確率は勝ち馬の確率のかけ算なので、組の確率の当たり具合に直接つながる。オッズから見た勝率と、そろえる前の確率（割り直しただけのもの）とも並べる |
| 確率の帯ごとの実際の勝率 | 確率の帯ごとに、平均の確率と実際の勝率を並べる。特に確率の小さい帯（人気薄）のずれ。組の確率は5つのかけ算なので、小さい確率のずれが重なると、穴の組を見積もりすぎる |

どれも **全レース** と **WIN5 の対象レースだけ** の2つで出す（利用者の決定）。対象レースは全レースよりずっと少ない（[08-training-data.md の 2.](08-training-data.md#2-配当の見積もりに使うデータ)）ので、対象レースだけの値は振れが大きい。ずれが大きければ、今のモデルの設計書で直すかを考える材料にする。

## 3. 組の当たる確率と期待値

```text
そろえた1着の確率  p = 今のモデルの1着の確率（2つのモデルの平均）÷ そのレースの全頭の合計
組の当たる確率      P(組) = p(1レース目の馬) × p(2レース目の馬) × … × p(5レース目の馬)
市場の組の確率      Q(組) = 5頭のオッズから見た勝率のかけ算（配当の見積もりの材料）
見積もりの配当      = 配当の見積もりの式の値に、自分の1票と払戻の上限を当てたもの（10-target.md の 2.）
買い目の当たる確率  = 買い目の全部の組の P(組) の合計
日の期待値          = 買い目の全部の組の（P(組) × 見積もりの配当）の合計 ÷（点数 × 100円）    （1 で元返し）
```

- 5つのレースは別々に決まるとみなして、かけ算する。同じ日の同じ競馬場のレースは、馬場の傾きなどで少し結び付くが、その結び付きを測る材料は無い。
- 見積もりの配当は組ごとに違う（人気薄の組ほど大きい）ので、日の期待値は組ごとに当たる確率と配当を掛けてから足す。
- 実際に予想するときは、オッズは1レース目の締め切り前の断面、発売票数は見積もり（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに分かること)）。

## 4. 買い目の組み方と買う日の線

### 買い目の形

**フォーメーション1枚**（対象レースごとに選んだ馬の、全部の組み合わせ）にする。利用者は、レースごとの馬番を投票の画面に入れるだけで買える（[15-decisions.md の 5](15-decisions.md#5-買い目の組み方と予算の決め方)）。組み方の手順は [06-flowchart.md の図3](06-flowchart.md#図3-買い目の組み方と買う日の判断)（予算に収まる頭数の並びを全部試し、見積もりの払戻の合計がいちばん大きいものを選ぶ）。

### 試す買い方（40 通り）

| 決めること | 候補 |
|---|---|
| 馬の並べ方（各レースで、上から何頭選ぶときの順） | **上乗せの順**（そろえた1着の確率 ÷ オッズから見た勝率）、**1着の確率の順** |
| 予算（1回の点数） | 20点（2,000円）、50点（5,000円）、100点（1万円）、240点（2万4,000円）、500点（5万円） |
| 買う日の線（日の期待値） | 1.00、1.25、1.50、2.00 |

- 上乗せの順は「市場より高く見ている馬」から選ぶので、期待値は高くなりやすいが、人気薄が入りやすく、当たる確率は下がる。1着の確率の順は、当たる確率を上げる代わりに、人気の馬が多くなり、期待値は下がりやすい。
- 240点は、比べる相手 (1)（ルール集の WIN5 のルール）と同じ金額である。

### 探索期間で1つ選ぶ決まり（結果を見る前に固定）

1. 探索期間で、40 通りのそれぞれについて、買った日数・回収率・的中率・90% の幅を出す。
2. 買った日が **30日以上** のものだけを残す（数日の大当たりで選ばないため）。
3. 残ったものから、**回収率がいちばん高いもの** を選ぶ。回収率が同じなら、的中率の高いほうを選ぶ。
4. 探索期間で回収率が 100% を超えるものが1つも無ければ、「選べる買い方なし」とし、確認期間には進まない（予想は出すが、買う日は無い）。

選んだ並べ方・予算・線が、`predict` の `--budget`・`--min-value` などの既定になる（[04-classes.md の 4.](04-classes.md#4-コマンドの引数)）。

### 予算ごとの成績の表（利用者への提案に使う）

予算の決め方は利用者が選ぶので、上の決まりで1つ選ぶのとあわせて、**予算ごとに、並べ方と線の組み合わせのうち探索期間でいちばん良かったものの成績**（買った日数・回収率・的中率・90% の幅・1回あたりの金額）を表にして出す。利用者は、この表を見て予算を決め直してよい（そのときも、確認期間で確かめるのは決め直した1つだけ）。

### 予想は毎回出す

日の期待値が線に届かない日も、選んだ予算での買い目・当たる確率・日の期待値を出す（「見送り」と添える）。利用者の希望「毎週予想はしてほしい」に合わせる。

| 相手 | 中身 | 買う日 | 何が分かるか |

## 6. 採用の基準

**この節の基準は、結果を見る前に固定する。** 結果を見てから基準を変えない。

| 項目 | 中身 |
|---|---|
| 期間 | 確認期間（2025年1月〜DB にある最後の日） |
| 測るもの | 探索期間で選んだ買い方（上の「4.」）の回収率と 90% の幅、的中率、買った日数 |
| 基準 | **回収率が 100% を超え、90% の幅の下の端も 100% を超える。** かつ、回収率が (1)・(2) を上回る |
| 満たさなかったとき | 「届いたが偶然と区別できない」（回収率は 100% を超えたが幅の下の端が届かない）か「届かなかった」を、そのまま書く。予想は毎回出し続け、日の期待値が線以上の日は、楽しむための参加費の財布（ポリシー用）から、選んだ予算で買う（[15-decisions.md の 8](15-decisions.md#8-採用の基準に届かなかったときの扱い)） |

- 確認期間の WIN5 は百数十回で、当たる日は多くない。WIN5 の払戻は回ごとに何桁もちらばるので、90% の幅は広くなりやすく、**この基準を満たすのは難しい** ことを先に書いておく。
- 確定オッズでの確かめなので、実際に買うとき（締め切り前のオッズ）より良く出ることがある（[11-leak-prevention.md の 7](11-leak-prevention.md#決まり)）。結果に書き添える。

## 7. 道具と全券種の回収率

**WIN5 の表は道具にする。** 「印の成績」（`tools/印の成績/mark_stats.py`）に `--win5 [当日と前日の区切りごとの1着の予測]`（省略すると上の「1.」の表の予測）を足し、区切りごとの予測と元DB の `wf` から、上の「4.」の 40 通りと比べる相手 (1)・(2) の、期間ごと（探索・確認・年ごと）・予算ごとの成績の表を出す。精算・組み方・配当の見積もりは、この予想の `settlement/`・`formation/`・`payout/` の部品を呼ぶ（[04-classes.md の 3.](04-classes.md#3-この予想だけのクラスの一覧)）。数値は Git の対象外の `reports/近走と適性からWIN5の買い目を決める/成績/` に出す（表の `WIN5の成績.md` と、買い方ごと・日ごとの精算の結果 `WIN5の精算.csv`）。

**全券種の回収率の決まりとの関係。** 予想モデルを作ったり直したりしたら、印から全券種の買い目を作り、券種ごとの回収率を同じ道具で出す決まりがある。この予想は今のモデルを変えず、印も付けないので、単勝・複勝・枠連・馬連・馬単・ワイド・3連複・3連単の買い目は今までと同じである。この予想で増えるのは WIN5 の表だけで、それは上の表で必ず出す。

**実際に予想した結果の記録。** `predict` の結果は自動で記録する（[04-classes.md の「repository/」](04-classes.md#repository--この予想だけの読み書き)）。道具「印の成績」の `--win5` は、記録がたまった開催日について、実際に予想した買い目の成績も、確定オッズで確かめた成績と同じ表に並べる（[15-decisions.md の 7](15-decisions.md#7-締め切り時点のオッズと確定オッズの差の扱い)）。

**今のモデルを直したとき。** 今のモデルを直すと、全券種の表（今までの決まり）に加えて、この予想の1着の確率も変わる。直したときは、区切りごとの予測を作り直し、道具「印の成績」の WIN5 の表も回して、WIN5 の成績が悪くなっていないかを並べて見る。

## 8. 配当の見積もりの確かめ

確認期間の当たり組（的中無の回を除く）について、区切りごとに作った式で見積もった配当と、実際の払戻を比べる。

| 見るもの | 中身 |
|---|---|
| 外れの大きさ | log(実際の払戻) − log(見積もりの配当) の平均と散らばり。平均が 0 から大きくずれていれば、式が配当を高く（低く）見ている |
| 帯ごとの比べ | 見積もりの配当の帯（桁ごとなど）ごとに、見積もりの平均と実際の平均を並べる。人気薄の組で見積もりすぎていないか |
| 式の傾き | 区切りごとの傾き1（市場の組の確率の逆数）が 1 からどれだけ離れているか。区切りによって大きく変わるなら、式が安定していない |
| 的中無の回 | 確認期間の的中無の回について、当たり組の見積もりの配当が上限や「払戻に回るお金」の近くまで大きく出ているか（当たる人がいない組を、そう見ているか） |

式が配当を高く見ていると、日の期待値が高く出て、買わなくてよい日を買うことになる。外れの平均が大きくずれていたら、上の「6.」の結果と一緒に書き、式の材料を見直す（そのときは新しい式として、次に増える回で確かめる）。

## 確かめた結果

数値は Git の対象外の `reports/近走と適性からWIN5の買い目を決める/成績/`（`WIN5の成績.md`・`WIN5の精算.csv`）にある。道具「印の成績」の `--win5` で出した（2026-11-08）。ここには回収率・的中率・日数と、採用の基準を満たしたかだけを書く。どれも確定オッズで確かめた値で、実際に買うとき（締め切り前のオッズ）より良く出ることがある。

**結論: 探索期間で決まりどおりに選んだのは「1着の確率の順・240点・線 1.50」。確認期間では回収率 37.3% で、採用の基準に届かなかった。** 15 の 8 のとおり、予想は毎回出し、日の期待値が線以上の日は楽しむための参加費の財布（ポリシー用）から買う。そのあと利用者が1回の予算を 50点（5,000円）に決めたので、50点の8通りの中で同じ決まりで選び直し（「1着の確率の順・50点・線 1.25」）、確認期間で1回だけ確かめた（下の「予算を 50点に決め直したあとの確かめ」）。こちらも採用の基準には届いていない（90% の幅の下の端が 0%）。`predict` の既定（`formation/buying_defaults.py`）は、この 50点の買い方にした。

### 配当の見積もり（上の「8.」）

- 区切りごとの式の傾き1（市場の組の確率の逆数の対数）は 1.065〜1.079 で、区切りによらず安定していた。傾き2（キャリーオーバーの比）は 0.20 から −0.03 まで動いた（キャリーオーバーの回が少ないため）。
