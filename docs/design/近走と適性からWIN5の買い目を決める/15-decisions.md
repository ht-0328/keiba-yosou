## 1. 1着の確率をこの予想で学ぶか

**決めたこと（2026-11-08、利用者の決定）。** 今毎週の予想に使っているモデル（設計書「近走と適性から3着以内を予想」。週末の予想・次のレースの予想・発走前の通知で使っている）が出している「1着の確率」を、そのまま借りて使う。WIN5 用に新しく学ばない。利用者の言葉は「その一着の確率をだしてるならそれをつかっていいよ」。

| 選び方 | 変わること |
|---|---|
| **今のモデルの1着の確率を、そのまま借りる（決定）** | 学習が要らない。この予想は WIN5 の部品（組・配当・買い目）だけを持つ。週末の予想と同じ1着の確率で WIN5 を組むので、値が食い違わない。今のモデルを直すと、WIN5 の予想も一緒に変わる。過去の WIN5 で確かめるときは、今のモデルと同じ作りで半年ごとに学び直した区切りごとの予測を使う（[16-evaluation.md の 1.](16-evaluation.md#1-期間の分け方)） |
| この予想で、今のモデルと同じ材料・作りの1着のモデルを学ぶ | 学習に時間がかかり、モデルの置き場所が増える。材料が同じなので、今のモデルとほぼ同じ確率になる。今のモデルの印に響かずに WIN5 用に直していける |
| WIN5 の対象レースだけで学ぶ別のモデル | 確認1で選ばなかった（対象レースは少なく、学ぶには足りない） |

## 5. 買い目の組み方と予算の決め方

**決めたこと（2026-11-08、利用者の決定。おすすめのとおり）。** フォーメーション1枚。40 通りから探索期間で決まりどおりに1つ選び、予算ごとの成績の表も出して提案する。

**何を決める項目だったか。** 1回の予算（点数）は「研究で決める」と決まった。あわせて、買い目の形と、各レースの馬をどの順に選ぶかを決める必要がある。

| 選び方 | 変わること |
|---|---|
| **フォーメーション1枚。並べ方（上乗せの順・1着の確率の順）× 予算（20・50・100・240・500点）× 線（1.00・1.25・1.50・2.00）の 40 通りから、探索期間で決まりどおりに1つ選び、予算ごとの成績の表も出して提案する（決定）** | 利用者はレースごとの馬番を入れるだけで買える。40 通りから選ぶので、探索期間に合わせすぎる心配があり、確認期間で1回だけ確かめて見分ける |
| 並べ方・予算・線を今決めて固定する（例: 1着の確率の順・240点・線 1.00） | 選びすぎの心配が無い。もっと良い組み合わせがあっても見逃す |
| 組ごとに期待値の高い順に、予算の点数だけ買う（フォーメーションにしない） | 同じ予算で期待値はいちばん高くなる。買い目がばらばらの組になり、投票で数百点を1組ずつ入れる手間が出る（利用者は基本買うだけ、に合わない） |
| フォーメーションを何枚か組み合わせる（ルール集の5セットのような形） | 当たり方の形を広げられる。組み方の探索が大きくなり、選ぶ決まりも複雑になる |

**予算の決め直し（2026-11-08、利用者の決定）。** 1回の予算を **50点（5,000円）** に決めた。並べ方と線は、探索期間の 50点の買い方の中から同じ決まりで選び直した「1着の確率の順・線 1.25」で、確認期間で1回だけ確かめた（[16-evaluation.md の「予算を 50点に決め直したあとの確かめ」](16-evaluation.md#予算を-50点に決め直したあとの確かめ)）。予算と線は `src/yosou/form_aptitude_win5_tickets/formation/buying_defaults.py` の1か所で決まり、`predict`・道具「発走前の通知」・買う計画の金額はすべてここから出る。

関連する資料: [16-evaluation.md の 4.](16-evaluation.md#4-買い目の組み方と買う日の線)、[06-flowchart.md の図3](06-flowchart.md#図3-買い目の組み方と買う日の判断)

## 7. 締め切り時点のオッズと確定オッズの差の扱い

**決めたこと（2026-11-08、利用者の決定。おすすめのとおり）。** 確定オッズで確かめ、結果に書き添える。実際に予想した結果は自動で記録しておき、たまったらその成績も同じ表で見る（`Win5ForecastRecordRepository`）。

**何を決める項目だったか。** 元DB の終わったレースのオッズは確定オッズだけなので、過去の WIN5 での確かめは確定オッズで行う。実際に予想するときは1レース目の締め切り前の断面で、2レース目より後は、週末の予想（レースごとに締め切りの直前に予想する）よりオッズの差が大きい（[11-leak-prevention.md の 7](11-leak-prevention.md#決まり)）。

| 選び方 | 変わること |
|---|---|
| **確定オッズで確かめ、結果に「実際に買うときより良く出ることがある」と書き添える。実際に予想した結果（使ったオッズの断面を含む）は自動で記録しておき、たまったらその成績も同じ表で見る（決定）** | ほかの予想と同じ扱い（確定オッズ ≒ 締め切り前のオッズを前提にする）。記録は Git の対象外の `reports/` に自動で書くので、利用者の作業は増えない |
| 時系列オッズ（単複枠。1年分）のある期間で、1レース目の締め切りの時点の断面を使って確かめ直す | 実際に近い確かめになる。WIN5 は1年で 70回ほどしか無い。今のモデルの1着の確率も、その断面のオッズで予測し直す必要があり、券種オッズの断面は無いので券種オッズなしのモデルで代える |

関連する資料: [11-leak-prevention.md の 7](11-leak-prevention.md#決まり)、[07-prediction-timing.md の「過去のレースで確かめるときの時点のまね方」](07-prediction-timing.md#過去のレースで確かめるときの時点のまね方)

## 8. 採用の基準に届かなかったときの扱い

**決めたこと（2026-11-08、利用者の決定。おすすめのとおり）。** 予想は毎回出し、日の期待値が線以上の日は、楽しむための参加費の財布（ポリシー用）から、選んだ予算で買う。予算は利用者が 1回 50点（5,000円）に決めた（上の 5）。50点で選び直した買い方も、確認期間で回収率は 100% を超えたが 90% の幅の下の端が 100% に届かず、採用の基準を満たさないので、この決まりのまま買う。

**何を決める項目だったか。** 確認期間の WIN5 は百数十回しか無く（[08-training-data.md の 2.](08-training-data.md#2-配当の見積もりに使うデータ)）、採用の基準（回収率と 90% の幅の下の端が 100% 超え）を満たすのは難しい（[16-evaluation.md の 6.](16-evaluation.md#6-採用の基準)）。届かなかったときに、WIN5 を買うかを先に決めておく。

| 選び方 | 変わること |
|---|---|
| **予想は毎回出し、日の期待値が線以上の日は、楽しむための参加費の財布（ポリシー用）から、選んだ予算で買う（決定）** | 「期待値が線を超える日だけ買う」決まりのまま、WIN5 を楽しめる。減るのは参加費として想定内に扱い、勝負用の資金は減らない。財布（`reports/回顧/財布.json`）と買う計画に WIN5 の分を足す作りが要る（設計書「買うレースと買い目を決める」の財布の決まりに足す） |
| 予想は毎回出し、買わない | お金は減らない。買いたい日の判断は利用者に任される |
| 勝負用の財布で買う | 勝負用は「回収率 100% 超えを確かめた買い方だけ」の決まりに反する |

基準を満たしたときは、勝負用の財布で買う形を、あらためて決める。

関連する資料: [16-evaluation.md の 6.](16-evaluation.md#6-採用の基準)、[買うレースと買い目を決める の 08](../買うレースと買い目を決める/08-bankroll-and-review.md)

## 9. 今のモデルの1着の確率の受け取り方

**決めたこと（2026-11-08、利用者の決定。おすすめのとおり）。** 今のモデルの予測を作る部品を `shared` に移し、この予想から呼ぶ。

**何を決める項目だったか。** 1 で、今のモデルの1着の確率を借りると決まった。WIN5 の1レース目の締め切り前に、対象レース5つの1着の確率を、自動で受け取る必要がある（利用者の作業は「買う」だけにする）。予想のパッケージどうしで import しない決まりがある（片方を直すと、もう片方が壊れるため）。

| 選び方 | 変わること |
|---|---|
| **今のモデルの予測を作る部品（予測の流れの組み立て・特徴量の一覧・時点の選び方など）を `shared` に移し、この予想から呼ぶ（決定）** | 手作業は無く、決まりにも合う。今のモデル・道具「今週の予想」・この予想が同じ部品と同じ学習済みモデルで予測するので、1着の確率が食い違わない。最初に移す作業があり、今のモデルのパッケージと道具「今週の予想」も、移した先を使う形に直す |
| 道具「今週の予想」の結果のファイル（`reports/今週の予想/` の予想の結果。`win_probability` の列）を読む | 部品を移す作業は要らない。ただ、結果のファイルは道具を動かした時点のもので、WIN5 の1レース目の締め切り前に5レースぶんがそろっている保証が無い（朝に作った、馬体重の無い時点の予想が残っていることがある）。そろえるには、先に道具を動かす段取りが要り、道具が動いていなければ予想が出ない。予想のパッケージ（`src/`）が道具（`tools/`）の出力を読む向きにもなる |

## 10. 過去のレースで馬体重が出ていたとみなす線

**決めたこと（2026-11-08、利用者の決定。おすすめのとおり）。** 1レース目の発走から 60分以上あとに発走するレースは「出ていない」とみなす（仮）。発表の時刻が DB で読めるようになったら決め直す。

**何を決める項目だったか。** 過去の WIN5 で確かめるとき、1レース目の締め切りの時点で、どのレースの馬体重が出ていたかをまねる必要がある。元DB の速報の馬体重の発表の時刻は空で、何分前に発表されるかを確かめられなかった。

| 選び方 | 変わること |
|---|---|
| **1レース目の発走から 60分以上あとに発走するレースは「出ていない」とみなす（仮）。発表の時刻が DB で読めるようになったら、その値で決め直す（決定）** | 実際に近い材料で確かめられる。線がずれていると、当日と前日の確率を使うレースの割合が実際と少し変わる |

## 11. 予想を届ける場所

**決めたこと（2026-11-08、利用者の決定。おすすめのとおり）。** 道具「発走前の通知」で1レース目の発走の 10分前に投稿し、開催日のまとめにも WIN5 の節を足す。

**何を決める項目だったか。** 予想は WIN5 のある日に毎回出す。利用者の作業は「買うだけ」にしたいので、自動で届ける必要がある。予想は1レース目の締め切り前に出すので、前日や朝にまとめて予想する道具の時点とは合わない。

| 選び方 | 変わること |
|---|---|
| **道具「発走前の通知」で、1レース目の発走の 10分前に WIN5 の予想（日のまとめ・買い目・当たる確率・日の期待値・買う／見送り）を投稿し、開催日のまとめ（`reports/今週の予想/<開催日>/まとめ.md`）にも WIN5 の節を足す（決定）** | 毎朝動くタスクのままで届く。通知の道具に、WIN5 の日を読んで1レース目の前に1回投稿する段が増える |
| 利用者が `predict` を自分で回す | 作る物は少ないが、毎回の手作業が要る |
| 開催日のまとめだけに出す | まとめは朝や前日に作るので、馬体重やオッズの無いレースが多い時点の予想になる |

作るときに決めた時刻: `predict` は 3〜6分かかるので、1レース目の発走の 10分前に始めると、WIN5 の発売の締め切りに間に合わないおそれがある。そのため、取り込みと予想は1レース目の発走の 25分前に始め、1レース目の発走の 15〜20分前に投稿する（道具「発走前の通知」の設定ファイルの `win5_minutes_before` で変えられる。[05-sequence.md の「今は無く、これから作るところ」](05-sequence.md#今は無くこれから作るところ) の 5）。
