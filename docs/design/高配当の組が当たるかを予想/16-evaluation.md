# 16 当たり具合の測り方

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。期間をどう分けるか。何と比べれば「当たっている」と言えるか。どうなれば、その券種の買い目を採用してよいか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 年で分ける。テストの年ごとに、2年前までで学習し、直前の年で早期終了し、その年を予測する（2020年から）。成績は、探す期間（2022年まで）と確かめる期間（2023年から）に分けて並べる |
| 2. 評価指標 | 確率は対数損失、買い目は券種ごと・年ごと・期間ごとの点数・的中数・回収率と、開催日を単位にしたブートストラップの 90% の幅、運用の目安（1日の点数と金額・落ち込み） |
| 3. 比べる基準 | 市場の確率（確率の当たり具合）と、形だけで買ったとき（買い目の成績） |
| 4. 年ごとの確かめ | `walk` で年ごとの予測を残し、道具「高配当の買い目」の `stats.py` で成績を数える |
| 5. 採用の基準 | 探す期間と確かめる期間のどちらでも回収率が 100% を超え、全体の 90% の幅の下の端が 100% を超えること |
| 6. 確かめた結果 | 正式なパッケージでの数え直しで、ワイド・馬連・馬単・3連複が、確率の高い順に 10点までの形で基準を満たした。3連単は届かなかった |
| 7. 気をつけること | 確かめは確定オッズである。1日単位では負ける日のほうが多い |
| 8. 本番のモデルの学習 | `train` の出力の、検証の期間での対数損失（市場の確率との比べ）を見る |

用語の意味は [02-glossary.md](02-glossary.md) を参照。数値は、Git の対象外の `reports/高配当の組が当たるかを予想/`（予測と学習の報告）と `reports/高配当の買い目/`（買い目の成績）に置く。この文書には、結果を言葉で書く。

## 1. 期間の分け方

| 区分 | 何に使うか | 期間 |
|---|---|---|
| 学習 | モデルの `fit` に渡す | 表のある最初の年（2015年）から、テストの年の2年前まで |
| 検証 | 木を足すのを止める判断（早期終了）にだけ使う | テストの年の直前の年 |
| テスト | 対象の組を全部予測して、成績を数える | 2020年から、表のある最後の年まで。1年ずつ |

- テストの年ごとに学び直す。たとえばテストの年が 2023年なら、2015〜2021年で学習し、2022年で早期終了し、2023年を予測する。
- 成績は、テストの年を2つに分けて並べる。**探す期間**（2020〜2022年）は、作りや線を比べるのに結果を見た年、**確かめる期間**（2023年から）は、同じ決まりで数えるだけの年である。
- 時期で分ける理由は、手本と同じである（[手本の 16 の「1. 期間の分け方」](../近走と適性から3着以内を予想/16-evaluation.md#1-期間の分け方)）。

## 2. 評価指標

| 見るもの | 指標 | 何が分かるか |
|---|---|---|
| 確率の当たり具合 | 対数損失（小さいほど良い）。テストの年の対象の組の全部で測る | 確率として使えるか。市場の確率より良いか（下の 3） |
| 買い目の成績 | 券種ごと・年ごと・期間ごとの、点数・的中数・回収率 | 買い目の決まり（[06-flowchart.md の図3](06-flowchart.md#図3-買い目の選び方)）で買ったときに、100% を超えるか。年によって割れないか |
| 偶然の幅 | 開催日を単位にしたブートストラップの 90% の幅 | 回収率が、たまたま大きい払戻が1つあっただけで決まっていないか |
| 運用の目安 | 1開催日の買うレース・点数・金額、1年の投資と収支、いちばん深い落ち込み、外れが続いた最長のレース数、高配当が1本以上当たった開催日の割合 | 実際に買い続けられる大きさか |
| 線の感度 | 期待値の線と上限の点数を変えたときの成績 | 線を少し動かしただけで成績が崩れないか。上限の点数を決める材料（[15-decisions.md の 16](15-decisions.md#16-1レース1券種の上限の点数)） |

買い目の成績の数え方は、1点 100円で、買い目の決まりに合う組を全部買う。回収率 = 払戻の合計 ÷ 買った金額の合計。

## 3. 比べる基準

| 基準 | 何を出すか | どの指標と比べるか |
|---|---|---|
| 市場の確率 | 出発点を確率に戻した値（市場の確率 q）と、それを当たりの数に合うように一律に定数倍した値の2つ。対象の組の市場の確率の合計は当たりの数と合わないので、合わせた値でも比べる（`MarketComparison`） | 対数損失。モデルの値が、当たりの数に合わせた市場の確率と同じなら、市場の確率に何も足せていない |
| 形だけで買う（下調べで比べた） | 予想の確率を使わず、形で選んだ高配当の組（6番人気以下で、複勝オッズより来ると見る馬を含む組など）を全部買ったときの回収率 | 買い目の回収率。確率を出して選ぶ意味があるかを見る（[15-decisions.md の 7](15-decisions.md#7-予想の確率を使わず形だけで買うか)） |

## 4. 年ごとの確かめ

```powershell
uv run python -m yosou.high_payout_combos walk
uv run python tools/高配当の買い目/stats.py
```

（1行目は、テストの年ごとに5券種のモデルを学習し、その年の対象の組の全部の確率を `reports/高配当の組が当たるかを予想/predictions/<券種の英名>_<年>.parquet` に残すコマンド。2行目は、残した予測に買い目の決まりを当てて、券種ごと・年ごと・期間ごとの成績と 90% の幅、運用の目安、線の感度の5つの表を出し、`reports/高配当の買い目/成績.md` にも書くコマンド。`--value-line`・`--max-points`・`--ticket` で決まりを替えて数え直せる。既定は、今週の予想が実際に出す買い目と同じ決まりである）

- `walk` の出力にも、券種ごとに、年ごとの学習の表（学習と検証の行数・木の数・予測した組の数）と、買い目の年ごとの成績の表（点数・的中数・買ったレースの数・回収率。`YearlyPickSummary`）が出る。その場で見るための表で、期間ごとの成績・90% の幅・運用の目安は `stats.py` で出す。`--value-line` で、成績を数えるときの期待値の線を変えられる（予測そのものは変わらない）。
- 残す列は、レースID・開催日・券種・組番・馬番・オッズ・払戻・当たり・確率（2つのモデルの平均と、モデルごと）・市場の確率である。
- テストの年の行は、間引かずに全部を予測する。間引くのは、学習と早期終了に使う行だけである（[08-training-data.md](08-training-data.md#4-外れの組の間引きと行の重み)）。
- 予測を残しておくので、買い目の決まり（期待値の線・上限の点数）を変えて数え直すときに、学習し直さなくて済む。

## 5. 採用の基準

**券種ごとに、次の2つを両方満たしたら、その券種の買い目を採用する。**

1. 探す期間と確かめる期間の**どちらでも**、回収率が 100% を超える。
2. テストの年の全部を合わせた回収率の、開催日を単位にしたブートストラップの 90% の幅の下の端が、100% を超える。

買い目の決まりは、全券種で同じ（オッズが高配当の線以上・上限未満、期待値 1.05 以上）にして数える。券種ごとに線を選ばない（[15-decisions.md の 10](15-decisions.md#10-期待値の線)）。

## 6. 確かめた結果

**下調べ（正式なパッケージにする前のスクリプト）の結果。**

| 券種 | 結果 |
|---|---|
| ワイド | 基準を満たした。どの年も 100% 以上だった |
| 馬連 | 基準を満たした。どの年も 100% 以上だった |
| 馬単 | 基準を満たした。どの年も 100% 以上だった |
| 3連複 | 学ぶ範囲を高配当の線より下まで広げた版で、探す期間と確かめる期間のどちらも 100% を超えた |
| 3連単 | 全体では 100% を超えたが、1レースの点数が多く、年によって 100% を割った |

確率の当たり具合（対数損失）は、木のモデルが少ない材料のロジスティック回帰より良かった（[15-decisions.md の 6](15-decisions.md#6-どの道具で学ぶか)）。比べた作りと、採らなかった理由は [15-decisions.md](15-decisions.md) を参照。

**正式なパッケージでの数え直しの結果。** `walk` で5券種を 2020〜2026年の年ごとに学び直して予測し、`stats.py` と同じ数え方（確定オッズ・1点 100円）で、期待値の線 1.05 と上限の点数（なし・10点）を比べた。

| 券種 | 上限なし | 確率の高い順に 10点まで |
|---|---|---|
| ワイド | 基準を満たした。どの年も 100% 以上 | 基準を満たした。どの年も 100% 以上で、上限なしより回収率が上がった |
| 馬連 | 探す期間・確かめる期間とも 100% を超えたが、幅の下の端は 100% とほぼ同じで、年によって割った | 基準を満たした。下の端も 100% をはっきり超えた |
| 馬単 | 基準を満たした。下の端も 100% をはっきり超えた | 基準を満たした（上限なしとほぼ同じ） |
| 3連複 | 探す期間・確かめる期間とも 100% を超えたが、下の端が届かず、年によって割った | 基準を満たした。探す期間・確かめる期間とも上限なしより上がり、下の端も 100% を超えた |
| 3連単 | 全体では 100% を超えたが、下の端が届かず、1レースの点数が多い | 届かない。年によって大きく割った |

3連単は、期待値の線（1.1〜1.3）・上限の点数（10〜30点）・オッズの上限（3,000倍・5,000倍）を替えても、幅の下の端が 100% を超えたのは1レースの点数が多い形だけで、それも年によって割った。そのため、本番で出す券種は **ワイド・馬連・馬単・3連複** の4つ、1レース・1券種の上限の点数は **確率の高い順に 10点** にした（[15-decisions.md の 15](15-decisions.md#15-本番で出す券種)・[16](15-decisions.md#16-1レース1券種の上限の点数)）。4券種とも、どの年も 100% を割ったのは1年までだった。数値は Git の対象外の `reports/高配当の買い目/成績.md`（`stats.py` の出力）にある。

## 7. 気をつけること

- **確かめは確定オッズである。** 本番は、発走の約10分前の締め切り前のオッズで買う。締め切り前のオッズの記録がある期間で見ると、高配当の組は確定オッズのほうが高くなりやすく、券種どうしのオッズのずれも、大半が確定まで同じ向きに残っていた。ただし、記録のある期間が短い。買い目の記録で、締め切り前のオッズでの成績を見ていく（[買うレースと買い目を決める の 08 の 2](../買うレースと買い目を決める/08-bankroll-and-review.md#高配当の買い目)）。
- **1日単位では、負ける日のほうが多い。** 高配当の組はめったに当たらないので、外れの日が続き、高配当の日にまとめて取り返す形になる。成績は、日や月ではなく、年の単位で見る。
- **3連単は、1レースの点数が多い。** 対象の組が多く、期待値の線を超える組も多いので、100円ずつでも1レースの金額が大きくなる。上限の点数（[15-decisions.md の 16](15-decisions.md#16-1レース1券種の上限の点数)）は、このために決める。
- **探す期間の結果は、作りを比べるのに見ている。** 探す期間の成績だけで採否を決めない。確かめる期間でも同じ向きかを見る（上の 5）。

## 8. 本番のモデルの学習

本番のモデル（`train`）は、券種ごとに、組の表のある最後の開催日の1年前までの行で学習し、最後の1年の行で早期終了する（`ProductionTraining`）。テストの期間は取らない。

`uv run python -m yosou.high_payout_combos train` の出力に、券種ごとの学習と検証の期間・行数・木の数の表と、検証の期間での対数損失が、市場の確率（上の 3 の基準）と並んだ表が出る。5券種とも、モデルの対数損失が、当たりの数に合わせた市場の確率より小さいことを見る。

本番のモデルは、テストの年を残さずに最後の1年を検証に使うので、この出力で成績の良し悪しは決めない。買い目の採否は、上の 4〜6 で決める。
