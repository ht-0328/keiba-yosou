# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの組・どの期間の行を入れるか。外れの組をどう減らすか。馬ごとの予想をどこから持ってくるか。

**結論: 1サンプル = 1レース × 1券種 × 1つの組。オッズが学ぶ下限以上・上限未満の組を入れる。当たりの組は全部、外れの組は券種ごとの割合で間引いて、割合の逆数の重みを付ける。馬ごとの予想は、過去のレースの「学習に使っていない期間の予測」に本番と同じ決め方で印を付けた、1頭1行の表（馬ごとの表）から取る。期間は 2015年からで、券種ごと・年ごとに組の表を作って保存する。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

架空の3つの組（ワイド）を例にすると、学習データは次の形になる。

| レースID | 組 | オッズ | 市場の確率の対数 | 1頭目の3着以内の確率 | 2頭目の3着以内の確率 | …（特徴量はあと 70個以上） | 出発点 | 当たり | 払戻 | 重み |
|---|---|---|---|---|---|---|---|---|---|---|
| 架空のレースA | 5-12 | 24.0 | −3.44 | 0.40 | 0.21 | … | −3.41 | 1 | 2,400 | 1.0 |
| 架空のレースA | 2-9 | 6.5 | −2.14 | 0.55 | 0.33 | … | −2.01 | 0 | 0 | 3.3 |
| 架空のレースA | 12-15 | 310.0 | ― | ― | ― | ― | ― | ― | ― | 入れない（上限以上） |

- 表は券種ごとに別である。券種で、組の頭数と特徴量の列が違うためである（[09-features.md](09-features.md#券種ごとの特徴量の数)）。
- 手本の学習データ（1行 = 1頭）とは、行の単位が違う。1レースから、対象の組の数だけ行ができる（16頭立てのワイドなら最大 120行、3連単なら最大 3,360行）。
- 重み 3.3 は、外れの組を 0.3 の割合で残したときの 1 ÷ 0.3 である（下の 4）。

## 2. 列の種類

| 種類 | 列 | モデルに渡すか |
|---|---|---|
| ID 列 | レースID、開催日、券種、組番、組の馬番（1頭目〜3頭目） | 渡さない |
| 特徴量 | まとまり A〜F。[09-features.md](09-features.md) を参照 | `fit` の `X` として渡す |
| 出発点 | 市場の確率のロジット（[10-target.md](10-target.md#出発点基準)） | LightGBM は `init_score`、CatBoost は `baseline` として渡す |
| 目的変数 | 当たり（1 か 0。[10-target.md](10-target.md#作り方)） | `fit` の `y` として渡す |
| 行の重み | 当たりの組は 1、間引いた外れの組は 割合の逆数（下の 4） | `fit` の重みの引数として渡す。予測には使わない |
| 評価用の列 | 組のオッズ、100円あたりの払戻（外れは 0） | 渡さない |

- 組のオッズは、評価用の列に置くのと別に、特徴量（オッズの対数）と出発点の元にもなる。
- 予測用データは、目的変数・行の重み・払戻が無いだけで、ほかは同じ列である。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 馬ごとの表にあり、その券種の確定オッズの板と3連単の確定オッズの板があるレース | 特徴量の元がそろうレースだけを使う |
| 対象の組 | その券種のオッズ（ワイドは最低オッズ）が、学ぶ下限以上・上限未満の組 | 高配当の線より下まで学ぶと当たりの例が増える。上限より上は当たりが極端に少ない（[10-target.md](10-target.md#オッズの帯)） |
| 馬ごとの表に無い馬・市場の見立ての無い馬を含む組 | 入れない | その馬の材料（まとまり D）が作れない |
| 市場の確率が無い組 | 入れない。オッズの無い組と、3連単から足し合わせた確率を作れない組 | 出発点とまとまり A が作れない || 期間 | 2015年から、馬ごとの表のある最後の開催日まで | 下の 6 |

判断の順は [06-flowchart.md](06-flowchart.md#図1-表に入れる組の選び方) を参照。ウォームアップ期間は要らない。過去走から作る特徴量が無く、近走や適性は馬ごとの予想を通して使うためである。

## 4. 外れの組の間引きと行の重み

**当たりの組は全部を残し、外れの組は券種ごとの割合でくじで選んで残す。残した外れの組には、重み = 1 ÷ 割合 を付ける。** 割合は、組の多い券種ほど小さくして、学習の行の数を券種の間でそろえる（`MISS_KEEP_RATES`。間引くクラスは `MissSampling`）。

| 券種 | 外れの組を残す割合 | 残した外れの組の重み |
|---|---|---|
| ワイド | 0.3 | 約 3.3 |
| 馬連 | 0.2 | 5 |
| 馬単 | 0.1 | 10 |
| 3連複 | 0.06 | 約 16.7 |
| 3連単 | 0.015 | 約 66.7 |

| 決まり | 理由 |
|---|---|
| 間引くのは外れの組だけ | 当たりの組は1レースに1つ（ワイドは3つ）しか無く、数が少ない。外れの組は 3連単で1年に数百万行あり、全部を学習に使うとメモリと時間が足りない |
| 重みを付ける | 重みを付けると、間引く前と同じ割合で当たりと外れを数えたことになり、出てくる確率の大きさがずれない。重みを付けずに間引くと、確率が実際より高く出て、期待値を大きく見積もる |
| 間引くのは学習データと、早期終了に使う検証データだけ | 年ごとの確かめで成績を数える行（テストの年）は、対象の組を全部（間引かずに）予測する（[16-evaluation.md](16-evaluation.md#4-年ごとの確かめ)） |
| くじの乱数の種は年ごとに固定する | 学習し直しても、同じ行が選ばれて同じ結果になるようにする |
| 組の表（下の 6）には全部の組を保存し、間引くのは学習データを作るとき | 割合を変えて試すときに、表を作り直さなくて済む |

## 5. 馬ごとの予想の出どころ

特徴量のまとまり C〜F は、1頭1行の「馬ごとの表」から作る。**学習に使うのは、過去のレースについて、予想のモデルが学習に使っていない期間に出した予測である**（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 1）。

| 項目 | 内容 |
|---|---|
| 作る道具 | 道具「高配当の買い目」の `tools/高配当の買い目/horses.py`。この予想のパッケージは読むだけ（`HorseTableRepository`）。もとの予測は、研究「既存モデルの改善」の、区切りごとに学んで次の期間を予測した結果のテスト期間の行である |
| 置き場所 | `reports/高配当の組が当たるかを予想/horses/*.parquet`（Git の対象外）。全部のファイルを読んでつなぐ。同じレース・馬番の行が2つのファイルにあれば誤りにする |
| 中身 | 過去のレースの、学習に使っていない期間の予測（3着以内の確率・1着の確率）に、本番（今週の予想の当日の予想）と同じ決め方で、市場の見立て・人気・印・危険な人気馬の判定・単勝と複勝の期待値を付けたもの |
| 2020年から | 今の本番の予想（近走と適性から3着以内を予想・1着の予想・人気馬が4着以下になるかを予想）の予測 |
| 2015〜2019年 | 前の版の予想の予測。学習の行を増やすために使う。年ごとの確かめで成績を数える年（2020年から）は、どの年も今の本番の予想の予測である（[15-decisions.md の 4](15-decisions.md#4-馬ごとの予想にどの版を使うか)） |
| 読む列 | レースID・開催日・馬番と、3着以内の確率・1着の確率・オッズから見た勝率・オッズから見た3着以内率・単勝オッズ・複勝の最低と最高のオッズ・単勝人気・3着以内の確率のレース内順位・危険な人気馬か・危険度・印・上げ下げ・単勝の期待値・複勝の期待値（[09-features.md](09-features.md#d-組の位置ごとの馬の材料)） |

本番の予測では、同じ列を持つ表を、今週の予想の当日の予想が1レースぶん作って渡す（[07-prediction-timing.md](07-prediction-timing.md#予測のときのオッズの与え方)）。

## 6. 期間の指定

学習データは、まず「組の表」として券種ごと・年ごとに作って保存し、学習と確かめはその表を読む。3連単は1年で 300〜400万行になるので、月ごとに作って年で1つのファイルに書き、全部の年を一度にメモリに持たない。

```powershell
uv run python -m yosou.high_payout_combos tables
uv run python -m yosou.high_payout_combos tables --from 2025-01-01 --ticket ワイド 馬連 --force
uv run python -m yosou.high_payout_combos walk
uv run python -m yosou.high_payout_combos train
```

（1行目は、2015年1月1日から馬ごとの表の最後の開催日までの、5券種の組の表を `reports/高配当の組が当たるかを予想/tables/<券種の英名>_<年>.parquet` に作るコマンド。済んだ券種・年は飛ばす。2行目は、期間と券種を絞って作り直すコマンド。3行目は、年ごとに前の年だけで学んで次の年を予測する確かめのコマンド。4行目は、本番のモデルを学習して保存するコマンド。引数は [04-classes.md](04-classes.md#4-コマンドの引数)）

年の途中の期間で作ると、その年のファイルは区切った範囲だけになる。年のファイルを作り直すときは、その年の全部の期間を渡す。

- 作った表を、学習・検証・テストにどう分けるかは、年ごとの確かめ（`walk`）は [16-evaluation.md の 1](16-evaluation.md#1-期間の分け方)、本番のモデル（`train`）は [16-evaluation.md の 8](16-evaluation.md#8-本番のモデルの学習) を参照。
- 2015年からにしたのは、馬ごとの表がある最初の年だからである。JRA-VAN は5券種のオッズを 2004年8月から（3連単がいちばん遅い）提供しているので、オッズの板は足りている（[09-features.md](09-features.md#使うデータの期間)）。
- 期間を時期で分ける理由は、手本と同じである（[手本の 16 の「1. 期間の分け方」](../近走と適性から3着以内を予想/16-evaluation.md#1-期間の分け方)）。

## 7. 行数の数え上げ

組の表の行数は、`tables` の出力に券種ごと・年ごとに出る。学習・検証の行数（間引いたあと）は `walk`・`train` の出力に出る。行数は期間と元DB の中身で変わるので、ここには書かない。大きさの目安は次のとおり。

| 券種 | 1レースの対象の組（16頭立てのとき） | 1年の行数の目安 |
|---|---|---|
| ワイド・馬連 | 最大 120 | 数十万行 |
| 馬単 | 最大 240 | 数十万行 |
| 3連複 | 最大 560 | 100万行ほど |
| 3連単 | 最大 3,360 | 300〜400万行 |
