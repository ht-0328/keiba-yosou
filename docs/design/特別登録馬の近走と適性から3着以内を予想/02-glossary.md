# 02 用語の意味

**この文書の目的:** この設計書に出てくる用語の意味を1か所にまとめる。

**結論: 機械学習の用語と、競馬とこの設計の用語の大半は、中央の予想の [02 用語の意味](../近走と適性から3着以内を予想/02-glossary.md) と同じである。** ここには、特別登録の予想で増える用語と、意味が変わる用語だけを書く。

## 中央の予想と同じ用語

二値分類・学習データ・サンプル・特徴量・目的変数・予測確率・欠損値・リーク・過学習・ハイパーパラメータ・アンサンブル・GBDT・早期終了・public メソッド・オーケストレーション・インターフェース・リポジトリ・エンコーダー・ID 列・評価用の列・確定オッズ・1着になる確率・ウォームアップ期間・レース内順位・事実表・出走別着度数は、中央の予想の [02 用語の意味](../近走と適性から3着以内を予想/02-glossary.md) を参照。単勝の期待値・◎ の期待値の帯・勝ち切る材料は、オッズの無いこの予想には出てこない。

## 特別登録の予想で増える用語・変わる用語

| 用語 | 意味 | この設計では |
|---|---|---|
| 特別競走 | 競走名の付いたレース（重賞・オープン特別・条件戦の特別）。平場（競走名の無いレース）と区別する。1 開催日 1 競馬場あたり 9〜12R の 3〜4 レースと、障害の特別がある | 対象のレース。事実表では `race_name` が空でない行（[08-training-data.md](08-training-data.md#3-どのサンプルを入れるか)） |
| 特別登録（特別登録馬。`tk`） | 特別競走に出走したい馬を、発走の前の週に登録したもの。JV-Data の TK レコード（jvdata-store の表 `tk` と、登録馬ごとの子表 `tk__登録馬毎情報`）。レースの条件（競馬場・距離・トラック・グレード・競走条件・重量種別・ハンデ発表日）と、登録馬ごとの血統登録番号・馬名・性別・調教師・負担重量・交流区分を持つ。騎手・枠番・馬番・出走頭数・馬場・馬体重・オッズは無い。仕様は jvdata-store の [TK](../../../../jvdata-store/docs/reference/TK.md) | 予測する時点の名前であり、登録馬の行の元（[07-prediction-timing.md](07-prediction-timing.md)） |
| ハンデ発表前・ハンデ発表後（データ区分 1・2） | 特別登録は、日曜の夕方にハンデ発表前（データ区分 1）、月曜の夕方にハンデ発表後（データ区分 2）の 2 回出る。ハンデ戦の負担重量は月曜の版から入る。提供期間は、月曜の版が 1 年、日曜の版は月曜の版が出るまで | 月曜の版を使う。無ければ日曜の版（[06-flowchart.md の図2](06-flowchart.md#図2-登録馬の行の作り方)） |
| 登録馬 | 特別登録に載っている馬。平均 17.5 頭で、実際に出走するのは平均 13.6 頭（約 8 割）。出走しない馬は、同じ週の別のレースにも登録して片方を選んだ馬（出走しない馬の約 3 割）と、除外か回避の馬 | 予測する行。全員に確率を出す |
| 出走しなかった登録馬 | 登録したが、そのレースに出走しなかった馬。結果が無い | 学習データに入れない。予測では確率が付くが、木曜に出走馬名表が出たら中央の予想に引き継ぐ（[10-target.md](10-target.md#出走しなかった登録馬の扱い)） |
| 登録馬の行 | 特別登録から作る、事実表と同じ列を持つ行（1 行 = 1 頭の登録）。レースの条件は `tk`、馬は `tk__登録馬毎情報` と競走馬マスタ（`um`）から作り、前走・累積の列は事実表と同じ SQL で付ける。騎手・枠番・馬番・ブリンカー・馬体重・馬場状態・オッズは欠損値 | 予測用データの元（[04-classes.md の 3.](04-classes.md#3-共通の部品に足すこと)） |
| 登録日相当（材料の締めの日） | 材料を数えるときに「この日までの記録」とする日。開催日より前の直近の月曜日（土曜のレースなら 5 日前、日曜なら 6 日前、月曜の開催なら 7 日前）。学習データの過去のレースにも、予測する登録馬の行にも、同じ決め方で付ける | 調教・通算と直近の成績・対戦レーティングは、この日までの記録で数える（[11-leak-prevention.md](11-leak-prevention.md#決まり)） |
| 出走馬名表（木曜） | 木曜に出る出走馬の表（`ra`・`se` のデータ区分 1）。出走馬・騎手・斤量が決まり、枠番・馬番は未定。中央の予想の最初の時点 | この予想は使わない。木曜以降の予測は中央の予想に引き継ぐ |
| 交流区分 | 登録馬が地方馬（1）か外国馬（2）か。中央の馬は 0 | 中央の過去走が無い馬は、近走・指数・対戦レーティングが欠損値になる。確率は出すが粗い（[15-decisions.md の 12](15-decisions.md#12-外国馬地方馬と日曜の版だけのレースの扱い)） |
| 相手と比べる材料 | 同じレースの馬の中で順位・偏差・最良との差に直した材料（M のレース内の比べ 60個・先頭率の合計 2個・セリの価格の比べ 2個、O の 3個、T の 3個の 70個）。学習では出走馬の中で、予測では登録馬の中で比べる | [09-features.md](09-features.md#相手と比べる材料70個)。外した版との比べは [16-evaluation.md の 4.](16-evaluation.md#4-7つの区切りでの確かめ) |
| 特別競走の印（Y） | 学習データの行が特別競走か平場かを表す 1 個の特徴量（1 か 0）。予測では必ず 1 | [09-features.md の Y](09-features.md#y-特別競走の印1個) |
| 頭数から見た割合 | 3 ÷ 頭数（3着以内）・1 ÷ 頭数（1着）を確率としたもの。オッズの無い時点で、何も見ないときの基準。この予想では登録馬の数ではなく出走頭数で割る（学習データの評価用の列） | [16-evaluation.md の 3.](16-evaluation.md#3-比べる基準) |
| 7つの区切り | 過去で学習して次の半年を予想する確かめ（ウォークフォワード）を、2023年前半〜2026年の 7 つで行うこと。中央の予想の 16 の 4. と同じ区切り | この予想の `backtest` が回す（[16-evaluation.md の 4.](16-evaluation.md#4-7つの区切りでの確かめ)） |
| 全頭評価 | 登録馬の全員について、有力馬の候補と、馬ごとの基本情報・強み・弱みを並べた 1レース 1枚の文書（Markdown）。道具「全頭評価」が書く | 登録の時点の出し方。印・的中率と配当率・買い目・想定人気は無い |
| 強み・弱み | 登録馬 1頭の良い点・不安な点を、事実表の数字（近走・能力指数・適性・調教師・血統・調教）とモデルの寄与（分類ごとのロジットの上げ下げ）、重賞の傾向から定型の文にしたもの | 文は定型で、根拠の数字を添える。語りは作らない |
| 有力馬の候補 | 1着になる確率の上位 3頭の馬名 | 全頭評価の冒頭に出す |
| 重賞の傾向（全頭評価） | 同じ重賞（特別競走番号が同じ）の過去の開催の出走馬のうち、登録馬と同じ条件（前走のレース・前走の人気・休み明け・関西馬・好走経験）の馬の成績（着別度数と単勝・複勝の回収率） | 3着以内率が全体より 5ポイント以上高ければ強み、低ければ弱み。出走数 8未満の条件は出さない |
| 木曜のモデル | 中央の予想「近走と適性から3着以内を予想」の、木曜（出走馬名表）の時点のモデル。この予想の材料の元 | 同じレースの当たり具合を比べる相手（[16-evaluation.md の 3.](16-evaluation.md#3-比べる基準)） |
