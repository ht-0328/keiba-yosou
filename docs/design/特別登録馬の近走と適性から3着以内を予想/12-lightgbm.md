# 12 LightGBM で学習・予測するための設計

**この文書で決めること:** 07〜09 で決めた学習データ（特徴量と目的変数）を、LightGBM で学習・予測するために、LightGBM だけに必要なことを決める。

| 決めること | 結論 |
|---|---|
| 1. 学習データの渡し方 | 中央の予想と同じ。180個はすべて数値特徴量なので、カテゴリ特徴量の変換（category 型にする・出走の少ない値を「その他」にまとめる）は、対象の列が無く何もしない。欠損値はそのまま渡す |
| 2. ハイパーパラメータの初期値 | 中央の予想と同じ値から始める。目的関数は二値分類（`binary`）、木の数は早期終了で決める |
| 3. 学習・予測・保存の手順 | 特別登録の1つの時点で、3着以内と1着のモデルを1つずつ学習する。保存先は `reports/特別登録馬の近走と適性から3着以内を予想/models/` |

- 使うクラスは中央と共通の `LightGbmModel`・`LightGbmEncoder`（`src/yosou/shared/ml_model/`）である。学習データの渡し方・ハイパーパラメータの初期値・カテゴリ特徴量の値の変え方（フローチャート）・学習と予測のやりとり（シーケンス図）は、中央の予想の [12 の 1.〜5.](../近走と適性から3着以内を予想/12-lightgbm.md#1-学習データの渡し方) を参照。ここには、この予想で違う点だけを書く。
- CatBoost の設計は [13-catboost.md](13-catboost.md) を参照。

## この予想で違う点

| 項目 | 中央の予想 | この予想 |
|---|---|---|
| カテゴリ特徴量 | 当日のモデルにある（騎手・調教師・父など）。木曜・前日のモデルには無い | 無い（180個はすべて数値）。`LightGbmEncoder` は、カテゴリの列が無いので何も変えずに渡す。`min_category_count` の初期値（2000）は使われないが、設定ファイルの形をそろえるために残す |
| 学習する時点とモデルの数 | 木曜・前日・当日と券種オッズなしの当日、3着以内と1着で 8組 | 特別登録の1つ、3着以内と1着で 2組（LightGBM と CatBoost で 4個） |
| 基準（出発点） | 前日・当日はオッズから作った基準を出発点にする。木曜は基準なし | 基準なし（中央の木曜と同じ） |
| 学習データの大きさ | 馬の力の材料は約 70 万行 × 213 列 | 約 70 万行 × 180 列。学習の時間は中央の木曜のモデルと同じ程度（十数分の見込み） |
| 保存先 | `reports/近走と適性から3着以内を予想/models/` | `reports/特別登録馬の近走と適性から3着以内を予想/models/`（Git の対象外）。3着以内は `models/thursday/`、1着は `models/1着/thursday/` |

1 と 0 の数の偏りを直す設定（`is_unbalance`・`class_weight`）は使わない。[10-target.md](10-target.md) の「1 と 0 の数の偏り」を参照。
