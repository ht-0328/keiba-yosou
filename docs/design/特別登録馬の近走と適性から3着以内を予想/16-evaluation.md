# 16 当たり具合の測り方

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。何と比べれば「当たっている」と言えるか。相手と比べる材料を外した版と、どう比べるか。登録馬の全員に出した予想を、どう確かめるか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 時期で分ける。既定は 学習 2012年1月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜。`train` の引数で変えられる |
| 2. 評価指標 | 中央の予想と同じ共通の指標（ログ損失・AUC・Brier と、人気の基準との比べ方・同じ人気の中での AUC）を、LightGBM・CatBoost・平均の3行で出す |
| 3. 比べる基準 | 頭数から見た割合（採用の基準）、同じレースの中央の木曜のモデル（参考）、1番人気（`train`・`backtest` の出力） |
| 4. 7つの区切りでの確かめ | `backtest` で、中央と同じ7つの半年の区切りで学習し直し、テスト期間の特別競走の行で当たり具合を測る。相手と比べない版（`--variant`）も同じ区切りで回し、良いほうを採る |
| 5. ハイパーパラメータの調整のやり方 | 中央と同じ。自動の探索はしない。設定ファイルを変えて `train --config` で学習し、2つの検証期間で初期値と比べる |
| 6. 印の成績（全券種の回収率の確かめ） | この予想は印を付けないが、モデルを作ったときの決まりとして、`backtest` の予測を道具「印の成績」に `--timing 木曜` で渡し、道具が仮に付けた印ごとの成績と、買い目（全券種）の回収率を出す。採用の基準にはせず、報告する |
| 8. 全頭評価の確かめ | 道具「全頭評価」を合成DB の特別登録で動かし、登録馬の全員に基本情報・強み・弱みが付いた文書が1枚書けることをテストで確かめる。実DB では今週の登録のレースで形を見る |
| 7. 登録馬全員に出した予想の確かめ | `registrations` で、テスト期間の特別登録の登録馬の全員に予測を出し、出走した登録馬だけでの当たり具合（登録馬の中で比べた材料のずれ）を見る。出走しなかった馬の割合は見ない |

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 期間の分け方

区分（ウォームアップ・学習・検証・テスト）の意味は、中央の予想の [16 の「1. 期間の分け方」](../近走と適性から3着以内を予想/16-evaluation.md#1-期間の分け方) と同じ。既定の日は [08-training-data.md の「4. 期間の指定」](08-training-data.md#4-期間の指定)。共通の `PeriodSplitter` が学習データを3つに分け、`train` は検証データだけで当たり具合を測り、早期終了にも検証データを使う。テストデータは `backtest`（下の 4.）で確かめる。

## 2. 評価指標

**指標の意味と良い向きは、穴馬の予想の [16 の「2. 評価指標」](../穴馬が3着以内に入るかを予想/16-evaluation.md#2-評価指標) と同じである。** 共通の `MetricCalculator` で計算し、`train` の出力の「検証データでの当たり具合」と「人気の基準との比べ方」の2つの表に出る。読み方は中央の予想の [16 の 2.](../近走と適性から3着以内を予想/16-evaluation.md#2-評価指標) と同じ（モデルの行は3行、判断は平均の行で行う）。

この予想で気を付ける点:

- `train` の検証データは全レース（平場を含む）の行である。この予想の使いどころは特別競走なので、`backtest` では特別競走の行（Y = 1）だけで測る。全レースの値も参考に出す。
- 人気の基準（確率1位の馬の3着以内率と1番人気の3着以内率の比べ、人気の中での AUC）は、確定人気（評価用の列）で測る。この予想はオッズを見ていないので、1番人気に届かないのが普通で、届かないこと自体は欠点ではない。

## 3. 比べる基準

| 基準 | 何を出すか | どこで比べるか | 何が分かるか |
|---|---|---|---|
| 頭数から見た割合 | 3 ÷ 出走頭数（3着以内）・1 ÷ 出走頭数（1着）を確率としたもの | `backtest` の出力（モデルの行の下に「頭数から見た割合」の行） | オッズの無い時点で、何も見ないよりは当たるか。**採用の基準** |
| 1番人気 | 各レースの1番人気を選ぶ | `train`・`backtest` の出力（人気最上位の馬の3着以内率・複勝回収率） | 1頭選ぶ使い方で、市場の本命にどれだけ近づくか（参考。オッズを見ない予想なので届かなくてよい） |
| 中央の木曜のモデル | 研究「既存モデルの改善」の7つの区切りの木曜の予測（`--timing 木曜` で印の成績に渡しているもの）を `backtest --compare` に渡し、同じレース・同じ馬（特別競走の出走馬）で、ログ損失・AUC を区切りごとに並べる | `backtest` の出力（`PredictionComparison` の表） | 木曜より 3 日早く・騎手なしで出すことで、どれだけ落ちるか（参考。木曜のモデルは材料が多いので、これより良いことは求めない） |
| 相手と比べない版 | 相手と比べる材料（70個）を外した 110個で、同じ区切りで学んだもの | `backtest --variant 相手と比べない` の出力を並べる | 登録馬の中で比べる材料が、出走しない馬が混ざっても効いているか。**良いほうを採る** |

## 4. 7つの区切りでの確かめ

`train` の既定の分け方では、検証データは半年1つだけである。特別競走は年に約 915 レースしか無く、テスト期間 1つ（2026年1月〜）では約 700 レースで、偶然の幅が大きい。そこで、**過去で学習して次の半年を予想する確かめ（ウォークフォワード）を、中央の予想の [16 の 4.](../近走と適性から3着以内を予想/16-evaluation.md#4-半年ずつずらした確かめ) と同じ7つの区切りで行う。** 回すのはこの予想の `backtest` で、流れは [05-sequence.md の図5](05-sequence.md#図5-7つの区切りでの確かめ)。

| 区切り | 学習 | 検証 | テスト |
|---|---|---|---|
| 2023年前半 | 2012年1月〜2022年6月 | 2022年7〜12月 | 2023年1〜6月 |
| 2023年後半 | 2012年1月〜2022年12月 | 2023年1〜6月 | 2023年7〜12月 |
| 2024年前半 | 2012年1月〜2023年6月 | 2023年7〜12月 | 2024年1〜6月 |
| 2024年後半 | 2012年1月〜2023年12月 | 2024年1〜6月 | 2024年7〜12月 |
| 2025年前半 | 2012年1月〜2024年6月 | 2024年7〜12月 | 2025年1〜6月 |
| 2025年後半 | 2012年1月〜2024年12月 | 2025年1〜6月 | 2025年7〜12月 |
| 2026年 | 2012年1月〜2025年6月 | 2025年7〜12月 | 2026年1月〜（DB にある最後の日まで） |

- 検証・テストの区切りは中央の研究と同じ。学習の始まりは、中央の研究（2017年1月）ではなく、この予想の既定（2012年1月。ウォームアップは 2011年）にそろえる。
- ハイパーパラメータは初期値のまま。LightGBM と CatBoost の両方を学習し、確率を平均する。
- 検証期間は、木を足すのを止める判断にだけ使う。テスト期間の結果は、どの線を決めるのにも使わない。
- 測るのは、テスト期間の特別競走の行（Y = 1）のログ損失・AUC・Brier・人気の中での AUC と、確率1位の馬の3着以内率（1着率）・複勝（単勝）回収率。3着以内のモデルと1着のモデルの両方で出す。全レースの行の値も参考に出す。

```powershell
uv run python -m yosou.special_registration_top3 backtest
uv run python -m yosou.special_registration_top3 backtest --variant 相手と比べない
uv run python -m yosou.special_registration_top3 backtest --compare reports/既存モデルの改善/predictions/<木曜の予測>.pkl
```

（1行目は、7つの区切りで学習し直してテスト期間を予測し、区切りごとの当たり具合の表を出して、印の成績が読む予測の表を `reports/特別登録馬の近走と適性から3着以内を予想/predictions/` に書くコマンド。2行目は、相手と比べる材料を外した版で同じことをするコマンド。3行目は、中央の木曜のモデルの7つの区切りの予測と、同じレース・同じ馬で比べるコマンド。学習を 7回 × 2つの目的変数くり返すので、2〜3時間の見込み）

**採用の基準（結果を見る前に決めた）。**

| 項目 | 基準 |
|---|---|
| 頭数から見た割合との比べ | 3着以内のモデルと1着のモデルの両方で、テスト期間の特別競走の行のログ損失が、頭数から見た割合より小さい区切りが 7つのうち 5つ以上あり、全期間を合わせても小さい |
| 相手と比べない版との比べ | 全部の材料の版と相手と比べない版のうち、上の基準を満たし、全期間を合わせたログ損失が小さいほうを採る。差が小さい（0.001 未満）ときは、学習と予測のずれが無い相手と比べない版を採る |
| 中央の木曜のモデルとの比べ | 基準にしない。差を区切りごとに書く（木曜に出し直す価値がどれだけあるかの目安） |
| 届かないとき | 届かなかったモデル（3着以内・1着）と理由をここに書く。作った予想は使える状態（学習・予測・印の成績が通る）で残し、木曜以降は今までどおり中央の予想を使う。材料を足して直すなら、中央の予想と同じく、この文書の 4. の基準で確かめてから採る |

## 5. ハイパーパラメータの調整のやり方

中央の予想の [16 の「5. ハイパーパラメータの調整のやり方」](../近走と適性から3着以内を予想/16-evaluation.md#5-ハイパーパラメータの調整のやり方) と同じ手順（設定ファイルを変えて `train --config` で学習し、2つの検証期間で初期値と比べ、両方で良ければ初期値のファイルを直す）。

```powershell
uv run python -m yosou.special_registration_top3 train --config 試す設定.toml --models reports/特別登録馬の近走と適性から3着以内を予想/models-試し
uv run python -m yosou.special_registration_top3 train --config 試す設定.toml --models reports/特別登録馬の近走と適性から3着以内を予想/models-試し --valid-from 2025-01-01 --test-from 2025-07-01
```

（1行目は、試す設定で学習し、既定の検証期間（2025年7〜12月）で当たり具合を出すコマンド。2行目は、検証期間を 2025年1〜6月に変えて同じことをするコマンド。どちらも本番のモデルとは別の置き場所に書く）

## 6. 印の成績

この予想は印を付けない（[15-decisions.md の 13](15-decisions.md#13-印の付け方と出し方)）。ただし、モデルを作ったときの決まり（全券種の回収率を同じ道具で出す）として、`backtest` の予測の表を道具「印の成績」に渡し、道具が木曜と同じオッズを使わない決め方（◎ は 1着の確率が1位、○▲△ は 3着以内の確率の順。[買うレースと買い目を決める の 07 の 5.](../買うレースと買い目を決める/07-expected-value.md#5-印の付け方)）で仮に付けた印ごとの成績と、買い目（全券種）の券種ごとの回収率を出す。

```powershell
uv run python tools/印の成績/mark_stats.py --form reports/特別登録馬の近走と適性から3着以内を予想/predictions/thursday.pkl --win reports/特別登録馬の近走と適性から3着以内を予想/predictions/thursday-1着.pkl --timing 木曜 --no-danger --out-dir reports/印の成績/特別登録
```

（7つの区切りのテスト期間の予測に、木曜と同じ決め方で印を付け、印ごとの成績（同じ人気の馬全体との比べ・年ごと）と、印のルールの買い目（単勝・複勝・ワイド・馬連・馬単・3連複・3連単）の買い方ごとの回収率を出すコマンド。`--timing 木曜` はオッズから出すもの（期待値・市場の見立て・絞り込み）を使わない指定、`--no-danger` は危険な人気馬の判定（人気が要る）を使わない指定。10〜15分）

| 項目 | 中身 |
|---|---|
| 期間 | 7つの区切りのテスト期間（2023年1月〜DB にある最後の日）の特別競走 |
| 行 | テスト期間の特別競走の出走馬（確定成績。`backtest` が書く予測の表は特別競走の行だけ）。登録馬のうち出走しなかった馬は印の成績には入らない |
| 測るもの | 印ごと（◎○▲△）の成績7つと、同じ人気の馬全体との比べ、◎ の年ごとの単勝回収率、印のルールの買い目（全券種）の回収率 |
| 採用の基準 | 無い。オッズを使わない仮の印なので、買う根拠にはしない（木曜以降の中央の予想で買う）。結果はそのまま報告する |
| 確定オッズでの値 | 回収率は確定オッズで数えたもの。この時点に買う手段は無いので、「木曜の予想とどれだけ違う印になるか」の目安として読む |

## 7. 登録馬全員に出した予想の確かめ

上の 4.〜6. は、確定成績の出走馬（出走した馬）だけで、出走馬の中で比べた材料で測る。実際の使いどころは登録馬の全員に出す予想で、相手と比べる材料は登録馬の中で数えるので、特別登録のあるテスト期間で、登録馬の全員に予測を出し、出走した馬の結果で当たり具合を確かめる。流れは [05-sequence.md の図6](05-sequence.md#図6-登録馬の確かめ)。出走するかどうかはこの予想が当てないことなので、出走しなかった馬の割合（全体・印ごと）は見ない。

```powershell
uv run python -m yosou.special_registration_top3 registrations
```

（テスト期間（2026年1月〜DB にある最後の日）の特別登録の全レースについて、2026年の区切りのモデル（学習は 2025年6月まで）で登録馬の全員を予測し、確定成績と突き合わせた表を出して、`predictions/registrations.pkl` に書くコマンド。1レース 5秒ほど）

| 見るもの | 何が分かるか |
|---|---|
| 出走した登録馬だけでの当たり具合（ログ損失・AUC・確率1位の馬の3着以内率）と、4. の 2026年の区切りの値との差 | 登録馬の中で比べた材料（70個）が、出走馬の中で比べたときとどれだけずれるか |
| 外国馬・地方馬（交流区分 1・2）の行の数と、その当たり具合 | 欠損値の多い馬の確率が使えるか |

- 特別登録は 1年分しか無いので、確かめられるのはテスト期間（2026年1月〜。約 700 レース）だけである。これより前の登録は取れない。
- 採用の基準は無い（登録馬の確率は、4. で確かめたモデルが出すものと同じ）。出走するかどうかを当てることは、この予想の範囲外である（[15-decisions.md の 1](15-decisions.md#1-何を当てるか)）。

## 8. 全頭評価の確かめ

全頭評価（[04-classes.md の tools/全頭評価](04-classes.md#tools全頭評価--全頭評価の道具)）は、確率の当たり具合（4.）の上に文を足すものなので、当たり具合の基準は別に持たない。確かめるのは次の2つ。

| 何を | どうやって | 何が出れば成功か |
|---|---|---|
| 形 | `tools/全頭評価/tests/` で、合成DB の特別登録（登録だけのレースと、出走馬名表に地方馬を1頭足した登録のあるレース）に評価を書く | 登録馬の全員に基本情報と強みか弱みの文が付き、評価順が 3着以内の確率の順で、有力馬の候補が 3頭、印・的中率と配当率・買い目の言葉が無い。1日の全レースを `--all` で書ける |
| 文の決め方 | 手で作った事実・特徴量・寄与で、強み・弱みの文（能力指数の順位、前走、同じコース、休み明け、昇級、距離延長、調教師と血統の率、調教、モデルの寄与）と、重賞の傾向の文（着別度数・回収率・全体との差）を確かめる | 決めたとおりの側（強み・弱み）に、根拠の数字付きで出る |

実DB では、今週の特別登録のレースの評価を書いて、文が読めるものになっているかを見る（JV-Data の実値を含むので設計書には載せない）。

## 今はしないこと

この設計書の範囲外のこと。残課題ではなく、この予想では扱わないと決めたものである。

| しないこと | 理由 |
|---|---|
| 今週の予想・検索画面・取得と予想の状況に、登録馬の予想を並べる | 道具「今週の予想」は出馬表（`ra`・`se`）を前提に動くので、登録馬の表を並べるには画面側の設計が要る。登録の時点の出し方は道具「全頭評価」の Markdown（[15-decisions.md の 13](15-decisions.md#13-印の付け方と出し方)） |
| 買う線・買い目 | オッズの無い時点なので買えない。買うのは木曜以降の中央の予想と買い方の設計書（[買うレースと買い目を決める](../買うレースと買い目を決める/07-expected-value.md)）で行う |
| 出走するかどうかの予想 | この予想は当てない（[15-decisions.md の 1](15-decisions.md#1-何を当てるか)）。作るなら、1年分の登録を学習データにする別の予想として設計する |
| 日曜の版（ハンデ発表前）の時点を別に持つ | 同じモデルで負担重量を欠損値にして出せる（[15-decisions.md の 12](15-decisions.md#12-外国馬地方馬と日曜の版だけのレースの扱い)） |
