## 1. 土日以外の開催日の扱い

**決定（2026-09-27）: 月曜なども、土日と同じく最低1レース（ノルマ）を買う。** 開催日ごとに1レースを満たす。

関連: [03 の 3](03-race-screening.md#3-購入ポリシーを満たすレースの選び方)

## 2. 障害の重賞の扱い

**決定（2026-09-27）: 必ず買う重賞に入れない。** 必ず買うのは平地の G1・G2・G3 だけ。障害は能力指数も予想も無く、期待値が出せないため。

関連: [03 の 3](03-race-screening.md#3-購入ポリシーを満たすレースの選び方)、[02 の「重賞」](02-glossary.md#競馬とこの提案の用語)

## 3. 危険な人気馬とレースの選び方

**決定（2026-09-27）: 理由にしない。** 利用者の言葉で、「1番人気が危険だから買う」のではなく、「期待値の高い穴馬を見つけて買ったら、結果的に1番人気は買っていなかった」という順序にする。

- レースは見込みの利益で選び、危険な人気馬がいるかどうかは条件に入れない。
- 危険な1番人気は補正後の確率が下がっているので、その馬を含む買い目は期待値が線に届かず、結果として買い目に入らない。「消」の印は、その結果を示す表示である。
- 背景: 研究「既存モデルの改善」で、1番人気を消したレースは、消さなかったレースより大きく負けた。

関連: [07 の 3](07-expected-value.md#3-危険な人気馬の判定)

## 4. 検証の済んでいない券種の扱い

**決定（2026-09-27）: 早く検証する。** これからのレースの記録がたまるのを待たずに、研究「回収率100超」を広げて、過去のデータ（2019〜2026年）で券種ごとに確かめる。採用の基準を満たした券種だけ、複勝と一緒に買う券種にする。満たさなかった券種は買わない。

**検証の結果（2026-09-27）: 単勝・ワイド・馬連・馬単・3連複・3連単のどれも、採用の基準を満たさなかった。今は複勝だけを買う。** 堅い重賞のノルマ参加も、ワイドをやめて複勝だけにした（[03 の 4](03-race-screening.md#4-堅い重賞での買い方)）。

関連: [08 の 2「複勝以外の券種の検証」](08-bankroll-and-review.md#複勝以外の券種の検証過去のデータで先に確かめる)

## 5. 勝負用の財布の掛け金

**決定（2026-09-27）: 勝負レースの予算は、勝負用の財布の残高の 5%。** 残高が減れば掛け金も減り、破産しにくい。

- 5% は1レースの予算として扱い、最大3点の複勝に均等に分ける（1点は残高の 5% ÷ 3 ≒ 1.7%）。5% を1点にまとめると、ケリー基準のほぼ満額に当たり、資金の上下がとても大きくなるため。
- 2つの財布に最初に入れる額は、実際に買い始めるときに決める。

関連: [08 の 1](08-bankroll-and-review.md#1-予算の分け方)

## 6. 購入ポリシーを守る費用

**決定（2026-09-27）: 競馬を楽しむための「エンタメ税（参加費）」として受け入れる。** 勝負レース用の資金と、ポリシーで楽しむ用の資金を別の財布に分け、ポリシー用の資金が少しずつ減るのは想定内とする。

- ノルマ参加（重賞・日）は、ポリシー用の財布から出す。額は残高に対する割合で決めるので、財布が減っても購入ポリシーは続けられる。
- 払戻は買った財布に戻し、勝負用の財布からポリシー用の財布を補わない。
- 成績は財布ごとに数える。勝負用には回収率 100% 超えを求め、ポリシー用には減り方が見込みどおりかだけを見る。

関連: [08 の 1](08-bankroll-and-review.md#1-予算の分け方)

## 7. 勝負レースの1日の上限

平地の重賞以外で、1日に何レースまで勝負レースにするか。

**決定（2026-09-30、おすすめどおり3レース）: 平地の重賞以外の勝負レースは、1日3レースまで。** 平地の重賞は、この上限の外で扱う
（[03 の 3](03-race-screening.md#3-購入ポリシーを満たすレースの選び方) の ① のとおり、期待値のある重賞は全部勝負レースにする）。

| 選び方 | 意味 |
|---|---|
| **① 3レース（決定）** | ルール集の「1日1〜3レースに絞る」と同じ。買うレースが増えるほど、期待値の見積もりの誤差で線を越えただけのレースが混ざる。締め切り前のオッズの記録がたまったら、検証で決め直す |
| ② 上限なし | 見込みの利益があるレースを全部買う。1日に使う額の上限（勝負用の残高の 20%）で止まる |

関連: [03 の 3](03-race-screening.md#3-購入ポリシーを満たすレースの選び方)

## 8. パドックの気配

**決定（2026-09-27）: 使わない。** JV-Data に無く、使うには人が手で記録する必要がある。利用者は「基本買うだけ」なので、手で記録する作業は仕組みに入れない。同じ理由で、回顧の不利も、JV-Data から自動で分かるものだけにした。

関連: [06 の 3](06-realtime-adjustment.md#3-パドックの気配)、[08 の 3](08-bankroll-and-review.md#3-回顧データの形)

## 9. 回顧データの置き場所

**決定（2026-09-27）: NotebookLM には上げない。** 人が後から NotebookLM で分析しないので、上げる手間は要らない。Python が自分で読み書きしやすいように、Git の対象外のローカルのフォルダ（`reports/回顧/`）に自動で保存する。

関連: [08 の 3](08-bankroll-and-review.md#3-回顧データの形)

## 10. 締め切り前のオッズでの確かめ

**決定（2026-09-27）: 実際のお金で買い始める前に、フォワードテストをする。** 確定オッズではなく締め切り10分前のオッズで、1か月ほどペーパーテスト（買ったつもりの記録）を回し、それでも回収率が 100% を超えるかを確かめる、としていた。

**変更（2026-10-01）: フォワードテストはしない。** 発走の直前に予想用のデータ（締め切り前の全券種のオッズ）を取って予想する仕組みは作れず、当日にしか確かめられないと利用者が判断した。そのための道具（keiba-yosou の `tools/フォワードテスト/` と、jvdata-store の発走前のオッズの取り直し）も消した（2026-10-02）。

- 検証は確定オッズまでとする。確定オッズでの回収率は上限の見積もりで、締め切り前のオッズでは下がりうることを、結果に書き添える（研究「回収率100超」の 04 の 6-1 に、過去の時系列オッズ（単複・馬連）での確かめがある）。
- 買う判断に使うオッズは、当日の予想を出す直前に jvdata-store の `jvstore realtime` で取り込んだ断面になる。
- 実際のオッズでの回収率は、買い始めたあとの買い目の記録で確かめる。

関連: [08 の 4](08-bankroll-and-review.md#4-実際に買い始める前の確かめフォワードテストはしない)
