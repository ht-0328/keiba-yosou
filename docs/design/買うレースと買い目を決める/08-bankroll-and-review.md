# 08 モジュール6: 資金の配分と、回顧データの蓄積

この文書で決めること: 勝負レースとノルマ参加のレースで、1レースの予算をどう変えるか。勝負レースの中で、買い目ごとに何円買うか。検証の済んでいない券種をどう確かめるか。レースのあとに何を記録し、次の予想にどう活かすか。実際に買い始める前に、何を確かめるか。

結論:

- **資金は「勝負用の財布」と「ポリシー用の財布」に分ける。** ノルマ参加（購入ポリシーで買うレース）は、競馬を楽しむための参加費（エンタメ税）と割り切り、ポリシー用の財布から出す。ポリシー用の財布が少しずつ減るのは想定内とする。利用者の決定（2026-09-27）。
- **勝負レースの予算は、勝負用の財布の残高の 5%。** 残高が減れば掛け金も減り、資金が尽きにくい。利用者の決定（2026-09-27）。ポリシー用の財布は、ノルマ参加（重賞）が残高の 3%、ノルマ参加（日）が残高の 1.5%。勝負用 10万円・ポリシー用 3万円なら、5,000円・900円・400円になる。
- **勝負レースの中は、期待値 1.25 以上の複勝を最大3点、1点 = 勝負用の残高の 5% ÷ 3 の均等で買う。** 期待値の大きさで掛け金を変えるのは、実際に買い始めてから、買い目の記録で 100% 超えを確かめてからにする。
- **複勝以外の券種（単勝・ワイド・馬連・馬単・3連複・3連単）は、過去のデータで先に検証した。** 利用者の決定（2026-09-27）。**どの券種も採用の基準を満たさなかったので、今は複勝だけを買う。**
- **回顧データは、Python が自動で作って自動で保存する。** 「買い目の記録」「レースの回顧」「馬の回顧ノート」の3つの表を、Git の対象外の `reports/回顧/` に置く。不利は、JV-Data から自動で分かるもの（出遅れ・展開・バイアス）だけを記録し、人が手で記録するものは扱わない。NotebookLM には上げない。利用者の決定（2026-09-27）。
- **実際のお金で買い始める前のフォワードテスト（締め切り10分前のオッズでの「買ったつもり」の記録）は、しない。** 利用者の決定（2026-09-27）で1か月ほど行うことにしていたが、発走の直前に予想用のデータを取って予想する仕組みは作れないと利用者が判断した（2026-10-01）。検証は確定オッズまでとする（この文書の 4）。

## 1. 予算の分け方

**要件の問い「勝負レースと、ポリシーで参加する重賞とで、予算の式をどう変えるか」への答え:**

**資金を2つの財布に分け、参加の種類ごとに、どちらの財布から出すかと額の式を変える。** 利用者の決定（2026-09-27）。

| 財布 | 何のための資金か | 求めること |
|---|---|---|
| 勝負用の財布 | 期待値で回収率 100% 超えを狙う勝負レースの資金 | 回収率 100% を超えること |
| ポリシー用の財布 | 購入ポリシー（重賞は必ず買う・毎日1レース）を守って、競馬を楽しむための参加費（エンタメ税） | 減り方が見込みどおりであること。減るのは想定内 |

```text
勝負用の財布:   勝負レースの予算 = 勝負用の財布の残高 × 5%
                1単位（1点の額） = 勝負レースの予算 ÷ 3
ポリシー用の財布: ノルマ参加（重賞）の予算 = ポリシー用の財布の残高 × 3%
                ノルマ参加（日）の予算   = ポリシー用の財布の残高 × 1.5%
どれも 100円未満は切り捨て。最低 100円
```

| 参加の種類 | 出す財布 | 勝負用 10万円・ポリシー用 3万円なら | 買う券種と点数 |
|---|---|---|---|
| 勝負レース（重賞も同じ） | 勝負用 | 5,000円（1点 1,600円） | 複勝。期待値 1.25 以上の馬を最大3点（この文書の 2） |
| ノルマ参加（重賞） | ポリシー用 | 900円 | 複勝を、期待値の高い順に最大2点（[03 の 4](03-race-screening.md#4-堅い重賞での買い方)） |
| ノルマ参加（日） | ポリシー用 | 400円 | 同じ選び方で1点 |

- **1点を「予算 ÷ 3」にする理由:** 5% を1点にまとめて載せると、ふつうの複勝の期待値と払戻倍率では、ケリー基準のほぼ満額に当たり、資金の上下がとても大きくなる。3点に分ける額にしておけば、1点は残高の 1.7% ほどで、1レースで使うのは最大 5% になる。
- **払戻は、買った財布に戻す。** 勝負用の財布からポリシー用の財布を補わない。逆もしない。
- 残高・投資・払戻・回収率は、財布ごとに別に数える（表1「買い目の記録」の「参加の種類」で分けられる）。
- 残高に対する割合で額を決めるので、財布が減っても空にはならない（額は小さくなっていく）。
- 毎月の初めに、その時点の残高で額を計算し直す。
- 2つの財布に最初に入れる額は、実際に買い始めるときに利用者が決める。10万円・3万円は例である。

### 購入ポリシーを守る費用の見積もり

ノルマ参加の見込みの損は、（1 − 期待値）× 予算 である。例（架空）: 期待値 0.85 の買い目に 900円なら、1レースあたり 135円の損が見込まれる。

JRA の平地の重賞は年に 130レースほどある。そのうち半分がノルマ参加になり、期待値が平均 0.85 だとすると、年に 65 × 135円 ≒ 8,800円。ノルマ参加（日）が年に 20日あれば、20 × 400円 × 0.15 = 1,200円。**ポリシー用の財布が 3万円なら、1年でおよそ 1万円減り、2万円ほどになる見込みである。** これは競馬を楽しむための参加費として、想定内とする（利用者の決定、2026-09-27）。見込みよりはっきり速く減っていれば、ノルマ参加の買い方の見積もりが外れているので、見直す。

### 上限

| 上限 | 値（初めの値） | 理由 |
|---|---|---|
| 1日に使う額（勝負用の財布） | 勝負用の財布の残高の 20%（勝負レース4つ分） | G1 の日に重賞の勝負レースが重なっても、1日で資金を大きく減らさない |
| 複勝1点の額 | その複勝プールの売上の見込みの 0.5% | 複勝のプールは小さく、自分の投票でオッズが下がる（研究「回収率100超」の 04 の 6-2） |
| 勝負用の財布が初めの 70% を下回ったとき | 勝負レースを買うのを止めて、線と買い方を見直す | 見積もりが外れている疑いがある。ポリシー用の財布は減るのが想定内なので、この上限は置かない |

## 2. 勝負レースの中の掛け金

### 採用している券種（複勝）

期待値 1.25 以上の馬を、期待値の高い順に最大3点、**1点1単位の均等**で買う。

**均等にする理由:** 研究「回収率100超」で、期待値の大きさで掛け金を変える（ケリー基準）と見かけの回収率は上がるが、それは掛け金の配分を結果に合わせただけで、当たる力が上がったわけではないと分かっている（[research/回収率100超 の 04 の 5](../../../research/回収率100超/docs/04-買い方.md)）。まず均等で 100% を超えることを確かめる。

実際に買い始めてから、買い目の記録（この文書の 3 の表1）で 100% を超え続けたら、次の段階に進める。

| 期待値 | 1点の額 |
|---|---|
| 1.25 以上 1.40 未満 | 1単位 |
| 1.40 以上 | 2単位（ただし、ケリー基準の4分の1を超えない。1レースの予算 5% も超えない） |

```text
ケリー基準の4分の1 = 勝負用の財布の残高 × （p × b − 1）÷（b − 1）÷ 4
  p = 補正後の3着以内の確率、b = 見込みの払戻倍率
```

### 複勝以外の券種の検証（過去のデータで先に確かめる）

**複勝以外の券種は、これからのレースの記録がたまるのを待たずに、過去のデータで先に検証する。** 利用者の決定（2026-09-27）。

**結果（2026-09-27）: 6券種とも、2通りの買い方のどちらでも採用の基準を満たさなかった。今は複勝だけを買う。** 同じ手順で出した複勝は基準を満たし、手順に誤りが無いことも確かめた。期待値が線を超えた組み合わせの買い目は、ほとんどが「確率を大きく見積もりすぎた人気薄の組」だった。くわしくは [research/回収率100超 の docs/05 の 3](../../../research/回収率100超/docs/05-券種ごとの検証.md)、数値は `reports/回収率100超/券種ごとの検証.md`。研究「回収率100超」の部品（プールから着順ごとの確率を取り出す部品、Harville の式と Stern の補正、ウォークフォワードと信頼区間）がそろっているので、この研究を広げて行う。

| 項目 | 中身 |
|---|---|
| 目的 | 単勝・ワイド・馬連・馬単・3連複・3連単を、複勝と同じ作り（全券種のオッズから作った確率に補正を足す）で、期待値の線を超える買い目だけ買ったとき、回収率が 100% を超えるかを確かめる |
| 置き場所 | 研究 `research/回収率100超/` に足した（入口 `extract_tickets.py`・`backtest_tickets.py`、やり方と分かったことは [research/回収率100超 の docs/05](../../../research/回収率100超/docs/05-券種ごとの検証.md)）。実測は Git の対象外の `reports/回収率100超/券種ごとの検証.md` |
| 期間と確かめ方 | 2019〜2026年のウォークフォワード（複勝と同じ）。線は前半（2019〜2021年）だけで決め、後半（2022〜2026年）で確かめる。開催日を単位にしたブートストラップで 90% の幅を出す |
| 採用の基準 | 後半の年で、回収率が 100% を超え、90% の幅の下の端も 100% を超える（複勝と同じ基準） |
| 採用したら | 複勝と一緒に買う券種にする |
| 採用しなかったら | 買わない。記録もしない |

手順:

1. **買い目ごとの確率を出す部品を足す。** 1着の確率は、3連単のプールから見た1着の確率を、モデルの3着以内の確率との食い違いで直して作る。2着・3着と買い目の確率は、Harville の式に Stern の補正を入れて出し、券種 × オッズの帯ごとの実績で較正する。
2. **払戻を決める。** 単勝・馬連・馬単・3連複・3連単は確定オッズ、ワイドは最低オッズ × 帯ごとの倍率（複勝と同じ見積もり方）。
3. **買い目の組み方を2通り試す。** ① 期待値が線を超える買い目を全部（券種ごとに点数の上限あり）。② 印のルールの買い目（下の表）のうち、期待値が線を超えるもの。
4. **券種ごとに、線を 1.0〜1.5 で動かして前半の年で決め、後半の年で確かめる。**
5. **確認を挟む場所:** 手順 1〜3 を作って架空の値のテストが通ったところで、一度報告する。検証の結果が出たら、券種ごとの採否を報告する。

**見込み:** 組み合わせの券種は、複勝より 100% を超えにくいと考えている。3連複の確率を3連複のプールから取れば、それは3連複のオッズそのものなので、差が出ない。差が出るのは、ほかのプール（特に3連単）や補正が、その券種の値段と食い違うところだけである。また、控除率も複勝（20%）より高い（ワイド・馬連 22.5%、3連複 25%、3連単 27.5%）。研究「既存モデルの改善」では、単勝オッズから作った確率で組み合わせの券種を買い、どの区切りでも 100% に届かなかった。今回は、出発点を全券種のプールに替えて確かめ直す。

印のルールの買い目（手順 3 の ②）。利用者の考え方「掛け金は券種・買い目ごとに変える」に合わせ、券種ごとに1点の額を変える。

| 券種 | 買い目 | 点数 | 1点の額 |
|---|---|---|---|
| ワイド | ◎ − ☆、◎ − 注 | 2 | 1単位 |
| 馬連 | ◎ − ○・▲・☆ | 3 | 0.5単位 |
| 3連複 | ◎ 軸 − ○・▲・☆ − ○・▲・△・☆ | 最大 9 | 0.3単位 |
| 3連複（荒れそうなとき） | ☆ 軸 − ◎・○・▲ − ◎・○・▲・△・注 | 最大 12 | 0.2単位 |
| 単勝 | ◎ | 1 | 1単位 |

- 荒れそうなときとは、3連複の中荒れ以上の確率が、その週のレースの上位 3割に入るとき（[03 の 1](03-race-screening.md#1-荒れるレースの定義)）。
- どれが当たってもその券種に使った額より少なくしか戻らない買い目（トリガミ）は外す（研究「既存モデルの改善」の `stake_allocator.py` と同じ）。
- 印は [07 の 5](07-expected-value.md#5-印の付け方) を参照。

### 表1: 買い目の記録

買った買い目1点が1行。自分の成績と較正の元になる。買い目を決めたときに書き、レースのあとに払戻を書き足す。

### 表2: レースの回顧

1レースが1行。予想した展開と馬場が、実際どうだったか。

| 列 | 例（架空） |

| 列 | 意味 | 例（架空） |

不利の種類と、自動で決める条件:

| 不利の種類 | 自動で決める条件（初めの値） |
|---|---|

| バイアスと逆だった | 結果の位置で出したバイアスの補正が −0.02 以下で、4着以下（[06 の 1](06-realtime-adjustment.md#1-トラックバイアスの検知)） |

進路の妨害・外を回された・折り合いを欠いた、のような不利は、JV-Data に無く、レースの映像を人が見ないと分からない。手で記録する作業は仕組みに入れないので、**扱わない。**

### 置き場所

- 3つの表は、keiba-yosou が書き込める DuckDB のファイル（例: `reports/回顧/review.duckdb`）に、Python が自動で保存する。jvdata-store の DB は読むだけにしているので、別のファイルにする。形の細かいところは Phase 2 で決める。
- **Git の対象外の `reports/回顧/` に置く。** 馬名・オッズ・払戻が入るので、公開リポジトリに載せない。
- **NotebookLM には上げない。** 人が後から NotebookLM で分析しないので、上げる手間は要らない。Python が自分で読み書きするだけにする（利用者の決定、2026-09-27）。

### 次走への活かし方

| 使い方 | 中身 | いつから |
|---|---|---|
| 補正の特徴量 | 「前走の不利の種類と程度」「見直す」を f に渡す（[07 の 1](07-expected-value.md#1-確率の作り方)） | 3種類とも自動で決めるので、過去のレースにもさかのぼって付けられる。Phase 3 で、ほかの材料と同じ基準（7区切りのうち5つ以上で良くなるか）で確かめる |
| 出馬表への表示 | 「前走: 出遅れ・大・見直す」のように、前走と前々走の回顧を並べる | 表3ができたらすぐ |

### 自分の記録からの学び直し（毎月、自動）

1. 買い目の記録から、券種 × オッズの帯ごとの「実際に当たった割合 ÷ 予想の平均」を数え、較正を直す（[07 の 1](07-expected-value.md#1-確率の作り方) の手順 5）。
2. 財布ごとの成績（勝負用の回収率、ポリシー用の減り方）を数える。
3. 半年ごとに、買う線（1.25）と勝負レースの上限（1日3つ）を見直す。見直しには、その前の期間の記録だけを使う。

## 4. 実際に買い始める前の確かめ（フォワードテストはしない）

**フォワードテスト（これから行われるレースで、締め切り10分前のオッズを使って1か月ほど「買ったつもり」の記録をとり、それでも回収率が 100% を超えるかを確かめること）は、しない。** 利用者の決定（2026-09-27）で行うことにしていたが、2026-10-01 に利用者が「発走の直前に予想用のデータを取って予想する仕組みは作れない。当日にしか確かめられない」と判断し、取りやめた。そのための道具（keiba-yosou の `tools/フォワードテスト/` と、jvdata-store の発走前のオッズの取り直し）も消した（2026-10-02）。

これまでの検証（研究「回収率100超」など）は、どれも確定オッズを使っている。実際に買うときに見られるのは締め切り前のオッズで、確定までにオッズは動く。**確定オッズでの回収率は、上限の見積もりでしかない。** 過去の時系列オッズ（単複・馬連）で確かめた範囲では、この差は大きかった（研究「回収率100超」の [04 の 6-1](../../../research/回収率100超/docs/04-買い方.md)。発走の10分前のオッズでは 100% を大きく割り、1分前なら確定オッズとほぼ同じ）。

そこで、実際に買い始める前の確かめは、次のとおりとする。

1. **検証は確定オッズまで。** 採用の基準（回収率 100% 超え、開催日を単位にしたブートストラップの 90% の幅の下の端も 100% 超え）は、確定オッズで満たすことを求める。結果には、締め切り前のオッズでは下がりうることを書き添える。
2. **買い始めたあとは、買い目の記録（この文書の 3 の表1）で確かめる。** 買ったときのオッズと払戻が自動で残るので、実際のオッズでの回収率はここで分かる。線（1.25）は、記録を見てすぐには動かさず、半年ごとの見直し（この文書の 3）で、その前の期間の記録だけを使って決め直す。
