# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。作った学習データをどうとっておくか。

**結論: 1サンプル = 1レース。地方 14場の平地の、結果が確定したレースを使う。目的変数の列は券種ぶん4つ持ち、モデルは券種ごとに、その券種の列で学習する。期間は `train` の引数で変えられ、既定は 2019年1月から（ウォームアップは 2016年。地方の全頭の予想と同じ）。学習データは作るのに 30〜60分かかるので pickle にとっておき、2回目からは読む。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

中央の荒れ具合の予想の [08 の「1. 学習データの形」](../レースの荒れ具合を4段階で予想/08-training-data.md#1-学習データの形) と同じで、列が2つ増える。架空の3レースを例にすると、学習データは次の形になる。

| レースID | 出走頭数 | 1番人気のオッズ | 10倍未満の頭数 | …（特徴量はあと 40個以上） | 当日の使う内の傾き | 当日の使う前の傾き | 荒れ具合（単勝） | 荒れ具合（馬連） | 荒れ具合（3連複） | 荒れ具合（3連単） |
|---|---|---|---|---|---|---|---|---|---|---|
| 架空レースA | 12 | 2.8 | 4 | … | +0.04 | +0.20 | 0 | 1 | 1 | 1 |
| 架空レースB | 8 | 1.4 | 3 | … | −0.02 | +0.18 | 0 | 0 | 0 | 0 |
| 架空レースC | 14 | 4.9 | 6 | … | +0.11 | +0.25 | 2 | 3 | 3 | 3 |

- 荒れ具合の値は、0 = 固い、1 = 中荒れ、2 = 大荒れ、3 = 超荒れ である（[10-target.md](10-target.md#券種ごとの線引き)）。架空レースA は、1番人気が勝って単勝は固かったが、3着に人気薄が来て3連単は万馬券（中荒れ）になった、という例である。
- 1頭ごとの特徴量は、レースに1つの値に集約して列にする（[09-features.md](09-features.md#表の見方)）。発売の無い券種（少頭数のレースの3連単など）は、その列だけ欠損値になる。

## 2. 列の種類

学習データの列は4種類ある。モデルに渡すのは**特徴量と、その券種の目的変数だけ**である。

| 種類 | 列 | モデルに渡すか |
|---|---|---|
| ID 列 | レースID、開催日、競馬場、レース番号 | 渡さない |
| 特徴量 | 51個（中央の 49個 ＋ U 2個）。[09-features.md](09-features.md) を参照 | `fit` の `X` として渡す。時点で列を絞る |
| 目的変数 | 荒れ具合（単勝）・（馬連）・（3連複）・（3連単）の4列（0〜3）。[10-target.md](10-target.md) を参照 | 学習する券種の列だけを `fit` の `y` として渡す |
| 評価用の列 | 4券種の払戻、4券種の払戻の人気順、勝ち馬の人気、1〜3着の人気の和、1番人気の確定着順、1番人気の確定オッズ、2〜5番人気の最大の確定オッズ、確定の出走頭数 | 渡さない |

- 学習データは1回作り、券種ごとに目的変数の列を選んで学習する（`TrainingData.with_label()`。中央と同じ）。
- 3つの時点のモデルは、同じ学習データから、その時点で使う列だけを渡して学習する（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。U の2列は当日のモデルだけに渡る。
- 確定の単勝オッズは、評価用の列に置くのと別に、特徴量（B・D）の元にもなる。予測のときは締め切り前のオッズか利用者が渡したオッズを使う。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 地方 14場（門別・盛岡・水沢・浦和・船橋・大井・川崎・金沢・笠松・名古屋・園田・姫路・高知・佐賀）の平地（ダートと、盛岡の芝）。ばんえい（帯広）は入れない | 事実表の元データ（`LOCAL_FACTS_SOURCE`）が地方 14場。ばんえいは走り方が違う（[地方の全頭の予想の 08](../地方競馬の近走と適性から3着以内を予想/08-training-data.md#3-どのサンプルを入れるか)） |
| 交流競走 | 入れる（中央の馬が出る地方のレースも、地方の競馬場のレース） | 地方の全頭の予想と同じ |
| 結果の確定 | 結果が確定して払戻のあるレースだけ | 払戻が無いレースには目的変数が無い |
| 券種ごとの成立 | 発売が無い・不成立・特払の券種は、その列だけ欠損値にし、その券種のモデルの学習から外す。レースそのものは入れる | 中央と同じ（[10-target.md](10-target.md#作り方)） |
| 出走頭数 | 頭数で入れる・入れないを決めない。7頭以下のレースも入れる | 地方は 8〜12頭立てが多く、少頭数も多い。出走頭数は特徴量にある |
| 期間 | 「学習データの始まり」から。既定は 2019年1月1日 | 下の「4. 期間の指定」 |
| 新馬戦 | 入れる | 中央と同じ |

**ウォームアップ期間。** まとまり C・D は出走馬の近走から、E は過去のレースの荒れ具合から、U は過去のレースの傾きから数える。学習データの始まりより前の期間（ウォームアップ期間。既定は 2016年1月1日から 2018年12月31日まで）の出走とレースも読み、サンプルにはせず、あとのサンプルの特徴量を計算するためだけに使う。地方の全頭の予想と同じく、DB にある最初の年（2016年）から読む（近走・対戦の数え方をそろえるため）。

## 4. 期間の指定

学習データの期間は、古い順に4つの日で区切る。4つはまとめて共通の `TrainingPeriod` が持ち、順になっていなければエラーにする。`train` の引数で変えられる。

| 区切り | 引数 | 既定 | 意味 |
|---|---|---|---|
| ウォームアップの始まり | `--warmup-from` | 2016-01-01 | ここからの出走を読むが、サンプルにしない。DB にある最初の年 |
| 学習データの始まり | `--train-from` | 2019-01-01 | ここからのレースがサンプルになる |
| 検証データの始まり | `--valid-from` | 2025-07-01 | この前日までが学習データ |
| テストデータの始まり | `--test-from` | 2026-01-01 | この前日までが検証データ。ここからはテストデータ（[16-evaluation.md](16-evaluation.md)） |

```powershell
uv run python -m yosou.local_upset_level train --train-from 2017-01-01
```

（2017年1月から学習するコマンド。ウォームアップは既定の 2016年1月から。学習データのとっておきは期間ごとに別のファイルになる）

- 既定の4つの日は、地方の全頭の予想と同じ（[地方の全頭の予想の 08 の 4](../地方競馬の近走と適性から3着以内を予想/08-training-data.md#4-期間の指定)）。研究「地方の万馬券」の段④は、学習 2019-01-01〜・検証 2023-07-01〜・テスト 2024-01-01〜 で学び、2024〜2026年を未見のまま確かめた（[16-evaluation.md](16-evaluation.md#5-確かめた結果)）。本番のモデルは、確かめた作り方のまま期間を既定に延ばして学ぶ。
- データの提供期間は 2005年からである（地方競馬DATA のセットアップデータ）。DB に入っているのは 2016年からなので、それより前を指定しても行が無いだけである。

## 5. 学習データのとっておき

学習データは、2016年からの全出走で1頭ごとの特徴量を作り、レース単位に集約し、U を年ごとのリーク防止で付けるので、作るのに 30〜60分かかる。そのあいだ元DB のロックを持ち、ほかの道具（発走前の通知など）が元DB を開けなくなる。そのため、作った学習データを pickle にとっておき、`train` は2回目からそれを読む（`TrainingDataCache`。[04-classes.md](04-classes.md#dataset--学習データ予測用データの決めごと)）。

| 項目 | 決まり |
|---|---|
| 置き場所 | `reports/地方のレースの荒れ具合を4段階で予想/cache/学習データ-<ウォームアップの始まり>-<学習データの始まり>.pkl`（`--cache` で変えられる。Git の対象外） |
| ファイルの名前 | 中身はウォームアップと学習データの始まりで決まる（検証・テストの区切りは学習のときに `PeriodSplitter` が分ける）ので、2つの日を名前にする |
| 作り直す | `train --rebuild`。新しい年の成績がたまって学び直すとき、元DB の表の作り方が変わったとき |
| 研究との関係 | 研究「地方の万馬券」の段④（`stages.py`）も同じクラスで同じ名前のファイルを使う（`reports/地方の万馬券/cache/`）。本番の最初の学習データは、研究で 2026-11-04 に作ったものを写して使った |

- とっておいたファイルには、作った時点の DB にある最後の開催日までのレースが入る。学び直すときは `--rebuild` で作り直す。
- 行数の数え上げ（学習・検証・テストそれぞれのレース数と4クラスの割合）は、`train` の出力の「学習データの期間」の表に出る（`reports/地方のレースの荒れ具合を4段階で予想/学習の結果.md`。Git の対象外）。2019年から 2026年11月までで約 10万レースである。
