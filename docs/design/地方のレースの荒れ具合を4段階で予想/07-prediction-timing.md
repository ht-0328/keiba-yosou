# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使えるまとまりが変わる。予測のときに、オッズをどうやって渡すか。

**結論: 出馬表（オッズなし）・前日（前売りのオッズ）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（4券種 × 3時点 × 2 = 24個）。当日の馬場傾向のレースの値（U）は当日だけ使う。推奨買目が使うのは当日の時点だけである。オッズは、前日・当日に、利用者が `--odds` で全頭ぶん渡すか、元DB の締め切り前のオッズ（速報 0B30）から読む（中央と同じ）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 中央の「木曜」と地方の「出馬表」

中央の予想の木曜（出走馬名表。枠番・馬番が未定）に当たる段階は、地方には無い。地方の出馬表はレースの 2〜5日前に出て、枠番・馬番は決まっているがオッズ・馬体重・馬場状態はまだ無い。この予想では、地方の全頭の予想と同じく、オッズのまだ無い最初の時点を「出馬表」と呼び、プログラムの中では共通の時点の値（`thursday`）を使って表示だけを替える（`TIMING_LABELS`。[地方の全頭の予想の 07](../地方競馬の近走と適性から3着以内を予想/07-prediction-timing.md#中央の木曜と地方の出馬表)）。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと | この予想で使うまとまり |
|---|---|---|---|
| 出馬表 | 出走馬、枠番・馬番、騎手、過去走、出走別着度数地方、過去のレースの払戻 | オッズ、馬体重、馬場状態、当日の馬場傾向 | A（馬場状態を除く）・C（持ち時計を除く）・E |
| 前日 | 上に加えて前日の馬場状態、前売りの単勝オッズ | 馬体重、当日の馬場状態、締め切り前のオッズ、当日の馬場傾向（前の日のレースの傾きだけ） | A・B・C・D（馬体重の増減を除く）・E |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前のオッズ、その日に先に終わった同じ競馬場のレースの結果 | 確定オッズ、結果 | A〜E の全部と U |

**当日の馬場傾向を当日だけに足す理由。** U は、その日に先に終わった同じ競馬場のレースの傾きを数える。前日の時点では前の日のレースしか無く、地方では弱い（[地方の全頭の予想の 15 の 11](../地方競馬の近走と適性から3着以内を予想/15-decisions.md#11-当日の馬場傾向を足すか)）。研究「地方の万馬券」の段④も当日だけで学んだ（[研究の docs/04](../../../research/地方の万馬券/docs/04-予想方法の段ごとの精度.md)）。

**出馬表・前日にも出す理由。** 推奨買目は当日だけ使うが、荒れそうなレースの目安は前から見たい。地方の全頭の予想と同じ3つの時点にそろえると、道具の `--timing` の並びが同じになる。

## 時点ごとに使う特徴量

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 51個のうち） | 特徴量の数 |
|---|---|---|
| 出馬表 | 馬場状態（A）、持ち時計の順位が付く馬の割合（C）、B の 10個、D の 10個、U の 2個 | 27 |
| 前日 | 1番人気の馬体重の増減（D）、U の 2個 | 48 |
| 当日 | なし | 51 |

- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書いてある。U の2個は当日（`PredictionTiming.RACE_DAY`）。
- 出馬表は馬場状態が分からないので、馬場状態を条件にして数える持ち時計も使わない（中央と同じ）。
- 出走頭数は、出馬表の時点では出馬表の頭数、前日・当日はその時点で取消・除外になっていない頭数（中央と同じ）。

## 予測のときのオッズの与え方

中央の荒れ具合の予想と同じ順で決める（[中央の 07 の「予測のときのオッズの与え方」](../レースの荒れ具合を4段階で予想/07-prediction-timing.md#予測のときのオッズの与え方)）。取り込む道具が `nvstore` になる。

| 順 | オッズの元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--odds 馬番:オッズ` で渡した単勝オッズ。**全頭ぶん渡す** | 前日・当日 |
| 2 | 元DB の締め切り前の単勝オッズ（速報 0B30 のいちばん新しい断面） | 前日・当日。予測の前に nvdata-store で `nvstore realtime` を実行して取り込んでおく。発走前の通知は発走 10分前に取り直す |
| 3 | 元DB の出走の行に入っている単勝オッズ | **終わったレースだけ**（確定オッズ）。これから走るレースでは空なので、止めて `--odds` を案内する |

```powershell
uv run python -m yosou.local_upset_level predict 架空レースA --timing 当日 --odds 1:2.8 2:5.1 3:7.0 …（12頭ぶん）
uv run python -m yosou.local_upset_level predict 架空レースA --timing 当日 --bet 3連複
uv run python -m yosou.local_upset_level predict 架空レースA --timing 出馬表
uv run python -m yosou.local_upset_level predict 終わった架空レースB --timing 当日
```

（1行目は、当日に、利用者が見た単勝オッズを全頭ぶん渡して、4券種の荒れ具合の確率を出すコマンド。2行目は、取り込んだ締め切り前のオッズを使い、3連複だけを出すコマンド。3行目は、出馬表の時点にオッズ無しで出すコマンド。4行目は、終わったレースを確定オッズで予測し直すコマンド）

- 全頭ぶん渡す理由（まとまり B は全頭のオッズから作る）と、学習の確定オッズと予測のオッズのずれは、[中央の 07](../レースの荒れ具合を4段階で予想/07-prediction-timing.md#予測のときのオッズの与え方) と同じ。発走 10分前のオッズ ≒ 確定オッズ を前提にする（[買い方の 01 の 4](../買うレースと買い目を決める/01-overview.md#まず知っておいてほしいこと何が問題か)）。
- 当日の馬場傾向は、速報 0B15（その日に先に終わったレースの結果）を取り込んであれば数える。取り込んでいなければ、前の日のレースと過去の傾きだけで出す（止めない。[11-leak-prevention.md](11-leak-prevention.md#決まり) の 11）。

## 時点ごとにモデルを分ける理由

中央の荒れ具合の予想と同じ理由である（[中央の 07 の「時点ごとにモデルを分ける理由」](../レースの荒れ具合を4段階で予想/07-prediction-timing.md#時点ごとにモデルを分ける理由)）。学習データは3つの時点で同じものを使い、モデルに渡す列だけを変える（[08-training-data.md](08-training-data.md#2-列の種類)）。
