# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。

**結論: 1サンプル = 1レース。中央競馬の芝・ダートの、結果が確定したレースを使う。目的変数の列は券種ぶん4つ持ち、モデルは券種ごとに、その券種の列で学習する。期間は `train` の引数で変えられ、既定は 2017年1月から（ウォームアップは 2016年。約 3.2 万行）。手本の既定（2021年8月から）より長くするのは、1頭単位の予想より行数が 15分の1ほどしか無いためである（[15-decisions.md](15-decisions.md#5-学習データの期間の既定)）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

架空の3レースを例にすると、学習データは次の形になる。

| レースID | 出走頭数 | 1番人気のオッズ | 10倍未満の頭数 | 前走3着以内の馬の割合 | 1番人気の前走の着順 | …（特徴量はあと 40個以上） | 荒れ具合（単勝） | 荒れ具合（馬連） | 荒れ具合（3連複） | 荒れ具合（3連単） |
|---|---|---|---|---|---|---|---|---|---|---|
| 架空レースA | 16 | 3.4 | 4 | 0.38 | 1 | … | 0 | 1 | 1 | 2 |
| 架空レースB | 8 | 1.6 | 3 | 0.50 | 2 | … | 0 | 0 | 0 | 0 |
| 架空レースC | 18 | 5.1 | 6 | 0.22 | 5 | … | 2 | 3 | 3 | 3 |

- 荒れ具合の値は、0 = 固い、1 = 中荒れ、2 = 大荒れ、3 = 超荒れ である（[10-target.md](10-target.md#券種ごとの線引き)）。架空レースA は、1番人気が勝って単勝は固かったが、3着に人気薄が来て3連単は大荒れになった、という例である。
- 1行が1レースなので、手本の学習データ（1行 = 1頭）とは、行の単位が違う。1頭ごとの特徴量（斤量、前走の着順など）は、そのままでは列にならず、レースに1つの値に集約して列にする（[09-features.md](09-features.md#表の見方)）。
- 発売の無い券種（架空レースB のような少頭数のレースの3連単など）は、その列だけ欠損値になる（[10-target.md](10-target.md#作り方)）。特徴量の欠損値は、手本と同じく欠損値のまま持つ。

## 2. 列の種類

学習データの列は4種類ある。モデルに渡すのは**特徴量と、その券種の目的変数だけ**である。

| 種類 | 列 | モデルに渡すか |
|---|---|---|
| ID 列 | レースID、開催日、競馬場、レース番号 | 渡さない |
| 特徴量 | 49個。[09-features.md](09-features.md) を参照 | `fit` の `X` として渡す |
| 目的変数 | 荒れ具合（単勝）・荒れ具合（馬連）・荒れ具合（3連複）・荒れ具合（3連単）の4列（0〜3）。[10-target.md](10-target.md) を参照 | 学習する券種の列だけを `fit` の `y` として渡す |
| 評価用の列 | 4券種の払戻、4券種の払戻の人気順、勝ち馬の人気、1〜3着の人気の和、1番人気の確定着順、1番人気の確定オッズ、確定の出走頭数、利用者の規則に当てはまるか | 渡さない |

- **学習データは1回作り、券種ごとに目的変数の列を選んで学習する。** 特徴量は券種によらず同じなので、券種ごとに学習データを作り直す理由が無い。`TrainingData` が「どの列を目的変数にするか」を持ち替える（[04-classes.md](04-classes.md#2-共通の部品に足すもの変えるもの)）。
- 3つの時点（木曜・前日・当日）のモデルは、同じ学習データから、その時点で使う特徴量の列だけを渡して学習する（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。モデルは 4券種 × 3時点 × 2 = 24個になる。
- 確定の単勝オッズは、評価用の列に置くのと別に、特徴量（まとまり B・D）の元にもなる。予測のときは、確定オッズの代わりに締め切り前のオッズか、利用者が渡したオッズを使う（[07-prediction-timing.md](07-prediction-timing.md#予測のときのオッズの与え方)）。
- 「利用者の規則に当てはまるか」は、評価の基準に使う列で、特徴量にはしない（[15-decisions.md](15-decisions.md#9-利用者の規則を特徴量に入れるか)）。
- ID 列と年を特徴量にしない理由は、[手本の 08 の「2. 列の種類」](../近走と適性から3着以内を予想/08-training-data.md#2-列の種類) と同じである。
- 予測用データは、この学習データから目的変数と評価用の列を除いた、1行の表になる。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 中央競馬の平地（芝とダート）。障害は入れない | 障害は走り方が違い、レースの数も少ない（手本と同じ） |
| 結果の確定 | 結果が確定したレース（`ra` のデータ区分が確定）だけ | 払戻が無いレースには目的変数が無い |
| 券種ごとの成立 | 発売が無い・不成立・特払の券種は、その列だけ欠損値にし、その券種のモデルの学習から外す。レースそのものは入れる | 1つの券種が無いだけで、ほかの券種の行まで減らさないため（[10-target.md](10-target.md#作り方)） |
| 出走頭数 | 頭数で入れる・入れないを決めない。7頭以下のレースも入れる | 少頭数は固くなりやすいが、それも学ばせる。出走頭数は特徴量にある（[15-decisions.md](15-decisions.md#12-7頭以下のレースを入れるか)） |
| 期間 | 「学習データの始まり」から。既定は 2017年1月1日 | 下の「4. 期間の指定」 |
| 新馬戦 | 入れる | 出走馬の実績（まとまり C・D）はほとんど欠損値になるが、レースの条件・オッズの形・過去の荒れ率で予測できる。「前走が無い馬の割合」が新馬戦を表す |

**ウォームアップ期間。** まとまり C・D は出走馬の近走から、まとまり E は過去のレースの荒れ具合から数える。学習データの始まりの直後のレースでは、DB に読んだ範囲が短いと、近走が「前走なし」に見え、過去の荒れ率も数えられない。そこで、学習データの始まりより前の期間（ウォームアップ期間。既定は 2016年1月から 2016年12月まで）の出走とレースも読み、サンプルにはせず、あとのサンプルの特徴量を計算するためだけに使う。E は前日までの 365日で数えるので、ウォームアップが1年あれば、最初のサンプルから数えられる。

## 4. 期間の指定

期間の区切り方（4つの日と `train` の引数）は、手本とまったく同じである。[手本の 08 の「4. 期間の指定」](../近走と適性から3着以内を予想/08-training-data.md#4-期間の指定) を参照。既定の値だけが違う。

| 区切り | 引数 | この予想の既定 | 手本の既定 |
|---|---|---|---|
| ウォームアップの始まり | `--warmup-from` | 2016-01-01（学習データの始まりの前の年の1月1日） | 2020-01-01 |
| 学習データの始まり | `--train-from` | **2017-01-01** | 2021-08-01 |
| 検証データの始まり | `--valid-from` | 2025-07-01 | 同じ |
| テストデータの始まり | `--test-from` | 2026-01-01 | 同じ |

```powershell
uv run python -m yosou.upset_level train
uv run python -m yosou.upset_level train --train-from 2021-08-01
```

（1行目は既定の期間で 4券種 × 3時点のモデルを学習するコマンド。2行目は、手本と同じ期間で学習して比べるコマンド。`--warmup-from` を省略すると、学習データの始まりの前の年の1月1日になる）

### 既定を 2017年1月からにした理由

- この予想の行数は、1頭単位の予想の 15分の1ほどしか無い（年に約 3,300 レース）。手本の既定（2021年8月から）だと約 1.7 万行で、超荒れは券種によって 900 行ほどしか無い。
- 手本では「10年に延ばしても当たり具合は上がらなかった」が、それは 20万行以上あっての話である。行数が少ないこの予想では、まず DB にある全部（2016年をウォームアップにして 2017年から）を既定にし、学習後に手本と同じ期間と比べる。
- JRA-VAN は、レース成績と払戻を 1986年から提供している（3連複は 2002年6月、3連単は 2004年8月から。[09-features.md](09-features.md#使うデータの期間)）。DB に今入っているのは 2016年からなので、それより前に延ばすには jvdata-store で取得する。延ばす案は [15-decisions.md](15-decisions.md#5-学習データの期間の既定) を参照。
- 2016年に延ばしても、この予想は調教の特徴量（ウッドチップ調教は 2021年7月27日から）を使わないので、記録の無い期間の問題は起きない（[09-features.md](09-features.md#使わない特徴量)）。

## 5. 行数の数え上げ

既定の期間（2017年1月から、中央の芝・ダート）で、学習データは**約 3.2 万行**になる（2026-09-23 時点の元DB で 32,370 行。`tools/任意SQL/sql.py` で数えた。SQL は `reports/upset_level/criteria/`）。年に約 3,330 行で、どの年も同じくらいである。

| 券種 | 超荒れの行数（2017年1月〜2026年9月） |
|---|---|
| 単勝 | 約 1,900 |
| 馬連 | 約 3,800 |
| 3連複 | 約 2,800 |
| 3連単 | 約 1,700 |

- 2016年以降は、全レースに4券種の払戻がある（発売の無い券種・不成立・特払は 0 件）。目的変数が欠損値になる行は、既定の期間には無い。
- 検証データ（2025年7〜12月、約 1,700 レース）の超荒れは、券種によって 90〜200 行である。少ないクラスの当たり具合は偶然の幅が大きい（[16-evaluation.md](16-evaluation.md#2-評価指標)）。
- この中を、学習データ・検証データ・テストデータに時期で分ける（[16-evaluation.md](16-evaluation.md#1-期間の分け方)）。
