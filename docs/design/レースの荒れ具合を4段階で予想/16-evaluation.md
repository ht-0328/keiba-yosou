# 16 当たり具合の測り方

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。何と比べれば「当たっている」と言えるか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 時期で分ける。既定は 学習 2012年1月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜（ウォームアップは 2011年）。`train` の引数で変えられる |
| 2. 評価指標 | 券種ごと・時点ごとに、4クラスの指標（正解率・マクロ F1・混同行列・クラスのずれの平均・多クラスのログ損失）と、累積確率の AUC（中荒れ以上・大荒れ以上・超荒れ）を出す。値は `reports/レースの荒れ具合を4段階で予想/` に置く |
| 3. 比べる基準 | 常に最多クラス、クラスの割合をそのまま出す予想、利用者の規則、1番人気のオッズだけの予想、の4つと並べる。基準と同じなら、モデルは何も学んでいない |

用語の意味は [02-glossary.md](02-glossary.md) を参照。指標を計算するクラス（`ClassMetricCalculator`）と学習の結果の表（`ClassTrainingReportTables`）は共通の部品に足すもので、[04-classes.md](04-classes.md#2-共通の部品に足すもの変えるもの) を参照。穴馬の予想の評価の考え方（人気の基準と比べる）と同じ発想で、この予想では「オッズの基準と比べる」。

## 1. 期間の分け方

| 区分 | 何に使うか | 既定 |
|---|---|---|
| ウォームアップ | 近走と過去の荒れ率を計算するためだけに読む。サンプルにしない | 2011年1月〜2011年12月 |
| 学習 | モデルの `fit` に渡す | 2012年1月〜2025年6月 |
| 検証 | 早期終了の判断と、下の指標で当たり具合を見る。特徴量やハイパーパラメータを直すときは、ここで比べる | 2025年7〜12月 |
| テスト | 最後に1回だけ確かめる。直す判断には使わない | 2026年1月〜 |

- 時期で分ける（レースを混ぜてくじで分けない）。同じ開催日のレースが学習と検証に散らばると、その日の馬場の傾向を先に知ってしまい、実際より当たって見えるためである。過去の荒れ率（E）は前日までで数えるので、時期で分ければ検証データの結果が学習データに漏れない。
- 区切りの日は `train` の引数で変えられる（[08-training-data.md](08-training-data.md#4-期間の指定)）。
- 検証データは約 1,700 レースで、超荒れは券種によって 90〜200 件しか無い（[08-training-data.md](08-training-data.md#5-行数の数え上げ)）。少ないクラスの指標は、偶然の幅が大きい。1つの検証期間の値で決めず、検証期間を変えて（2025年1〜6月など）同じ向きの差が出るかを見る。

## 2. 評価指標

学習の報告（`train` の出力）に、券種ごと・時点ごとに出す。どれも検証データで測る。

| 指標 | 意味 | 良い向き | 何が分かるか |
|---|---|---|---|
| 正解率 | いちばん高いクラスが、実際のクラスと一致した割合 | 大きいほど良い | 4段階を当てる使い方での的中率。常に最多クラスの基準と比べて初めて意味を持つ |
| マクロ F1 | クラスごとの F1 を、クラスの数で平均した値 | 大きいほど良い | 超荒れのような少ないクラスも当てているか。正解率は多いクラスだけで上がるので、これで補う |
| 混同行列 | 予測したクラス × 実際のクラス の件数（4 × 4） | ― | 外れ方が「隣のクラス」なのか「両端の取り違え」なのか |
| クラスのずれの平均 | 予測したクラスの番号 − 実際のクラスの番号 の絶対値の平均 | 小さいほど良い | 順序を活かせているか。多クラス分類は順序を見ずに学習するので、これで確かめる（[15-decisions.md](15-decisions.md#3-目的変数の載せ方)） |
| 多クラスのログ損失 | 4つの確率が正解から外れた大きさ | 小さいほど良い | 確率として使えるか。クラスの割合をそのまま出す基準と比べる |
| 累積確率の AUC（3つ） | 「中荒れ以上の確率」「大荒れ以上の確率」「超荒れの確率」を二値の予測とみなした AUC | 大きいほど良い（0.5 はでたらめ） | 「荒れるレースだけ買う」ように、レースを並べる使い方での当たり |
| 期間ごとのクラスの割合 | 学習・検証・テストそれぞれの、4クラスの割合 | ― | 期間で荒れ方が変わっていないか。基準の計算にも使う |

**指標を券種ごとに出す理由。** 券種ごとに別のモデルなので、当たり具合も別に見る。単勝の4段階は1番人気の勝ち負けに近く当てやすいが、3連単は 2・3着まで見るので当てにくい、というような違いが出るはずである。

## 3. 比べる基準

モデルによらない4つの基準を、同じ検証データで出して並べる。**基準と同じなら、モデルは何も学んでいない。**

| 基準 | 何を出すか | どの指標と比べるか |
|---|---|---|
| 常に最多クラス | 学習データでいちばん多いクラスを、全レースに出す | 正解率の下限 |
| クラスの割合をそのまま確率にする | 学習データの4クラスの割合を、全レースに同じ確率として出す | 多クラスのログ損失の下限 |
| 利用者の規則 | 1番人気が 4.0倍以上かつ 2〜5番人気の最大オッズが 10倍未満なら「中荒れ以上」、そうでなければ「固い」と出す（`UserRuleBaseline`。[04-classes.md](04-classes.md#3-この予想だけのクラスの一覧)） | 規則が当てはまるレースの数だけ、モデルの「中荒れ以上の確率」の高い順に選んだときの的中率・再現率と比べる。事例では、規則に当てはまるレースは 3連単で 9割弱が中荒れ以上だった（[10-target.md](10-target.md#理由)）。モデルが同じ件数でこれを下回るなら、規則のほうがよい |
| 1番人気のオッズだけの予想 | 特徴量を「1番人気のオッズ」の1つだけにして、同じ手順（同じ設定・同じ期間の LightGBM と CatBoost の平均）で学習したモデル（`FavoriteOddsBaseline`） | 全部の指標。市場（オッズ）がすでに知っていること以上を、49個の特徴量から学べているか。オッズは前日から分かるので、前日と当日の平均と比べる（前日と当日は同じ列なので、基準の値は1つ）。木曜はオッズを使わないので比べない |

`train` の報告には、券種ごとに、4つの基準すべてとの比べを出す（`UpsetComparisonTables`。[04-classes.md の「6. コマンドの引数」](04-classes.md#6-コマンドの引数)）。常に最多クラスとクラスの割合の2つは、時点ごとにこの予想の平均と並べた1つの表にする（`ClassShareBaseline`。特徴量を使わないので、基準の値は時点によらない。常に最多クラスは確率ではないので、ログ損失と AUC は空欄）。利用者の規則は、上の決まりの表。1番人気のオッズだけの予想は、前日・当日の、この予想の平均と基準の平均を並べた表にする。

**「荒れるレースだけ買う」使い方の線引き。** 「中荒れ以上の確率」がしきい値以上のレースを「荒れる」とみなす使い方をするなら、しきい値は検証データで「しきい値ごとのレース数・中荒れ以上だった割合」を並べて決める。`train` の報告に、券種ごと・時点ごとに、しきい値 0（全レース）と 0.3〜0.9（0.1 刻み）の行で、レース数・実際に中荒れ以上だった割合・中荒れ以上のうち選んだ割合を出す（`UpsetThresholdSummary`）。決めたしきい値は設計書に書かず、`reports/レースの荒れ具合を4段階で予想/` に置く（値は学習し直すたびに変わるため。穴馬の予想と同じ決まり）。

## 決めたこと
