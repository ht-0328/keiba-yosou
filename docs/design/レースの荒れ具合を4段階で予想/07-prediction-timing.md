# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使えるまとまりが変わる。予測のときに、オッズをどうやって渡すか。

**結論: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする（2026-09-23 に利用者が決定。[15-decisions.md](15-decisions.md#4-いつ予測するか)）。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（4券種 × 3時点 × 2 = 24個）。木曜はオッズが無いので、オッズの形（B）と1番人気の危うさ（D）を使わない、弱い予想になる。オッズは、前日・当日に、利用者が `--odds` で全頭ぶん渡すか、元DB の締め切り前のオッズから読む（手本と同じ）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと | この予想で使うまとまり |
|---|---|---|---|
| 木曜（出走馬名表） | 出走馬、騎手、過去走、出走別着度数（20時ごろ）、過去のレースの払戻 | 枠番・馬番、オッズ、馬体重、馬場状態 | A（馬場状態を除く）・C（持ち時計を除く）・E |
| 前日（出馬表） | 上に加えて枠番・馬番、前日発表の馬場状態、前日発売の単勝オッズ（JRA の発表） | 馬体重、当日の馬場状態、締め切り前のオッズ | A・B・C・D（馬体重の増減を除く）・E |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前のオッズ | 確定オッズ、結果 | A〜E の全部 |

**木曜にも出す理由と、その代わりに引き受けること。** 木曜はオッズが無く、利用者のイメージ（オッズの形、1番人気が飛ぶか）を使えない。それでも、レースの条件・出走馬の実績のばらつき・過去の同条件の荒れ率だけで「荒れやすいレースか」の目安は出せる。前日・当日に出し直して、オッズを含めた予想に置き換える。木曜に見立てのオッズを渡す案・木曜は出さない案は [15-decisions.md](15-decisions.md#4-いつ予測するか) を参照。

## 時点ごとに使う特徴量

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 49個のうち） | 特徴量の数 |
|---|---|---|
| 木曜（出走馬名表） | 馬場状態（A）、持ち時計の順位が付く馬の割合（C）、B の 10個、D の 10個 | 27 |
| 前日（出馬表） | 1番人気の馬体重の増減（D） | 48 |
| 当日（馬体重の発表のあと） | なし | 49 |

- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書いてある（手本と同じ仕組み）。時点のクラスは、時点の前後を答えるだけである。
- 木曜は馬場状態が分からないので、馬場状態を条件にして数える持ち時計も使わない（手本と同じ）。
- 前日の馬場状態は、前日発表の値を使う。理由は [手本の 07 の「時点ごとに使う特徴量」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量) と同じである。
- 木曜の出走頭数は、出走馬名表の頭数である。あとで取消が出ると変わり、荒れ具合も変わりうる。前日・当日に出し直す。

## 予測のときのオッズの与え方

オッズは、レースの前には確定しない。予測のときは、手本と同じ順で単勝オッズを決める（判断の手順は [手本の 06 の図2](../近走と適性から3着以内を予想/06-flowchart.md#図2-予測に使うオッズの決め方)。決めるクラスは手本の `OddsResolver` で、この予想でも使うので `shared` に移す。[04-classes.md](04-classes.md#2-共通の部品に足すもの変えるもの)）。

| 順 | オッズの元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--odds 馬番:オッズ` で渡した単勝オッズ。**全頭ぶん渡す** | 前日・当日 |
| 2 | 元DB の締め切り前の単勝オッズ（時系列オッズのいちばん新しい断面） | 前日の夜と当日。予測の前に jvdata-store で `uv run jvstore realtime --date <開催日>` を実行して取り込んでおく。今の元DB には断面がごく少数しか無く、取り込んでいないレースでは使えない |
| 3 | 元DB の出走の行に入っている単勝オッズ | **終わったレースだけ**（確定オッズ）。これから走るレースでは空なので、止めて `--odds` を案内する |

```powershell
uv run python -m yosou.upset_level predict 架空レースA --timing 当日 --odds 1:3.4 2:6.8 3:7.5 …（16頭ぶん）
uv run python -m yosou.upset_level predict 架空レースA --timing 当日 --bet 3連単
uv run python -m yosou.upset_level predict 架空レースA --timing 木曜
uv run python -m yosou.upset_level predict 終わった架空レースB --timing 当日
```

（1行目は、当日に、利用者が見た単勝オッズを全頭ぶん渡して、4券種の荒れ具合の確率を出すコマンド。`--odds` は「馬番:オッズ」の組を並べる。コンマ区切りで `--odds 1:3.4,2:6.8` とも書ける。2行目は、取り込んだ締め切り前のオッズを使い、3連単だけを出すコマンド。3行目は、木曜にオッズ無しで出すコマンド。4行目は、終わったレースを確定オッズで予測し直すコマンド）

- **全頭ぶん渡す理由。** まとまり B は「10倍未満の頭数」「市場勝率の合計」のように、全頭のオッズから作る。1頭でも無いと値がずれる。手本は渡されなかった馬を欠損値のまま予測するが、この予想では、前日・当日にオッズの無い馬が1頭でもいれば止めて、全頭ぶん渡すよう案内する（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 8）。
- 学習データのオッズは確定オッズである。渡したオッズや締め切り前のオッズは、確定オッズと少しずれる。当日の締め切り直前に出し直すと、ずれは小さくなる（[手本の 11 の決まり 5](../近走と適性から3着以内を予想/11-leak-prevention.md#決まり)）。
- 木曜はオッズを使わないので、`--odds` は要らない（渡しても使われない）。
- `--bet` は出力を絞るだけである。付けなければ、4券種すべてを出す。

## 時点ごとにモデルを分ける理由

手本と同じ理由である。[手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由) を参照。1つのモデルで済ませると、木曜の予測では、学習のときに値が入っていた B・D の 20個を欠損値で渡すことになり、学習と予測でデータの様子が大きくずれる。

学習データは3つの時点で同じものを使い、モデルに渡す列だけを変える（[08-training-data.md](08-training-data.md#2-列の種類)）。
