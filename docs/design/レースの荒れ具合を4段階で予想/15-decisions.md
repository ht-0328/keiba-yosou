# 15 決めたこと

**この文書の目的:** 設計の中で決めたことを、ここに集める。**どれも 2026-09-23 に決まった。** 1・2・4・6 は確認1で利用者が選び、ほかは「おすすめのとおりで決める」という利用者の指示により、おすすめの方針で決めた。あとで見直せるように、選ばなかった選び方も残す。

各文書には「決めてほしいこと」の節を作っていない。見直したい項目があれば、この文書から関連する資料をたどって直す。

用語のうち、目的変数とは「モデルに当てさせる答えの列」、特徴量とは「予測の手がかりにする列」、多クラス分類とは「答えが3通り以上ある分類」である（[02-glossary.md](02-glossary.md)）。

## 1. 荒れ具合の物差し

| 選び方 | 変わること |
|---|---|
| **券種ごとの払戻（決定）** | 目的変数が4列になり、券種ごとにモデルを学習する。1番人気が勝って単勝は固いが3連単は荒れた、という違いをそのまま持てる |
| 3連単の払戻だけ | 目的変数は1列、モデルは6つ。単勝・馬連・3連複の荒れは見えない |
| 1〜3着の人気の和、または券種ごとの払戻の人気順 | オッズの大きさを見ないので、1.5倍の1番人気が飛んだ荒れと、4倍の1番人気が飛んだ荒れが同じになる |

**決めた理由。** 利用者の指示（「3連複や馬連・単勝でも見ておきたい」）による。事例では、単勝が固いレースでも 3連単の 3割以上が中荒れ以上だった。

関連する資料: [10-target.md の「理由」](10-target.md#理由)。

## 2. 券種ごとの4クラスの線引き

| 選び方 | 変わること |
|---|---|
| **切りのよい払戻の額で区切る（候補A。決定）** | どの券種でも固い 3〜5割・超荒れ 5〜12%。額が競馬の言い方（万馬券など）と合う。線引きは `UpsetLevelRule` の定数で、変えても学習し直すだけで済む |
| 別の切りのよい額（候補B。単勝 300・1,000・3,000円、馬連 2,000・5,000・2万円、3連複 2,000・1万・10万円、3連単 1万・5万・20万円） | 単勝は 3倍未満だけが固い（28%）になり、3連単の超荒れが 13% と多くなる |
| 券種ごとに分位点で分ける（下から 50・30・15・5% など） | クラスの割合が券種でそろう。線が端数の円になり、期間を変えると動く。利用者が暗算できない |
| 出走頭数の帯ごとに線を変える | 少頭数でも「荒れ」を定義できる。決まりが券種 × 3組に増え、過去の荒れ率の意味も帯で変わる。頭数の影響は特徴量「出走頭数」に任せる |

**決めた理由。** 2026-09-23 の確認1で、候補A と候補B と分位点の3つから、利用者が候補A を選んだ。分布の調べ方と、クラスの割合は [10-target.md](10-target.md#券種ごとの線引き) を参照。

関連する資料: 線引きの表は [10-target.md の「券種ごとの線引き」](10-target.md#券種ごとの線引き)。判断の手順は [06-flowchart.md の図1](06-flowchart.md#図1-学習データに入れるレースの選び方と4クラスの付け方)。

## 3. 目的変数の載せ方

| 選び方 | 変わること |
|---|---|
| **多クラス分類。4つの確率を1つのモデルで出す（決定）** | モデルは券種 × 時点 × 2 = 24個。4つの確率がそのまま答えになり、足し合わせれば「中荒れ以上の確率」も出る。順序は目的関数では見ず、評価指標（クラスのずれの平均）で確かめる。共通の部品に多クラス用のモデル2つと評価を足す |
| 順序を活かした二値分類3つ（中荒れ以上か・大荒れ以上か・超荒れか） | 既存の二値のモデルをそのまま使える。モデルは 3倍の 72個。3つを別々に学習するので確率が単調にならず、差し引いて4つの確率にするときに負の値を丸める処理が要る。線引きを1つ変えると 3分の1を学習し直す |
| 払戻の対数を回帰して、線引きで4つに切る | 線引きを変えても学習し直さなくてよい。4つの確率が出ない。払戻は同じレースでも「どの3頭が来たか」で桁が変わり、ばらつきが大きくて境目の誤りが多い |

関連する資料: 足す部品は [04-classes.md の「2. 共通の部品に足すもの・変えるもの」](04-classes.md#2-共通の部品に足すもの変えるもの)、選ばなかったときに変わるクラスは [04-classes.md の「5.」](04-classes.md#5-選ばなかった選び方で変わるクラス)。多クラスのコード例は [03-library-basics.md](03-library-basics.md#この予想で違う点)。

## 4. いつ予測するか

**3つの時点で出すことは、確認1で利用者が決めた。** オッズの無い木曜の扱いは、おすすめのとおり決めた。

| 選び方 | 変わること |
|---|---|
| **木曜はオッズを使わず、A・C・E の 27個で出す（決定）** | 特別な部品が要らない（`Feature.known_from` の仕組みだけで実現できる）。木曜は「条件と顔ぶれだけからの荒れやすさ」で、前日・当日より当たりは落ちる |
| 木曜に `--odds 馬名:オッズ` で見立てのオッズを渡す | 木曜も B・D を使える。`OddsInput` を馬名対応に広げる。見立ての誤差が利用者の規則の線（4.0倍・10倍）をまたぐと結果が変わり、学習（確定オッズ）とのずれが大きい |
| 木曜は出さない（危険な人気馬の予想と同じ） | モデルは 16個に減る。利用者は3つの時点で出すと決めたので、選ばない |

関連する資料: [07-prediction-timing.md の「時点ごとに分かること」](07-prediction-timing.md#時点ごとに分かること)、[「時点ごとに使う特徴量」](07-prediction-timing.md#時点ごとに使う特徴量)。

## 6. 券種ごとに別のモデルにするか

| 選び方 | 変わること |
|---|---|
| **券種ごとに別のモデル。学習データは1回作り、目的変数の列を持ち替える（決定）** | モデルは 24個。`--bet` で券種を絞れる。学習時間は 3連単だけの4倍 |
| 3連単だけのモデル。ほかの券種は評価用の列だけ持つ | モデルは6個。単勝・馬連・3連複の荒れ具合は出ない |
| 4券種の最大のクラスを1つの目的変数にする | モデルは6個。「どの券種が荒れるか」が分からず、ほとんど3連単の荒れ具合と同じになる |

**決めた理由。** 確認1で利用者が「4券種すべて」を選んだ。

関連する資料: [05-sequence.md の図1](05-sequence.md#図1-学習)、[04-classes.md の「5.」](04-classes.md#5-選ばなかった選び方で変わるクラス)。

## 7. 発売なし・不成立・特払・返還・同着の扱い

| 選び方 | 変わること |
|---|---|
| **発売なし・不成立・特払はその券種の列を欠損値にして学習から外す。返還は普通に入れる。同着は最大の払戻（決定）** | 2016年以降の中央・平地では、欠損値になる行は無い（発売なし・不成立・特払が 0 件）。返還は年 110〜150 レースで、払戻は普通にある |
| 欠損値のレースを、レースごと外す | 1つの券種が無いだけで、ほかの券種の行も減る |
| 同着は最小の払戻 | 「人気どおりの組み合わせも来た」側で見る。年に十数レースなので、学習にはほとんど響かない |
| 返還のあるレースを外す | 出走取消があったレースが全部消え、年 110〜150 行減る |

関連する資料: [10-target.md の「作り方」](10-target.md#作り方)、件数は [08-training-data.md の「5. 行数の数え上げ」](08-training-data.md#5-行数の数え上げ)。

## 8. 過去の荒れ率の鍵と券種の数

「過去の荒れ率」は、まとまり E（[09-features.md](09-features.md#e-過去の同条件の荒れ率8個)）である。

| 選び方 | 変わること |
|---|---|
| **鍵は2つ（競馬場・芝ダ・距離帯と、クラス）、券種は4つ。8個（決定）** | 列が少なく、どの券種のモデルにも同じ8個を渡す |
| 鍵を4つに増やす（出走頭数の帯、競走名を足す）。16個 | 特別戦ごとの荒れやすさ（毎年荒れる重賞など）を拾える。平場は競走名が無く欠損値。列が倍になり、少ない行数で過学習しやすい |
| 学習する券種の荒れ率だけ（2個） | 列が減る。学習データを券種ごとに変えることになり、「学習データは1回作る」の決まりが崩れる |

関連する資料: [09-features.md の E](09-features.md#e-過去の同条件の荒れ率8個)、数える部品は [04-classes.md の「2.」](04-classes.md#2-共通の部品に足すもの変えるもの)。

## 9. 利用者の規則を特徴量に入れるか

| 選び方 | 変わること |
|---|---|
| **入れない。B の「1番人気のオッズ」「2〜5番人気の最大オッズ」で表せる。規則は評価の基準に使う（決定）** | 決定木は2列に線を引いて同じ規則を作れる。基準と比べることで、モデルが規則より当たるかが分かる |

## 10. 出力の形

| 選び方 | 変わること |
|---|---|
| **券種 × 4つの確率の表に、いちばん高いクラスと中荒れ以上の確率を付ける（決定）** | 4段階を当てる使い方（いちばん高いクラス）と、荒れるレースだけ買う使い方（中荒れ以上の確率）の両方に使える |
| いちばん高いクラスだけ | 表は短い。確率の大きさ（迷っているか）が見えない |
| 4つの確率だけ | 利用者が毎回、いちばん高いクラスと合計を自分で読む |

関連する資料: [01-overview.md の「1レースの例」](01-overview.md#1レースの例)、表を作る部品は [04-classes.md の「2.」](04-classes.md#2-共通の部品に足すもの変えるもの)。

## 11. 共通部品の置き方

| 選び方 | 変わること |
|---|---|
| **レース単位の部品・多クラスのモデル・払戻のリポジトリ・多クラス用の評価を `shared` に新設し、手本のオッズの部品（`MarketFeatures`・`OddsInput`・`OddsResolver`）を `shared` に移す（決定）** | 既存の `DatasetBuilder`・`FeatureBuilder` は触らない。手本の予想を、移したあとの形に直す作業が最初に要る |
| この予想のパッケージの中に全部閉じる | `shared` を触らない。オッズの部品を手本から複製することになり、片方だけ直したときに食い違う。次にレース単位の予想を作るとき、また同じものを作る |
| 既存の `DatasetBuilder` にレース単位の口を足す | クラスは増えない。3つの予想が使う入口の中身（ID 列・評価用の列の定数）を差し替え式にする必要があり、既存の予想に影響する |
