# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。

**結論: 1サンプル = 1レースの1頭。中央競馬の芝・ダートの出走を使う。期間は `train` の引数で変えられ、既定は 2021年8月から（ウォームアップは 2020年。約 23.6 万行）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

架空の1レースの一部を例にすると、学習データは次の形になる。

| レースID | 馬番 | 馬齢 | 斤量 | 前走の着順 | 近5走の平均着差 | …（特徴量はあと 50個以上） | 目的変数: 3着以内 | 目的変数: 1着 |
|---|---|---|---|---|---|---|---|---|
| 架空レースA | 1 | 3 | 55.0 | 2 | 0.4 | … | 1 | 1 |
| 架空レースA | 2 | 3 | 57.0 | 8 | 1.3 | … | 0 | 0 |
| 架空レースA | 3 | 3 | 57.0 | （欠損値） | （欠損値） | … | 1 | 0 |

- 3番の馬は DB に過去走が無いので、前走の特徴量は欠損値になる。学習データでは、欠損値を 0 で埋めず、欠損値のまま持つ。0 で埋めると「前走 0着」のような、ありえない値になる。モデルに渡すときの欠損値の扱いは、[12-lightgbm.md](12-lightgbm.md)・[13-catboost.md](13-catboost.md) の「学習データの渡し方」を参照。
- 14頭立てのレースなら、目的変数「3着以内」が 1 のサンプルは 3つ、0 のサンプルは 11 になる。

## 2. 列の種類

学習データの列は4種類ある。モデルに渡すのは**特徴量と目的変数だけ**である。

| 種類 | 列 | モデルに渡すか |
|---|---|---|
| ID 列 | レースID、馬ID、開催日 | 渡さない |
| 特徴量 | 68個。[09-features.md](09-features.md) を参照 | `fit` の `X` として渡す |
| 目的変数 | 3着以内（1/0）、1着（1/0）。[10-target.md](10-target.md) を参照 | `fit` の `y` として渡す |
| 評価用の列 | 確定着順、確定の単勝オッズ、確定の単勝人気、単勝の払戻、複勝の払戻 | 渡さない |

3つの時点（木曜・前日・当日）のモデルは、同じ学習データから、その時点で使う特徴量の列だけを渡して学習する（[07-prediction-timing.md の「時点ごとに使う特徴量」](07-prediction-timing.md#時点ごとに使う特徴量)）。

ID 列と年を特徴量にしない理由は次のとおり。

- 馬ID を入れると、モデルは「この馬はよく来る」と個々の馬を覚えるだけになり、新しい馬に役立たない。
- 開催日や年を入れても、学習データに無い将来の年には役立たない。

予測用データは、この学習データから目的変数と評価用の列を除いた形になる。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 中央競馬の平地（芝とダート）。障害は入れない | 障害は走り方が違い、レースの数も少ない |
| 対象の馬 | 出走した馬。出走取消・発走除外・競走除外はサンプルにしない | 走っていない馬には目的変数が無い |
| 期間 | 「学習データの始まり」から。既定は 2021年8月1日 | 下の「4. 期間の指定」と「ウォームアップ期間」 |
| 新馬戦 | 入れる | 過去走の特徴量は欠損値になるが、血統・騎手・調教師で予測できる |

**ウォームアップ期間。** 近走の特徴量は、DB にある過去走から数える。学習データの始まりの直後に走った馬は、実際には何戦もしていても、DB に読んだ範囲が短いと「前走なし」に見えてしまう。そこで、学習データの始まりより前の期間（ウォームアップ期間。既定は 2020年1月から 2021年7月まで）の出走も読み、サンプルにはせず、あとのサンプルの過去走の特徴量を計算するためだけに使う。通算の成績は、ウォームアップより前も含む出走別着度数から取るので、この影響を受けない（[09-features.md](09-features.md) の「表の見方」を参照）。

既定の決まりで、学習データは約 23.6 万行になる（2021年8月〜2026年9月の芝・ダートの出走。2026-09-22 時点の DB で 236,055 行）。この中を、学習データ・検証データ・テストデータに時期で分ける。分け方は次の設計書で決める。

## 4. 期間の指定

学習データの期間は、古い順に4つの日で区切る。4つはまとめて `TrainingPeriod`（[04-classes.md](04-classes.md) の「dataset/」）が持ち、順になっていなければエラーにする。`train` の引数で変えられる。

| 区切り | 引数 | 既定 | 意味 |
|---|---|---|---|
| ウォームアップの始まり | `--warmup-from` | 学習データの始まりの前の年の1月1日（既定なら 2020-01-01） | ここからの出走を読むが、サンプルにしない |
| 学習データの始まり | `--train-from` | 2021-08-01 | ここからの出走がサンプルになる |
| 検証データの始まり | `--valid-from` | 2025-07-01 | この前日までが学習データ |
| テストデータの始まり | `--test-from` | 2026-01-01 | この前日までが検証データ。ここからはテストデータ（最後に1回だけ確かめる用） |

例: 2024年1月から学習し、2023年をウォームアップにする（`--warmup-from` を省略しても同じ）。

```powershell
uv run python -m yosou.form_aptitude_top3 train --warmup-from 2023-01-01 --train-from 2024-01-01
```

- 使った期間は、学習の結果の表「学習データの期間」に、ウォームアップの行も含めて出る。
- ウォームアップを「前の年の1月1日から」にするのは、学習データの始まりが年の途中でも、ウォームアップが1年より短くならないようにするためである。
- DB に入っている期間より前を指定しても、エラーにはならず、行が無いだけである。JRA-VAN が提供している期間（[09-features.md](09-features.md) の「使うデータの期間」）を見て、足りなければ jvdata-store で取得する。
- 2021年7月27日より前を入れると、ウッドチップ調教の記録が無い期間が入る。その扱いは [09-features.md](09-features.md) の「I. 調教」を参照。
- 期間を変えたとき、LightGBM の `min_category_count` を見直す（[12-lightgbm.md](12-lightgbm.md) の「2000 にした理由」）。

### 既定を 2021年8月からにした理由

学習データの始まりを3つ試し、検証データの期間を2つ（2025年7〜12月と、2025年1〜6月）変えて、当たり具合を比べた（2026-09-22）。

| 学習データの始まり | ウォームアップ | 学習データの行数（検証 2025年7〜12月のとき） | 結果 |
|---|---|---|---|
| 2024年1月 | 2023年 | 約 6.9 万行 | 2つの検証期間とも、いちばん低い |
| **2021年8月** | 2020年 | 約 18 万行 | **2つの検証期間とも、いちばん良い（採用）** |
| 2017年1月（DB にある10年全部） | 2016年 | 約 39 万行 | 2021年8月からと同じか、少し低い。学習にかかる時間は約2倍 |

- 行を増やすと当たり具合は上がるが、10年全部まで延ばしても、それ以上は上がらない。古い年ほど、今のレースと傾向がずれていると考えられる。
- 2021年8月は、ウッドチップ調教の記録がそろう最初の月である（記録は 2021年7月27日から）。学習データのほぼ全部の行で、調教の特徴量を「不明」にせずに使える。
- 当たり具合の値は、Git の対象外の `reports/form_aptitude_top3/period/summary.txt` にある。
