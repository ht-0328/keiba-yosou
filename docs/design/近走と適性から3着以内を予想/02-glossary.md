# 02 用語の意味

この設計書では、機械学習で普通に使う用語をそのまま使う。どの文書に出てくる用語も、意味はここにまとめる。

## 機械学習の用語

| 用語 | 意味 | この設計では |
|---|---|---|
| 二値分類 | 当てたい値が 1 か 0 の2通りしかない問題 | 3着以内に入るか、入らないか |
| 学習データ（訓練データ） | モデルに学ばせるための表。行がサンプル、列が特徴量と目的変数 | どの出走を使うかは [08-training-data.md](08-training-data.md) を参照 |
| サンプル | 学習データの1行 | 1レースの1頭 |
| 特徴量（説明変数） | 予測の手がかりにする列。`model.fit(X, y)` の `X` | 斤量、前走の着順など 68個 |
| 目的変数（ラベル） | 当てたい値の列。`model.fit(X, y)` の `y` | 3着以内なら 1、それ以外は 0 |
| 予測確率 | `model.predict_proba(X)` が返す、目的変数が 1 になる確率 | 3着以内に入る確率 0.34 |
| 数値特徴量 | 大小に意味がある数の特徴量 | 斤量 55.0、距離 1600 |
| カテゴリ特徴量（カテゴリ変数） | 種類を表す特徴量。大小に意味は無い | 競馬場、騎手、父 |
| 欠損値 | 値が無いこと。表では空欄（NaN） | 前走が無い馬の「前走の着順」 |
| リーク（データリーケージ） | 予測する時点では分からないはずの情報が、特徴量に混ざること。検証では当たるのに、本番では当たらないモデルになる | 確定オッズや着順を特徴量に入れる |
| 過学習 | 学習データの細かいくせまで覚えてしまい、新しいデータで当たらなくなること | 数回しか出てこない父の成績を丸覚えする |
| 学習データ・検証データ・テストデータ | 学ばせる用、ハイパーパラメータを調整する用、最後に1回だけ確かめる用に分けたデータ。競馬では時期で分ける | 分け方は次の設計書で決める |
| 予測用データ | 学習が終わったあと、予測したいレースについて作る表。目的変数は無い | 今日のレースの出走馬 |
| ハイパーパラメータ | 学習の前に人が決めるモデルの設定 | 木の数、木の深さ |
| 評価指標 | モデルの良し悪しを測る数値 | 次の設計書で決める |
| アンサンブル | 複数のモデルの予測を組み合わせて、1つの予測にすること | LightGBM と CatBoost の予測確率の平均 |
| 決定木 | 「前走は3着以内か」のような、はい／いいえの問いを重ねて答えを出す木の形の仕組み。問いの中身と順番は、学習データから機械が決める | LightGBM と CatBoost の中で使われる |
| 勾配ブースティング決定木（GBDT） | 決定木をたくさん作り、前の木が外したところを次の木が直す、をくり返して、全部の木の答えを足し合わせる方法 | LightGBM と CatBoost は、どちらもこの方法の道具 |
| 目的関数（損失関数） | 予測が正解からどれだけ外れたかを測る式。学習は、これを小さくするように進む | 二値分類用のもの（LightGBM は `binary`、CatBoost は `Logloss`） |
| 木の数 | モデルの中に作る決定木の本数。木を1本足すごとに、前の木が外したところを少し直す。多いほど学習データに合うが、多すぎると過学習する | 早期終了で決める（LightGBM は `n_estimators`、CatBoost は `iterations` が上限） |
| 学習率 | 木を1本足すごとに、その木の答えをどれだけ効かせるかの割合。小さいほど慎重に学び、木が多く要る | 0.05 |
| 早期終了 | 検証データでの当たり具合が良くならなくなったところで、木を足すのをやめること | 100 本続けて良くならなければやめる |
| public メソッド | クラスの外から呼んでよいメソッド。名前が `_` で始まらない。1回呼ぶと、引数を受け取り、中の作業（引数のチェック・元DB の読み取り・if 文・計算）を全部終えて、戻り値を返す | `DatasetBuilder.build_training_data()`（学習データを作って返す） |
| オーケストレーション | いくつかのクラスを決まった順に呼び、データを受け渡して、流れを進めること。流れを進めるクラスは、自分では計算しない | `TrainingWorkflow`（学習）・`PredictionWorkflow`（予測） |
| インターフェース | いくつかのクラスが共通に持つメソッドの決まり。Python では `Protocol` で書く。決まりを守るクラスどうしは、呼ぶ側から見て入れ替えられる | `ProbabilityModel`（`LightGbmModel` と `CatBoostModel` が守る） |
| リポジトリ（Repository） | データの読み書きだけを受け持つクラスの、設計でよく使う呼び方。この設計では、1つの SQL につき1つのリポジトリにする | `EntryRepository`（出走の行を読む）・`WorkoutRepository`（調教を読む）・`ModelRepository`（モデルを保存する） |
| エンコーダー（Encoder） | 特徴量を、モデルが受け取れる形に変えるクラスの、機械学習でよく使う呼び方。`fit()` で変え方を覚え、`transform()` で変える | `LightGbmEncoder`・`CatBoostEncoder` |
| 順序付きターゲット統計 | CatBoost が、カテゴリの値（例: 騎手A）を、その値のサンプルで目的変数が 1 だった割合に置き換える方法。各サンプルより前に並んだサンプルだけから数えるので、リークしない | CatBoost のカテゴリ特徴量の扱い |

## 競馬とこの設計の用語

| 用語 | 意味 | この設計では |
|---|---|---|
| ID 列 | どのレースのどの馬かを示す列。特徴量にしない | レースID、馬ID、開催日 |
| 評価用の列 | 回収率などを計算するためだけに置く列。特徴量にしない | 確定オッズ、払戻 |
| ウォームアップ期間 | サンプルにはせず、過去走の特徴量を計算するためだけに使う期間 | [08-training-data.md](08-training-data.md) の「どのサンプルを入れるか」を参照 |
| レース内順位 | 同じレースに出る馬の中で並べた順位 | 持ち時計が 16頭中 4番目なら 4 |
| 事実表 | このリポジトリにすでにある一時的な表。1行 = 1頭の出走に、レース・馬・結果・前走を並べたもの。多くの特徴量はここから取る | `tools/共通/facts.py` |
| 出走別着度数 | JRA-VAN のデータ（表 `ck`）。出走馬名表の時点での、その馬の通算の着回数（1着〜着外）を、芝ダ・距離帯・馬場状態・競馬場ごとに持つ。2023年より前の出走も含む | 通算の出走数、同じ距離帯での通算の3着以内の数 |
