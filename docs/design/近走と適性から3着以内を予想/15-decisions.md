## 3. オッズと人気を特徴量に入れるか

| 選び方 | 変わること |
|---|---|
| **入れる（2026-09-23 に決定）** | 前日・当日の特徴量に、単勝オッズ・人気順位・オッズから見た勝率（まとまり J）を足す。予測のときは、利用者が渡したオッズか、締め切り前のオッズを使う。予測確率は市場の見方に近づき、モデルの仕事は「市場の見立てに馬柱からどれだけ上乗せできるか」になる |
| 入れない（2026-09-21 の決定。取り下げ） | オッズと人気は評価用の列にだけ置き、予測確率と比べるのに使う |

**決め直した理由（2026-09-23）。** オッズを使わないモデルを検証データ（2025年7〜12月）で確かめたところ、次のことが分かった。

- 各レースで確率がいちばん高い馬（モデルの本命）の3着以内率は、1番人気を全部選ぶより低かった。
- 1番人気を除いて選び直しても、2番人気を全部選ぶより低かった。比べる相手が2番人気に変わるだけで、モデルが市場の順位付けより弱いことは変わらない。
- モデルが市場と違う馬を選んだレースでは、市場のほうが正しかった。

つまり、オッズを見ないモデルは、市場がすでに知っていることを馬柱から学び直しているだけで、しかも市場より下手だった。オッズを入れれば、市場の見立てを出発点にして、馬柱から上乗せできる分だけを学べばよくなる。数値は Git の対象外の `reports/近走と適性から3着以内を予想/exclude-favorite-valid-2025H2.txt` にある。

**決め直したあとの確かめ（2026-09-23）。** オッズを足して学習し直し、同じ検証データで確かめた。

- AUC は上がり、市場（オッズから見た勝率だけで並べたとき）を少し上回った。
- モデルの本命の3着以内率は、1番人気を全部選ぶのと同じ水準になった（本命は9割のレースで1番人気と同じ馬）。
- 本命が1番人気と違う馬になったレースでは、その馬のほうが、同じレースの1番人気より3着以内に入った。オッズを入れる前は逆だった。
- 予測確率と実際の3着以内率は、確率の帯ごとに見てよく合っている。

数値は Git の対象外の `reports/近走と適性から3着以内を予想/with-odds-valid-2025H2.txt` にある。

**入れることによる注意。** 学習は確定オッズ、予測は締め切り前のオッズになるので、値が少しずれる（[11-leak-prevention.md の決まり 5](11-leak-prevention.md#決まり)）。木曜はオッズが無いので使わない。

関連する資料: まとまり J は [09-features.md の J](09-features.md#j-市場の評価4個)。予測のときのオッズの与え方は [07-prediction-timing.md](07-prediction-timing.md#予測のときのオッズの与え方)。

| 直したこと | 直す前 | 直した後 | 理由 |
|---|---|---|---|
| オッズの使い方 | 単勝オッズ・人気順位・オッズから見た勝率を、ほかの特徴量と同じように入れた | 単勝オッズから Harville の式で出した「オッズから見た3着以内率」を基準にし、モデルは基準からの上げ下げだけを学ぶ（LightGBM の `init_score`、CatBoost の `baseline`。木曜はオッズが無いので基準なしで学ぶ）。特徴量に「オッズから見た3着以内率」を足して 75個 | 「1 ÷ 単勝オッズ」をそろえた勝率は、3着以内の確率ではない。オッズで説明できる部分と、馬の情報で新しく説明できる部分を分けるため |
| 3着以内と複勝的中 | 目的変数は3着以内だけ | 目的変数「3着以内」は残し、払戻と照合した「複勝的中」の列を足した（7頭以下は2着まで、同着は払戻どおり、4頭以下は複勝を売らない） | 複勝を買う判断に3着以内をそのまま使うと、複勝が2着までのレースでずれるため |
| 買う候補 | 確率の高い順に並べるだけ | 並べ方は同じ。予測の表に「オッズから見た3着以内率」「複勝的中の確率」「複勝の期待値」（複勝的中の確率 × 見込みの払戻の倍率）を足した。見込みの倍率は学習のときに保存する | 「来やすい」と「払戻まで考えて買う価値がある」は違うため |

人気帯で分けることは、まず基準の補正で足りるかを見てからにした（計画の 2）。基準の補正だけで下の基準を満たしたので、分けていない。

オッズだけの基準より小さかった（計画の採用の基準は 7つのうち 5つ以上）。複勝を期待値で買ったときの回収率は、直す前より高くなったが、
100% にはわずかに届かなかった（推定の幅は 100% をまたぐ）。

**材料を足す実験と、条件で分ける実験。** 直した後の予想に、材料を1つずつ足した作り方と、条件で学習データを分けた作り方を比べた

条件で分ける5つの作り方（芝ダ・競馬場・距離帯・芝ダ×距離帯・頭数帯）は満たさなかった。券種ごとのオッズは、予想する時点で全券種の
締め切り前のオッズが要るので、まだ特徴量に入れていない。騎手・調教師・血統の市場に対する成績は、効き目はごく小さいが、
**採用（2026-09-30 利用者が決定）。** まとまり L の4個として足した（[09-features.md の L](09-features.md#l-騎手調教師血統の市場に対する成績4個)）。

## 8. アンサンブルの平均のしかた

プログラムは、はじめから単純な平均で作ってあったが、設計書では「次の設計書で決める」のままだった（仮の作り）。2026-09-28 に、今の作りのまま決めた。利用者の「任せる」による。

| 選び方 | 変わること |
|---|---|
| **重みを付けない単純な平均（決定）** | 決めることが無い。学習し直しても、平均のしかたは変わらない |
| 検証データで重みを選ぶ（例: LightGBM 0.7・CatBoost 0.3） | 学習し直すたびに重みが変わる。検証データを、早期終了に加えて重みの選択にも使うことになる |
| 良いほうの1つだけを使う | 利用者の「LightGBM と CatBoost の両方を使う」という指示に合わない |

**決めた理由。** 研究「既存モデルの改善」の7つの区切り（[16-evaluation.md の 4.](16-evaluation.md#4-半年ずつずらした確かめ)）で残した、モデルごとのテスト期間の予測で比べた（2026-09-28）。

- この予想では、7つのうち 6つの区切りで、平均のログ損失が2つのモデルのどちらよりも小さかった。
- 検証期間で重みを 0.1 刻みに選び、テスト期間で使うと、単純な平均より良くなった区切りは 7つのうち 3つで、全体ではほぼ同じだった。
- どちらのモデルが良いかは、区切りによって入れ替わった（LightGBM が良かったのは 7つのうち 5つ）。決まって良いほうが無いので、重みを付ける根拠が無い。

穴馬と人気馬の予想でも、同じ比べ方で同じ結論になった（[穴馬の 15 の 13](../穴馬が3着以内に入るかを予想/15-decisions.md#13-アンサンブルの平均のしかた)・[人気馬の 15 の 12](../人気馬が4着以下になるかを予想/15-decisions.md#12-アンサンブルの平均のしかた)）。数値は、Git の対象外の `reports/既存モデルの改善/predictions/`（モデルごとの予測）から計算した。

**確率どうしを平均する理由。** 各モデルは、オッズから作った基準を足して確率に戻してから返す。確率の平均なら、0〜1 に収まり、多クラス分類（荒れ具合）でも同じ計算で済む。ロジット（確率を 0〜1 の外に広げた値）どうしの平均も考えられる。同じ7つの区切りで比べると、2つのモデルの確率の差は平均で 1〜2ポイントと小さく、ロジットの平均にしてもテスト期間のログ損失はほとんど変わらず、良くなる区切りと悪くなる区切りが半々だった（穴馬・人気馬の予想でも同じ）。そのため、簡単なほうにした。

関連する資料: 平均のしかたの決まりは [03-library-basics.md の 6.](03-library-basics.md#6-2つの予測確率を合わせる)。平均が悪くなっていないかの確かめ方は [16-evaluation.md の 2.](16-evaluation.md#2-評価指標)。

## 9. 期間の分け方と評価指標

プログラムの `PeriodSplitter` は「分け方は設計書でまだ決まっていない。いまは仮に、2つの区切りの日で3つに分ける」として作られ、評価指標は穴馬の予想の設計書で決めたものを使っていた。2026-09-28 に、今の作りのまま決めた。利用者の「任せる」による。

| 選び方 | 変わること |
|---|---|
| **既定の区切りで学習・検証・テストに分け、予想を直すときは 7つの半年の区切りで確かめる（決定）** | ふだんの `train` は1回の学習で済む。直すかどうかの判断は、7つの区切りで偶然の幅を見てから行う |
| 既定の区切りの1回だけで判断する | 速いが、検証の半年1つの結果に、偶然の幅がそのまま入る |
| `train` でも毎回 7つの区切りで学習し直す | 判断はいちばん確かだが、学習に7倍の時間がかかる。本番の予測には、いちばん新しい区切りのモデル1つしか使わない |

**決めた理由。**

- 時期で分けるのは、同じ開催日のレースや同じ馬の前後の走が、学習と検証に散らばらないようにするためである（穴馬の [16 の 1.](../穴馬が3着以内に入るかを予想/16-evaluation.md#1-期間の分け方)）。
- 指標は、どの予想でも共通の `MetricCalculator` で出す。予想ごとに別の指標にすると、予想どうしを並べて見られない。
- 7つの区切りの確かめは、2026-09-24 の既存モデルの修正で実際に使い、直した後の予想の採用を決めた（上の [7](#7-既存モデルの修正計画での直し)）。同じ手順を、これから直すときの決まりにした。
- ハイパーパラメータの調整は、学習データの始まりと LightGBM の `min_category_count` を決めたとき（2026-09-22）と同じく、2つの検証期間で比べるやり方にした。研究の7つの区切りの確かめは設定ファイルを受け取らないので、ハイパーパラメータの比べ方には使えない。

関連する資料: [16-evaluation.md](16-evaluation.md)。

## 11. 研究「一番人気を疑う」の直し方を移す

研究「一番人気を疑う」（`research/一番人気を疑う/`。結果は [02-結果.md](../../../research/一番人気を疑う/docs/02-結果.md)）で、予想の◎が1番人気より
多く3着以内に来るように直す方法を探し、良かった直し方が2つ見つかった。2026-10-01 に、利用者が「両方移す」と決めた。

| 直し方 | 研究で分かったこと | 移した形 |
|---|---|---|
| 1. オッズを使わない予想を、研究「馬の力と展開でオッズに勝つ」の 197個の材料（とセリの価格）で作り直す | 木曜の◎の3着以内率が、今の木曜版より大きく上がった（1番人気には届かない） | まとまり M（202個）。木曜は M だけ、前日は M と J で学ぶ（[09-features.md の M](09-features.md#m-馬の力の材料202個木曜前日のモデル)） |
| 2. 当日の予想に、券種ごとのオッズから見た支持を足す | 7つの区切りすべてで◎が1番人気を上回った。予想する時点で全券種の速報オッズ（`0B30`）が要る | まとまり N（6個）。当日のモデルに足す（[09-features.md の N](09-features.md#n-券種ごとのオッズから見た支持6個当日のモデルだけ)） |

**確かめ方。** 予想のパッケージで作った学習データで、研究「既存モデルの改善」と同じ7つの区切り（[16-evaluation.md の 4.](16-evaluation.md#4-半年ずつずらした確かめ)）で、
時点ごとに今の予想と移した作り方を学習し直して比べた（研究の入口 `port_check.py`）。採用の基準も同じで、テスト期間のログ損失が今の予想より
小さい区切りが 7つのうち 5つ以上あり、全期間を合わせても小さいこと。研究「一番人気を疑う」と同じ、◎の3着以内率を1番人気と比べる表も出した。
数値は Git の対象外の `reports/一番人気を疑う/移したあとの確かめ/結果.md` にある。

| 時点 | 比べた作り方 | 結果 | 判断 |
|---|---|---|---|
| 木曜 | 今の木曜版（A〜I・L）と、M だけ | 7つすべての区切りでログ損失が小さく、差もはっきり大きかった。◎の3着以内率も上がったが、1番人気にはまだ届かない | 採用 |
| 前日 | 今の前日版（A〜J・L と基準）と、M と J と基準 | 7つすべての区切りでログ損失が小さかった（差は木曜より小さい）。◎は7つすべての区切りで1番人気を上回った | 採用 |
| 当日 | 今の当日版（A〜J・L と基準）と、それに N を足したもの | 7つすべての区切りでログ損失が小さかった。◎は7つすべての区切りで1番人気を上回り、疑ったレースで◎のほうがよく来た | 採用 |

- 前日に M を使うことは、研究では試していなかった（研究は木曜だけで比べた）。オッズのある前日でも、A〜I・L より M のほうが確率の誤差が小さかったので、前日も M にした。
- **当日にも M を足す（2026-10-02。PR #52 の残課題）。** 今の材料と N の当日版に、M のうち今の材料と名前の重ならない 200個を足して、同じ7つの区切りで比べた。
  7つすべての区切りでログ損失が小さく（差は N を足したときより小さい）、◎が1番人気を上回る区切りも 7つのまま、疑ったレースの◎もわずかに良くなったので採用した。
  券種オッズなしのモデルも、同じ学習データから N を外したもの（279個）にした。
- **CatBoost の木の数の上限は変えない（2026-10-02。PR #52 の残課題）。** [13-catboost.md の 2.](13-catboost.md#2-ハイパーパラメータの初期値) を参照。
- **木曜・前日の予測を速くした（2026-10-02。PR #52 の残課題）。** M の計算を、対象の出走に要る出走だけに絞った（値は変わらない。[09-features.md の M](09-features.md#m-馬の力の材料202個木曜前日のモデル)）。
- 移した作り方は、本番と同じ学習データの始まりで学んだ（M は 2012年から、今の材料は研究「既存モデルの改善」と同じく 2017年から）。

**当日に券種のオッズが無いとき（決定）。**

| 選び方 | 変わること |
|---|---|
| **N を外して学んだ「券種オッズなし」のモデルに切り替える（決定）** | 予測は止まらない。券種のオッズが無いレースは、N だけを外したモデル（今は 279個）で予測する。学習は1回増える |
| 止めて、券種のオッズの取り込みを案内する | 取り込み忘れに気づけるが、すぐに予測が欲しいときに使えない |
| N を欠損値のまま、N を使うモデルに渡す | 学習データには券種のオッズが丸ごと無いレースがほとんど無いので、学習のときと違う様子のデータになる |

- 6つの券種のどれか1つでも、そのレースの全部の馬で無ければ「無い」とする（[06-flowchart.md の図3](06-flowchart.md#図3-当日のモデルの選び方)）。
- 券種オッズの SQL は、custom_binary（特徴量と条件を選んで予想）と同じものを `shared` に移して両方から使う（同じ SQL を2か所に書かない）。

**研究からの直し。** 研究のコードは予想から import せず、要る部品を `src/yosou/shared/` に移した。そのとき、学習と予測で同じ値になるように2つ直した

## 12. 対戦レーティングを足すか

研究「回収率100超」を始めたときの残課題（補正時計・対戦レーティング・展開は未着手）のうち、対戦レーティングを 2026-10-02 に作って確かめた
（利用者の「作って試す」による）。同じレースを走った馬どうしの着順の勝ち負けから Elo のレーティングを開催日の順に更新して作る7個の材料で、
作り方と似た材料との違いは [09-features.md の O](09-features.md#o-対戦レーティング7個木曜前日のモデル)。

| 選び方 | 変わること |
|---|---|
| 採用の基準を満たした時点だけ足す | その時点のモデルの特徴量が7個増え、学習データを読むときに過去の全出走の着順を読む SQL が1つ増える。満たさない時点は今のまま |
| どの時点にも足さない | 何も変わらない。部品と研究の比べは残す |
| 全部の時点に足す | 基準を満たさない時点でも足すことになり、研究「既存モデルの改善」の決まり（材料は未学習の期間で良くなったものだけ残す）に合わない |

**確かめ方。** 研究「既存モデルの改善」の入口⑧（`h2h_check.py`）。今の本番と同じ材料の学習データ（木曜・前日は M と J、当日は A〜L と N）に
対戦レーティングの7個を足し、研究「既存モデルの改善」と同じ7つの区切り（[16-evaluation.md の 4.](16-evaluation.md#4-半年ずつずらした確かめ)）で、
時点ごとに今の予想と足した作り方を学習して比べた。採用の基準も同じで、テスト期間のログ損失が今の予想より小さい区切りが 7つのうち 5つ以上あり、
全期間を合わせても小さいこと。研究「一番人気を疑う」と同じ、◎の3着以内率を1番人気と比べる表も出した。
数値は Git の対象外の `reports/既存モデルの改善/compare/対戦レーティング-20261002.md` にある。

| 時点 | 比べた作り方 | 結果 | 判断 |
|---|---|---|---|
| 木曜 | 今の木曜版（M）と、それに O を足したもの | 7つのうち6つの区切りでログ損失が小さく、全期間でも小さかった。差はごく小さい（M に移したときの差の数十分の一）。人気別 AUC はわずかに上がり、◎の3着以内率も少し上がったが、1番人気にはまだ届かない | 採用 |
| 前日 | 今の前日版（M と J と基準）と、それに O を足したもの | 7つのうち5つの区切りで小さく、全期間でもごくわずかに小さかった（基準ちょうど）。◎は今の前日版と同じく7つすべての区切りで1番人気を上回ったが、◎の3着以内率はごくわずかに下がった | 採用（基準を満たしたので、決まりどおり） |
| 当日 | 今の当日版（A〜L・N・M と基準）と、それに O を足したもの | 小さかった区切りは 7つのうち 3つで、全期間ではわずかに大きかった。M を足す前の当日版（A〜L と N）と比べても 4つで、基準に届かなかった | 採用しない |

- **当日に効かないのは、当日にはオッズ（J・N）があるため**と考えられる。単勝や券種のオッズには、誰に勝って誰に負けたかという相手関係がすでに織り込まれていて、
  対戦レーティングの上乗せはほとんど残らない。オッズの無い木曜にいちばん効き、オッズのある前日は差が小さくなった。
- **木曜と前日は同じ一覧（`ABILITY_CATALOG`）を使うので、O をその一覧に足して、木曜・前日の両方のモデルで使う。** O は木曜から分かる材料で、
  前日だけ外す・木曜だけ外す必要は無かった（両方とも基準を満たした）。当日のモデル（`RACE_DAY_CATALOG`）と券種オッズなしのモデルは今のまま。
- 木曜・前日のモデルの特徴量は、木曜 199個（M 192・O 7）、前日 210個（M 199・O 7・J 4）になった（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。
- 2026-10-02 に、今の本番のモデルを `reports/近走と適性から3着以内を予想/models-直す前-20261002-対戦レーティング/` に控えてから学習し直した
  （当日のモデルは材料が変わらないので、同じ学習データで学び直しただけ）。
- K（1レースで動く幅）の大きさは1通り（走ったレースが5つ未満は 40、以降は 20）しか試していない。効き目はごく小さいので、K を変えて探すことはしていない。
## 13. 展開の予想の結果を特徴量に足すか

予想「展開から着順を予想」（`docs/design/展開から着順を予想/`）の前半・後半の展開の予想（① 先頭の馬・② 序盤の位置・③ 前半のペース・
④ 4コーナーの位置・⑤ 上がりの速さ・⑥ 後半のペース）は、簡単な基準よりちゃんと当たっている（展開の [16-evaluation.md の 9.](../展開から着順を予想/16-evaluation.md#9-2026-09-30-の確かめの結論)）。
一方、その着順の予想（⑦）は採用の基準を満たさなかった。展開の設計書は「既存の予想に渡さない（この設計では）」（展開の [15 の 11](../展開から着順を予想/15-decisions.md#11-既存の予想に渡すか)）としていたので、
2026-10-02 に利用者が「試す」と決めた。展開の予想の結果を、この予想の特徴量（まとまり P）として渡し、当たりが良くなるかを確かめる。

**採用の基準（2026-10-02。結果を見る前に決めた）。** 研究「既存モデルの改善」の材料の実験・研究「一番人気を疑う」の移したあとの確かめ（上の 11）と同じ。

| 決めること | 決めた内容 |
|---|---|
| 比べ方 | 研究「既存モデルの改善」の7つの区切り（[16-evaluation.md の 4.](16-evaluation.md#4-半年ずつずらした確かめ)。2023年前半〜2026年、学習は木曜・前日が 2012年から、当日が 2017年から）で、「今の予想」と「今の予想 ＋ P」を学習し直して比べる |
| 比べる相手（今の予想） | 本番と同じ材料。木曜は M と O、前日は M と O と J とオッズの基準、当日は今の材料（A〜J・L）と N と M とオッズの基準（上の 11・12） |
| 時点 | 木曜・前日・当日のそれぞれで判定する。P は、その時点の展開のモデルの予測から作る（木曜のモデルには木曜の展開の予測） |
| 採用の基準 | テスト期間の確率の誤差（ログ損失）が今の予想より小さい区切りが 7つのうち 5つ以上あり、全期間を合わせても小さいこと。満たした時点だけ P を足して本番のモデルを学習し直し、満たさない時点は足さない |
| 併せて出すもの（判断には使わない） | 人気別 AUC と、研究「一番人気を疑う」と同じ ◎（確率1位）の3着以内率と1番人気の比べ |
| 全部の時点で満たさなかったとき | 「展開の予想は一般の予想の材料にならない（市場に織り込み済み）」と、この文書・[09-features.md](09-features.md)・展開の 15 の 11 と 16・研究の 02-結果の読み方 に書き、P のコードは残すが本番のモデルには足さない |

**リークを防ぐ決まり。** 学習データの各レースの P は、「そのレースより前だけで学習した展開のモデル」の予測（展開の年ごとの確かめ `reports/展開から着順を予想/out_of_sample/` の、年ごとに学習し直した予測）から作る（展開の [11-leak-prevention.md の決まり 11](../展開から着順を予想/11-leak-prevention.md#決まり) と同じ）。
予測が無い年（前半は 2016年より前、後半は 2017年より前）は欠損値にする。本番の予測では、保存済みの展開のモデル（`reports/展開から着順を予想/models/`）でそのレースを予測して付ける。

**結果。** 確かめたあとに書く（2026-10-02 時点では確認中）。数値は Git の対象外の `reports/既存モデルの改善/compare/展開の予想-<日付>.md` に置く。
