## 1. いつ予測するか

| 選び方 | 変わること |
|---|---|
| **3つの時点のどれでも出す（決定）** | 時点ごとに使う特徴量を変えた、別のモデルを学習する（LightGBM と CatBoost に3つずつ） |
| 当日だけ | モデルは2つで済むが、前日までに予測を見られない |
| 前日だけ | 馬体重・馬体重の増減を使えない |

関連する資料: 時点ごとに使う特徴量は [07-prediction-timing.md の「時点ごとに使う特徴量」](07-prediction-timing.md#時点ごとに使う特徴量)。モデルを分ける理由は [07-prediction-timing.md の「時点ごとにモデルを分ける理由」](07-prediction-timing.md#時点ごとにモデルを分ける理由)。

## 3. オッズと人気を特徴量に入れるか

| 選び方 | 変わること |
|---|---|
| **入れる（2026-09-23 に決定）** | 前日・当日の特徴量に、単勝オッズ・人気順位・オッズから見た勝率（まとまり J）を足す。予測のときは、利用者が渡したオッズか、締め切り前のオッズを使う。予測確率は市場の見方に近づき、モデルの仕事は「市場の見立てに馬柱からどれだけ上乗せできるか」になる |
| 入れない（2026-09-21 の決定。取り下げ） | オッズと人気は評価用の列にだけ置き、予測確率と比べるのに使う |

**決め直した理由（2026-09-23）。** オッズを使わないモデルを検証データ（2025年7〜12月）で確かめたところ、次のことが分かった。

- 各レースで確率がいちばん高い馬（モデルの本命）の3着以内率は、1番人気を全部選ぶより低かった。
- 1番人気を除いて選び直しても、2番人気を全部選ぶより低かった。比べる相手が2番人気に変わるだけで、モデルが市場の順位付けより弱いことは変わらない。
- モデルが市場と違う馬を選んだレースでは、市場のほうが正しかった。

つまり、オッズを見ないモデルは、市場がすでに知っていることを馬柱から学び直しているだけで、しかも市場より下手だった。オッズを入れれば、市場の見立てを出発点にして、馬柱から上乗せできる分だけを学べばよくなる。数値は Git の対象外の `reports/form_aptitude_top3/exclude-favorite-valid-2025H2.txt` にある。

**決め直したあとの確かめ（2026-09-23）。** オッズを足して学習し直し、同じ検証データで確かめた。

- AUC は上がり、市場（オッズから見た勝率だけで並べたとき）を少し上回った。
- モデルの本命の3着以内率は、1番人気を全部選ぶのと同じ水準になった（本命は9割のレースで1番人気と同じ馬）。
- 本命が1番人気と違う馬になったレースでは、その馬のほうが、同じレースの1番人気より3着以内に入った。オッズを入れる前は逆だった。
- 予測確率と実際の3着以内率は、確率の帯ごとに見てよく合っている。

数値は Git の対象外の `reports/form_aptitude_top3/with-odds-valid-2025H2.txt` にある。

**入れることによる注意。** 学習は確定オッズ、予測は締め切り前のオッズになるので、値が少しずれる（[11-leak-prevention.md の決まり 5](11-leak-prevention.md#決まり)）。木曜はオッズが無いので使わない。

関連する資料: まとまり J は [09-features.md の J](09-features.md#j-市場の評価3個)。予測のときのオッズの与え方は [07-prediction-timing.md](07-prediction-timing.md#予測のときのオッズの与え方)。

## 5. 特徴量に、要らないもの・足りないものはあるか

設計時の 68個のままとした。そのあと（2026-09-22）、血統の産駒の近1年の3着以内の割合3個を足して 71個になった（[09-features.md の H](09-features.md#h-血統6個)、`CHANGELOG.md`）。

関連する資料: 71個の一覧は [09-features.md](09-features.md)。9つのまとまりの見取り図は [01-overview.md の「使うデータ」](01-overview.md#使うデータ)。
