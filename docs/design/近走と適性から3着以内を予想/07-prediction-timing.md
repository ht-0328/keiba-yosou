# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使える情報が変わる。

**結論: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う。木曜と前日は馬の力の材料（M。前日は市場の評価 J も）、当日は今の材料（A〜J・L）に券種ごとのオッズから見た支持（N）を足して学ぶ。当日に券種のオッズが無いレースのために、N を使わない当日のモデルも持つ（LightGBM と CatBoost に4つずつ、計8つ）。3着以内のモデルと1着のモデル（[10-target.md](10-target.md)）は、どの時点も同じ材料・同じ列で別々に学ぶので、モデルは合わせて 16個になる。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと |
|---|---|---|
| 木曜（出走馬名表） | 出走馬、騎手、斤量、過去走、出走別着度数（20時ごろ）、それまでの調教 | 枠番・馬番、オッズ、馬体重、馬場状態 |
| 前日（出馬表） | 上に加えて枠番・馬番、前日発表の馬場状態、前日発売の単勝オッズ（JRA の発表） | 馬体重、当日の馬場状態、締め切り前のオッズ |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前のオッズ | 確定オッズ、結果 |

単勝オッズは、前日と当日に特徴量に使う（まとまり J。[09-features.md の J](09-features.md#j-市場の評価4個)）。木曜は前売りがまだ始まっていないので、使わない。予測のときのオッズの与え方は、下の「予測のときのオッズの与え方」を参照。

## 時点ごとに使う特徴量

| 時点 | 材料（[09-features.md](09-features.md)） | 使わない特徴量 | 特徴量の数 |
|---|---|---|---|
| 木曜（出走馬名表） | 馬の力の材料（M の 202個と O の7個と J の4個）と展開の予想の結果（P の 20個） | M のうち枠番・馬番・馬場状態・馬体重を使う 10個（`frame_no`・`condition_order`・`cond_places_before`・`馬番の位置`・`枠の傾向` の3個・`body_weight`・`weight_change`・`体重_近走の平均との差`）、J の4個 | 219 |
| 前日（出馬表） | 馬の力の材料（M と O と J）。オッズから作った基準を出発点にする | M のうち馬体重を使う3個 | 210 |
| 当日（馬体重の発表のあと） | 今の材料（A〜J・L の 79個）と N の6個と M のうち今の材料と名前の重ならない 200個。オッズから作った基準を出発点にする | なし | 285 |
| 当日・券種オッズなし（券種のオッズが無いレース） | 今の材料と M の 200個 | N の6個 | 279 |

- 木曜は馬場状態が分からないので、馬場状態を条件にして数える特徴量も使わない。オッズもまだ無いので、まとまり J の4個も使わない。
- **1着のモデルも、この表のとおり時点ごとに同じ列で学ぶ。** 基準は、3着以内のモデルの「オッズから見た3着以内率」の代わりに「オッズから見た勝率」（どちらも前日から）。木曜は基準なしで学ぶ。単勝の期待値（1着になる確率 × 単勝オッズ）は、オッズの分かる前日・当日だけ出す（[15-decisions.md の 14](15-decisions.md#14-1着のモデルを足して--を単勝の期待値で選ぶ)）。
- **木曜と前日を馬の力の材料にしたのは、研究「一番人気を疑う」の直し方を移して、7つの区切りで今の木曜版・前日版と比べ、どちらも確率の誤差（ログ損失）が7つすべての区切りで小さかったため**（[15-decisions.md の 11](15-decisions.md#11-研究一番人気を疑うの直し方を移す)）。当日は、今の材料に N を足すほうが、7つすべての区切りで今の当日版より誤差が小さく、さらに M も足すと、7つすべての区切りで N だけのときより誤差が小さかった。
- **木曜だけ、展開の予想の結果（P）を足す。** 7つの区切りで、木曜は P を足すと確率の誤差が小さくなり、オッズのある前日・当日は小さくならなかった（[15-decisions.md の 13](15-decisions.md#13-展開の予想の結果を特徴量に足すか)）。木曜に予測するには、予想「展開から着順を予想」の木曜のモデル（`reports/展開から着順を予想/models/`）が要る。
- まとまり L（騎手・調教師・血統の市場に対する成績）の4個は、今の材料（当日）で使う。木曜と前日の馬の力の材料には、騎手・調教師・父・母父の通算と直近の成績が入っている（[09-features.md の M](09-features.md#m-馬の力の材料202個木曜前日のモデル)）。
- N（券種ごとのオッズから見た支持）には、予想する時点の全券種の締め切り前のオッズ（jvdata-store の速報オッズ `0B30`）が要る。取り込んでいないレースは、N を使わないモデルで予測する（[06-flowchart.md の図3](06-flowchart.md#図3-当日のモデルの選び方)）。
- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書いてある。時点のクラスは、時点の前後を答えるだけである。
- 前日の馬場状態は、前日発表の値を使う。学習データの馬場状態は発走時点の確定の値なので、当日に馬場が変わると少しずれる。前日発表の値は速報でしか提供されず（提供期間は1週間）、過去の分を学習データに入れられないためである。
- 木曜の出走頭数は、出走馬名表の頭数である。あとで取消が出ると変わる。

## 予測のときのオッズの与え方

オッズは、レースの前には確定しない（確定オッズは、発売の締め切り後に決まる）。そのため、予測のときは、次の順で単勝オッズを決める。判断の手順は [06-flowchart.md](06-flowchart.md#図2-予測に使うオッズの決め方) を参照。

| 順 | オッズの元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--odds 馬番:オッズ` で渡した単勝オッズ | 前日・当日。利用者が JRA の発表や投票サイトで見た単勝オッズを、そのまま渡す |
| 2 | 元DB の締め切り前の単勝オッズ（時系列オッズのいちばん新しい断面） | 前日の夜（前日発売のあと）と当日。予測の前に jvdata-store で `uv run jvstore realtime --date <開催日>` を実行して、速報オッズ（`0B31`）を `o1` に取り込んでおく。1日ぶんで1分もかからない |
| 3 | 元DB の出走の行に入っている単勝オッズ | **終わったレースだけ**（確定オッズ）。これから走るレースでは空なので、止めて `--odds` を案内する |

3番目は、**終わったレースで「この予想が当たっていたか」を確かめるためにある。** 走る前の予測では、1 か 2 でしかオッズが分からない。

```powershell
uv run python -m yosou.form_aptitude_top3 predict 2026092706040511 --timing 当日 --odds 3:2.4 7:5.1 12:38
uv run python -m yosou.form_aptitude_top3 predict 2025052506050411 --timing 当日
```

（1行目は、これから走るレースの出走馬について、3着以内に入る確率を出すコマンド。`--odds` は「馬番:オッズ」の組を並べる。コンマ区切りで `--odds 3:2.4,7:5.1` とも書ける。2行目は、終わったレースを確定オッズで予測し直すコマンド）

- 全頭ぶん渡すのがよい。渡されなかった馬番は、オッズが欠損値のまま予測され、人気順位とオッズから見た勝率も、渡された馬だけで計算される。
- 学習データの単勝オッズは確定オッズである。渡したオッズや締め切り前のオッズは、確定オッズと少しずれる。当日の締め切り直前に出し直すと、ずれは小さくなる。このずれの扱いは [11-leak-prevention.md](11-leak-prevention.md#決まり) の 5 を参照。
- 木曜はオッズを使わないので、`--odds` は要らない（渡しても使われない）。

## 時点ごとにモデルを分ける理由

- 1つのモデルで済ませると、木曜の予測では、学習のときに値が入っていた「馬体重」などを欠損値で渡すことになる。学習と予測でデータの様子がずれ、予測確率が狂う。
- 時点ごとに、その時点で分かる特徴量だけで学習すれば、学習と予測で同じ列がそろう。
- 学習データは材料ごとに1つ作り（馬の力の材料と今の材料）、同じ材料の時点ではモデルに渡す列だけを変える（[08-training-data.md の「2. 列の種類」](08-training-data.md#2-列の種類)）。
