# 01 近走と適性から3着以内を予想する: 概要

**近走の内容と適性と、市場の評価（単勝オッズ）から、レースに出る1頭ずつについて「3着以内に入る確率」と「1着になる確率」を出す予想である。** 2つの確率は、同じ学習データから別々に学んだモデルが出す（[10-target.md](10-target.md)）。3着以内の確率は複勝の期待値と ○▲△・軸に、1着の確率は単勝の期待値と ◎ に使う。
適性とは、そのコース・距離・馬場に向いているかどうかで、同じ条件での過去の成績・持ち時計・血統から見る。
市場の評価とは、馬券を買う人たち全体がその馬をどう見ているかで、単勝オッズから見る（前日と当日だけ。木曜はまだオッズが無い）。
**JRA-VAN のマイニング予想は使わない。**

- 作り方: 機械学習の二値分類。LightGBM と CatBoost の2つのモデルで予測確率を出し、平均する（アンサンブル）。
- 予測する時点: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つのどれでも出せる。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（[07-prediction-timing.md](07-prediction-timing.md)）。木曜と前日は馬の力の材料（M）、当日は今の材料に券種ごとのオッズから見た支持（N）を足して学ぶ。
- データの元: JRA-VAN Data Lab. の中央競馬のデータ（jvdata-store が DuckDB に貯めたもの）。
- 用語の意味: [02-glossary.md](02-glossary.md) を参照。
- 状態: 決めてほしいことは決まり（[15-decisions.md](15-decisions.md)）、プログラムも作った（`src/yosou/form_aptitude_top3/`。クラスとフォルダは [04-classes.md](04-classes.md)）。ほかの予想でも使う部品は `src/yosou/shared/` に置き、この予想のパッケージには、この予想だけの決めごとを置く。

## 1頭の例

架空の1頭を当日に予測する場合で、モデルに何を渡して何が返ってくるかを示す。

> - **レース**: 2025年5月、東京・芝1600m・良、オープン、16頭立て
> - **馬**: 7枠14番、3歳の牝馬、斤量 55kg、馬体重 468kg（前走から +4）
> - **人**: 騎手A（前走から継続）、調教師B
> - **前走**: 3着、勝ち馬と 0.2秒差、上がり3F はこのレースの出走馬の中で 2番目に速い、35日ぶり
> - **近5走**: 平均 4.2着、最高は 1着、推定脚質は差し
> - **通算**: 8戦1勝、3着以内が 4回。東京・芝1600m は 1戦して 3着以内が 1回
> - **調教**: 直近は坂路で 4ハロン 52.8秒、ラスト1ハロン 12.3秒。14日以内に 3本
> - **血統**: 父A、母の父C。父Aの産駒は近1年で 3着以内が 31%（芝では 34%）、母父Cの産駒は 27%
> - **市場の評価**: 単勝 6.8倍で、このレースの 2番人気。オッズから見た勝率は 0.13
> - **市場に対する成績**: 騎手Aの市場に対する超過3着以内率は 0.012（近1年、オッズの期待より少し多く3着以内に来ている）
>
> → モデルの予測確率: **3着以内に入る確率 0.34**、**1着になる確率 0.14**（単勝の期待値 = 0.14 × 6.8 = 0.95）

## 使うデータ

時点によって材料を使い分ける（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量) を参照）。当日は 79個の特徴量（今の材料）を 11 のまとまり（A〜J と L）に分けて使い、券種ごとのオッズから見た支持（N）の6個と、馬の力の材料（M）のうち今の材料と名前の重ならない 200個を足した 285個で学ぶ。木曜と前日は、馬の力の材料（M）の 202個のうち、その時点で分かるものと対戦レーティング（O）の7個（前日は J の4個も）で学ぶ。木曜は、さらに展開の予想の結果（P）の 20個を足す（[15-decisions.md の 12・13](15-decisions.md#13-展開の予想の結果を特徴量に足すか)）。記号の K は、穴馬・人気馬の予想だけが使うまとまりなので、この予想には無い。一覧は [09-features.md](09-features.md) を参照。

| まとまり | 何が分かるか | 特徴量の例 |
|---|---|---|
| A. レースの条件 | どんなレースか | 競馬場、芝ダ、距離、馬場状態、クラス、頭数 |
| B. 馬のこと | 今日の馬の条件と状態 | 馬齢、性別、枠番、斤量、馬体重とその増減 |
| C. 騎手と調教師 | 誰が乗り、誰が育てたか | 騎手、乗り替わり、騎手の近1年の3着以内の割合 |
| D. 前走 | 前のレースでどうだったか | 着順、着差、上がり3F、前走からの日数、距離の変更 |
| E. 近走のまとめ | 最近の調子と通算の成績 | 近5走の平均着順・平均着差、推定脚質、通算の3着以内の数 |
| F. この条件での経験 | 同じコース・距離・馬場で走れるか | 同じ距離帯・馬場状態での通算の3着以内の数、持ち時計の順位 |
| G. 同じレースの馬との比較 | このメンバーの中で強いか | 近5走の平均着差のレース内順位 |
| H. 血統 | どんな血か、その血統の産駒が近1年でどれだけ走っているか | 父、父の父、母の父、父の産駒の近1年の3着以内の割合 |
| I. 調教 | 仕上がり | 坂路・ウッドの直近の4ハロンとラスト1ハロン |
| J. 市場の評価 | 馬券を買う人たち全体が、この馬をどう見ているか（前日・当日だけ） | 単勝オッズ、人気順位、オッズから見た勝率 |
| L. 騎手・調教師・血統の市場に対する成績 | 騎手・調教師・血統が、オッズの期待より3着以内に来ているか（過去のレースのオッズだけを使う） | 騎手の市場に対する超過3着以内率 |
| M. 馬の力の材料（全部の時点） | スピード指数・過去走の位置取りと相手の強さ・人と馬主と生産者と血統の成績・調教・セリの価格（研究「馬の力と展開でオッズに勝つ」の材料） | 指数_条件の重み、騎手_勝率、坂路_4F最速14日 |
| N. 券種ごとのオッズから見た支持（当日） | 3連単・馬連などの人が、単勝の人よりこの馬を高く見ているか | 3連複から見た3着以内率と単勝の比（log） |
| O. 対戦レーティング（木曜・前日） | 同じレースを走った馬どうしの勝ち負けから見た強さ | 対戦レーティング、そのレース内順位 |
| P. 展開の予想の結果（木曜） | 予想「展開から着順を予想」が見た、この馬の前半・後半の位置取りとペース | 展開の予想_先頭の確率、展開の予想_4コーナーの位置 |

使わないデータとその理由は、[09-features.md](09-features.md) の「使わない特徴量」と [11-leak-prevention.md](11-leak-prevention.md) を参照。

## 図の使い分け

この設計書では、図を2種類だけ使い、次の方針で使い分ける。

| 図 | 表すこと | 図の1つの部品が、コードの何に当たるか | 例 |
|---|---|---|---|
| シーケンス図 | 利用者・jvdata-store・元DB と、この AI のクラスの間で、どのメソッドを、どの順に呼び、何を渡して何が返るか | 実線の矢印1本 = 呼び出し1回（クラスなら public メソッドを1回、元DB なら SQL を1回、ライブラリのモデルなら `fit` か `predict_proba` を1回）。点線の矢印1本 = その戻り値 | `PredictionWorkflow.run()` が `DatasetBuilder.build_prediction_data()` を呼び、予測用データを受け取る |
| フローチャート | 1つの public メソッドの中で、if 文によってどちらに進むか | 図1枚 = public メソッド1つの中。ひし形1つ = if 文1つ（引数のチェックのような、どのメソッドにもある if 文は描かない） | `RunnerSelector.training_samples()` が、事実表の1行ごとに「障害レースか」「出走したか」「学習データの始まり以降か」で、学習データに入れるかを決める |

public メソッドの意味は [02-glossary.md](02-glossary.md) を、クラスの一覧は [04-classes.md](04-classes.md) を参照。

- **迷ったときの決め方:** 見せたいのが「どのクラスがどのメソッドを呼び、何を渡すか」ならシーケンス図にする。「メソッドの中の if 文で、どちらに進むか」ならフローチャートにする。
- **同じ手順を両方の図で描かない。** シーケンス図の中で if 文の判断が要るところは、自分に戻る矢印に「（〇〇のフローチャート）」と書いて参照する。
- **分かれ道の無い一続きの作業は、フローチャートにしない。** シーケンス図の、自分に戻る矢印で書く。
- **置き場所:** 両方のモデルに共通の図は、シーケンス図を [05-sequence.md](05-sequence.md)、フローチャートを [06-flowchart.md](06-flowchart.md) に置く。モデルごとの図は [12-lightgbm.md](12-lightgbm.md)・[13-catboost.md](13-catboost.md) に置く。
- **見方:** 図は Mermaid で書いてある。GitHub ではそのまま図になる。VS Code のプレビューで見るには、拡張機能「Markdown Preview Mermaid Support」（`bierner.markdown-mermaid`）が要る。
