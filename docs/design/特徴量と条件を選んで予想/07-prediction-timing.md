# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。時点ごとに、どの特徴量を選べるか。予測のときに、人気とオッズをどうやって渡すか。

**結論: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点から、設定ファイルごとに1つを選ぶ。3つの時点で予測したいときは、時点だけを変えた設定を3つ作って、それぞれ学習する。その時点で分からない特徴量を選ぶと、学習を始める前に止める（自動では外さない）。人気とオッズは、ほかの予想と同じく `--pops`・`--odds` か元DB の締め切り前のオッズから決める。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。時点ごとに分かることは、手本と同じである（[手本の 07 の「時点ごとに分かること」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに分かること)）。

## 時点ごとに分かること

| 時点 | 手本に加えて分かること | 選べる特徴量の数 |
|---|---|---|
| 木曜（出走馬名表） | 利用者が見立てた人気（`--pops 馬名:人気`） | 66 |
| 前日（出馬表） | 枠番・馬番、前日発表の馬場状態、前日発売の単勝オッズ | 76 |
| 当日（馬体重の発表のあと） | 馬体重、締め切り前の単勝オッズ、締め切り前の券種オッズ（jvdata-store で取り込んだとき） | 90 |

## 時点ごとに使う特徴量

**設定の時点で分からない特徴量は、選べない。** 特徴量テキストに書くと、設定を読む段で、行番号付きで止める（[06-flowchart.md](06-flowchart.md#図2-特徴量を計算する順番の決め方)）。依存項目と、条件に使う特徴量にも同じ確かめを当てる。

| 時点 | 選べない特徴量（[09-features.md](09-features.md) の 90個のうち） |
|---|---|
| 木曜 | 前日から分かる10個（馬場状態、枠番、馬番、同じ芝ダ・馬場状態での通算の出走数・3着以内の数、持ち時計のレース内順位（コース単位・距離単位）、単勝オッズ、オッズから見た勝率、オッズから見た3着以内率）と、当日から分かる14個 |
| 前日 | 当日から分かる14個（馬体重、馬体重の増減、券種オッズの12個） |
| 当日 | なし |

- **自動で外さずに止める理由。** 選んだ10個が黙って8個になると、利用者の思ったモデルにならない。何を選んだかは利用者が決めることなので、合わないものを示して、書き直してもらう（[15-decisions.md](15-decisions.md#4-時点に合わない特徴量を自動で外すか)）。
- **オッズの基準（`odds_baseline: true`）は、前日・当日だけで使える。** オッズが分かるのが前日からだからである（[12-lightgbm.md](12-lightgbm.md#1-学習データの渡し方)）。
- 券種オッズの12個は当日だけである。前日発売のあるレースでも、全券種がそろうのは当日だからである。

## 予測のときの人気とオッズの与え方

**人気とオッズを決める部品は、ほかの予想と共通である**（`PopularityApplier`・`OddsResolver`。[人気馬の 07 の「予測のときの人気の与え方」](../人気馬が4着以下になるかを予想/07-prediction-timing.md#予測のときの人気の与え方)）。この予想での使い方は次のとおり。

| 順 | 人気の元 | 使うとき |
|---|---|---|
| 1 | 利用者が `--pops` で渡した人気（木曜は `馬名:人気`、前日・当日は `馬番:人気`） | 3つの時点すべて。木曜は、これしか使えない |
| 2 | 利用者が `--odds 馬番:倍率` で渡した単勝オッズの順 | 前日・当日 |
| 3 | 元DB の締め切り前の単勝オッズの順 | 前日・当日。jvdata-store の `jvstore realtime --date <開催日>` で取り込んでおく |
| 4 | 元DB の出走の行の単勝人気 | 終わったレースだけ（確定単勝人気） |

```powershell
uv run python -m yosou.custom_binary predict 架空レースA --models reports/custom_binary/架空の設定 --pops 3:1 7:2 11:3 …（全頭ぶん）
uv run python -m yosou.custom_binary predict 架空レースA --models reports/custom_binary/架空の設定 --odds 3:2.4 7:4.1 …（全頭ぶん）
```

（1行目は、見た人気を馬番で渡して予測するコマンド。2行目は、見た単勝オッズを渡して、オッズの順から人気を作るコマンド）

- 人気範囲を指定したモデルで、人気の分からない馬が1頭でもいれば止める（[06-flowchart.md](06-flowchart.md#図1-学習データに入れる行の選び方)）。人気範囲を指定しないモデルでは、人気は要らない（特徴量「人気順位」を選んだときを除く）。
- 選んだ特徴量が単勝オッズや券種オッズを使うのに、元DB に無ければ止める。券種オッズは、jvdata-store の `jvstore realtime`（`realtime_today.bat`）が単勝・複勝と一緒に取り込む（[05-sequence.md](05-sequence.md#今は無くこれから作るところ)）。
- 渡した人気・オッズと、締め切り後に確定する値は、ずれることがある。学習は確定の値で行っている（[11-leak-prevention.md](11-leak-prevention.md#決まり)）。

## 時点ごとにモデルを分ける理由

手本と同じ理由である（[手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由)）。この予想では、手本のように1回の学習で3つの時点のモデルを作るのではなく、**設定ファイル1つにつき1つの時点**にした。設定ごとに選ぶ特徴量が違い、時点ごとに選べる特徴量も違うので、1つの特徴量テキストを3つの時点で使い回せないためである（[15-decisions.md](15-decisions.md#3-時点を設定ごとに1つにするか)）。
