# 16 当たり具合と回収率の測り方

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合と回収率をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。どの買い方を「使える」と判断するか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 手本と同じ既定（学習 2021年8月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜）。設定ファイルの `training` で変えられる |
| 2. 評価指標 | 当たり具合（件数・正例率・ログ損失・Brier・AUC、人気ごと）と、回収率（対象の全頭・各レースの確率1位・期待値の線ごとの、単勝と複勝の的中率・回収率・回収率の下限） |
| 3. 「使える」の判断 | 期待値の線は検証期間で選び、テスト期間で1回だけ確かめる。テスト期間で回収率 100% 以上・点数 300 以上・回収率の下限 100% 以上なら「使える」とする。線の数字は設計書に書かない |

用語の意味は [02-glossary.md](02-glossary.md) を参照。指標は `evaluation.py` が計算する（[04-classes.md](04-classes.md#3-この予想だけのクラスの一覧)）。

## 1. 期間の分け方

| 区分 | 何に使うか | 既定 |
|---|---|---|
| ウォームアップ | 過去走の特徴量を計算するためだけに読む | 2020年1月〜2021年7月 |
| 学習 | モデルの `fit` に渡す。複勝の想定払戻倍率の帯ごとの倍率も、ここの払戻から求める | 2021年8月〜2025年6月 |
| 検証 | 早期終了の判断。当たり具合と回収率を `train` の結果に出す。期待値の線や設定を選ぶのはここで行う | 2025年7〜12月 |
| テスト | `evaluate` で最後に1回だけ確かめる。直す判断には使わない | 2026年1月〜 |

- 時期で分ける（レースを混ぜてくじで分けない）。理由は手本と同じ（[手本の 08 の「4. 期間の指定」](../近走と適性から3着以内を予想/08-training-data.md#4-期間の指定)）。
- **検証期間は早期終了にも使うので、検証の成績はやや良く出る。** `train` の結果の表に、この注意を添える。
- 期間の書き方は [08-training-data.md の「4. 期間の指定」](08-training-data.md#4-期間の指定) を参照。

## 2. 評価指標

### 当たり具合

| 指標 | 意味 | 良い向き |
|---|---|---|
| 件数・正例率 | 対象の馬の数と、目的変数が 1 だった割合 | ― |
| ログ損失 | 確率が正解から外れた大きさ | 小さいほど良い |
| Brier | 確率と正解（0 か 1）の差の2乗の平均 | 小さいほど良い |
| AUC | 1 の馬に、0 の馬より高い確率を付けられた割合 | 大きいほど良い（0.5 はでたらめ） |

LightGBM・CatBoost・平均のそれぞれで全体の値を出し、平均については確定単勝人気ごとの値も出す。正解が片方しか無い人気では AUC を計算できないので、空欄にして理由を書く。

### 回収率

1点100円で、次の買い方をしたときの単勝・複勝の的中率・回収率・回収率の下限を出す。

| 買い方 | 買う馬 | 何が分かるか |
|---|---|---|
| 対象の全頭（モデルなし） | 人気範囲と条件に当てはまる馬を全部 | 条件そのものの良し悪し（モデルを使わないルールとしての回収率） |
| 各レースで確率1位 | 対象の馬のうち、確率がいちばん高い1頭 | 1頭選ぶ使い方で儲かるか |
| 期待値 1.0・1.1・1.2・1.3・1.5・2.0 以上 | 期待値がその値以上の馬を全部 | 期待値で買う使い方で儲かるか |

**期待値の出し方。**

| 目的 | 期待値 |
|---|---|
| 勝利 | 確率 × 確定の単勝オッズ |
| 馬券内 | 3着以内の確率 × 複勝の想定払戻倍率 |
| 馬券外 | （1 − 確率）× 複勝の想定払戻倍率 |

- **複勝の想定払戻倍率 = 確定の最低オッズ × オッズ帯ごとの倍率。** 倍率は、学習期間の当たった複勝の「払戻 ÷ 最低オッズ」の平均である（共通の `PlacePriceEstimator`）。最低オッズのままだと、期待値を低く見積もりすぎるためである。
- **3着以内の確率は、同じレースの全頭がそろっているときだけ、合計が3（7頭以下は2）になるようにそろえ直す。** 1頭ずつ学習した確率は、足しても3にならないためである。人気範囲や馬の条件で一部の馬だけになったレースは、合計の基準が無いので、そのまま使う。
- **回収率の下限。** 開催日を丸ごと取り直して回収率を1000回計算し、その下側 5% の値を出す（乱数の種を固定する）。同じ日のレースは結果が似るので、1頭ずつではなく開催日ごとに取り直す。
- 払戻は実際の払戻なので、複勝が7頭以下で2着までしか付かないことも、同着も、そのまま入る。
- **確定オッズで計算した回収率は、上限の見積もりである**（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 8）。結果の表に、この注意を添える。

## 3. 「使える」の判断

- 期待値の線は、**検証期間の結果だけ**で選ぶ。点数が少なすぎる線（検証期間で 100点未満）は選ばない。
- 選んだ線を、テスト期間で1回だけ確かめる。テスト期間を見てから線を動かさない（動かすと、テストの結果に合わせたことになる）。
- **テスト期間で、回収率 100% 以上・点数 300 以上・回収率の下限 100% 以上**のすべてを満たしたら「使える」とする。回収率は 100% 以上だが、ほかを満たさないものは「参考」とし、偶然と区別できないと書く。
- 線の数字と、各設定の結果は設計書に書かず、`reports/`（Git 対象外）に置く。学習し直すたびに変わり、JV-Data から作った値だからである。
- 設定を何十通りも試すときは、たまたま良く見えるものが混ざる（多重比較）。研究「特徴量の組み合わせ探索」は、この判断の決まりで設定を比べている（`research/特徴量の組み合わせ探索/README.md`）。
