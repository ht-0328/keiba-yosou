# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの馬・どの期間の行を入れるか。人気範囲と条件で、どう絞るか。

**結論: 1サンプル = 1レースの対象の馬1頭。中央競馬の芝・ダートを走った馬のうち、設定の人気範囲と条件のすべてに当てはまる馬を行にする。絞るのは、全頭で特徴量を作ったあとにする。期間の既定は手本と同じ（学習 2021年8月から、ウォームアップ 2020年から）で、設定ファイルで変えられる。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

[01-overview.md の「1頭の例」](01-overview.md#1頭の例) の設定（6〜10番人気、芝で距離 1600m 以下、特徴量 10個）なら、学習データは次の形になる。

| レースID | 馬番 | 競馬場 | 距離 | 前走の着順 | …（選んだ特徴量はあと 6個） | 3連複から見た3着以内率と単勝の差 | 目的変数: 馬券内 | 確定着順（渡さない） | 複勝の払戻（渡さない） |
|---|---|---|---|---|---|---|---|---|---|
| 架空レースA | 14 | 東京 | 1600 | 3 | … | +0.37 | 1 | 3 | 780 |
| 架空レースA | 2 | 東京 | 1600 | 9 | … | −0.12 | 0 | 11 | 0 |
| 架空レースB | 5 | 中山 | 1200 | （欠損値） | … | +0.05 | 0 | 6 | 0 |

- 列の数は、特徴量テキストの行数と同じである（10行なら 10列）。条件に使った特徴量（この例では「芝ダ」）は、特徴量テキストに書いていなければ列にならない。
- 欠損値は 0 で埋めず、欠損値のまま持つ（手本と同じ）。

## 2. 列の種類

| 種類 | 列 | モデルに渡すか |
|---|---|---|
| ID 列 | レースID、開催日、馬ID、馬番、馬名 | 渡さない |
| 特徴量 | 特徴量テキストに書いたもの（[09-features.md](09-features.md)） | `fit` の `X` として渡す |
| 目的変数 | 設定で選んだ1つ（馬券内・馬券外・勝利。[10-target.md](10-target.md)） | `fit` の `y` として渡す |
| オッズの基準 | `odds_baseline: true` のときだけ。単勝オッズから見た確率のロジット | LightGBM の `init_score`、CatBoost の `baseline` として渡す（[12-lightgbm.md](12-lightgbm.md#1-学習データの渡し方)） |
| 評価用の列 | 確定着順、確定の単勝人気、確定の単勝オッズ、単勝の払戻、複勝の払戻、複勝オッズ（最低）、出走頭数 | 渡さない。回収率の計算に使う（[16-evaluation.md](16-evaluation.md)） |

**人気は、行を選ぶのに使うが、特徴量テキストに「人気順位」を書かない限り、モデルには渡さない。** 人気範囲で絞っただけでモデルに人気が入ると、利用者の選んだ特徴量のモデルにならないためである。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 中央競馬の平地（芝とダート）。障害は入れない | 手本と同じ |
| 取消・除外 | サンプルにしない | 走っていない馬には目的変数が無い |
| 結果の無い行 | 正常に走ったのに着順が無い行は入れない。競走中止・失格は入れる | 確定前のレースの行を負例にしない（[10-target.md](10-target.md#作り方)） |
| 人気範囲 | 設定の `popularity.min`〜`max`（両端を含む）。省略すれば全人気。片方だけなら、その側だけを区切る | 利用者が選ぶ |
| 条件 | 設定の `conditions` のすべてに当てはまる馬。値が欠けている馬は当てはまらない | 利用者が選ぶ |
| 期間 | 学習データの始まりから（下の「4. 期間の指定」） | 手本と同じ |

**条件の書き方。** 数値の特徴量は `{min: …, max: …}`（両端を含む。片方だけでもよい）、カテゴリの特徴量は値1つか値のリストで書く。

```yaml
conditions:
  芝ダ: 芝                 # 芝の馬だけ
  距離: {max: 1400}        # 1400m 以下
  競馬場: [東京, 中山]     # 東京か中山
  馬体重: {max: 440}       # 440kg 以下（当日の設定だけで使える）
```

- 条件に使える特徴量は、特徴量テキストと同じく、登録された 90個である。設定の時点で分からない特徴量は使えない（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。
- 条件は学習・評価・予測のすべてに当てる。予測するレースの馬が条件に当てはまらなければ「対象なし」になる。

**全頭で特徴量を作ってから絞る。** 同じレースの馬との比較（まとまり G の順位や平均との差）、単勝との差、オッズの基準は、同じレースの全頭の値から作る。先に人気範囲や条件で絞ると、同じ馬でも、絞り方によって特徴量の値が変わってしまう。そのため、特徴量を全頭で作ったあとに絞る（[06-flowchart.md](06-flowchart.md#図1-学習データに入れる行の選び方)）。

**学習データの行数は、設定で大きく変わる。** 全人気・条件なしなら、手本と同じ約 23.6 万行である。人気範囲や条件で絞るほど少なくなる。学習データか検証データが空のとき、または目的変数が片方の値だけのときは、学習を始める前に止め、期間・人気範囲・条件を広げるよう案内する。

## 4. 期間の指定

期間の区切り方（ウォームアップ・学習・検証・テストの4つの日）と既定の値は、手本と同じである（[手本の 08 の「4. 期間の指定」](../近走と適性から3着以内を予想/08-training-data.md#4-期間の指定)）。この予想では、コマンドの引数ではなく設定ファイルの `training` に書く。

```yaml
training:
  warmup_from: 2020-01-01
  train_from: 2021-08-01
  valid_from: 2025-07-01
  test_from: 2026-01-01
```

- 省略すれば既定の値になる。`train_from` だけ変えて `warmup_from` を省略すると、ウォームアップは学習の始まりの前の年の1月1日からになる。
- 調教の特徴量を選ばない設定なら、2017年からのように早く始めてもよい（調教の記録がそろうのが 2021年8月からであることが、既定の理由だからである。[手本の 08 の「既定を 2021年8月からにした理由」](../近走と適性から3着以内を予想/08-training-data.md#既定を-2021年8月からにした理由)）。
