# 09 特徴量

**この文書で決めること:** 予測の手がかり（特徴量）に、何を使えるか。利用者はどう選ぶか。特徴量をどう足すか。

**結論: 登録された 90個の中から、利用者が特徴量テキストで選ぶ。90個は、手本の A〜I（71個）、人気の履歴 J（4個）、単勝オッズから見た評価 K（3個）、券種オッズ（12個）である。特徴量は、決まったインターフェースを守るクラスを1つ書き、登録の一覧に1行足せば、選べるようになる。学習やコマンドを直す必要はない。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 特徴量の選び方

特徴量テキストに、正式な名前を1行に1つ書く。`features` コマンドで、選べる名前・説明・型・利用可能な時点・依存項目の一覧が出る。

```text
# 1行1項目。空行と # から始まる行は数えない。
競馬場
距離
前走の着順
3連複から見た3着以内率と単勝の差
```

（特徴量テキストの例。この例では、モデルの入力は4列になる）

| 決まり | 理由 |
|---|---|
| 書いた順番のまま、書いた数だけをモデルに渡す。10行なら 10列 | 利用者が選んだとおりのモデルにする |
| 重複・未登録の名前・空の一覧は、行番号付きでエラーにする | 書き間違いに気づけるようにする |
| 設定の時点で分からない特徴量はエラーにする（自動で外さない） | [07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量) |
| 依存項目は、書かなくても計算するが、モデルには渡さない | 「単勝との差」だけを入れたいときに、元の確率を入れずに済む |
| UTF-8（BOM 付きでもよい）で保存する | Windows のメモ帳で保存しても読めるようにする |

## 券種オッズ（12個）

**3連単・馬単・3連複・馬連・ワイド・複勝のオッズから見た、馬ごとの確率と、その単勝オッズとの差である。** 当日から分かる。

| 特徴量 | 意味 | 例 |
|---|---|---|
| 3連単から見た勝率 | 3連単の全買い目の 1/オッズ をレース内で合計1にそろえ、この馬が1着の買い目を足した値 | 0.031 |
| 馬単から見た勝率 | 同じ計算を馬単で | 0.028 |
| 3連複から見た3着以内率 | この馬が入った 3連複の買い目を足した値。レース内の合計は3 | 0.13 |
| 馬連から見た2着以内率 | この馬が入った馬連の買い目を足した値。レース内の合計は2 | 0.07 |
| ワイドから見た3着以内率 | この馬が入ったワイドの買い目を足して 1.5倍した値。レース内の合計は3 | 0.12 |
| 複勝から見た3着以内率 | 複勝の 1/オッズ をそろえて 3倍した値。レース内の合計は3 | 0.10 |
| 〜と単勝の差（6個） | log（上の確率）− log（単勝オッズから見た同じ意味の確率）。勝率どうし・2着以内率どうし・3着以内率どうしで比べる | +0.37 |

- **なぜ使うか。** JRA では、券種ごとに投票の集まり（プール）が別で、3連単・3連複には単勝より大きな金が入る。大きなプールのほうが多くの人の判断を含むので、単勝と食い違うとき、単勝・複勝が見誤っている手がかりになる（研究「回収率100超」の [03-実験と結果](../../../research/回収率100超/docs/03-実験と結果.md)）。
- **ワイドを 1.5倍、複勝を 3倍にする理由。** ワイドは3組が当たり、1頭は2組に入るので、買い目の確率の和を 3 ÷ 2 倍するとその馬の3着以内率になる。複勝は3頭が当たるので3倍する。こうすると名前どおりの確率になり、単勝から見た確率と比べられる。
- **オッズは、確定の断面を使う。** 終わったレースは確定オッズ、これから走るレースは締め切り前のいちばん新しい断面である（[11-leak-prevention.md](11-leak-prevention.md#決まり)）。
- 例の値は、[01-overview.md の「1頭の例」](01-overview.md#1頭の例) の架空の馬（8番人気）のもの。

## 特徴量を足す仕組み

**特徴量1個 = クラス1つ。** 次の決まり（インターフェース `FeatureDefinition`）を守るクラスを書き、`feature/registrations.py` の一覧に1行足す。

| 持つもの | 意味 | 例（券種オッズの単勝との差） |
|---|---|---|
| `name` | 正式な名前（特徴量テキストに書く名前） | 3連複から見た3着以内率と単勝の差 |
| `description` | 説明（`features` コマンドに出る） | log(…) − log(…) |
| `kind` | 数値かカテゴリか | 数値 |
| `known_from` | 利用可能な時点 | 当日 |
| `dependencies` | 依存項目の名前 | 3連複から見た3着以内率 |
| `sources`（省略できる） | 追加の元データの名前 | （なし。依存項目のほうが「券種オッズ」を持つ） |
| `compute(記録, 依存項目の列)` | 出走の行と同じ並び・同じ index の1列を返す | log の差の列 |

- 計算は、同じレースの全頭がそろった出走の行で行う。絞るのは、そのあとである。
- 依存の順に1回ずつ計算する。名前の重複・未登録の依存先・循環・時点に合わない依存・行の並びの食い違いは、登録したときか計算したときに止める（[06-flowchart.md](06-flowchart.md#図2-特徴量を計算する順番の決め方)）。
- 元DB から新しいデータを読むなら、`extra_data/` に読むクラスを作って `SOURCES` に登録し、特徴量の `sources` にその名前を書く。その特徴量を選んだときだけ読む（[04-classes.md](04-classes.md#3-この予想だけのクラスの一覧)）。
- 過去走を使う特徴量は、そのレースより前の記録だけから計算する。`known_from` は時点を表すだけで、計算の中の未来の情報を防ぐ仕組みではない（[11-leak-prevention.md](11-leak-prevention.md#決まり)）。
- 特徴量の型・時点・依存項目を変えたら、保存したモデルは読み込めなくなる（学習し直す。[12-lightgbm.md](12-lightgbm.md#6-保存)）。

## カテゴリ特徴量の渡し方

90個のうち 21個がカテゴリ特徴量で、手本と同じ顔ぶれ（競馬場・騎手・父など）である。券種オッズの12個はすべて数値である。モデルに渡す形はモデルごとに違う（[12-lightgbm.md](12-lightgbm.md#1-学習データの渡し方)・[13-catboost.md](13-catboost.md#1-学習データの渡し方)）。

## 使うデータの期間

方針は手本と同じで、元DB に今入っている期間を、特徴量を外す理由にしない（[手本の 09 の「使うデータの期間」](../近走と適性から3着以内を予想/09-features.md#使うデータの期間)）。券種オッズは、元DB に 2016年から入っている確定オッズを使う。2017〜2025年は、平地の全出走で欠けが無いことを確かめた。直近の週は、jvdata-store の取り込みが済むまで欠けることがある。

## 使わない特徴量

| 特徴量 | 使わない理由 |
|---|---|
| JRA-VAN のデータマイニング予想 | 手本と同じ理由（モデルがまねるだけになりやすい） |
| 3連単の着順ごとの確率（2着・3着）と票数の配分 | 研究「回収率100超」では効いたが、今の12個で足りるかを見てから足す（[15-decisions.md](15-decisions.md#7-券種オッズの特徴量をどこまで入れるか)） |
| そのレースの結果 | リークになるので候補にもしない（[11-leak-prevention.md](11-leak-prevention.md#決まり)） |
