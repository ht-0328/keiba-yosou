# 12 LightGBM で学習・予測するための設計

**この文書で決めること:** 07〜10 で決めた学習データ（特徴量と目的変数）を、LightGBM で学習・予測するために、LightGBM だけに必要なことを決める。**節の番号と題名は、手本の 12 とそろえてある。**

| 決めること | 結論 |
|---|---|
| 1. 学習データの渡し方 | 手本と同じ。選んだ特徴量だけを渡す。`odds_baseline: true` なら、オッズの基準を `init_score` に渡す |
| 2. ハイパーパラメータの初期値 | 手本と同じ値から始める。設定ファイルの `lightgbm` で変えられる |
| 3. カテゴリ特徴量の値の変え方 | 手本と同じ |
| 4.〜6. 学習・予測・保存の手順 | 設定1つにつき、選んだ1つの時点のモデルを1つ学習する。保存先は `reports/custom_binary/<設定の name>/` |

- 用語の意味は [02-glossary.md](02-glossary.md) を参照。
- 学習データ・特徴量・目的変数は CatBoost と共通で、[08-training-data.md](08-training-data.md)・[09-features.md](09-features.md)・[10-target.md](10-target.md) を参照。

- LightGBM の使い方の基本は [手本の 03 の「4. LightGBM の使い方」](../近走と適性から3着以内を予想/03-library-basics.md#4-lightgbm-の使い方) を参照。

## 1. 学習データの渡し方

**列ごとの渡し方は手本と同じである**（数値はそのまま、カテゴリは `category` 型、出走の少ない値は「その他」にまとめる、ID 列と評価用の列は渡さない）。[手本の 12 の「1. 学習データの渡し方」](../近走と適性から3着以内を予想/12-lightgbm.md#1-学習データの渡し方) を参照。渡すのは、特徴量テキストに書いた列だけで、依存項目と条件の列は渡さない。

**オッズの基準（`odds_baseline: true`）のとき。** 単勝オッズから見た確率のロジットを `init_score` に渡す。LightGBM は、この値を出発点にして、特徴量からの上げ下げだけを学ぶ。既存の予想モデルと同じ共通の `LightGbmModel` の仕組みで、予測のときも同じ基準を足してから確率に戻す。

| 目的 | 基準（単勝オッズから見た確率） | 例（架空の 8番人気の馬） |
|---|---|---|
| 勝利 | 勝率（1/オッズ をレース内で合計1にそろえた値） | 0.025 → ロジット −3.66 |
| 馬券内 | 3着以内率（勝率から Harville の式で出した値） | 0.09 → ロジット −2.31 |
| 馬券外 | 1 − 3着以内率 | 0.91 → ロジット +2.31 |

- **なぜ基準を使うか。** 基準を使わないモデルは、大穴にも数%の確率を付けやすい。オッズ 100倍の馬に 2% を付けると期待値が 2 になり、期待値で買うと大穴ばかり買ってしまう。基準を使うと、確率がオッズから大きく外れにくくなり、確率として使える値になる（[15-decisions.md](15-decisions.md#6-オッズを出発点にするか)）。
- 基準は、同じレースの全頭のオッズから作ってから、対象の馬に絞る（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 7）。オッズの無い馬は、頭数から見た割合（1 ÷ 頭数、3 ÷ 頭数）にする。

## 2. ハイパーパラメータの初期値

**初期値は手本と同じ値である。** 引数と意味の表は [手本の 12 の「2. ハイパーパラメータの初期値」](../近走と適性から3着以内を予想/12-lightgbm.md#2-ハイパーパラメータの初期値) を参照（`objective` は `binary`、`learning_rate` 0.05、`n_estimators` 2000、早期終了 100 回、`num_leaves` 31、`min_child_samples` 100、`subsample` 0.8、`colsample_bytree` 0.8、`random_state` 42、`min_category_count` 2000）。設定ファイルの `lightgbm` で変えられる（[14-hyperparameter-settings.md](14-hyperparameter-settings.md)）。

- `objective` は変えられない（二値分類に決まっているため）。
- 1 と 0 の数の偏りを直す設定（`is_unbalance`・`class_weight`）は使わない（[10-target.md](10-target.md#1-と-0-の数の偏り)）。
- **人気範囲や条件で絞ると、学習データが少なくなる。** 行数が数千まで減ると、`min_category_count` 2000 では騎手・父などがほとんど「その他」になる。少ない行数で学習するときは、設定ファイルで小さくする。

## 6. 保存

保存先は、Git の対象外の `reports/custom_binary/<設定の name>/` である。設定ごとにフォルダを分け、**同じ名前のフォルダがあれば上書きせずに止める。** 条件を変えたら、別の名前で学習する。

| ファイル | 中身 |
|---|---|
| `<時点>/`（例 `race_day/`） | LightGBM と CatBoost のモデルと、学習に使ったハイパーパラメータ（共通の `ModelRepository` が書く） |
| `validation.json` | 検証期間の当たり具合と回収率 |
| `test_evaluation.json` | テスト期間の当たり具合と回収率（`evaluate` を実行したとき） |
| `model.json` | 設定（特徴量の名前と順番・目的・時点・人気範囲・条件・オッズの基準・期間・ハイパーパラメータ）、特徴量の形（型・時点・依存項目）、コードの版（Git のリビジョンと、Python のソースのハッシュ）、保存形式の版、学習した日時、行数 |

- **`model.json` は最後に書く。** 途中で失敗したフォルダには `model.json` が無く、読み込まれない。
- **予測は `model.json` の設定だけを使う。** 元の設定ファイルと特徴量テキストは読まない。
- **読み込むときに、特徴量の形を今のコードと比べる。** 型・時点・依存項目が保存したときと違えば、学習し直すよう案内して止める。計算式を変えた場合は、形が同じでも検出できないので、学習し直す。
- モデルは JV-Data から作ったもので、公開しないため、Git の対象外に置く。
