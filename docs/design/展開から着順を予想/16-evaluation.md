# 16 当たり具合の測り方と採用の基準

**この文書で決めること:** 学習に使っていないデータで、7つの予想の当たり具合をどう測るか。学習・検証・テストの期間をどう分けるか。何と比べれば「当たっている」と言えるか。どうなれば使ってよいと判断するか。過去のレースで、券種ごと・年ごとの的中率と回収率をどう出すか。そのとき、どう買うか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 時期で分ける。学習も確かめも、予測する年ごとに、その年より前だけで学習し直す（7.）。①③⑥⑦ は、検証を前半（早期終了）と後半（温度・λ・80% の幅の倍率）に分ける |
| 2. 評価指標 | 予想ごとに、いちばん大事な指標を1つ決める。①はレースごとのログ損失、②③の区分は多クラスのログ損失、③の秒数は MAE。ほかの指標は補助に出す |
| 3. 比べる基準 | モデルによらない簡単な予想（全馬に同じ確率、先頭率をそろえただけのもの、今ある推定脚質、学習データの割合、基準の秒数だけ）と並べる。基準と同じなら、モデルは何も学んでいない |
| 4. 正解を作らなかったレースの確かめ | 先頭が決まらないレースなどの割合を、理由ごとに頭数・競馬場・ペースの区分・年で出し（年ごとの確かめの表6）、一部を元の記録と照らし合わせる |
| 5. 採用の基準 | 結果を見る前に決めておく（[15-decisions.md の 10](15-decisions.md#10-採用の基準)） |
| 6. 期間をずらした確かめ | 年ごとの確かめ（7.）で見る（最初の設計の「半年ずつずらした6回」を置き換えた） |
| 7. 年ごとの的中率と回収率 | 2018〜2026年の各年を、その前の年までのデータだけで学習し直したモデル（既定は当日の時点。`--timing` で前日も）で予測する（ウォークフォワード）。券種 × 年ごとに、的中率・回収率などを表にする。期待値の線と券種の配分は、確かめる年より前の年だけで選んだ場合も出す |
| 8. 券種ごとの買い方 | 着順の確率の高い順に印を付ける。「印どおりに買う」（券種ごとに決めた点数を 1点100円）と「期待値で買う」（当たる確率 × 確定オッズ が 1.0 以上の買い目を 1点100円）の2通りで測る。人気順に印を付けて同じように買った場合と比べる |

用語の意味は [02-glossary.md](02-glossary.md) を参照。当たり具合を測るクラスは [04-classes.md の「evaluation/」](04-classes.md#evaluation--当たり具合) を参照。

## 1. 期間の分け方

**学習も確かめも、年ごとに期間を分ける（7.）。** 予測する年 y のモデルは、学習が組の最初の年の1月 〜（y−1）年9月、検証が（y−1）年10〜12月で、y年のレースはそのモデルの学習に使っていない。学習（`train --year y`）で保存するモデルも、年ごとの確かめの y年のモデルと同じ期間で作る。

| 区分 | 何に使うか | y = 2026 のとき（前半の組） |
|---|---|---|
| ウォームアップ | 序盤と末脚の履歴と、前半・後半タイムの基準を数えるためだけに読む。サンプルにしない（基準は、さらに 1095日前から読む） | 2013年1〜12月 |
| 学習 | モデルの `fit` に渡す | 2015年1月〜2025年9月 |
| 検証 | 早期終了（①③⑥⑦は、その前半）と、温度・λ（①⑦）と 80% の幅の倍率（③⑥）（その後半） | 2025年10〜12月 |
| 予測する年 | 学習に使っていないレースとして、当たり具合と回収率を測る | 2026年1月〜 |

- 時期で分ける（レースを混ぜてくじで分けない）。同じ開催日のレースや、同じ馬の前後の走が学習と検証に散らばると、実際より当たって見えるためである（手本と同じ）。
- ①⑦ と③⑥ は検証を開催日の真ん中で2つに分ける。木の数と、温度（①⑦）・80% の幅の倍率（③⑥）を別のデータで決めるためである（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 10・12）。②④⑤ は温度も倍率も使わないので、検証データ全体で早期終了する。
- 最初の設計では、1つの期間（学習 2017年1月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜）で学習し、6. の「期間を半年ずらした6回」で確かめることにしていた。後半と着順の学習データには、年ごとに学習し直した前の組の予測が要るので、学習と確かめを年ごとの期間の1通りにそろえた（5. の採用の基準も、年ごとの確かめで読み替えた）。

## 2. 評価指標

年ごとの確かめ（`backtest`）の表4・表3 に、予想ごと・年ごとに出す（既定は当日の時点。`--timing 前日` で前日の時点）。どれも、その年より前だけで学習したモデルの予測で測る。**太字がいちばん大事な指標**で、採用の判断はこれで行う。

| 予想 | 指標 | 意味 | 良い向き |
|---|---|---|---|
| ① 先頭 | **レースごとのログ損失** | 各レースで、実際に先頭になった馬に付けた確率 p の `−log(p)` を、レースで平均した値 | 小さいほど良い |
| ① 先頭 | 確率1位の的中率 | 確率がいちばん高い馬が先頭だったレースの割合 | 大きいほど良い |
| ① 先頭 | 上位3頭の的中率 | 確率の高い3頭の中に先頭がいたレースの割合 | 大きいほど良い |
| ① 先頭 | 確率の帯ごとの実際の割合 | 「先頭の確率 0.2〜0.3」と出した馬が、実際に何割先頭だったか。頭数（〜10頭・11〜14頭・15頭〜）別にも出す | 出した確率に近いほど良い |
| ②・③の区分 | **多クラスのログ損失** | 3つの確率が正解から外れた大きさ（1行ずつの平均） | 小さいほど良い |
| ②・③の区分 | 正解率・マクロ F1・混同行列・クラスのずれの平均 | 年ごとの表には、正解率だけを出す（マクロ F1・混同行列などは、共通の `ClassModelEvaluator` で出せる。[荒れ具合の 16 の「2. 評価指標」](../レースの荒れ具合を4段階で予想/16-evaluation.md#2-評価指標)） | ― |
| ③ 前半タイム・⑥ 後半タイム | **MAE** | 予測の真ん中の値（50% の分位点）と、実際の前半（後半）タイムの差の絶対値の平均（秒） | 小さいほど良い |
| ③ 前半タイム・⑥ 後半タイム | 分位点の損失 | 10%・50%・90% の分位点の当たり具合（scikit-learn の `mean_pinball_loss`）の平均 | 小さいほど良い |
| ③ 前半タイム・⑥ 後半タイム | 80% の予測区間の包含率と平均の幅 | 実際の前半タイムが 10%〜90% の幅に入った割合と、その幅の平均（秒）。測る区間（500・550・600m）別にも出す（年ごとの表には全体だけを出す） | 包含率は 80% に近く、幅は狭いほど良い。幅を広げて包含率だけを上げても良いとはしない |
| ④ 4コーナーの位置・⑤ 上がりの速さ | **MAE** | 予測と実際の値（0〜1）の差の絶対値の平均 | 小さいほど良い |
| ④ 4コーナーの位置・⑤ 上がりの速さ | レース内の順位相関 | 1レースの中で、予測の順と実際の順がどれだけ合っているか（スピアマンの順位相関を、レースで平均） | 大きいほど良い |
| ⑦ 着順 | **レースごとのログ損失（1着）** | 各レースで、実際に1着になった馬に付けた確率 p の `−log(p)` を、レースで平均した値 | 小さいほど良い |
| ⑦ 着順 | 確率1位の勝率・3着以内率 | 1着の確率がいちばん高い馬（◎）が、1着・3着以内だった割合 | 大きいほど良い |
| ⑦ 着順 | 2着・3着の条件付きログ損失 | 1着（1・2着）を実際の馬に決めたときの、実際の 2着（3着）の馬に付けた確率の `−log` の平均。λ を決める値（[10-target.md の 10.](10-target.md#10-着順の目的変数と確率の出し方)） | 小さいほど良い |
| ⑦ 着順 | 3着以内の確率の帯ごとの実際の割合 | 「3着以内の確率 0.3〜0.4」と出した馬が、実際に何割3着以内だったか。Harville の式の偏りが残っていないかを見る | 出した確率に近いほど良い |

- **時点ごとに出す。** 木曜は枠が分からないので、前日・当日より当たりにくいはずである。その差の大きさも見る。
- **条件ごとにも出す。** 芝ダ・距離帯・頭数・新馬戦かどうか・基準の段（同じクラス／クラスをまとめた）ごとに出し、`reports/展開から着順を予想/` に置く。件数が少ない条件は「確かめきれない」として扱い、一部の条件だけの良さを全体に広げない。
- **今ある見立てとの比べ方。** ①は、推定脚質が「逃げ」の馬を先頭とみなす今ある見立て（下の 3.）と比べる。

## 3. 比べる基準

モデルによらない簡単な予想を、同じ年・同じ指標で出して並べる（年ごとの確かめの表4。`StageBaselines`・`StageYearMetrics`・`FinishYearMetrics`）。**いちばん強い基準と同じなら、モデルは何も学んでいない。** 割合を数える基準（割合の表・平均）は、その年より前の年の行だけで数える。

| 予想 | 基準 | 何を出すか |
|---|---|---|
| ① 先頭 | 全馬に同じ確率 | 1 ÷ 頭数 |
| ① 先頭 | 先頭率をそろえただけ | K の先頭率（平滑化したもの）を、レースの中で合計 1 に割り直したもの。モデルが「過去の先頭率」以上のことを学べているか |
| ① 先頭 | 推定脚質 | 推定脚質が逃げの馬に、確率を等分する。逃げの馬がいなければ全馬に等分する。今ある見立て（事実表の `style_before`） |
| ② 序盤の位置 | 前年までの割合 | 先団・中団・後方の、その年より前の年の割合を、全馬に同じ確率として出す |
| ② 序盤の位置 | 前走の区分からの割合 | 前走の序盤の区分ごとに、今回の区分の割合を、その年より前の年で数えた表。前走が無ければ全体の割合 |
| ③ ペースの区分 | 前年までの割合 | ハイ・平均・スローの、その年より前の年の割合 |
| ③ ペースの区分 | 逃げそうな馬の数からの割合 | 逃げそうな馬の数（0・1・2・3以上）ごとの、ペースの区分の割合を、その年より前の年で数えた表。今ある見立て |
| ③ 前半タイム | 基準だけ | 基準との差を 0 と予測する（前半タイム = 基準）。MAE だけを比べる |
| ④ 4コーナーの位置 | 近走の平均 | 「近5走の平均4コーナー位置」（E）をそのまま予測にする。無ければ、その年より前の年の平均 |
| ⑤ 上がりの速さ | 近走の平均 | 「近5走の上がりの速さの平均」（N）をそのまま予測にする。無ければ、その年より前の年の平均 |
| ⑥ 後半タイム | 基準だけ | ③と同じ作り方 |
| ⑦ 着順 | 全馬に同じ確率 | 1 ÷ 頭数 |
| ⑦ 着順 | 前半・後半の予想を入れない着順のモデル | ⑦と同じ作り方で、S・T を除いた特徴量だけで学習したモデル（既存の予想の結果 V は入れる）。**既存の予想の傾向に、前半と後半の予想を組み合わせたことで当たりが良くなったか**を、これとの差で見る |
| ⑦ 着順（原因を調べる） | S を外したモデル・T を外したモデル | ⑦ から S だけ・T だけを外して学習したモデル（2026-09-30 に足した）。⑦ と比べて、S と T のどちらが効いているか（効いていないか）を見る。どれも ⑦ と同じ行（S・T のそろった行）で学習する |
| ⑦ 着順（別の比べ） | オッズを着順の段にだけ入れたモデル | ⑦ に W（確定の単勝オッズから見た勝率と人気）を足したモデル（当日の時点だけ）。この設計はオッズを特徴量に使わない（[15-decisions.md の 16](15-decisions.md#16-オッズを特徴量に入れるか)）ので、既定は変えず、当たりと回収率がどう変わるかを別に示すだけ。採用の基準には使わない |
| ⑦ 着順（参考） | 単勝オッズから見た勝率 | 確定の単勝オッズの逆数を、レースの中で合計 1 にそろえたもの（市場の見立て）。オッズを使うので、採用の基準には使わず、参考として並べる |

## 4. 正解を作らなかったレースの確かめ

正解を作れるレースだけで学習・評価すると、「作れるレース」だけで当たりが良く見えることがある（[10-target.md の 2.](10-target.md#2-先頭の馬の目的変数)）。そのため、次を確かめる。**2026-09-30 に、年ごとの確かめ（`backtest`）の表6（正解を作らなかったレースの割合）と、先頭が決まらないレースの一覧を出すようにした（`UnlabeledRaceTable`）。** 数値は `reports/展開から着順を予想/backtest/results.md` にある。直線コースとコーナーを5回以上通るレースが①②から外れることは変わらない。

| 確かめること | 出し方 |
|---|---|
| 正解を作らなかったレースの割合 | 理由（直線・コーナーを5回以上通る・通過順位の記録なし・先頭が決まらない、③⑥ はタイムの記録なし・基準なし）ごとに、全体・頭数・競馬場・ペースの区分・年別の割合を表にする（表6。学習データの全部の年） |
| 先頭が決まらないレースの中身 | 先頭が決まらないレースを新しい順に最大 20 レース出し（表6の下の一覧）、`tools/レース詳細/race.py` の通過順と照らし合わせて、決まらない理由が「並んで先頭」だけかを目で見る |
| 数え方の元の記録との一致 | 事実表に足した列（最初のコーナーの番号・先頭の馬番）を、同じ 20 レースで元の `ra__コーナー通過順位` の文字列と照らし合わせる |

## 5. 採用の基準

**結果を見る前に決めておく。** 結果を見てから基準を決めると、都合のよい基準を選んでしまうためである。予想ごとに判断し、基準を満たしたものだけを使う。前半の3つ（①〜③）は下の表のとおり。後半と着順（④〜⑦）は、表の下に書く。

| 判断すること | 使ってよい条件（[15-decisions.md の 10](15-decisions.md#10-採用の基準) で決めたものを、年ごとの確かめで読み替えた。読み替えは 2026-09-30 に利用者が確認した） |
|---|---|
| 年ごとの当たり具合（最初の設計の「検証データ」） | 2016〜2025年（2026-09-30 より前は 2019〜2025年、2026-09-27 より前は 2018〜2025年）を合わせて、いちばん大事な指標が、いちばん強い基準より 1% 以上良い |
| 年ごとの確かめ（最初の設計の「期間をずらした確かめ」） | 2016〜2025年の10の年のうち 8つ以上（2026-09-30 より前は 2019〜2025年の7つのうち 5つ以上、2026-09-27 より前は 2018〜2025年の8つのうち 6つ以上）で、いちばん強い基準より良い（6つのうち5つとほぼ同じ割合） |
| 2026年（最初の設計の「テストデータ」） | 候補を1つに決めてから1回だけ見て、いちばん強い基準より悪くない。悪ければ、2026年に合わせて直すことはせず、採用しない |
| 確率・幅の当てはまり | ①の確率の帯ごとの実際の割合が、帯から大きく外れていない。③の 80% の予測区間の包含率が 70〜90% に入っている |

**後半と着順（④〜⑦）の採用の基準。** 年ごとの確かめ（7.）の結果で判断する。

| 判断すること | 使ってよい条件 |
|---|---|
| 年ごとの当たり具合 | いちばん大事な指標が、いちばん強い基準（参考の単勝オッズとオッズを足したモデルを除く）より、確かめる年を合わせて 1% 以上良く、確かめる年のうち、6つのうち5つとほぼ同じ割合以上で良い（2026-09-30 からは、後半は 2017〜2026年の10の年のうち 8つ以上、着順は 2018〜2026年の9つの年のうち 7つ以上。2026-09-27 からは 6つの年のうち 5つ以上、それより前は 7つの年のうち 5つ以上） |
| 確率の当てはまり（⑦） | 3着以内の確率の帯ごとの実際の割合が、帯から大きく外れていない |

- ⑦が「前半・後半の予想を入れない着順のモデル」に勝てなかったときは、⑦は採用しない。前半と後半を組み合わせたことが役に立っていないためである。そのときは、原因（S・T のどれが効いていないか）を調べてから直す。2026-09-27 からは、比べる基準にも既存の予想の結果（V）が入るので、この比べ方は「既存の予想だけを材料にした着順」に、展開が上乗せになっているかを見ることになる。
- 回収率には、採用の基準を置かない。回収率は、予想の良さだけでなく買い方で決まるためである。回収率は 7. の表で、券種ごと・年ごとに示す。
- 1% は、差が偶然でないと言うための目安で、この値なら当たるという保証ではない。
- 基準を満たさなかった予想も、結果と理由を `reports/展開から着順を予想/` に残す。表示用・研究用としては使える。
- 既存の予想（3着以内など）に渡してよいかは、この基準とは別に、渡したときに既存の予想が良くなるかで決める（[15-decisions.md の 11](15-decisions.md#11-既存の予想に渡すか)）。逆向き（既存の予想の結果をこの予想に入れる）は、2026-09-27 に入れることにした（[15-decisions.md の 22](15-decisions.md#22-既存の予想をどう組み合わせるか)）。

## 6. 期間をずらした確かめ

最初の設計では、検証期間を半年ずつずらして6回学習し、同じ向きの差が出るかを見ることにしていた。1つの検証期間の結果は、その期間の偶然に左右されるためである。作ったプログラムでは、年ごとの確かめ（7.）が同じ役目を果たす（1年ずつずらして、その年より前だけで学習し直す）ので、年ごとの確かめの年（2026-09-30 からは、前半は 2016〜2026年、後半は 2017〜2026年、着順は 2018〜2026年。2026-09-27 からは、前半は 2019〜2026年、後半は 2020〜2026年、着順は 2021〜2026年）で見る。

- 特徴量や設定を直すたびに、同じ年の並びで確かめる。直すたびに年を選び直すと、たまたま良い年を選んでしまう。
- 年ごとの結果を見ながら直しを重ねると、それらの年にも合わせてしまう。**年ごとの確かめの年は「独立したテスト」ではない。** 最後の判断は、直す判断に使わなかった年（2026年）で行う。

## 7. 年ごとの的中率と回収率

**何をするか。** 2018年から 2026年（1〜9月）の各年について、その前の年までのデータだけで、既存の4つの予想（傾向の組）と7つの予想のモデルを学習し直し、その年のレースを当日の時点で予測する（ウォークフォワード検証。`--timing 前日` なら前日の時点）。予測した1着・2着・3着の確率から印と買い目を決め（8.）、実際の払戻で精算して、券種 × 年ごとに的中率と回収率を出す。

**なぜ年ごとに学習し直すか。** 1つのモデルで 2021〜2026年を予測すると、2021年の予測に 2025年までのデータで学んだことが入り、実際にはできなかった予想になる。年ごとに学習し直せば、どの年も「その年の1月1日の時点で持っていたデータだけで予想した」ことになる。

### 学習し直す期間

前の組の予想の結果を後の組の特徴量に入れるので、後の組の学習データには「前の組が学習に使っていない予測」が付いている必要がある（[11-leak-prevention.md の決まり 11](11-leak-prevention.md#決まり)）。そのため、組ごとに、予測を出し始める年がずれる。

| 組 | 予測する年 y | 学習 | 検証（早期終了） | 検証（温度・λ） |
|---|---|---|---|---|
| 傾向（既存の4つの予想） | 2015〜2026年 | 2014年1月 〜（y−1）年9月 | （y−1）年10〜12月 | ― |
| 前半（①〜③） | 2016〜2026年 | 2015年1月 〜（y−1）年9月 | （y−1）年10〜12月（①③は、その前半） | ①の温度と③の幅の倍率を、（y−1）年10〜12月の後半 |
| 後半（④〜⑥） | 2017〜2026年 | 2016年1月 〜（y−1）年9月 | （y−1）年10〜12月（⑥は、その前半） | ⑥の幅の倍率を、（y−1）年10〜12月の後半 |
| 着順（⑦） | 2018〜2026年 | 2017年1月 〜（y−1）年9月 | （y−1）年10〜12月の前半 | （y−1）年10〜12月の後半（温度と λ） |

- 前半の学習データの V（既存の予想の結果）は、傾向の組が 2015年から出した「その年より前だけで学習した予測」である。後半の学習データの S（前半の予想の結果）も、前半のモデルが 2016年から出した同じ種類の予測である。着順の学習データの V・S・T も同じ。
- 傾向の組は、既存の予想の作り方（学習データ・特徴量・目的変数・基準・区分）のまま、期間だけを上の区切りにして学習し直す（[15-decisions.md の 23](15-decisions.md#23-既存の予想のモデルをどう作るか)）。
- 温度も幅の倍率も使わない予想（②④⑤）は、検証の 10〜12月の全部で早期終了する。①③⑥⑦ は、検証の 10〜12月を開催日の真ん中で前半と後半に分け、前半で早期終了、後半で温度（⑦ は λ も）か 80% の幅の倍率（③⑥）を決める（`ValidationHalves`）。
- ウォームアップは 2013年（序盤と末脚の履歴を数えるためだけに読む。前半・後半タイムの基準は、さらに 1095日前の 2011年から読む）。2026-09-30 より前は、元DB が 2016年からで、ウォームアップも 2016年だった。
- **最初の年ほど、学習データが少ない。** 着順の 2018年のモデルは、2017年1〜9月だけで学習する。2026年のモデルは 2017年1月〜2025年9月で学習する。年ごとの表に、着順のモデルの学習データの行数を並べる。早い年の結果が悪くても、それが学習データの少なさのせいかを見分けるためである。
- 2026-09-30 に、元DB に 2011〜2015年が入っていることを確かめ、傾向の組の学習を 2014年から始めて、確かめる年を 2018〜2026年に増やした（[15-decisions.md の 18・25](15-decisions.md#25-年ごとの確かめの年)）。さらに前を確かめる年にするには、jvdata-store で 2010年より前を取り込む。
- 予測する時点の既定は当日にする。馬券を買うのは当日だからである。2026-09-30 に `--timing` を足し、前日の時点でも同じ表を出せるようにした（結果は `results_day_before.md`）。前日は馬体重と確定オッズが分からないので、当日より当たりにくいはずで、その差を見る。
- ハイパーパラメータは、年ごとに調整しない（どの年も設定ファイルの同じ値）。年ごとに調整すると、確かめる年に合わせてしまう。

## 8. 券種ごとの買い方

**印の付け方。** 着順の予想⑦の1着の確率で、1レースの馬を並べて付ける。

| 印 | 付ける馬 | 買い方に使うか |
|---|---|---|
| ◎ | 1着の確率が 1位の馬 | 使う |
| ○ | 2位の馬 | 使う |
| ▲ | 3位の馬 | 使う |
| △ | 4位の馬 | 使う |
| ☆ | 5位以下の馬のうち、単勝の期待値（1着の確率 × 単勝オッズ）がいちばん高い馬。期待値が 1.0 以上のときだけ付ける | 使わない（表示だけ） |
| 注 | 印の無い馬のうち、先頭の確率（①）がいちばん高い馬。逃げ残りに注意する馬 | 使わない（表示だけ） |

☆と注の付け方は、利用者の「任せる」で決めた（[15-decisions.md の 21](15-decisions.md#21-印のと注の付け方)）。判断の手順は [06-flowchart.md の図4](06-flowchart.md#図4-印の付け方) を参照。

**印どおりに買う（1点100円）。** 利用者が 2026-09-26 に決めた（[15-decisions.md の 15](15-decisions.md#15-券種ごとの買い方)）。

| 券種 | 買い目 | 点数 |
|---|---|---|
| 単勝 | ◎ | 1点 |
| 複勝 | ◎ | 1点 |
| ワイド | ◎-○、◎-▲ | 2点 |
| 馬連 | ◎-○、◎-▲、◎-△ | 3点 |
| 馬単 | ◎→○、◎→▲、◎→△ | 3点 |
| 3連複 | ◎ を軸に、○▲△ から2頭（◎-○-▲、◎-○-△、◎-▲-△） | 3点 |
| 3連単 | ◎ を1着、○▲ を2着、○▲△ を3着（◎→○→▲、◎→○→△、◎→▲→○、◎→▲→△） | 4点 |

- 4頭立て以下などで印が足りないときは、組める買い目だけを買う。
- 券種の中で1点の金額がそろっていれば、回収率は金額によらず同じである。券種ごとに金額を変える配分は、この結果を見てから決める。

**期待値で買う（1点100円）。** 券種ごとに、そのレースで買えるすべての買い目について、当たる確率（[10-target.md の 10.](10-target.md#10-着順の目的変数と確率の出し方)）× 確定オッズ を出し、1.0 以上の買い目をすべて買う。

- 複勝とワイドは、オッズが「最低〜最高」の幅で発表されるので、最低オッズで計算する（[15-decisions.md の 20](15-decisions.md#20-複勝ワイドの期待値に使うオッズ)）。
- 期待値 1.0 以上の買い目が無いレースは、その券種を買わない。

**比べる基準: 人気順の印で、印どおりに買う。** 確定の単勝オッズが低い順に ◎○▲△ を付け、上と同じ買い目を買う。モデルの印が、人気順の印より回収率・的中率が良いかを見る。

**精算。** 払戻の表（`hr`）の買い目と照らし合わせる。

| 場合 | 払戻 |
|---|---|
| 買い目が払戻の表にある | 払戻金（100円あたり）。同着で複数あれば、当たったそれぞれの買い目の払戻金 |
| 買い目が払戻の表に無い | 0円 |
| その券種が不成立・特払のレース | その券種は、そのレースでは買わない（見送り。研究「馬券の買い方の検証」と同じ扱い） |
| 出走取消・競走除外の馬を含む買い目 | 買わない（当日の時点で分かっている） |

## 9. 2026-09-30 の確かめの結論

2018〜2026年を、当日と前日の時点で確かめた結果（共通の事実表の前走の直しを取り込んだ学習データ）。数値は `reports/展開から着順を予想/backtest/results.md`（当日）と `results_day_before.md`（前日）にある。

| 確かめたこと | 結論 |
|---|---|
| 正解を作らなかったレース（4.） | 先頭が決まらないレースと、通過順位の記録が無いレースは無かった。①② から外れるのは直線とコーナーを5回以上通るレースだけで、③⑥ の「基準なし」は、小さい頭数・一部の競馬場（改修で新しくなったコースのある年など）にやや多い。学習データの始まりの年だけ「基準なし」が多いことは、元DB の 2011年からの記録を使うことで無くなった |
| ③⑥ の 80% の幅 | 検証データの後半で幅の倍率を決めるようにしたら、幅に入った割合が、どの年も 70〜90% の中に入り、全体で 80% に近づいた（前は全体で 77% ほど）。そのぶん幅は少し広がった。年によって 76〜83% ほどの揺れがあるのは、倍率を決める検証データ（前の年の10〜12月の後半）が少ないためである |
| ⑦ に前半・後半の予想を入れた効果 | ⑦ は「前半・後半を入れないモデル」より良くならなかった（採用の基準を満たさない）。S を外しても、T を外しても、当たりは変わらなかった。前半と後半の予想を掛け合わせた特徴量（展開の噛み合わせ）を足す直し方も試したが、良くならなかったので既定には入れなかった（`reports/展開から着順を予想/backtest/噛み合わせの試し/`）。オッズを着順の段にだけ入れても、当たりは変わらなかった |
| なぜ上乗せにならないか | ⑦ の当たりは、どの年も単勝オッズから見た勝率とほぼ同じである。⑦ には、オッズを出発点にした既存の予想の確率（V）が入っていて、市場の見立てはそこから入っている。オッズを足しても変わらないことから、⑦ はすでに市場と同じ見立てになっていて、展開（前半と後半）の予想が持つ情報も、市場がすでに値段に入れていると考えられる。前半・後半の予想そのものは、どれも簡単な基準より当たっている（表4）ので、予想が外れているのではなく、着順の段で市場を超える分が残っていない |
| 回収率を上げる直し方（15 の 15・16） | 期待値の線を上げても回収率は上がらず、多くの券種で下がった。モデルが市場より高く見た買い目ほど、実際には市場の見立てのほうが正しかったためである。線と券種の配分を前の年までで選ぶと、多くの年で「印どおりの複勝」が選ばれたが、どの選び方も 100% には届かなかった。オッズを着順の段に入れた ⑦ で買っても、回収率は上がらなかった。既定（オッズを特徴量に使わない・期待値の線 1.0）は変えない |
| 前日の時点 | 前日の時点の的中率と回収率は、当日とほぼ同じだった。当日に分かる馬体重と確定オッズは、⑦ の当たりをほとんど変えていない |
