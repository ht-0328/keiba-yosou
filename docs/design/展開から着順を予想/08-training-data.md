# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。

**結論: 学習データは2つ作る。予想①②④⑤⑦は 1サンプル = 1レースの1頭、予想③⑥は 1サンプル = 1レース。どの予想の学習データにも、傾向の組（既存の4つの予想）の学習に使っていない予測（V）の列を足す。後半と着順の予想（④〜⑦）の学習データは、さらに前の組の学習に使っていない予測（S・T）の列を足したものである。既存の予想の学習データは、それぞれの予想の作り方で別に作る（6.）。どちらも中央競馬の平地（芝・ダート）を使う。期間は `train` の引数で変えられ、既定は 2017年1月から（ウォームアップは 2016年）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

### 1頭ごと（予想①②）

架空の1レースの一部を例にすると、次の形になる。

| レースID | 馬番 | 枠番 | 近5走の序盤の位置の平均 | 先頭率 | ほかの馬の先頭率の合計 | …（特徴量はあと 90個あまり） | 目的変数: 先頭 | 目的変数: 序盤の位置の区分 |
|---|---|---|---|---|---|---|---|---|
| 架空レースA | 1 | 1 | 0.42 | 0.06 | 1.3 | … | 0 | 1（中団） |
| 架空レースA | 3 | 2 | 0.15 | 0.27 | 1.1 | … | 1 | 0（先団） |
| 架空レースA | 5 | 3 | （欠損値） | 0.07 | 1.3 | … | 0 | 2（後方） |

- 5番の馬は DB に過去走が無い（新馬など）ので、近5走の序盤の位置は欠損値になる。先頭率は、走った数が 0 なので全体の割合になる（平滑化。[09-features.md の K](09-features.md#k-序盤の位置取りの履歴15個)）。
- 16頭立てのレースなら、目的変数「先頭」が 1 のサンプルは 1つ、0 のサンプルは 15 になる。

### 1レースごと（予想③）

| レースID | 距離 | 先頭率の1位 | 先頭率の2位 | 前半タイムの基準 | …（特徴量はあと 20個あまり） | 目的変数: ペースの区分 | 目的変数: 前半タイムの基準との差 |
|---|---|---|---|---|---|---|---|
| 架空レースA | 1600 | 0.29 | 0.27 | 35.1 | … | 2（ハイ） | −0.5 |
| 架空レースB | 1200 | 0.61 | 0.08 | 34.0 | … | 1（平均） | +0.1 |

## 2. 列の種類

| 種類 | 1頭ごと（①②） | 1レースごと（③） | モデルに渡すか |
|---|---|---|---|
| ID 列 | レースID、馬ID、馬番、開催日 | レースID、開催日、競馬場、レース番号 | 渡さない |
| 特徴量 | 98個（[09-features.md](09-features.md)） | 27個（[09-features.md](09-features.md#予想③の特徴量1レースごと)） | `fit` の `X` として渡す |
| 目的変数 | 先頭（1/0）、序盤の位置の区分（0〜2）（[10-target.md](10-target.md)） | ペースの区分（0〜2）、前半タイムの基準との差（秒） | 予想ごとに1列を `fit` の `y` として渡す（`with_label()` で持ち替える） |
| 評価用の列 | 序盤の位置（0〜1）、最初のコーナーでの順位、確定着順 | 前半タイム（秒）、前半タイムの基準（秒）、測る区間、基準の段 | 渡さない |

- 3つの時点（木曜・前日・当日）のモデルは、同じ学習データから、その時点で使う特徴量の列だけを渡して学習する（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。
- 目的変数が欠損値の行（直線コース、先頭が1頭に決まらないレースなど）は、その予想の学習からだけ外れる。例えば、先頭が決まらないレースの馬は、①からは外れるが、②には入る（[06-flowchart.md の図1](06-flowchart.md#図1-先頭と序盤の位置の正解の付け方)）。
- ID 列と年を特徴量にしない理由は手本と同じ（[手本の 08 の「2. 列の種類」](../近走と適性から3着以内を予想/08-training-data.md#2-列の種類)）。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 中央競馬の平地（芝とダート）。障害は入れない | 障害は走り方が違い、コーナーの記録の仕方も違う |
| 対象の馬 | 出走した馬の全頭。出走取消・発走除外・競走除外はサンプルにしない | 相手の数え方（L・P）を、レースの全出走馬でそろえるため |
| 期間 | 「学習データの始まり」から。既定は 2014年1月1日 | 下の「5. 期間の指定」 |
| 新馬戦 | 入れる | 序盤の履歴は無いが、枠・騎手・血統で予測できる。履歴が無いことも特徴量（走った数 0）で渡す |
| 直線コース | ①②には入れず、③には入れる | コーナーが無いので先頭と位置の正解が無い。前半タイムはある（[10-target.md の 1.](10-target.md#1-最初のコーナーの決め方)） |
| コーナーを5回以上通るレース | ①②には入れず、③には入れる | 最初に通ったコーナーが記録から抜けるため（同上） |

**ウォームアップ期間。** 序盤の履歴（K）は、DB にある過去走から数える。学習データの始まりの直後に走った馬が「過去走なし」に見えないよう、学習データの始まりの前の年（既定は 2013年）の出走も読み、サンプルにはせず、特徴量の計算にだけ使う。前半・後半タイムの基準（3年ぶん）とコースの形（M）は、さらに前の記録が要るので、ウォームアップの始まりの 1095日前からのレースを読む。元DB は 2011年1月からあるので、2014年からの学習データは、どのレースも3年ぶんの記録で基準を作れる（[10-target.md の 5.](10-target.md#5-前半タイムの基準の作り方)）。2026-09-30 より前は、元DB が 2016年からしかなく、学習データを 2017年から（ウォームアップは 2016年）にしていたので、2017〜2018年のレースは基準に数えられる年が3年に満たなかった。

**行数の見込み（2026-09-26 時点の DB で数えた。2026-09-30 に学習データの始まりを 2014年に早めた）。** 2014年〜2026年9月の平地のレースは、約 4.2 万レースある。

| 数え方 | 割合 |
|---|---|
| 最初のコーナーの通過順位の記録があるレース | 約 99%（記録が無いのは、ほぼ直線コースのレース） |
| そのうち、先頭の馬が1頭に決まるレース（①に入る） | ほぼ全部（事実表で数えると、記録があるレースは全部決まった） |
| コーナーを5回以上通るレース（①②に入らない） | 約 2% |
| 直線コースのレース（①②に入らない） | 1% 足らず |
| 前半タイムがあるレース | 全部 |

既定の期間（2014年1月〜）では、1頭ごとの学習データは約 60 万行、1レースごとは約 4.2 万行になる（2026-09-30 に作った学習データで数えた）。この中を、学習・検証・テストに時期で分ける（[16-evaluation.md](16-evaluation.md#1-期間の分け方)）。

## 4. 後半と着順の学習データ

**1頭ごとの学習データ（④⑤⑦）と 1レースごとの学習データ（⑥）は、①②・③と同じ行に、列を足したものである。** 足すのは次の列である（V は ①〜③ にも足す）。

| 足す列 | どの予想に | 作り方 |
|---|---|---|
| N・O（末脚の履歴と比較） | ④⑤⑦ | `DatasetBuilder` の中で、K・L と同じく作る |
| U（後半の材料） | ⑥ | `RaceDatasetBuilder` の中で、P・Q と同じく作る |
| 目的変数（4コーナーの位置・上がりの速さ・1着・後半タイムの基準との差） | ④⑤⑦⑥ | `LateLabeler`・`FinishLabeler`（1頭ごとは `HorseLabeler` がまとめる）・`RaceLabeler`（[10-target.md の 7.〜10.](10-target.md#7-4コーナーの位置の目的変数)） |
| V（既存の予想から見た傾向） | ①〜⑦ | 学習データを作ったあと、`WalkForwardPredictor` が作った傾向の組（既存の4つの予想）の学習に使っていない予測を、`StackedColumns` で結ぶ（6.） |
| S（前半の予想の結果） | ④⑤⑥⑦ | 学習データを作ったあと、`WalkForwardPredictor` が作った前半の学習に使っていない予測を、`StackedColumns` で結ぶ |
| T（後半の予想の結果） | ⑦ | 同じく、後半の学習に使っていない予測を結ぶ |

架空の1レースの一部を例にすると、⑦の学習データは次の形になる。

| レースID | 馬番 | 近5走の上がりの速さの平均 | 先頭の確率（S） | ハイペースの確率（S） | 4コーナーの位置の予測（T） | 上がりの速さの予測（T） | …（特徴量はあと 120個あまり） | 目的変数: 1着 |
|---|---|---|---|---|---|---|---|---|
| 架空レースA | 1 | 0.52 | 0.04 | 0.45 | 0.48 | 0.55 | … | 0 |
| 架空レースA | 3 | 0.45 | 0.31 | 0.45 | 0.12 | 0.38 | … | 1 |
| 架空レースA | 5 | （欠損値） | 0.06 | 0.45 | 0.71 | 0.49 | … | 0 |

**後の組の学習データは、前の組が予測を出し始めた年からになる。** V は、傾向の組（既存の予想）が「その年より前だけで学習して、その年を予測した」値なので、傾向の組の学習データの最初の年（2014年）には無い。S も同じで、前半のモデルの学習データの最初の年には無い。そのため、前半の組の学習データは 2015年から、後半の組は 2016年から、着順の組は 2017年からになる（[16-evaluation.md の 7.](16-evaluation.md#7-年ごとの的中率と回収率)）。

| 組 | 学習データの始まり（既定） | 行数の見込み（1頭ごと。学習データの最後が 2025年のとき） |
|---|---|---|
| 傾向（既存の予想） | 2014年1月 | 既存の予想ごとに違う（3着以内は約 55 万行、1レースごとの荒れ具合は約 3.9 万行） |
| 前半 | 2015年1月 | 約 50 万行 |
| 後半 | 2016年1月 | 約 45 万行 |
| 着順 | 2017年1月 | 約 40 万行 |

## 5. 期間の指定

学習データは、2014年1月から（ウォームアップは 2013年）、指定の年の年末までのレースで作る（`DatasetLoader`。展開の予想の1頭ごと・1レースごとの学習データと、既存の4つの予想の学習データを、同じ期間で作る）。学習・検証・予測の区切りは、予測する年ごとに決まる（[16-evaluation.md の 1.・7.](16-evaluation.md#1-期間の分け方)）。

| コマンド | 指定するもの | 既定 |
|---|---|---|
| `train` | `--year`: 学習するモデルの年。学習は組の最初の年 〜 前の年の9月、検証は前の年の10〜12月 | 今年 |
| `train` | `--timings`: 学習する時点 | 木曜・前日・当日の3つ全部 |
| `backtest` | `--years`: 確かめる年 | 2018〜2026年 |
| `backtest` | `--timing`: 予測する時点 | 当日 |

学習データの始まりを 2014年1月にしたのは、予想①の正解（先頭 = 1）が1レースに1つしかなく、サンプルの数をなるべく多くしたいためと、元DB の 2011年からの記録で、どのレースにも3年ぶんの基準を作れるためである（[15-decisions.md の 9](15-decisions.md#9-学習データの期間)）。手本の予想は 2021年8月からにしたが、それは手本の特徴量（調教）がそろう月に合わせたためで、この予想の中心の特徴量（序盤の履歴）は元DB の始まり（2011年）からそろう。

```powershell
uv run python -m yosou.race_development train
uv run python -m yosou.race_development train --year 2026 --timings 当日
```

（1行目は、今年のモデルを3つの時点ぶん学習して保存するコマンド。2行目は、2026年の当日の時点のモデルだけを学習するコマンド）

## 6. 傾向の組（既存の予想）の学習データ

**既存の4つの予想の学習データは、それぞれの予想の `dataset_builder` で、展開の予想とは別に作る。** 行の選び方（人気馬だけ・穴馬だけ・1レース1行）、特徴量（オッズから見た確率・人気の履歴など）、目的変数、基準（オッズから見た確率のロジット）が、展開の予想とは違うためである（[15-decisions.md の 23](15-decisions.md#23-既存の予想のモデルをどう作るか)）。

| 既存の予想 | 1行 | 目的変数 | 別々に学ぶ単位 |
|---|---|---|---|
| 近走と適性から3着以内 | 平地の出走馬の全頭 | 3着以内 | 1つ |
| 人気馬が4着以下 | 人気馬（13頭以下なら 1〜3番人気、14頭以上なら 1〜5番人気） | 4着以下 | 人気帯（1番人気・2〜3番人気・4〜5番人気） |
| 穴馬が3着以内 | 穴馬（13頭以下なら 4番人気以下、14頭以上なら 6番人気以下） | 3着以内 | 穴馬の区分（中穴・大穴） |
| レースの荒れ具合 | 1レース | 券種ごとの荒れ具合（固い・中荒れ・大荒れ・超荒れ） | 券種（単勝・馬連・3連複・3連単） |

- 作った学習データは、展開の予想の学習データと一緒に `reports/展開から着順を予想/datasets/tendency_<既存の予想>.pkl` に残す（元DB が変わっていなければ、次からは読むだけ）。
- 予測した値は、(レースID, 馬ID) か レースID で、展開の予想の学習データの行に結ぶ。既存の予想が予測しない馬（人気馬でない馬の、人気馬の4着以下の確率など）は欠損値になる。
