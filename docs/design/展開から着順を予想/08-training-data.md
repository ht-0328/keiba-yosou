# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。

**結論: 学習データは2つ作る。予想①②④⑤⑦は 1サンプル = 1レースの1頭、予想③⑥は 1サンプル = 1レース。後半と着順の予想（④〜⑦）の学習データは、同じ2つの学習データに、前の組の学習に使っていない予測（S・T）の列を足したものである。どちらも中央競馬の平地（芝・ダート）を使う。期間は `train` の引数で変えられ、既定は 2017年1月から（ウォームアップは 2016年）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

### 1頭ごと（予想①②）

架空の1レースの一部を例にすると、次の形になる。

| レースID | 馬番 | 枠番 | 近5走の序盤の位置の平均 | 先頭率 | ほかの馬の先頭率の合計 | …（特徴量はあと 90個あまり） | 目的変数: 先頭 | 目的変数: 序盤の位置の区分 |
|---|---|---|---|---|---|---|---|---|
| 架空レースA | 1 | 1 | 0.42 | 0.06 | 1.3 | … | 0 | 1（中団） |
| 架空レースA | 3 | 2 | 0.15 | 0.27 | 1.1 | … | 1 | 0（先団） |
| 架空レースA | 5 | 3 | （欠損値） | 0.07 | 1.3 | … | 0 | 2（後方） |

- 5番の馬は DB に過去走が無い（新馬など）ので、近5走の序盤の位置は欠損値になる。先頭率は、走った数が 0 なので全体の割合になる（平滑化。[09-features.md の K](09-features.md#k-序盤の位置取りの履歴15個)）。
- 16頭立てのレースなら、目的変数「先頭」が 1 のサンプルは 1つ、0 のサンプルは 15 になる。

### 1レースごと（予想③）

| レースID | 距離 | 先頭率の1位 | 先頭率の2位 | 前半タイムの基準 | …（特徴量はあと 20個あまり） | 目的変数: ペースの区分 | 目的変数: 前半タイムの基準との差 |
|---|---|---|---|---|---|---|---|
| 架空レースA | 1600 | 0.29 | 0.27 | 35.1 | … | 2（ハイ） | −0.5 |
| 架空レースB | 1200 | 0.61 | 0.08 | 34.0 | … | 1（平均） | +0.1 |

## 2. 列の種類

| 種類 | 1頭ごと（①②） | 1レースごと（③） | モデルに渡すか |
|---|---|---|---|
| ID 列 | レースID、馬ID、馬番、開催日 | レースID、開催日、競馬場、レース番号 | 渡さない |
| 特徴量 | 98個（[09-features.md](09-features.md)） | 27個（[09-features.md](09-features.md#予想③の特徴量1レースごと)） | `fit` の `X` として渡す |
| 目的変数 | 先頭（1/0）、序盤の位置の区分（0〜2）（[10-target.md](10-target.md)） | ペースの区分（0〜2）、前半タイムの基準との差（秒） | 予想ごとに1列を `fit` の `y` として渡す（`with_label()` で持ち替える） |
| 評価用の列 | 序盤の位置（0〜1）、最初のコーナーでの順位、確定着順 | 前半タイム（秒）、前半タイムの基準（秒）、測る区間、基準の段 | 渡さない |

- 3つの時点（木曜・前日・当日）のモデルは、同じ学習データから、その時点で使う特徴量の列だけを渡して学習する（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)）。
- 目的変数が欠損値の行（直線コース、先頭が1頭に決まらないレースなど）は、その予想の学習からだけ外れる。例えば、先頭が決まらないレースの馬は、①からは外れるが、②には入る（[06-flowchart.md の図1](06-flowchart.md#図1-先頭と序盤の位置の正解の付け方)）。
- ID 列と年を特徴量にしない理由は手本と同じ（[手本の 08 の「2. 列の種類」](../近走と適性から3着以内を予想/08-training-data.md#2-列の種類)）。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 中央競馬の平地（芝とダート）。障害は入れない | 障害は走り方が違い、コーナーの記録の仕方も違う |
| 対象の馬 | 出走した馬の全頭。出走取消・発走除外・競走除外はサンプルにしない | 相手の数え方（L・P）を、レースの全出走馬でそろえるため |
| 期間 | 「学習データの始まり」から。既定は 2017年1月1日 | 下の「4. 期間の指定」 |
| 新馬戦 | 入れる | 序盤の履歴は無いが、枠・騎手・血統で予測できる。履歴が無いことも特徴量（走った数 0）で渡す |
| 直線コース | ①②には入れず、③には入れる | コーナーが無いので先頭と位置の正解が無い。前半タイムはある（[10-target.md の 1.](10-target.md#1-最初のコーナーの決め方)） |
| コーナーを5回以上通るレース | ①②には入れず、③には入れる | 最初に通ったコーナーが記録から抜けるため（同上） |

**ウォームアップ期間。** 序盤の履歴（K）は、DB にある過去走から数える。学習データの始まりの直後に走った馬が「過去走なし」に見えないよう、学習データの始まりの前の年（既定は 2016年）の出走も読み、サンプルにはせず、特徴量の計算にだけ使う。前半タイムの基準（3年ぶん）とコースの形（M）は、さらに前の記録が要るが、DB には 2016年より前のレース成績がほとんど無い。そのため、2016〜2018年のレースは、基準に数えられるレースが少なく、「クラスをまとめた」段や「基準なし」が多くなる（[10-target.md の 5.](10-target.md#5-前半タイムの基準の作り方)）。JRA-VAN は 1986年からのレース成績を提供しているので、足りなければ jvdata-store で取得する（[09-features.md の「使うデータの期間」](09-features.md#使うデータの期間)）。

**行数の見込み（2026-09-26 時点の DB で数えた）。** 2016年〜2026年9月の平地のレースは、約 3.5 万レースある。

| 数え方 | 割合 |
|---|---|
| 最初のコーナーの通過順位の記録があるレース | 約 99%（記録が無いのは、ほぼ直線コースのレース） |
| そのうち、先頭の馬が1頭に決まるレース（①に入る） | ほぼ全部（事実表で数えると、記録があるレースは全部決まった） |
| コーナーを5回以上通るレース（①②に入らない） | 約 2% |
| 直線コースのレース（①②に入らない） | 1% 足らず |
| 前半タイムがあるレース | 全部 |

既定の期間（2017年1月〜）では、1頭ごとの学習データは約 45 万行、1レースごとは約 3.2 万行になる見込みである。この中を、学習・検証・テストに時期で分ける（[16-evaluation.md](16-evaluation.md#1-期間の分け方)）。

## 4. 後半と着順の学習データ

**1頭ごとの学習データ（④⑤⑦）と 1レースごとの学習データ（⑥）は、①②・③と同じ行に、列を足したものである。** 足すのは次の列である。

| 足す列 | どの予想に | 作り方 |
|---|---|---|
| N・O（末脚の履歴と比較） | ④⑤⑦ | `DatasetBuilder` の中で、K・L と同じく作る |
| U（後半の材料） | ⑥ | `RaceDatasetBuilder` の中で、P・Q と同じく作る |
| 目的変数（4コーナーの位置・上がりの速さ・1着・後半タイムの基準との差） | ④⑤⑦⑥ | `LateLabeler`・`FinishLabeler`（1頭ごとは `HorseLabeler` がまとめる）・`RaceLabeler`（[10-target.md の 7.〜10.](10-target.md#7-4コーナーの位置の目的変数)） |
| S（前半の予想の結果） | ④⑤⑥⑦ | 学習データを作ったあと、`WalkForwardPredictor` が作った前半の学習に使っていない予測を、`StackedColumns` で結ぶ |
| T（後半の予想の結果） | ⑦ | 同じく、後半の学習に使っていない予測を結ぶ |

架空の1レースの一部を例にすると、⑦の学習データは次の形になる。

| レースID | 馬番 | 近5走の上がりの速さの平均 | 先頭の確率（S） | ハイペースの確率（S） | 4コーナーの位置の予測（T） | 上がりの速さの予測（T） | …（特徴量はあと 120個あまり） | 目的変数: 1着 |
|---|---|---|---|---|---|---|---|---|
| 架空レースA | 1 | 0.52 | 0.04 | 0.45 | 0.48 | 0.55 | … | 0 |
| 架空レースA | 3 | 0.45 | 0.31 | 0.45 | 0.12 | 0.38 | … | 1 |
| 架空レースA | 5 | （欠損値） | 0.06 | 0.45 | 0.71 | 0.49 | … | 0 |

**後の組の学習データは、前の組が予測を出し始めた年からになる。** S は、前半のモデルが「その年より前だけで学習して、その年を予測した」値なので、前半のモデルの学習データの最初の年（2017年）には無い。そのため、後半の組の学習データは 2018年から、着順の組の学習データは 2019年からになる（[16-evaluation.md の 7.](16-evaluation.md#7-年ごとの的中率と回収率)）。

| 組 | 学習データの始まり（既定） | 行数の見込み（1頭ごと。学習データの最後が 2025年のとき） |
|---|---|---|
| 前半 | 2017年1月 | 約 40 万行 |
| 後半 | 2018年1月 | 約 35 万行 |
| 着順 | 2019年1月 | 約 30 万行 |

## 5. 期間の指定

学習データは、2017年1月から（ウォームアップは 2016年）、指定の年の年末までのレースで作る（`DatasetLoader`）。学習・検証・予測の区切りは、予測する年ごとに決まる（[16-evaluation.md の 1.・7.](16-evaluation.md#1-期間の分け方)）。

| コマンド | 指定するもの | 既定 |
|---|---|---|
| `train` | `--year`: 学習するモデルの年。学習は組の最初の年 〜 前の年の9月、検証は前の年の10〜12月 | 今年 |
| `train` | `--timings`: 学習する時点 | 木曜・前日・当日の3つ全部 |
| `backtest` | `--years`: 確かめる年 | 2020〜2026年 |

学習データの始まりを 2017年1月にしたのは、予想①の正解（先頭 = 1）が1レースに1つしかなく、サンプルの数をなるべく多くしたいためである（[15-decisions.md の 9](15-decisions.md#9-学習データの期間)）。手本の予想は 2021年8月からにしたが、それは手本の特徴量（調教）がそろう月に合わせたためで、この予想の中心の特徴量（序盤の履歴）は 2016年からそろう。

```powershell
uv run python -m yosou.race_development train
uv run python -m yosou.race_development train --year 2026 --timings 当日
```

（1行目は、今年のモデルを3つの時点ぶん学習して保存するコマンド。2行目は、2026年の当日の時点のモデルだけを学習するコマンド）
