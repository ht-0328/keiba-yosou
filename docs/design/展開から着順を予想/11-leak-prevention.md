# 11 リークを防ぐ決まり

**この文書で決めること:** 学習では当たるのに本番では当たらないモデル（リーク）にならないよう、特徴量と目的変数を作るときに守る決まり。

**結論: 特徴量は、予測する時点（木曜・前日・当日。[07-prediction-timing.md](07-prediction-timing.md)）で分かることだけから作る。手本の決まり 1〜4 をそのまま守り、この予想では、今回の序盤の結果・過去のレースの記録・前半タイムの基準・相手の数え方・温度についての決まり（6〜10）と、予想の結果を次の予想に入れるとき・今回の後半の結果・過去のレースで的中率と回収率を確かめるときの決まり（11〜13）を足す。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 決まり

1〜4 は手本と同じで、[手本の 11 の「決まり」](../近走と適性から3着以内を予想/11-leak-prevention.md#決まり) を参照する（そのレースの結果を使わない、過去走から作る特徴量は開催日より前のものだけから計算する、マスタの累計の成績を使わない、学習データと予測用データを同じプログラムで作る）。手本の 5（確定オッズ）は、この予想ではオッズを使わないので当てはまらない。この予想では、6〜13 を足す。

**6. 今回のレースの序盤と後半の結果は、目的変数と評価用の列にだけ使う。**

- 事実表に足す列のうち、今回のレースの値である 1〜4コーナーの順位（`corner1`〜`corner4`）、最初のコーナーの番号と周回数、先頭の馬番（`first_corner_leader_no`）、前3ハロン（`first3f`）は、特徴量にしない。手本の決まり 1 の列（脚質 `style` など）と同じ扱いである。
- 後半と着順も同じである。今回のレースの 4コーナーの順位（`corner4`）・上がり3ハロン（`last3f`）とその順位・後3ハロン（`last3f_race`）・確定着順・走破タイムは、特徴量にしない。
- 特徴量に使うのは、過去走の同じ列（前走の値・近5走の値）だけである。
- 最初のコーナーの番号（M）は、そのレース自身の記録ではなく、同じコースの過去のレースの記録から決める。そのレース自身の記録は、レースが終わるまで無いためである。

**7. 過去のレースの記録（`race_history`）は、開催日の前日までの行だけを見る。**

- `race_history` には、予測するレースと、同じ日のほかのレースも入っている（学習のときは、同じ日のレースの結果もすでに DB にある）。コースの形（M）・全体の先頭率・前半タイムの基準は、同じ日の先に終わったレースも数えない。予測のときは、同じ日のレースの結果はまだ無いためである。
- 手本の「騎手の近1年の3着以内の割合」と同じく、共通の `AsOfLookup`（前日まで）の1か所で守る。

**8. 前半タイムの基準は、前日までの3年のレースだけから作る。そのレース自身の前半タイムは、基準にも特徴量にも入れない。**

- 学習データの全期間から1つの基準を作ると、昔のレースの基準に、その後のレースが混ざる（[10-target.md の 5.](10-target.md#5-前半タイムの基準の作り方)）。
- 後半タイムの基準（⑥の目的変数と U）も、同じ決まりで作る。そのレース自身の後半タイムは、基準にも特徴量にも入れない。
- `PaceRecordSource` が返す表には、そのレース自身の前半タイム（目的変数の元）と基準が並んでいる。特徴量（Q）を作る `PaceBaselineFeatures` は、基準の列（平均・標準偏差・件数）だけを読む。

**9. 相手（L・P）は、予測の時点で出走する馬から作る。学習データは、確定した出走馬から作る。**

- 予測では、前日・当日は速報の取消を反映したあとの馬、木曜は出走馬名表の馬で作る（[07-prediction-timing.md の「取消が出たときの扱い」](07-prediction-timing.md#取消が出たときの扱い)）。
- 学習データでは、実際に走った馬で作る。木曜・前日の時点の出走予定の馬は、元DB に残っていない（出馬表は新しい版で上書きされる）ので作れない。**これはリークではないが、学習と予測で相手の数え方が少し違う。** 取消の多いレースほど、木曜・前日の予測は、学習のときより条件が違う。
- 今後の予測のたびに、その時点の予測用データを残す（`PredictionArchiveRepository`。[15-decisions.md の 12](15-decisions.md#12-予測の記録を残すか)）。残った記録で、「その時点の材料で予測したら、どれだけ当たったか」を後から確かめられる。

**10. 木の数（早期終了）・先頭の確率の温度・当たり具合の確かめは、別のデータで行う。テストデータは、直す判断に使わない。**

- 早期終了は検証データの前半、温度は検証データの後半で決める（[16-evaluation.md の 1.](16-evaluation.md#1-期間の分け方)）。同じデータで両方を決めると、確率が実際より当たって見える。
- テストデータ（既定は 2026年1月から）は、候補を1つに決めたあとに1回だけ確かめる。テストの結果を見て特徴量や線引きを直さない。

**11. 前の組の予想の結果を後の組の特徴量に入れるときは、そのサンプルを学習に使っていないモデルの予測を入れる。**

- 例: 2023年のレースの「先頭の確率」（S）を、後半と着順のモデルの学習データに入れるなら、それは 2022年までのデータだけで学習した前半のモデルが、2023年のレースを予測した値でなければならない。2023年のレースも学習に使った前半のモデルの予測は、正解を覚えているので、実際より当たって見える。後の組のモデルは、その「当たりすぎる予測」を信じるように学んでしまい、本番（前半の予測が外れることもある）で当たらなくなる。
- そのため、前の組のモデルは、年ごとに「その年より前だけで学習し、その年を予測する」をくり返して、学習に使っていない予測を作る（ウォークフォワード。[16-evaluation.md の 7.](16-evaluation.md#7-年ごとの的中率と回収率)）。後の組は、この予測が付いた年のサンプルだけで学習する。
- 予測（本番）のときは、その時点の最新の前半のモデルで予測した値を、後半と着順のモデルに入れる。学習のときと同じく、そのレースを学習に使っていないモデルの予測である。
- 時点ごとに、その時点の前の組のモデルの予測を入れる。木曜の後半のモデルに、当日の前半のモデルの予測を入れない（当日の特徴量が混ざるため）。

**12. 1つのモデルの中で、木の数・温度・ならしの指数と、当たり具合の確かめは、別のデータで行う。**

- 1着の確率（⑦）の温度と、2着・3着の割り当てのならしの指数 λ は、先頭（①）の温度と同じく、検証データの後半で決める。早期終了は検証データの前半で行う。
- 後の組のモデルの検証データにも、学習に使っていない前の組の予測を入れる（11.）。

**13. 過去のレースで的中率と回収率を確かめるときは、その年のレースを学習にも、線の決め方にも使わない。**

- 年ごとの確かめ（[16-evaluation.md の 7.](16-evaluation.md#7-年ごとの的中率と回収率)）では、確かめる年ごとに、その前の年までのデータだけで、7つの予想のモデルを学習し直す。温度・λ・早期終了の木の数も、その前の年までのデータで決める。
- 買い方の線（期待値 1.0、印の買い目の点数）は、結果を見る前に決めておく（[16-evaluation.md の 8.](16-evaluation.md#8-券種ごとの買い方)）。結果を見てから線を選び直すと、その年に合った線を選んでしまう。線を変えて試したいときは、変えたことを結果に書き、変える前の結果と並べて残す。
- 期待値に使うオッズは確定オッズである。確定オッズは締め切りのあとに決まるので、実際に買う時点のオッズとは少し違う。**これはリークではないが、期待値で買ったときの回収率は、実際より少し良く出るおそれがある。** 結果の表にこのことを書く。
- 出走取消・競走除外の馬は、買い目に入れない（当日の時点では、取消・除外は分かっている）。
