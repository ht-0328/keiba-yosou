# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。

**結論: 1サンプル = 1レースの1頭。地方 14場（ばんえいを除く）の平地の出走を使う。学習データは1つで、既定は 2019年1月から（ウォームアップは 2016年1月から。学習・検証・テストを合わせて約 104万行）。期間は `train` の引数で変えられる。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

架空の1レースの一部を例にすると、学習データは次の形になる。

| レースID | 馬番 | 馬齢 | 斤量 | 前走の着順 | 近5走の平均着差 | クラス | …（特徴量はあと 90個近く） | 目的変数: 3着以内 | 目的変数: 1着 |
|---|---|---|---|---|---|---|---|---|---|
| 架空レースA | 1 | 5 | 56.0 | 2 | 0.4 | 9（B2） | … | 1 | 1 |
| 架空レースA | 2 | 4 | 56.0 | 8 | 1.3 | 9（B2） | … | 0 | 0 |
| 架空レースA | 3 | 6 | 56.0 | （欠損値） | （欠損値） | 9（B2） | … | 1 | 0 |

- 3番の馬は DB に地方の過去走が無い（中央から移ってきた直後、など）ので、前走の特徴量は欠損値になる。通算の成績は出走別着度数地方（`nd`）の総合着回数から取るので、中央での出走も数に入る（[09-features.md の E](09-features.md#e-近走のまとめ10個)）。欠損値は 0 で埋めず、そのまま持つ。モデルに渡すときの欠損値の扱いは [12-lightgbm.md](12-lightgbm.md)・[13-catboost.md](13-catboost.md) の「学習データの渡し方」を参照。
- 12頭立てのレースなら、目的変数「3着以内」が 1 のサンプルは 3つ、0 のサンプルは 9 になる。

## 2. 列の種類

学習データの列は4種類ある。モデルに渡すのは**特徴量と目的変数だけ**である。中央の予想の [08 の「2. 列の種類」](../近走と適性から3着以内を予想/08-training-data.md#2-列の種類) と同じ分け方で、特徴量の中身だけが違う。

| 種類 | 列 | モデルに渡すか |
|---|---|---|
| ID 列 | レースID、馬ID、開催日、馬番、馬名 | 渡さない |
| 特徴量 | 96個（土台 65・J 4・L 4・O 7・N 6・Q 10。[09-features.md](09-features.md)）。各時点のモデルには、その時点で使う列だけを渡す（[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量)） | `fit` の `X` として渡す |
| 目的変数 | 3着以内（1/0）、1着（1/0）。[10-target.md](10-target.md) を参照 | `fit` の `y` として渡す。3着以内のモデルには「3着以内」を、1着のモデルには「1着」を渡す |
| 評価用の列 | 確定着順、確定の単勝オッズ、確定の単勝人気、単勝の払戻、複勝の払戻、複勝オッズ（最低・最高）、確定の出走頭数、オッズから見た勝率・2着以内率・3着以内率 | 渡さない（オッズから見た3着以内率・勝率は、基準の元になる） |

学習データは1つで、4つの学習（3着以内・1着・券種オッズなしの3着以内と1着）はこの学習データから列を外すか持ち替えて作る（[05-sequence.md の図1](05-sequence.md#図1-学習)）。ID 列と年を特徴量にしない理由は中央と同じ（個々の馬を覚えるだけになる・将来の年に役立たない）。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象の競馬場 | 地方 14場（門別・盛岡・水沢・浦和・船橋・大井・川崎・金沢・笠松・名古屋・園田・姫路・高知・佐賀。競馬場コード 30〜61 のうち、期間に開催のある場）。ばんえい（83）は入れない | ばんえいは距離・負担重量・馬体重の意味が違い、上がりと通過順も無い。平地の予想と同じ特徴量が作れない |
| 対象のレース | 平地（ダートと、盛岡の芝）。障害は無い | 地方に障害レースは無い。問いは中央と共通の部品のまま残す（[06-flowchart.md の図1](06-flowchart.md#図1-学習データに入れる行の選び方)） |
| 交流競走 | 入れる。出走した中央の馬もサンプルにする | 地方の競馬場のレースで、馬券も同じ。中央の馬は所属（B）で見分けられる |
| 対象の馬 | 出走した馬。出走取消・発走除外・競走除外はサンプルにしない | 走っていない馬には目的変数が無い |
| 期間 | 「学習データの始まり」から。既定は 2019年1月1日 | 下の「4. 期間の指定」と「ウォームアップ期間」 |
| 新馬戦 | 入れる | 過去走の特徴量は欠損値になるが、血統・騎手・調教師で予測できる |

**ウォームアップ期間。** 近走の特徴量は、DB にある過去走から数える。学習データの始まりの直後に走った馬は、実際には何戦もしていても、DB に読んだ範囲が短いと「前走なし」に見えてしまう。そこで、学習データの始まりより前の期間（ウォームアップ期間。既定は 2016年1月から 2018年12月まで）の出走も読み、サンプルにはせず、あとのサンプルの過去走の特徴量と対戦レーティングを計算するためだけに使う。通算の成績は出走別着度数地方から取るので、この影響を受けない。

既定の決まりで、学習データは約 104万行になる（2019年1月〜2026年9月の地方 14場の出走。約 10.3万レース）。このうち学習が約 87万行、検証が約 7.2万行、テスト（2026年1月〜）が約 10万行である。中央の今の材料（約 24万行）の 4倍ほどで、半年で約 7万行（中央の2年分に近い）が増える。

## 4. 期間の指定

学習データの期間は、古い順に4つの日で区切る。4つはまとめて共通の `TrainingPeriod` が持ち、順になっていなければエラーにする。`train` と `backtest` の引数で変えられる。

| 区切り | 引数 | 既定 | 意味 |
|---|---|---|---|
| ウォームアップの始まり | `--warmup-from` | 2016-01-01 | ここからの出走を読むが、サンプルにしない。DB にある最初の年 |
| 学習データの始まり | `--train-from` | 2019-01-01 | ここからの出走がサンプルになる |
| 検証データの始まり | `--valid-from` | 2025-07-01 | この前日までが学習データ |
| テストデータの始まり | `--test-from` | 2026-01-01 | この前日までが検証データ。ここからはテストデータ（最後に1回だけ確かめる用。[16-evaluation.md](16-evaluation.md)） |

```powershell
uv run python -m yosou.local_form_aptitude_top3 train --train-from 2017-01-01
```

（2017年1月から学習するコマンド。ウォームアップは既定の 2016年1月から）

- 使った期間は、学習の結果の表「学習データの期間」に、ウォームアップの行も含めて出る。
- ウォームアップの既定を「前の年の1月1日」ではなく 2016年1月1日に固定するのは、対戦レーティングと近走を、DB にある最初の年から数えるためである。
- **データの提供期間は 2005年からである**（地方競馬DATA のセットアップデータ。nvdata-store の [データ種別と提供範囲](../../../../nvdata-store/docs/03-dataspecs.md)）。DB に入っているのは 2016年からなので、それより前を指定しても行が無いだけである。延ばすときは nvdata-store で取得する。
- 検証・テストの区切りは中央の予想と同じ日にそろえてある。

### 学習データの始まりを 2019年1月にした理由

中央の予想では、学習データの始まりを3つ比べ、長いほど良いが 10年全部まで延ばしてもそれ以上は上がらなかった（[中央の 08](../近走と適性から3着以内を予想/08-training-data.md#既定を-2021年8月からにした理由)）。地方は中央の4倍の出走があるので、6年半（2019年〜2025年6月）で約 87万行になり、中央の 10年分（約 39万行）を超える。2017年からも同じ検証データで比べたが、当たり具合は同じで良くならなかった（[15-decisions.md の 6](15-decisions.md#6-学習データの期間)）。
