# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使える情報が変わる。

**結論: 出馬表（オッズなし）・前日（前売りの単勝オッズ）・当日（馬体重の発表のあと、締め切り前のオッズ）の3つの時点のどれでも、予測を出せるようにする。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う。3つの時点とも同じ学習データ（当日の全部の特徴量で作ったもの）から、その時点で使う列だけで学ぶ。当日に券種のオッズが無いレースのために、N を使わない当日のモデルも持つ。3着以内のモデルと1着のモデル（[10-target.md](10-target.md)）は、同じ材料で別々に学ぶ（当日の1着のモデルだけは勝ち切る材料 Q も使う）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 中央の「木曜」と地方の「出馬表」

中央競馬は、木曜に出走馬名表（枠番・馬番が未定）、金・土に出馬表（枠番・馬番が決まる）が出る。地方競馬には出走馬名表の段階が無く、レースの 2〜5日前（多くは3日前）に枠番・馬番の決まった出馬表が出る。そのため、オッズのまだ無い最初の時点を「出馬表」と呼ぶ。

プログラムの中では、中央と共通の時点の値（`PredictionTiming.THURSDAY`。保存フォルダの名前 `thursday`）をそのまま使い、表示名だけをこの予想の `TIMING_LABELS` で「出馬表」にする（[04-classes.md](04-classes.md#3-中央だけの決めごとを外から渡す形)）。共通の値を使うのは、印の成績（`--timing`）など時点を受け取る道具を、中央と同じまま使うためである。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと |
|---|---|---|
| 出馬表（2〜5日前） | 出走馬、枠番・馬番、騎手、斤量、過去走、出走別着度数地方（出走時点の値） | オッズ、馬体重、馬場状態 |
| 前日 | 上に加えて、前日発表の馬場状態、前売りの単勝オッズ（時系列オッズ `0B41` の断面） | 馬体重、当日の馬場状態、締め切り前のオッズ |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前の単勝オッズと全券種のオッズ（`0B30`） | 確定オッズ、結果 |

- 出馬表の時点で枠番・馬番が分かるのが、中央の木曜との違いである。中央で前日から使う枠番・馬番は、この予想では出馬表から使う。
- 馬場状態は、出馬表の時点では分からない（レースの数日前）。馬場状態で分けて数える特徴量（同じ芝ダ・馬場状態での通算の成績、持ち時計の順位）も、前日から使う。
- 単勝オッズは、前日と当日に特徴量に使う（まとまり J）。地方の前売りは前日の夕方ごろから始まる。前日の夜に予測すれば、前日発売のオッズが使える。

## 時点ごとに使う特徴量

| 時点 | 材料（[09-features.md](09-features.md)） | 使わない特徴量 | 特徴量の数 |
|---|---|---|---|
| 出馬表 | 土台（A〜H）のうち出馬表で分かるもの、L、O | 馬体重の2個、馬場状態を使う5個（馬場状態・同じ芝ダ・馬場状態での通算の出走数と3着以内の数・持ち時計の順位2個）、J、N | 69 |
| 前日 | 土台のうち前日で分かるもの、J、L、O。オッズから見た3着以内率（基準）を出発点にする | 馬体重の2個、N | 78 |
| 当日 | 土台の全部、J、L、O、N。基準を出発点にする | なし | 86 |
| 当日・券種オッズなし | 当日から N の6個を除く | N | 80 |

- **1着のモデルも、この表のとおり時点ごとに同じ列で学ぶ。ただし当日の1着のモデルだけは、勝ち切る材料（Q の 10個）を足した 96個（券種オッズなしは 90個）で学ぶ**（中央の予想と同じ決まり。[09-features.md の Q](09-features.md#q-勝ち切る材料10個当日の1着のモデルだけ)）。基準は、3着以内のモデルが「オッズから見た3着以内率」、1着のモデルが「オッズから見た勝率」（どちらも前日から）。出馬表は基準なしで学ぶ。
- 単勝の期待値（1着になる確率 × 単勝オッズ）と期待度は、オッズの分かる前日・当日だけ出す。
- 対戦レーティング（O）は、過去のレースの結果だけから作るので、3つの時点すべてで使う。中央の予想は当日に O を使わないが、それは当日の材料に馬の力の材料（M）があり、O を足しても誤差が小さくならなかったためである。この予想には M が無いので、当日も使う（[15-decisions.md の 3](15-decisions.md#3-特徴量を何にするか)）。
- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書いてある。この予想の一覧 `LOCAL_BASE_FEATURES` は、共通の一覧から枠番・馬番の「いつから分かるか」を出馬表に付け直したものである（[04-classes.md](04-classes.md#feature--特徴量の一覧この予想作るクラスは-shared)）。
- 前日の馬場状態は、前日発表の値（速報 `0B14`）を使う。学習データの馬場状態は発走時点の確定の値なので、当日に馬場が変わると少しずれる（中央と同じ）。

## 予測のときのオッズの与え方

中央の予想の [07 の「予測のときのオッズの与え方」](../近走と適性から3着以内を予想/07-prediction-timing.md#予測のときのオッズの与え方) と同じ順で決める（判断の手順は [06-flowchart.md の図4](06-flowchart.md#図4-予測に使うオッズの決め方)）。

| 順 | オッズの元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--odds 馬番:オッズ` で渡した単勝オッズ | 前日・当日 |
| 2 | 元DB の締め切り前の単勝オッズ（時系列オッズ `0B41` のいちばん新しい断面） | 前日の夜（前売りのあと）と当日。予測の前に nvdata-store で `uv run nvstore realtime --date <開催日>` を実行して速報を取り込んでおく |
| 3 | 元DB の出走の行に入っている単勝オッズ | **終わったレースだけ**（確定オッズ）。これから走るレースでは空なので、止めて `--odds` を案内する |

```powershell
uv run python -m yosou.local_form_aptitude_top3 predict 2026101544000112 --timing 当日 --odds 3:2.4 7:5.1 12:38
uv run python -m yosou.local_form_aptitude_top3 predict 2026101544000112 --timing 出馬表
```

（1行目は、これから走るレースの出走馬について、3着以内に入る確率と1着になる確率を出すコマンド。`--odds` は「馬番:オッズ」の組を並べる。2行目は、オッズを使わない出馬表の時点で予測するコマンド。rid は架空）

## 時点ごとにモデルを分ける理由

中央の予想の [07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由) と同じ。1つのモデルで済ませると、出馬表の予測で、学習のときに値が入っていた「馬体重」「単勝オッズ」を欠損値で渡すことになり、学習と予測でデータの様子がずれる。学習データは1つ作り、時点ごとにモデルに渡す列だけを変える（[08-training-data.md の「2. 列の種類」](08-training-data.md#2-列の種類)）。
