# 02 用語の意味

**この文書の目的:** この設計書に出てくる用語の意味を1か所にまとめる。

**結論: 機械学習の用語と、競馬とこの設計の用語の大半は、中央の予想の [02 用語の意味](../近走と適性から3着以内を予想/02-glossary.md) と同じである。** ここには、地方の予想で増える用語と、意味が変わる用語だけを書く。

## 中央の予想と同じ用語

二値分類・学習データ・サンプル・特徴量・目的変数・予測確率・欠損値・リーク・過学習・ハイパーパラメータ・アンサンブル・GBDT・早期終了・public メソッド・オーケストレーション・インターフェース・リポジトリ・エンコーダー・順序付きターゲット統計・ID 列・評価用の列・確定オッズ・締め切り前のオッズ・オッズから見た勝率・1着になる確率・勝ち切る材料・単勝の期待値・期待度・ウォームアップ期間・レース内順位・事実表は、中央の予想の [02 用語の意味](../近走と適性から3着以内を予想/02-glossary.md) を参照。

## 地方の予想で増える用語・変わる用語

| 用語 | 意味 | この設計では |
|---|---|---|
| 地方競馬DATA | 地方競馬（NAR）の出馬表・成績・オッズ・マスタを配信する有料サービス。UmaConn（NV-Link）を通して受け取る。JV-Data と同じ形のレコードで、違いは nvdata-store の [全体像](../../../../nvdata-store/docs/01-overview.md) にまとめてある | この予想の元のデータ |
| nvdata-store | 地方競馬DATA を取得して DuckDB（`nvdata.duckdb`）に貯める隣のリポジトリ。表の作り方と列名は jvdata-store と同じ | 元DB を作る道具。この予想は読むだけ |
| 元DB | nvdata-store が作った DuckDB。1レコード種別 = 1表（`ra` `se` `hr` `o1`〜`o6` `nd` `nu` …）。列名は仕様書の日本語のまま、値は全部文字列 | `../nvdata-store/nvdata.duckdb`（[04-classes.md の「コマンドの引数」](04-classes.md#コマンドの引数)） |
| 出馬表（時点） | レースの 2〜5日前（多くは3日前）に出る出走馬の表。枠番・馬番は決まっているが、オッズ・馬体重・馬場状態はまだ無い。地方競馬には、中央の「出走馬名表（木曜）」に当たる枠番の無い段階は無い | オッズのまだ無い予測の時点の名前（[07-prediction-timing.md](07-prediction-timing.md)）。プログラムの中では、中央と共通の時点の値（`thursday`）を使い、表示を「出馬表」にする |
| 出走別着度数地方（`nd`） | 出走ごとに、その出走の時点でのその馬の通算の着回数（1着〜5着・着外）を、総合・地方合計・競馬場別（大井ダ など）・距離帯別・馬場状態別に持つ表。中央の出走別着度数（`ck`）に当たる | 通算の成績（E）と、この条件での経験（F）の元（[09-features.md](09-features.md)） |
| 総合着回数 | `nd`・`nu` の着回数のうち、中央と地方の両方のレースを合わせた数。地方だけの数は「地方合計着回数」 | 通算の出走数・勝利数・3着以内の数に使う。中央で走った馬の中央での成績が、ここで数に入る |
| 競走馬マスタ地方（`nu`） | 地方競馬DATA の競走馬マスタ。3代血統情報（父・母・父父・母父 …）を持つ。中央の `um` に当たる | 血統（H）の元 |
| 格（Ａ・Ｂ・Ｃ） | 地方競馬のクラス分け。Ａ が上、Ｃ が下で、格の中を番号（Ａ１・Ｂ２・Ｃ３ など）でさらに分ける競馬場が多い。番号を付けない競馬場もある。同じ「Ｂ１」でも競馬場によって強さは違う | 競走条件名称の文字列から読み、クラスの並び順にする（[09-features.md の A](09-features.md#a-レースの条件9個)、[06-flowchart.md の図2](06-flowchart.md#図2-クラスの読み取り)） |
| 競走条件名称 | レースの条件を表す文字列（例 `３歳上Ｃ３　二`・`Ｂ１－２`・`ＯＰ`）。地方では競走条件コードがすべて `000` なので、クラスはこの文字列にしか無い。書き方は競馬場ごとに違う | クラスを読む元 |
| 交流競走 | 中央の馬が地方の競馬場で走るレース（ダートグレード競走など）。逆に、地方の馬が中央で走るレースもあるが、それは中央の予想の対象 | 地方の競馬場のレースなので、出走した中央の馬も含めてサンプルにする |
| 所属 | 馬が属する厩舎の所属。東西所属コードで、中央（美浦・栗東）か地方かが分かる | 特徴量「所属」（B）。地方の中の所属競馬場（大井・名古屋 など）は使わない（[15-decisions.md の 7](15-decisions.md#7-所属競馬場と遠征を特徴量にするか)） |
| ばんえい | 帯広で行われる、そりを引く競馬。競馬場コード `83`、距離 200m、負担重量と馬体重が16進で書かれ、上がりと通過順が無い | 対象から外す（[08-training-data.md](08-training-data.md#3-どのサンプルを入れるか)） |
| 対戦レーティング | 同じレースを走った馬どうしの着順の勝ち負けから、チェスの Elo と同じ形で開催日の順に更新する強さの数。中央の予想のまとまり O と同じ作り | 3つの時点すべてで使う（[09-features.md の O](09-features.md#o-対戦レーティング7個)） |
| テスト期間の確かめ | 学習に使っていないテスト期間の全レースを、保存したモデルで予測し直して当たり具合と印の成績を見ること。コマンドは `backtest` | [16-evaluation.md の 4.](16-evaluation.md#4-テスト期間での確かめ) |
