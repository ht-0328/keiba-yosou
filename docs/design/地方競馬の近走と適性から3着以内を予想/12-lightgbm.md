# 12 LightGBM で学習・予測するための設計

**この文書で決めること:** 07〜09 で決めた学習データ（特徴量と目的変数）を、LightGBM で学習・予測するために、LightGBM だけに必要なことを決める。

| 決めること | 結論 |
|---|---|
| 1. 学習データの渡し方 | 中央の予想と同じ。カテゴリ特徴量を category 型にし、出走の少ない値は「その他」にまとめる |
| 2. ハイパーパラメータの初期値 | 中央の予想と同じ値から始める。目的関数は二値分類（`binary`）、木の数は早期終了で決める |
| 3. 学習・予測・保存の手順 | 3つの時点（出馬表・前日・当日）ごとに、3着以内と1着のモデルを1つずつ、当日は券種オッズなしも学習する。保存先は `reports/地方競馬の近走と適性から3着以内を予想/models/` |

- 使うクラスは中央と共通の `LightGbmModel`・`LightGbmEncoder`（`src/yosou/shared/ml_model/`）である。学習データの渡し方・ハイパーパラメータの初期値・カテゴリ特徴量の値の変え方（フローチャート）・学習と予測のやりとり（シーケンス図）は、中央の予想の [12 の 1.〜5.](../近走と適性から3着以内を予想/12-lightgbm.md#1-学習データの渡し方) を参照。ここには、この予想で違う点だけを書く。
- CatBoost の設計は [13-catboost.md](13-catboost.md) を参照。

## この予想で違う点

| 項目 | 中央の予想 | この予想 |
|---|---|---|
| 「その他」にまとめる対象のカテゴリ特徴量 | 騎手・調教師・父・父の父・母の父 | 同じ。競馬場（14）・コース・所属のように値の種類が少ないものは、そのまま category 型にする |
| `min_category_count` の初期値 | 2000 | 2000 から始める。地方は学習データが約 87万行と中央の 3〜4倍あり、騎手・調教師の名前が 2000 回以上残りやすい。検証データで比べて初期値を直す（[16-evaluation.md の 5.](16-evaluation.md#5-ハイパーパラメータの調整のやり方)） |
| 学習する時点とモデルの数 | 木曜・前日・当日と券種オッズなしの当日、3着以内と1着で 8組 | 出馬表・前日・当日と券種オッズなしの当日、3着以内と1着で 8組（同じ数。材料は1つの学習データから） |
| 保存先 | `reports/近走と適性から3着以内を予想/models/` | `reports/地方競馬の近走と適性から3着以内を予想/models/`（Git の対象外。地方競馬DATA から作ったもので、公開しない） |

1 と 0 の数の偏りを直す設定（`is_unbalance`・`class_weight`）は使わない。[10-target.md](10-target.md) の「1 と 0 の数の偏り」を参照。
