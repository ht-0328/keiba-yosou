# 16 当たり具合の測り方

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。何と比べれば「当たっている」と言えるか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 時期で分ける。既定は 学習 2019年1月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜。`train` の引数で変えられる |
| 2. 評価指標 | 中央の予想と同じ共通の指標（ログ損失・AUC・Brier と、人気の基準との比べ方・同じ人気の中での AUC）を、時点ごとに LightGBM・CatBoost・平均の3行で出す |
| 3. 比べる基準 | 1番人気（`train`・`backtest` の出力）と、市場の確率（オッズから見た3着以内率・勝率をそのまま確率としたもの。`backtest` の出力） |
| 4. テスト期間での確かめ | `backtest` で、テスト期間の全レースを保存したモデルで予測し直し、時点ごとにログ損失を市場の確率と比べる。採用の基準は、前日・当日でログ損失が市場の確率より小さいこと。出馬表は頭数から見た割合（3 ÷ 頭数）と比べる |
| 5. ハイパーパラメータの調整のやり方 | 中央と同じ。自動の探索はしない。設定ファイルを変えて `train --config` で学習し、2つの検証期間で初期値と比べる |
| 6. ◎ の単勝回収率の確かめ（期待度） | `backtest` の予測を道具「印の成績」に渡し、◎ の期待度ごとの単勝回収率と、印のルールの買い目（全券種）の回収率を出す。採用の基準は中央と同じ（期待度「高」の ◎ の単勝回収率と 90% の幅の下の端が 100% を超えること） |

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 期間の分け方

区分（ウォームアップ・学習・検証・テスト）の意味は、中央の予想の [16 の「1. 期間の分け方」](../近走と適性から3着以内を予想/16-evaluation.md#1-期間の分け方) と同じ。既定の日は [08-training-data.md の「4. 期間の指定」](08-training-data.md#4-期間の指定)。共通の `PeriodSplitter` が学習データを3つに分け、`train` は検証データだけで当たり具合を測り、早期終了にも検証データを使う。テストデータは `backtest`（下の 4.）で1回だけ確かめる。

## 2. 評価指標

**指標の意味と良い向きは、穴馬の予想の [16 の「2. 評価指標」](../穴馬が3着以内に入るかを予想/16-evaluation.md#2-評価指標) と同じである。** 共通の `MetricCalculator` で計算し、`train` の出力の「検証データでの当たり具合」と「人気の基準との比べ方」の2つの表に出る。読み方は中央の予想の [16 の 2.](../近走と適性から3着以内を予想/16-evaluation.md#2-評価指標) と同じ（モデルの行は時点ごとに3行、判断は平均の行で行う）。

地方で気を付ける点: 地方は 8〜12頭立てが多く、3着以内の割合（1 の割合）が中央より高い。ログ損失・Brier の絶対の値は中央と比べられないので、同じ期間の市場の確率（下の 3.）と比べる。

## 3. 比べる基準

| 基準 | 何を出すか | どこで比べるか | 何が分かるか |
|---|---|---|---|
| 1番人気 | 各レースの1番人気を選ぶ | `train`・`backtest` の出力（人気最上位の馬の3着以内率・複勝回収率） | 1頭選ぶ使い方で、市場の本命より当たるか |
| 市場の確率 | オッズから見た3着以内率（3着以内のモデル）・オッズから見た勝率（1着のモデル）を、そのまま確率として使ったときのログ損失・AUC・Brier | `backtest` の出力（モデルの行の下に「市場の確率」の行） | 近走・適性・血統などの馬の情報が、オッズで分かること以上を足しているか。モデルは市場の確率を出発点（基準）に学ぶので、これより悪ければ、学んだ上げ下げが害になっている |
| 頭数から見た割合 | 3 ÷ 頭数（3着以内）・1 ÷ 頭数（1着）を確率としたもの | `backtest` の出馬表の行 | オッズの無い時点で、何も見ないよりは当たるか |

中央の予想は「オッズだけで学習したモデル」も基準にするが、それは研究「既存モデルの改善」の仕組みで作るもので、この予想では使わない。市場の確率は、オッズだけで学習したモデルとほぼ同じ強さの基準である（オッズを確率に直すだけで、学習は要らない）。

## 4. テスト期間での確かめ

`train` の既定の分け方では、検証データは半年1つだけである。予想を採用してよいかは、学習にも早期終了にも使っていないテスト期間（2026年1月〜DB にある最後の日）で確かめる。

```powershell
uv run python -m yosou.local_form_aptitude_top3 train
uv run python -m yosou.local_form_aptitude_top3 backtest
```

（1行目は、既定の期間で 8組のモデルを学習して保存するコマンド。2行目は、保存したモデルでテスト期間の全レースを予測し直し、当たり具合の表を出して、印の成績が読む予測の表を `reports/地方競馬の近走と適性から3着以内を予想/predictions/` に書くコマンド。流れは [05-sequence.md の図4](05-sequence.md#図4-テスト期間の確かめ)）

`backtest` が出す表は、時点ごと（出馬表・前日・当日）× 目的変数ごと（3着以内・1着）に、LightGBM・CatBoost・平均の3行と、市場の確率（出馬表は頭数から見た割合）の1行で、ログ損失・AUC・Brier・確率1位の馬の3着以内率（1着率）・複勝（単勝）回収率・人気最上位の馬の同じ値・人気の中での AUC を出す。当日は、券種のオッズが無いレースの行を券種オッズなしのモデルで予測して合わせる（[06-flowchart.md の図3](06-flowchart.md#図3-当日のモデルの選び方)）。

**採用の基準（結果を見る前に決めた）。**

| 時点 | 基準 |
|---|---|
| 前日・当日 | 3着以内のモデルと1着のモデルの両方で、テスト期間のログ損失が市場の確率より小さい |
| 出馬表 | 3着以内のモデルと1着のモデルの両方で、テスト期間のログ損失が頭数から見た割合より小さい。市場の確率より小さいことは求めない（オッズを見ていないので） |
| 届かないとき | 届かなかった時点と理由をここに書く。作った予想は使える状態（学習・予測・印の成績が通る）で残し、特徴量を足す候補（M の地方版・遠征 など）を次の作業にする |

**7つの区切りにしない理由。** 中央の予想は、半年1つの結果に偶然の幅があるので、7つの半年の区切り（ウォークフォワード）で確かめる。地方は年に約 1.5万レースあり、テスト期間 9か月で約 1万レース・約 10万の出走になる。これは中央の7つの区切りのテスト期間（3年半で約 1.2万レース）に近い数で、1つの期間で十分に偶然と区別できる。学習を7回くり返す時間（1回に数十分〜1時間）も省ける。予想を直すときに時期のずれを見たくなったら、そのとき区切りを足す。

## 5. ハイパーパラメータの調整のやり方

中央の予想の [16 の「5. ハイパーパラメータの調整のやり方」](../近走と適性から3着以内を予想/16-evaluation.md#5-ハイパーパラメータの調整のやり方) と同じ手順（設定ファイルを変えて `train --config` で学習し、2つの検証期間で初期値と比べ、両方で良ければ初期値のファイルを直す）。学習データの始まり（[15-decisions.md の 6](15-decisions.md#6-学習データの期間)）も、この比べ方で決める。

```powershell
uv run python -m yosou.local_form_aptitude_top3 train --config 試す設定.toml --models reports/地方競馬の近走と適性から3着以内を予想/models-試し
uv run python -m yosou.local_form_aptitude_top3 train --config 試す設定.toml --models reports/地方競馬の近走と適性から3着以内を予想/models-試し --valid-from 2025-01-01 --test-from 2025-07-01
```

（1行目は、試す設定で学習し、既定の検証期間（2025年7〜12月）で当たり具合を出すコマンド。2行目は、検証期間を 2025年1〜6月に変えて同じことをするコマンド。どちらも本番のモデルとは別の置き場所に書く）

## 6. ◎ の単勝回収率の確かめ（期待度）

単勝の期待値・◎・期待度の決め方は、中央の予想の [16 の 6.](../近走と適性から3着以内を予想/16-evaluation.md#6--の単勝回収率の確かめ期待度) と同じ（◎ は単勝 30倍以下の馬の中で単勝の期待値が1位、期待度は 1.00 以上なら高）。

```powershell
uv run python tools/印の成績/mark_stats.py --form reports/地方競馬の近走と適性から3着以内を予想/predictions/day_before.pkl --win reports/地方競馬の近走と適性から3着以内を予想/predictions/day_before-1着.pkl --no-danger --db ../nvdata-store/nvdata.duckdb --models reports/地方競馬の近走と適性から3着以内を予想/models --scene 地方 --out-dir reports/印の成績/地方
```

（前日の予測に、今週の予想と同じ決め方で印を付け、印ごとの成績と、印のルールの買い目（全券種）の券種ごとの回収率を出すコマンド。`--no-danger` は危険な人気馬の判定（中央のモデル）を使わない指定、`--scene 地方` は場面の表の帯（クラス・競馬場）を地方の区分にする指定。当日は `race_day.pkl`・`race_day-1着.pkl` と `--timing 当日`、出馬表は `thursday.pkl`・`thursday-1着.pkl` と `--timing 木曜`）

| 項目 | 中身 |
|---|---|
| 期間 | テスト期間（2026年1月〜DB にある最後の日） |
| 時点 | 前日と当日（出馬表はオッズが無いので期待値が出ない。印だけ付ける） |
| 測るもの | 期待度ごと（高・低）の ◎ の単勝の成績7つと、単勝回収率の 90% の幅、印のルールの買い目（全券種）の買い方ごとの回収率 |
| 採用の基準 | **期待度「高」の ◎ の単勝回収率が 100% を超え、90% の幅の下の端も 100% を超える** |
| 満たさなかったとき | 「届いたが偶然と区別できない」か「届かなかった」をそのまま書く。◎ の決め方と期待度は残し、「高」を単勝を買う根拠にはしない |

- 確定オッズでの検証なので、実際に買うとき（締め切り前のオッズ）より良く出る。結果に書き添える。
- 道具「印の成績」の場面の表（クラス・競馬場の帯）は、`--scene 地方` で地方の区分（クラス: 新馬・未勝利 / C / B / A・オープン / 重賞、競馬場: 南関東 / それ以外）にする。
- 危険な人気馬の判定（予想「人気馬が4着以下になるかを予想」）は中央のモデルなので使わない（`--no-danger`）。消の印は付かない。

## 確かめた結果

数値は Git の対象外の `reports/地方競馬の近走と適性から3着以内を予想/`（`train.md`・`backtest.md`）と `reports/印の成績/地方/` にある。ここには採用の基準を満たしたかと、その読み方だけを書く。

### 学習（`train`。既定の期間）

| 見たこと | 結果 |
|---|---|
| 学習データ | 学習 2019年1月〜2025年6月（約 87万行）、検証 2025年7〜12月（約 7.2万行）、テスト 2026年1月〜10月初め（約 10.4万行・約 1万レース） |
| 検証データでの当たり具合（3着以内） | 3つの時点とも、確率1位の馬の3着以内率と複勝回収率が、1番人気（人気最上位の馬）と同じか少し上。人気の中での AUC は出馬表 0.59、前日 0.65、当日 0.68 で、時点が進むほど人気で説明できないところを当てている |
| 検証データでの当たり具合（1着） | 前日・当日は、確率1位の馬の1着率が1番人気と同じで、人気の中での AUC は 0.70〜0.72。出馬表はオッズが無いので1番人気に届かない |
| 券種の支持（N） | 当日のモデルは、N を外した券種オッズなしのモデルより、3着以内・1着ともログ損失が小さい（N が効いている） |
| 木の数 | 早期終了で決まった木の数は最大 1,545（出馬表の CatBoost）で、上限 2,000 には届いていない |

### テスト期間での確かめ（`backtest`。上の 4.）

| 時点 | 3着以内のモデル | 1着のモデル | 採用の基準 |
|---|---|---|---|
| 出馬表 | ログ損失が頭数から見た割合より 0.1 ほど小さい。確率1位の馬の3着以内率は1番人気に届かない（オッズを見ていないので当然） | 同じく頭数から見た割合より小さい | **満たした** |
| 前日 | ログ損失が市場の確率より 0.01 ほど小さい。確率1位の馬の3着以内率・複勝回収率は1番人気を少し上回る | 市場の確率よりわずかに小さい（差は 0.001）。確率1位の馬の1着率は1番人気と同じ | **満たした** |
| 当日 | ログ損失が市場の確率より 0.02 ほど小さい（前日より差が開く。券種の支持 N の分）。確率1位の馬の3着以内率・複勝回収率は1番人気を上回る | 市場の確率より 0.003 小さい。確率1位の馬の1着率は1番人気を少し上回る | **満たした** |

- 3つの時点とも、LightGBM・CatBoost・平均の3つで、平均（アンサンブル）がいちばん良いか同じだった。
- 1着のモデルの上乗せ（市場の確率との差）は3着以内のモデルより小さい。単勝の期待値で選ぶ ◎ の成績は、下の印の成績で見る。
- テスト期間は約 1万レースで、中央の7つの区切りのテスト期間の合計に近い数である。

### 印の成績（上の 6.）

数値は `reports/印の成績/地方/predictions_<時点>.md`（表1〜12）と `reports/印の成績/地方/買い目/` にある。テスト期間の約 1万レース、確定オッズでの値である。

| 見たこと | 当日 | 前日 | 出馬表 |
|---|---|---|---|
| ◎ 全体の単勝回収率 | 100% には届かないが、同じ人気の馬全体を控除率の分より大きく上回る。◎ が1番人気になるのは4レースに1つで、残りの ◎（1番人気以外）が同じ人気の馬全体を大きく上回る | 当日とほぼ同じ | 1番人気が ◎ になるレースが6割を超え、同じ人気の馬全体をわずかに上回るだけ（オッズを見ないので） |
| 期待度「高」の ◎ の単勝 | **採用の基準を満たした。** 「高」は全レースの3分の1（1開催日に 12レースほど）で、単勝回収率が 100% を超え、90% の幅の下の端も 100% を超えた。「高」で LightGBM と CatBoost の両方の期待値が 1.00 以上のレース（2モデル一致。全レースの 13%）はさらに高く、幅の下の端も 100% を超えた | 「高」が全レースの 2.5%（1開催日に1レースほど）しか無い。単勝回収率は 100% を超えるが、90% の幅は 100% をまたぐ（**基準を満たさない**） | 期待値が出ないので無い |
| 複勝（期待値 1.25 以上） | 全レースでも「高」でも回収率が 100% を大きく超え、90% の幅の下の端も 100% を超えた。買うのは全レースの 8% ほど・1レースに 1.1点 | 同じく 100% を超え、幅の下の端も 100% を超えた。買うのは全レースの 14% ほど | 期待値が出ないので無い |
| ワイド・馬連・馬単 | ワイドは「高」で 100% 前後だが幅が 100% をまたぐ。馬連・馬単は 100% に届かない | 同じ傾向 | 単勝・馬連・馬単とも 100% に届かず、同じ人気の馬全体と同じ水準（オッズを見ない印なので） |
| 3連複・3連単（元の買い目、◎軸・軸馬の流し） | 期待値で絞っても 100% に届かない | 同じ | ― |
| 買い目の合計 | 全レースでも「高」でも 100% に届かない | 同じ | 届かない |

**判断。** 地方の予想は、当日のモデルで、◎ の単勝（期待度「高」）と複勝（期待値 1.25 以上）が採用の基準を満たした。
前日は「高」のレースが少なく、確かめるには足りない。中央と同じく、確定オッズでの検証は締め切り前のオッズで買うときより良く出るので、
実際のお金で買う前に締め切り前のオッズでの確かめが要る（買い方の決まりは地方には無く、この設計書の範囲外）。
