# 16 当たり具合の測り方と「危険」の線引き

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。予測確率から、どの人気馬を「危険」とするか。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 時期で分ける。既定は 学習 2021年8月〜2025年6月、検証 2025年7〜12月、テスト 2026年1月〜（ほかの予想と同じ共通の既定）。`train` の引数で変えられる |
| 2. 評価指標 | 穴馬の予想で決めた共通の指標を、人気帯ごと・時点ごとに LightGBM・CatBoost・平均の3行で出す。目的変数が「4着以下」なので、割合の列は「4着以下率」になる |
| 3. 「危険」の線引き | 危険度（4着以下になる確率 − オッズから見た4着以下の確率）が線以上の人気馬を「危険」とする。線は時点ごと・人気帯ごとに、学習のあと検証データで決めて保存する。線の値は設計書に書かない |
| 4. 半年ずつずらした確かめ | 予想を直すときは、手本と同じ7つの半年の区切りで学習し直す。危険とした馬が、同じ人気帯の全体より実際に4着以下になりやすいかを、1番人気でも確かめる |

用語の意味は [02-glossary.md](02-glossary.md) を参照。指標を計算するクラスは共通の `MetricCalculator`・`ModelEvaluator`（[手本の 04 の「evaluation/」](../近走と適性から3着以内を予想/04-classes.md#evaluation--当たり具合を測るshared)）、線を決めるクラスはこの予想の `DangerThreshold`・`DangerThresholdStep`（`src/yosou/favorites_out_of_top3/danger/`・`command/`）である。

## 1. 期間の分け方

**区分の意味と既定の日は、穴馬の予想の [16 の「1. 期間の分け方」](../穴馬が3着以内に入るかを予想/16-evaluation.md#1-期間の分け方) と同じである。** 実装で決まっていること（空の期間があれば止まる、`train` はテストデータを使わない、早期終了にも検証データを使う）は、[手本の 16 の「1. 期間の分け方」](../近走と適性から3着以内を予想/16-evaluation.md#1-期間の分け方) と同じである。区切りの日を変える引数は、[手本の 08 の「4. 期間の指定」](../近走と適性から3着以内を予想/08-training-data.md#4-期間の指定) と同じ `--warmup-from`・`--train-from`・`--valid-from`・`--test-from` である。

この予想で違うのは、**検証データを「危険」の線を決めるのにも使う**ことである（下の「3.」）。テストデータは、線を決めるのにも使わない。

## 2. 評価指標

**指標の意味と良い向きは、穴馬の予想の [16 の「2. 評価指標」](../穴馬が3着以内に入るかを予想/16-evaluation.md#2-評価指標) と同じである。** 学習は人気帯ごとなので（[15-decisions.md の 11](15-decisions.md#11-既存モデルの修正計画での直し)）、`train` の出力の表も「1番人気: 検証データでの当たり具合」のように、人気帯ごとに出る。

この予想での読み方は次のとおり。

| 表の列 | この予想では |
|---|---|
| ログ損失・AUC・Brier | 「4着以下になる確率」の当たり具合。良い向きは穴馬の予想と同じ |
| 確率1位の馬の4着以下率 | 各レースの同じ人気帯の中で、4着以下になる確率がいちばん高い馬が、実際に4着以下だった割合。大きいほど良い |
| 人気最上位の馬の4着以下率 | 各レースの同じ人気帯の中で、人気がいちばん上の馬（1番人気・2番人気・4番人気）の同じ値。モデルによらない**基準** |
| 確率1位の馬の複勝回収率・人気最上位の馬の複勝回収率 | その馬の複勝を 100円ずつ買ったときの回収率。この予想は負ける馬を当てるので、**確率1位の馬の値が基準より低いほど、負ける馬を選べている**。参考として見る |
| 人気の中での AUC | 同じ人気（2番人気どうし、3番人気どうし…）で比べた AUC。0.5 より大きいほど、人気で分からない負けやすさを当てている |

- **1番人気の帯では、確率1位の馬と人気最上位の馬は同じ馬になる。** 1レースに1番人気は1頭しかいないためである。そのため、1番人気の当たり具合は、ログ損失・AUC（同じ人気の中での AUC と同じ値になる）と、下の「3.」の危険の判定で見る。
- モデルの行は、時点ごとに LightGBM・CatBoost・平均の3行である。判断は平均の行で行う（[手本の 16 の 2.](../近走と適性から3着以内を予想/16-evaluation.md#2-評価指標)）。

## 3. 「危険」の線引き

**危険度が線以上の人気馬を「危険」とする。** 危険度は「平均の4着以下になる確率 − オッズから見た4着以下の確率」で、同じオッズの馬より、どれだけ負けやすいかを表す。オッズから見た4着以下の確率は、単勝オッズから Harville の式で出した3着以内率を 1 から引いたものである。確率そのものの高さで決めると、もともと負けやすい 4・5番人気ばかりが危険になるので、オッズとの差で決める（[15-decisions.md の 11](15-decisions.md#11-既存モデルの修正計画での直し)）。

線は、`train` の最後に `DangerThresholdStep` が、**時点ごと・人気帯ごとに**、検証データで決める。

| 手順 | 内容 |
|---|---|
| 1. 危険度を出す | 学習したモデル（平均）で検証データを予測し、1頭ずつ危険度を出す |
| 2. 線の候補を並べる | 0.00〜0.20 を 0.01 刻み（21通り） |
| 3. 候補ごとに点を付ける | 危険度が候補以上の馬を「危険」としたとき、その馬たちの物差しの値（下の表）の平均が、同じ人気帯の全体の平均をどれだけ上回るかに、√（危険とした頭数）を掛ける。危険とした馬が 30頭に満たない候補は選ばない |
| 4. いちばん点の高い候補を線にする | どの候補も選べなかった人気帯は線を持たず、その人気帯は危険と判定しない |
| 5. 点が偶然と区別できるかを確かめる | いちばん点の高い候補でも、点 ÷ 物差しの値の標準偏差が 1.645（片側 5% の目安）に届かなければ、その人気帯は線を持たない（危険と判定しない） |
| 6. 保存する | モデルの置き場所の `danger_thresholds.json` に書く。`train` の出力にも「危険の判定の線（検証データで決めた値）」の表を出す |

物差しは人気帯で違う（[15-decisions.md の 13](15-decisions.md#13-期間の分け方評価指標危険の線引き)）。

| 人気帯 | 物差し（1頭の値） | 拾う馬 |
|---|---|---|
| 1番人気 | 実際の4着以下（1 か 0） | 1番人気の中で、実際に負けやすい馬 |
| 2〜3番人気・4〜5番人気 | 実際の4着以下 − オッズから見た4着以下の確率 | オッズの割に負ける馬（買われすぎの馬） |

- **2〜5番人気を市場の見立てとの差で比べる理由。** 2〜5番人気は人気帯の中でオッズの幅が広く、危険度の高い馬ほど、オッズから見た4着以下の確率は低い（人気帯の中では強いと見られている）。そのため4着以下率そのものでは、危険度の高い馬と人気帯の全体に差が出ず、線が候補のいちばん下（0.00）に張り付いて、ほぼ全頭が「危険」になる。市場の見立てとの差で比べると、オッズの割に負ける馬を拾う線になる。こうして拾った2〜5番人気は、3着以内率は人気帯の全体とほぼ同じで、単勝・複勝の回収率が全体より低い。
- **1番人気を4着以下率そのもので比べる理由。** 1番人気は人気帯の中でオッズの幅が狭いので、どちらで比べても同じ向きになる。道具「印の成績」で比べると、4着以下率そのもので選んだ線のほうが、全券種の回収率がわずかに良かった。
- **点が偶然と区別できるかを確かめる理由。** 半年の検証データでは、人気帯によって危険度と負け方の関係がはっきり出ないことがある。そのときも、たまたま点のいちばん高かった低い線が選ばれ、人気帯のほとんどの馬が「危険」になる。関係のはっきりしない人気帯は、危険と判定しない。
- **√（頭数）を掛ける理由。** 差だけで選ぶと、数頭だけを「危険」にするごく高い線が、偶然の大きい差で選ばれやすい。頭数が多いほど、同じ差でも偶然では出にくいので、差と頭数の両方を見る。
- **30頭に満たない線を選ばない理由。** 半年の検証データで数十頭しか当てはまらない線は、偶然の幅が大きすぎるためである。
- 予測では、`predict` がこのファイルを読み、表に「オッズから見た4着以下の確率」「危険度」「危険」の列を足す。ファイルが無いモデル（2026-09-24 より前に学習したもの）では、どの馬も危険と判定しない。
- 線の値は設計書に書かない。学習し直すたびに変わるためである（穴馬の予想の「買い」の線と同じ決まり。[穴馬の 16 の 3.](../穴馬が3着以内に入るかを予想/16-evaluation.md#3-買いの線引き)）。
- **1レースで、複数の人気馬を「危険」にできる。** 線は1頭ずつに当てるので、この予想では1レースで危険とする頭数の上限は設けない（[15-decisions.md の 10](15-decisions.md#10-危険と判定する線引きを設計書に入れるか)）。印で「消」にするのは、そのうち1レース1頭だけである（買い方の設計書の [07 の 3](../買うレースと買い目を決める/07-expected-value.md#3-危険な人気馬の判定)）。

## 4. 半年ずつずらした確かめ

予想を直すときの確かめ方（7つの半年の区切りで学習し直す、区切りの日、動かし方）は、[手本の 16 の「4. 半年ずつずらした確かめ」](../近走と適性から3着以内を予想/16-evaluation.md#4-半年ずつずらした確かめ) と同じである。`walk_forward.py` の `--model` に `favorites_out_of_top3` を渡し、表は `reports/既存モデルの改善/compare/favorites_out_of_top3.md` に出る。

この予想で違うところは次のとおり。

| 項目 | この予想では |
|---|---|
| 比べる作り方 | 直す前（現行）・オッズだけで学習したモデル・基準＋補正（人気帯で分けない）・直した後（人気帯で分ける）の4つ |
| 危険の線 | 区切りごとに、その区切りの検証期間だけで、上の「3.」と同じ決め方で決める |
| 採用の基準 | 人気帯ごとに、テスト期間のログ損失がオッズだけのモデルより小さいこと。そのうえで、危険と判定した馬が、同じ人気帯の全体より実際に4着以下になりやすく、それが 1番人気でも成り立ち、頭数と複数の区切りで裏付けられること |

2026-09-24 に、この確かめで直した後の予想を採用した。結果は [15-decisions.md の 11](15-decisions.md#11-既存モデルの修正計画での直し) を参照。

ハイパーパラメータの調整のやり方は、[手本の 16 の「5.」](../近走と適性から3着以内を予想/16-evaluation.md#5-ハイパーパラメータの調整のやり方) と同じである（初期値のファイルは `src/yosou/favorites_out_of_top3/setting/default_settings.toml`）。
