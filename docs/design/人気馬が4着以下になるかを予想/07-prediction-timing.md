# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。予測のときに、人気をどうやって渡すか。

**結論: 前日（出馬表）・当日（馬体重の発表のあと）の2つの時点で、予測を出せるようにする。木曜（出走馬名表）は出さない。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（LightGBM と CatBoost に2つずつ、計4つ）。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと | この予想で出すか |
|---|---|---|---|
| 木曜（出走馬名表） | 出走馬、騎手、斤量、過去走、出走別着度数（20時ごろ）、それまでの調教 | 枠番・馬番、**人気**、馬体重、馬場状態 | 出さない |
| 前日（出馬表） | 上に加えて枠番・馬番、前日発表の馬場状態、前日発売の単勝オッズ（JRA の発表） | 馬体重、当日の馬場状態、締め切り前のオッズ | 出す |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前のオッズ | 確定オッズ、結果 | 出す |

**木曜に出さない理由。** この予想は、人気馬（1〜3番人気か 1〜5番人気）を選んでから、その馬の確率を出す。木曜は馬番も人気も決まっていないので、誰が人気馬になるかが分からない。前売りの発売は前日からなので、人気の見当を付けられるのも前日からである。

木曜にも出したい場合は、利用者が「この馬が何番人気になりそうか」を自分で決めて渡すことになる。その見立てが外れると、対象の馬から選び直しになる。やり方は [15-decisions.md](15-decisions.md#5-いつ予測するか) の「選ばなかった選び方」に残す。

## 予測のときの人気の与え方

人気は、レースの前には確定しない（確定単勝人気は、発売の締め切り後に決まる）。そのため、予測のときは、次の順で人気を決める。判断の手順は [06-flowchart.md](06-flowchart.md#図2-予測用データに人気を当てる) を参照。

| 順 | 人気の元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--pops 馬番:人気` で渡した人気 | 前日・当日。利用者が JRA の発表や投票サイトで見た人気を、そのまま渡す |
| 2 | 元DB の締め切り前の単勝オッズ（小さい順に人気を付ける） | 前日の夜（前日発売のあと）と当日。予測の前に jvdata-store で `uv run jvstore realtime --date <開催日>` を実行して、速報オッズ（`0B31`）を `o1` に取り込んでおく。1日ぶんで1分もかからない |
| 3 | 元DB の出走の行に入っている単勝人気 | **終わったレースだけ**（確定単勝人気）。これから走るレースでは空なので、止めて `--pops` を案内する |

3番目は、**終わったレースで「この予想が当たっていたか」を確かめるためにある。** 走る前の予測では、1 か 2 でしか人気が分からない。

```powershell
uv run python -m yosou.favorites_out_of_top3 predict 架空レースA --timing 当日 --pops 3:1 7:2 11:3 5:4 14:5
uv run python -m yosou.favorites_out_of_top3 predict 終わった架空レースB --timing 当日
```

（1行目は、これから走るレースの人気馬について、4着以下になる確率を出すコマンド。`--pops` は「馬番:人気」の組を並べる。コンマ区切りで `--pops 3:1,7:2` とも書ける。2行目は、終わったレースを確定単勝人気で予測し直すコマンド）

- 人気馬の範囲に入る馬番だけを渡せばよい（16頭立てなら、1〜5番人気の5頭）。渡されなかった馬番は、人気馬ではないものとして扱う。
- 渡した人気と、締め切り後に確定する人気は、ずれることがある。確定人気で選ばれる馬と、予測した馬が違うこともある。当日の締め切り直前に出し直すと、ずれは小さくなる。
- 学習データでは、確定単勝人気で人気馬を選ぶ。このずれの扱いは [11-leak-prevention.md](11-leak-prevention.md#決まり) の 5 を参照。

## 時点ごとに使う特徴量

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 75個のうち） | 特徴量の数 |
|---|---|---|
| 前日（出馬表） | 馬体重、馬体重の増減 | 73 |
| 当日（馬体重の発表のあと） | なし | 75 |

- 前日の馬場状態は、前日発表の値を使う。学習データの馬場状態は発走時点の確定の値なので、当日に馬場が変わると少しずれる。理由は [手本の 07](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量) と同じである。
- まとまり J（人気と人気の履歴）は、前日も当日も使う。どちらの時点も、上の「予測のときの人気の与え方」で人気が決まっているためである。

## 時点ごとにモデルを分ける理由

手本と同じ理由である。[手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由) を参照。1つのモデルで済ませると、前日の予測では、学習のときに値が入っていた「馬体重」を欠損値で渡すことになり、学習と予測でデータの様子がずれる。

学習データは2つの時点で同じものを使い、モデルに渡す列だけを変える（[08-training-data.md](08-training-data.md#2-列の種類)）。
