# 13 CatBoost で学習・予測するための設計

**この文書で決めること:** 07〜10 で決めた学習データ（特徴量と目的変数）を、CatBoost で学習・予測するために、CatBoost だけに必要なことを決める。**節の番号と題名は、手本の 13 とそろえてある。**

| 決めること | 結論 |
|---|---|
| 1. 学習データの渡し方 | 手本と同じ。K の 10個は数値特徴量なので、そのまま渡す |
| 2. ハイパーパラメータの初期値 | **手本より木を浅く・正則化を強くする。** 学習データが手本の 1/10 以下しかないため |
| 3. カテゴリ特徴量の値の変え方 | 手本と同じ |
| 4.〜6. 学習・予測・保存の手順 | 手本と同じ。3つの時点ごとに1つずつ、計3つのモデルを学習する。保存先は `reports/重賞の傾向と近走から3着以内を予想/models/` |

- 用語の意味は [02-glossary.md](02-glossary.md) を参照。
- 学習データ・特徴量・目的変数は LightGBM と共通で、[08-training-data.md](08-training-data.md)・[09-features.md](09-features.md)・[10-target.md](10-target.md) を参照。
- LightGBM の設計は [12-lightgbm.md](12-lightgbm.md) を参照。
- CatBoost の使い方の基本は [手本の 03 の「5. CatBoost の使い方」](../近走と適性から3着以内を予想/03-library-basics.md#5-catboost-の使い方) を参照。

## 1. 学習データの渡し方

**手本と同じである。** 列ごとの渡し方（数値はそのまま、カテゴリは文字列のまま `cat_features` に指定、カテゴリの欠損値だけ文字列「不明」、出走の少ない値はまとめない、ID 列と評価用の列は渡さない）は、[手本の 13 の「1. 学習データの渡し方」](../近走と適性から3着以内を予想/13-catboost.md#1-学習データの渡し方) を参照。

まとまり K の 10個は数値特徴量で、欠損値も出ない（傾向が無ければ 0。[09-features.md の K](09-features.md#k-重賞の傾向10個)）ので、そのまま渡す。この予想で増えるカテゴリ特徴量は無い。

前日・当日のモデルは、手本と同じく、オッズから作った基準を出発点にする（`baseline`。木曜は基準なしで学ぶ）。

## 2. ハイパーパラメータの初期値

`catboost.CatBoostClassifier` の引数名で書く。ここの値は設定ファイルの初期値で、プログラムを書き換えずに設定ファイルで変えられる（[14-hyperparameter-settings.md](14-hyperparameter-settings.md)）。値は仮で、検証データで調整する。調整のやり方は [16-evaluation.md の 5](16-evaluation.md#5-ハイパーパラメータの調整のやり方) を参照。

**手本と違う値にする理由は LightGBM と同じで、学習データが手本の 1/10 以下（約 2万5千行）しかないためである**（[12-lightgbm.md の 2](12-lightgbm.md#2-ハイパーパラメータの初期値)）。

| 引数 | 初期値 | 手本 | 意味 | 理由 |
|---|---|---|---|---|
| `loss_function` | `Logloss` | 同じ | 目的関数。二値分類 | `predict_proba` が 3着以内に入る確率を返すようにする |
| `learning_rate` | 0.03 | 0.05 | 学習率 | 小さくして慎重に学ぶ。木の数は早期終了で決まる |
| `iterations` | 3000 | 2000 | 木の数の上限 | 学習率を下げたぶん、上限を上げる。実際の数は早期終了で決まる |
| `early_stopping_rounds` | 100 | 同じ | 検証データの当たり具合が、木を 100 本足しても良くならなければ止める | 過学習を防ぐ |
| `depth` | 5 | 6 | 木の深さ | 木を浅くして、少数の行のくせを覚えないようにする |
| `l2_leaf_reg` | 5 | 3 | 葉の値を大きくしすぎないように抑える強さ | 正則化を強くする |
| `random_seed` | 42 | 同じ | 乱数の種 | 同じ学習データから同じモデルができるようにする |

1 と 0 の数の偏りを直す設定（`auto_class_weights`）は、手本と同じく使わない（[10-target.md](10-target.md#1-と-0-の数の偏り)）。

カテゴリの値をまとめる設定（LightGBM の `min_category_count` に当たるもの）は無い。CatBoost は順序付きターゲット統計で、数の少ない値を全体の割合に寄せて扱うためである（[手本の 13 の「1. 学習データの渡し方」](../近走と適性から3着以内を予想/13-catboost.md#1-学習データの渡し方)）。学習データが小さいこの予想では、この性質が LightGBM の「その他」にまとめるやり方より働きやすい。

## 3. カテゴリ特徴量の値の変え方（フローチャート）

**手本と同じである。** `CatBoostEncoder` が、欠損値だけを文字列「不明」に置き換え、それ以外をすべて文字列にする手順は、[手本の 13 の「3. カテゴリ特徴量の値の変え方（フローチャート）」](../近走と適性から3着以内を予想/13-catboost.md#3-カテゴリ特徴量の値の変え方フローチャート) を参照。

## 4. 学習のやりとり（シーケンス図）

**手本と同じである。** `TrainingWorkflow` → `CatBoostModel` → `CatBoostEncoder` → `CatBoostClassifier` の呼び出しは、[手本の 13 の「4. 学習のやりとり（シーケンス図）」](../近走と適性から3着以内を予想/13-catboost.md#4-学習のやりとりシーケンス図) を参照。この流れを行う回数も、手本と同じ3回（木曜・前日・当日）である。

## 5. 予測のやりとり（シーケンス図）

**手本と同じである。** [手本の 13 の「5. 予測のやりとり（シーケンス図）」](../近走と適性から3着以内を予想/13-catboost.md#5-予測のやりとりシーケンス図) を参照。`CatBoostModel` が返すのは「3着以内に入る確率」で、手本と同じである。

## 6. 保存

- 保存のしかた（`save_model()`・`load_model()`）は、[手本の 13 の「6. 保存」](../近走と適性から3着以内を予想/13-catboost.md#6-保存) と同じである。
- 保存するのは、3つの時点ごとのモデルと、学習に使った設定である。
- 保存先: Git の対象外の `reports/重賞の傾向と近走から3着以内を予想/models/`（[04-classes.md の 3](04-classes.md#3-パッケージ構成)）。モデルは JV-Data から作ったもので、公開しないため。
