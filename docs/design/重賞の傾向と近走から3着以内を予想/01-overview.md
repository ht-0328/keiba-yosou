# 01 重賞の傾向と近走から3着以内を予想する: 概要

**重賞（G1・G2・G3 の平地）だけを対象に、そのレースごとの傾向と、近走・適性・調教・血統と、市場の評価（単勝オッズ）から、出走馬ごとの「3着以内に入る確率」を出す予想である。**
レースごとの傾向とは、同じ重賞の過去の開催から数えた「1番人気の信頼度・前に行く馬・内枠などの有利不利が、ふつうのレースとどれだけずれているか」である。同じ重賞は、競走名ではなく特別競走番号で見分ける（[02-glossary.md](02-glossary.md)）。
狙いは、**1番人気が本当に強いのかをレースごとの傾向で疑い、人気のわりに走る（期待値の高い）馬を重賞で見つける**ことである。
**JRA-VAN のマイニング予想は使わない。**

- 作り方: 機械学習の二値分類。LightGBM と CatBoost の2つのモデルで予測確率を出し、平均する（アンサンブル）。前日・当日は、手本の予想と同じく、オッズから作った基準（オッズから見た3着以内率）を出発点にして、傾向と馬の情報で上げ下げだけを学ぶ。
- 予測する時点: 木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つのどれでも出せる。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う（[07-prediction-timing.md](07-prediction-timing.md)）。
- データの元: JRA-VAN Data Lab. の中央競馬のデータ（jvdata-store が DuckDB に貯めたもの）。
- 用語の意味: [02-glossary.md](02-glossary.md) を参照。
- 状態: 決めることは決まった（利用者の「任せる」2026-09-29。[15-decisions.md](15-decisions.md)）。プログラムは作った（`src/yosou/stakes_tendency_top3/` と、共通部品への追加。分析ツール `tools/重賞攻略/` も実装済み）。テスト（合成DB）と実データでの学習・評価まで済んでいる（学習済みモデルは Git 対象外の `reports/重賞の傾向と近走から3着以内を予想/models/`）。

手本とした予想（[手本の 01](../近走と適性から3着以内を予想/01-overview.md)）は、中央の平地の全レースの全頭について同じ確率を出す。この予想は、対象を重賞だけに絞り、そのぶん「そのレースならでは」の傾向（まとまり K）を特徴量に足したものである。重賞は毎年ほぼ同じ条件（競馬場・コース・距離・時期）で行われるので、レースごとの傾向を過去の開催から数えられる。ふつうの条件戦では、同じレースの過去の開催という考え方が成り立たないため、手本にはこのまとまりが無い。

## 1頭の例

架空の1頭を当日に予測する場合で、モデルに何を渡して何が返ってくるかを示す。傾向（まとまり K）の値の意味は [09-features.md の K](09-features.md#k-重賞の傾向10個) を参照。

> - **レース**: 2025年11月、東京・芝1800m・良の G3、16頭立て。このレース（特別競走番号は毎年同じ）の過去の開催は、DB に 14回ぶんある
> - **このレースの傾向**: 過去の開催では、1〜3番人気の複勝率が同じ G3 全体より高め（上位人気の信頼度のずれ +0.04）。前に行く馬は同じコースの平均より不利（前に行く馬のずれ −0.05）。内枠の有利不利はほぼ無し（+0.01）
> - **馬**: 4枠7番、4歳の牡馬、斤量 57kg、栗東所属（関西馬のずれ +0.03 のレースで、自分も栗東）
> - **前走**: G2 で 4着、勝ち馬と 0.3秒差、42日ぶり（中9週未満なので「休み明け」ではない）
> - **近5走**: 平均 3.8着、推定脚質は差し（前に行く馬のずれは、この馬には掛からない）
> - **このレースの経験**: 去年の同じレースで 3着（好走経験者のずれ +0.06 のレースで、自分に経験がある）
> - **調教・血統**: 手本と同じ作りの特徴量（直近は坂路で 4ハロン 53.1秒、父B の産駒の近1年の3着以内の割合 0.29 など）
> - **市場の評価**: 単勝 9.5倍で、このレースの 4番人気
>
> → モデルの予測確率: **3着以内に入る確率 0.31**

## 使うデータ

85個の特徴量を、11 のまとまり（A〜K）に分けて使う（当日の場合。木曜・前日は一部を使わない。[07-prediction-timing.md](07-prediction-timing.md#時点ごとに使う特徴量) を参照）。85個の一覧は [09-features.md](09-features.md) を参照。

- **A〜I の9つのまとまり（71個）と J（市場の評価。4個）は、手本と同じである。** 何が分かるかの見取り図は [手本の 01 の「使うデータ」](../近走と適性から3着以内を予想/01-overview.md#使うデータ) を参照。
- **K（重賞の傾向。10個）が、この予想だけのまとまりである。**

| まとまり | 何が分かるか | 特徴量の例 |
|---|---|---|
| K. 重賞の傾向 | このレースでは、上位人気・前に行く馬・内枠・休み明け・関西馬・好走経験者が、ふつうよりどれだけ走るか | 1番人気の信頼度のずれ、前に行く馬のずれ×前に行くか |

使わないデータとその理由は、[09-features.md の「使わない特徴量」](09-features.md#使わない特徴量) と [11-leak-prevention.md](11-leak-prevention.md) を参照。

## 関連する道具（分析ツール「重賞攻略」）

- 分析ツール `tools/重賞攻略/` が、この予想と同じ数え上げで、重賞ごとの「攻略ポイント」のページ（人気の信頼度・脚質・枠・ローテ・属性のずれと回収率）を、Git の対象外の `reports/重賞攻略/` に書く。
- レースの同定と傾向の数え上げの SQL は `tools/共通/stakes.py` にあり（実装済み）、分析ツールと予想モデル（[04-classes.md](04-classes.md) の `StakesTendencyRepository`）が共通で使う。同じ数え方を二重に定義しない。
- 分析ページには、特徴量にしない切り口（荒れ度・二桁人気の好走）も、持続しないという注意書き付きで載せる（[09-features.md の「使わない特徴量」](09-features.md#使わない特徴量)）。
