# 08 学習データ

**この文書で決めること:** 学習データの1行を何にするか。どのレース・どの期間の行を入れるか。期間をどう指定するか。

**結論: 1サンプル = 1つの重賞の1頭。中央競馬の平地の重賞（グレードコード A・B・C）の出走を使う。期間は `train` の引数で変えられ、既定は 2012年1月から（ウォームアップは 2011年。全体で約 2万5千行）。共通の既定（2021年8月から）とは違う既定にする。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 1. 学習データの形

架空の1つの G3（[01-overview.md の「1頭の例」](01-overview.md#1頭の例) のレース）の一部を例にすると、学習データは次の形になる。

| レースID | 馬番 | 馬齢 | 斤量 | 前走の着順 | 1番人気の信頼度のずれ | 好走経験者のずれ×好走経験があるか | …（特徴量はあと 70個以上） | 目的変数: 3着以内 | 目的変数: 1着 |
|---|---|---|---|---|---|---|---|---|---|
| 架空G3レースA | 7 | 4 | 57.0 | 4 | 0.02 | 0.06 | … | 1 | 0 |
| 架空G3レースA | 3 | 5 | 58.0 | 1 | 0.02 | 0.00 | … | 0 | 0 |
| 架空G3レースA | 12 | 4 | 56.0 | 9 | 0.02 | 0.00 | … | 1 | 1 |

- 「1番人気の信頼度のずれ」のような、まとまり K のレース単位の列は、同じレースの馬でみな同じ値になる（レースの傾向だからである）。「×好走経験があるか」のような掛けた列は、馬ごとに変わる。
- 欠損値の扱い（0 で埋めず、欠損値のまま持つ）は手本と同じである（[手本の 08 の「1. 学習データの形」](../近走と適性から3着以内を予想/08-training-data.md#1-学習データの形)）。

## 2. 列の種類

**手本と同じ4種類（ID 列・特徴量・目的変数・評価用の列）で、モデルに渡すのは特徴量と目的変数だけである。** 種類ごとの列と、ID 列・年を特徴量にしない理由は [手本の 08 の「2. 列の種類」](../近走と適性から3着以内を予想/08-training-data.md#2-列の種類) を参照。この予想で違うのは、特徴量が 85個（当日。[09-features.md](09-features.md)）になることだけである。

3つの時点（木曜・前日・当日）のモデルは、同じ学習データから、その時点で使う特徴量の列だけを渡して学習する（[07-prediction-timing.md の「時点ごとに使う特徴量」](07-prediction-timing.md#時点ごとに使う特徴量)）。

## 3. どのサンプルを入れるか

| 決まり | 内容 | 理由 |
|---|---|---|
| 対象のレース | 中央競馬の平地の重賞。グレードコード A（G1）・B（G2）・C（G3）の全部 | この予想の対象（[01-overview.md](01-overview.md)）。G1 だけでは行数が足りず、G1〜G3 で傾向の数え方は同じ |
| 障害の重賞 | 入れない（グレードコード F・G・H） | 障害は走り方が違い、平地の傾向と混ざる。障害レースはどの予想でも入れない（共通の `FlatRunnerFilter`） |
| 対象の馬 | 出走した馬。出走取消・発走除外・競走除外はサンプルにしない | 走っていない馬には目的変数が無い（手本と同じ） |
| 期間 | 「学習データの始まり」から。既定は 2012年1月1日 | 下の「4. 期間の指定」 |
| 重賞でないレース | サンプルにしないが、読む。過去走の特徴量と、傾向の基準（同じ競馬場・コース・距離の全クラスの複勝率）の計算に使う | [06-flowchart.md の図1](06-flowchart.md#図1-学習データに入れる行の選び方) |

行の選び方の判断の手順は [06-flowchart.md の図1](06-flowchart.md#図1-学習データに入れる行の選び方) を参照。重賞に新馬戦は無いので、手本の「新馬戦を入れる」の決まりはこの予想では出てこない。

**ウォームアップ期間。** 意味は手本と同じ（[手本の 08 の「3. どのサンプルを入れるか」](../近走と適性から3着以内を予想/08-training-data.md#3-どのサンプルを入れるか)）で、既定は 2011年1月から 2011年12月までの1年になる。傾向の数え上げ（まとまり K）はウォームアップ期間に依らず、DB にある確定成績のうち、そのレースより前の開催すべてから数える（[09-features.md の「使うデータの期間」](09-features.md#使うデータの期間)）。

## 4. 期間の指定

学習データの期間は、手本と同じ4つの日で区切り、`train` の引数で変えられる（共通の `TrainingPeriod`。順になっていなければエラー）。**既定の値だけが、手本（共通の既定）と違う。**

| 区切り | 引数 | この予想の既定 | 共通の既定（手本） |
|---|---|---|---|
| ウォームアップの始まり | `--warmup-from` | 2011-01-01（学習データの始まりの前の年の1月1日。省略時の決まりは手本と同じ） | 2020-01-01 |
| 学習データの始まり | `--train-from` | 2012-01-01 | 2021-08-01 |
| 検証データの始まり | `--valid-from` | 2025-01-01 | 2025-07-01 |
| テストデータの始まり | `--test-from` | 2026-01-01 | 2026-01-01 |

### 既定を 2012年1月からにした理由

**重賞は行数が少ないので、共通の既定では学習データが足りない。** 重賞は1年に約 125レース・約 1,900行しかない。

| 学習データの始まり | 学習データ（全体） | どうなるか |
|---|---|---|
| 2021年8月（共通の既定） | 約 8千行 | 85個の特徴量を学ぶには少ない。1 のサンプル（3着以内）は年に約 400 しかない |
| **2012年1月（採用）** | **約 2万5千行** | JRA-VAN の提供期間の中で、レースの同定を確かめた範囲（2011年以降。[09-features.md の「レースの同定」](09-features.md#レースの同定)）を全部使う |

- 手本は「古い年ほど今のレースと傾向がずれる」ことから 2021年8月以降に絞ったが、重賞ではそもそも行数が確保できないので、行数を優先する。古い年のずれには、ハイパーパラメータを小さめの木・強めの正則化にして備える（[12-lightgbm.md](12-lightgbm.md#2-ハイパーパラメータの初期値)・[13-catboost.md](13-catboost.md#2-ハイパーパラメータの初期値)）。
- 検証データを半年でなく1年（2025年1〜12月）にするのも同じ理由で、半年では重賞が約 60レースしかなく、当たり具合の値が偶然で大きく振れる（[16-evaluation.md の 1](16-evaluation.md#1-期間の分け方)）。
- 2021年7月27日より前の行は、ウッドチップ調教の記録が無い期間になる。手本の 09 の I の決まり（記録の無い期間は欠損値にする）のままで扱え、この予想では学習データの大半がこれに当たる。
- DB には 2011年からの中央の確定成績が要る。JRA-VAN はレース成績を 1986年から提供しているので取得できる。足りなければ jvdata-store で取得する（DB に今入っている期間を理由に期間を縮めない）。
- 期間を変えたとき、LightGBM の `min_category_count` を見直す（[12-lightgbm.md の「300 にした理由」](12-lightgbm.md#300-にした理由)）。

```powershell
uv run python -m yosou.stakes_tendency_top3 train
uv run python -m yosou.stakes_tendency_top3 train --train-from 2016-01-01
```

（1行目は、この予想の既定の期間で学習するコマンド。2行目は、学習データの始まりを 2016年に変えて学習するコマンド。ウォームアップは省略すると前の年の1月1日になる）
