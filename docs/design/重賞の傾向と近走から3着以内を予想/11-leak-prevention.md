# 11 リークを防ぐ決まり

**この文書で決めること:** 学習では当たるのに本番では当たらないモデル（リーク）にならないよう、特徴量を作るときに守る決まり。

**結論: 特徴量は、予測する時点（木曜・前日・当日。[07-prediction-timing.md](07-prediction-timing.md)）で分かることだけから作る。決まり 1〜5 は手本と同じで、この予想では、重賞の傾向（まとまり K）についての決まり 6 を足す。**

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 決まり

1〜5 は手本と同じで、[手本の 11 の「決まり」](../近走と適性から3着以内を予想/11-leak-prevention.md#決まり) を参照する（そのレースの結果を使わない、過去走と調教は開催日より前のものだけから計算する、マスタの累計の成績を使わない、学習データと予測用データを同じプログラムで作る、確定オッズは特徴量に使ってよいが予測では締め切り前のオッズになる）。この予想では、6 を足す。

**6. 重賞の傾向は、そのレースの開催日より前の開催だけから数える。**

- そのレース自身の結果はもちろん、**同じ日に先に終わったほかのレース**も数えに入れない。過去の開催を並べる SQL（`StakesTendencyRepository` が使う `tools/共通/stakes.py` の `edition_runners_sql`）が「開催日がそのレースより前」で切っているためで、この決まりはこの1か所で守る。
- 学習でも予測でも、同じ SQL で過去の開催を並べ、同じクラス（`StakesTendencyFeatures`）で帯に分けて数える（決まり 4 と同じ理屈）。予測するレースは確定前の行だが、数えるのは過去の開催だけなので、木曜の時点で値が確定している。
- 過去の開催の馬の帯は、その開催の**確定値**（確定単勝人気・確定オッズ・確定した脚質判定）で分ける。どれも過去のレースの確定値なので、リークにならない（手本の「前走の人気」と同じ理屈）。予測する馬自身の帯は、走る前に分かる値（推定脚質、締め切り前のオッズとその順位、出馬表の枠番）で分ける（[09-features.md の K](09-features.md#k-重賞の傾向51個)）。
- 前走のレースの鍵は、その馬のそのレースより前の最後の出走から引く。対象の馬の行（確定前）も、事実表のその馬の過去の出走だけから引く。
