# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使える情報が変わる。

**結論: 手本と同じく、木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする。時点ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う。材料は手本の新しい構成と同じで（木曜・前日は馬の力の材料 M と対戦レーティング O、当日は今の材料に券種ごとの支持 N と M）、どの時点にも重賞の傾向（K）を足す（2026-10-02 に作り直した。[15-decisions.md の 9](15-decisions.md#9-新しい一般の予想の材料で作り直し採用か引退かを決める2026-10-02)）。当日に券種のオッズが無いレースのために、N を使わない当日のモデルも持つ（LightGBM と CatBoost に4つずつ、計8つ）。前日・当日は、オッズから作った基準（`Top3Baseline`）を出発点にする（手本と同じ）。**

- 時点ごとに分かること（出走馬名表・出馬表・速報で何がいつ分かるか）は、[手本の 07 の「時点ごとに分かること」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに分かること) と同じである。
- 用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに使う特徴量

| 時点 | 材料（[09-features.md](09-features.md)） | 使わない特徴量 | 特徴量の数 |
|---|---|---|---|
| 木曜（出走馬名表） | 手本の木曜と同じ馬の力の材料（M）・対戦レーティング（O）と K | 手本の木曜と同じ（M のうち枠番・馬番・馬場状態・馬体重を使う10個、J の4個）と、**内枠のずれ×枠の内寄り**（枠番がまだ無い） | 199 + 9 = 208 |
| 前日（出馬表） | 手本の前日と同じ M・O・J に K。オッズから作った基準を出発点にする | M のうち馬体重を使う3個 | 210 + 10 = 220 |
| 当日（馬体重の発表のあと） | 手本の当日と同じ今の材料（A〜J・L の 79個）・N の6個・M のうち名前の重ならない 200個に K。オッズから作った基準を出発点にする | なし | 285 + 10 = 295 |
| 当日・券種オッズなし | 上から N を外したもの | N の6個 | 289 |

- 時点ごとの材料の分け方は、手本の 07（[手本の 07 の「時点ごとに使う特徴量」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量)）と同じで、K を足したところだけが違う。
- まとまり K（重賞の傾向）の 10個のうち、9個は木曜から使える。傾向は過去の開催の確定成績だけから数えるので、出走馬名表が出た時点で全部決まっているためである。「内枠のずれ×枠の内寄り」だけは自分の枠番を使うので、枠番の決まる前日からになる。
- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書く。時点のクラス（共通の `PredictionTiming`）は、時点の前後を答えるだけである。
- 木曜に馬場状態・オッズを使わない理由、前日の馬場状態が前日発表の値になる理由は、[手本の 07 の「時点ごとに使う特徴量」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量) と同じである。

## 予測のときのオッズの与え方

**手本とまったく同じである。** 利用者が `--odds 馬番:オッズ` で渡したオッズ → 元DB の締め切り前のオッズ（`jvstore realtime` で取り込む） → 無し（終わったレースなら確定オッズ）の順で決める。順序と理由は [手本の 07 の「予測のときのオッズの与え方」](../近走と適性から3着以内を予想/07-prediction-timing.md#予測のときのオッズの与え方) を参照。

```powershell
uv run python -m yosou.stakes_tendency_top3 predict 2026122806050811 --timing 当日 --odds 3:2.4 7:9.5 12:38
uv run python -m yosou.stakes_tendency_top3 predict 2025112906050911 --timing 当日
```

（1行目は、これから走る重賞の出走馬について、3着以内に入る確率を出すコマンド。2行目は、終わった重賞を確定オッズで予測し直すコマンド。レースID は架空の例。重賞でないレースを渡すと「エラー:」の1行で止まる）

## 時点ごとにモデルを分ける理由

**手本と同じである。** 1つのモデルで済ませると、学習と予測でデータの様子がずれて予測確率が狂う。理由の説明は [手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由) を参照。学習データは3つの時点で同じものを使い、モデルに渡す列だけを変える（[08-training-data.md の「2. 列の種類」](08-training-data.md#2-列の種類)）。

重賞は数が少ない（1年に約125レース）ので、「当日だけにしてモデルを2つに減らす」ことも考えられるが、重賞は前日までに予想を立てて買い目を検討することが多く、木曜・前日の予測に使い道がある。手本の決定（3つの時点すべて）をそのまま引き継ぐ（[15-decisions.md の 7](15-decisions.md#7-予測の時点と基準)）。
