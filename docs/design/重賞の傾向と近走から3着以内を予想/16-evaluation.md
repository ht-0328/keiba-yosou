# 16 当たり具合の測り方

**この文書で決めること:** 学習に使っていないデータで、この予想の当たり具合をどう測るか。学習データ・検証データ・テストデータの期間をどう分けるか。何と比べれば「当たっている」と言えるか。

**手本の 16（[../近走と適性から3着以内を予想/16-evaluation.md](../近走と適性から3着以内を予想/16-evaluation.md)）に準拠する。** 指標・1番人気の基準・「オッズだけで学習したモデル」との比べ方の考え方は同じで、この予想で違うのは次の3つである。

| 決めること | 結論 |
|---|---|
| 1. 期間の分け方 | 区分の意味は手本と同じ。既定の区切りが違う（学習 2012年1月〜2024年12月、検証 2025年1〜12月の**1年**、テスト 2026年1月〜） |
| 2. 評価指標 | 手本と同じ共通の指標。「人気最上位の馬」= 1番人気の基準が、この予想の狙いの確かめそのものになる |
| 3. 比べる基準 | 手本と同じ2つ（1番人気・オッズだけで学習したモデル）。オッズだけのモデルとは、ウォークフォワードの重賞版（1年ずつの7つの区切り）で比べる |
| 4. `evaluate` コマンド | この予想に足すコマンド。学習に使っていない期間（検証・テスト）の重賞で、複勝を期待値で買ったときの回収率（帯別）と、本命と1番人気の比べ方を出す |
| 5. ハイパーパラメータの調整 | 手本と同じ手順。検証期間を2つに変えて比べる |

用語の意味は [02-glossary.md](02-glossary.md) を参照。指標を計算するクラス（`MetricCalculator`・`ModelEvaluator`）と学習の結果の表（`TrainingReportTables`）は共通の部品である（[04-classes.md の 1](04-classes.md#1-共通の部品とこの予想だけの部品の分け方)）。

## 1. 期間の分け方

**区分（ウォームアップ・学習・検証・テスト）の意味と、時期で分ける理由（レースを混ぜてくじで分けない）は、手本の [16 の「1. 期間の分け方」](../近走と適性から3着以内を予想/16-evaluation.md#1-期間の分け方) と同じである。** 既定の区切りだけが違う（[08-training-data.md の 4](08-training-data.md#4-期間の指定)）。

| 区分 | 何に使うか | この予想の既定 |
|---|---|---|
| ウォームアップ | 過去走の特徴量を計算するためだけに読む。サンプルにしない | 2011年1月〜2011年12月 |
| 学習 | モデルの `fit` に渡す | 2012年1月〜2024年12月 |
| 検証 | 早期終了の判断と、当たり具合を見る。直すときはここで比べる | **2025年1〜12月（1年）** |
| テスト | 最後に1回だけ確かめる。直す判断には使わない | 2026年1月〜 |

**検証を半年でなく1年にする理由。** 重賞は半年に約 60レースしかなく、半年の3着以内率や回収率は偶然で大きく振れる。1年（約 125レース・約 1,900行）にして、偶然の幅を狭める。それでも手本の検証データ（半年で約 2万行）よりずっと少ないので、値の小さな差で判断しない。

## 2. 評価指標

**手本と同じである。** どの予想でも共通の指標（ログ損失・AUC・Brier と、確率1位の馬の3着以内率・複勝回収率、人気最上位の馬の同じ値、人気の中での AUC）を、時点ごとに LightGBM・CatBoost・平均の3行で出す。指標の意味は [穴馬の 16 の「2. 評価指標」](../穴馬が3着以内に入るかを予想/16-evaluation.md#2-評価指標)、表の読み方は [手本の 16 の「2. 評価指標」](../近走と適性から3着以内を予想/16-evaluation.md#2-評価指標) を参照。

この予想での読み方は次のとおり。

- **「人気最上位の馬」= 各レースの1番人気の3着以内率・複勝回収率が、そのままこの予想の狙いの確かめになる。** この予想の狙いは「1番人気を疑い、人気のわりに走る馬を見つける」ことなので、本命（確率1位）の値がこの基準を上回らなければ、狙いは果たせていない。
- 本命が1番人気と同じ馬になったレースの割合も見る。ほぼ全レースで同じなら、傾向（まとまり K）は市場の見立てに何も足せていない。
- 対象が重賞だけなので、どの値も行数が少ない。半年・1年の1つの値で決めず、`evaluate`（下の 4）で検証とテストの両方を見る。

## 3. 比べる基準

**手本と同じ2つである**（[手本の 16 の「3. 比べる基準」](../近走と適性から3着以内を予想/16-evaluation.md#3-比べる基準)）。

| 基準 | この予想では |
|---|---|
| 1番人気 | `train` と `evaluate` の出力で比べる（上の 2） |
| オッズだけで学習したモデル | 特徴量をオッズから出した値と出走頭数だけにして、同じ手順で学習したモデル。**傾向（K）と馬の情報が、オッズで分かること以上を足しているか**が分かる。手本と同じく、ウォークフォワードで比べる。この予想の区切りは1年ずつの7つ（テストは 2020年〜2026年。重賞はレースが少ないため）で、研究「既存モデルの改善」の仕組みで回す。時点は木曜・前日・当日の3つ全部で回し、木曜はオッズが無いので当日のオッズだけのモデルと比べる。結果と判断は [15-decisions.md の 8](15-decisions.md#8-当たり具合の確かめ方) |

## 4. `evaluate` コマンド（学習に使っていない期間での確かめ）

`train` は検証データの指標しか出さない（手本と同じ）。この予想では、買い方の判断に使える形の確かめを `evaluate` コマンド（[04-classes.md の 4](04-classes.md#4-この予想だけのクラスの一覧)）にする。

**何をするか。** 保存したモデルで、学習に使っていない期間（検証・テスト）の重賞を予測し、期間 × 時点ごとに次の2つの表を出す。

| 表 | 中身 | 見ること |
|---|---|---|
| 本命と1番人気の比べ方 | 本命（確率1位）の3着以内率・複勝回収率、1番人気の同じ値、本命が1番人気と違ったレースの数と、そのレースでの本命・1番人気それぞれの3着以内率 | 本命が1番人気の基準を上回るか。1番人気と違う馬を選んだとき、市場より正しいか |
| 期待値の帯ごと（前日・当日だけ） | 共通の `ValueBands` の表。複勝の期待値の帯ごとに、頭数・期待値の平均・予想の的中率・実際の的中率・回収率 | **複勝を期待値で買ったときの回収率。** 期待値の帯が上がるほど回収率も上がり、期待値の平均に近いか |

- 複勝の期待値は、手本と同じ作り（平均の確率 → 複勝的中の確率 → 学習のときに保存した見込みの倍率を掛ける）である。
- 引数は `train` と同じ期間の4つと、共通の引数（[04-classes.md の 5](04-classes.md#5-コマンドの引数)）。学習のときと同じ区切りを渡すと、モデルが見ていない期間で測れる。
- 検証期間は早期終了に使っているので、最後の判断はテスト期間の値で行う（手本と同じ考え方）。
- 数値は Git の対象外の `reports/重賞の傾向と近走から3着以内を予想/` に置き、設計書には書かない。

## 5. ハイパーパラメータの調整のやり方

**手本と同じ手順である**（[手本の 16 の「5. ハイパーパラメータの調整のやり方」](../近走と適性から3着以内を予想/16-evaluation.md#5-ハイパーパラメータの調整のやり方)）。自動の探索はせず、設定ファイルを変えて `train --config` で学習し、2つの検証期間で初期値と比べ、両方で良くなったときだけ初期値のファイル（[14-hyperparameter-settings.md](14-hyperparameter-settings.md)）を直す。

この予想の2つの検証期間は、既定（2025年1〜12月）と、`--valid-from 2024-01-01 --test-from 2025-01-01`（2024年1〜12月）にする。検証が1年ずつなのは、上の 1 と同じ理由である。

```powershell
uv run python -m yosou.stakes_tendency_top3 train --config 試す設定.toml --models reports/重賞の傾向と近走から3着以内を予想/models-試し
uv run python -m yosou.stakes_tendency_top3 train --config 試す設定.toml --models reports/重賞の傾向と近走から3着以内を予想/models-試し --valid-from 2024-01-01 --test-from 2025-01-01
```

（1行目は、試す設定で学習し、既定の検証期間（2025年）で当たり具合を出すコマンド。2行目は、検証期間を 2024年に変えて同じことをするコマンド。どちらも本番のモデルとは別の置き場所に書く）

| しないこと | 理由と、代わりにすること |
