# 16 当たり具合の測り方と、買い分けの確かめ方

**この文書で決めること:** 学習に使っていないデータで、1番人気の買い分けが役に立つかをどう確かめるか。どんな表を出し、どう読むか。判定ごとに、単勝と複勝にいくら賭けるか。

| 決めること | 結論（実装は `YearlyEvaluation`・`EvaluationTables`・`StakePlan`） |
|---|---|
| 1. 評価のしかた | 1年ごとのウォークフォワード。評価する年（2019〜2026年）ごとに、2017年1月からその前年までで学習し直し、その年の1番人気を判定する |
| 2. 出す表 | 年ごとの結果・判定ごとの成績・単位ごとの結果の3つ。1頭ずつの表も CSV で書ける |
| 3. 表の見方 | 消した1番人気の馬券外率、単勝も買った1番人気の勝率、買い分けたときの回収率を、それぞれ1番人気全体・全部を同じ買い方で買ったときと比べる |
| 4. 買い方と掛け金 | 「単勝と複勝」は単勝 100円・複勝 200円、「複勝だけ」は複勝 300円、「消す」は買わない |
| 5. 単位で分けない場合との比べ方 | 設定で `min_rows` を大きくすると芝ダごとに1つの単位になる。この形で評価して比べる |
| 6. 方針を決める年と確かめる年 | 評価の年を、方針を決める年（2019〜2023年）と確かめる年（2024〜2026年）に分ける。方針は前の年だけで選び、後の年でその方針のまま確かめる。**確かめた結果: 今の方針も、選び直した方針も、確かめる年で「全部を複勝だけで買う」を上回れなかった** |
| 7. 締め切り前のオッズで1番人気を選んだとき | `evaluate --favorite-odds 締め切り前` で、発走の 10分前までの締め切り前のオッズで1番人気を選んで判定し、確定オッズで選んだときと比べる。**確かめた結果: 1番人気が入れ替わるレースは少なくないが、買い分けの回収率の下がり方は1点に満たない** |
| 8. 近さの測り方を見直すときの、採用の基準と選び方 | 確かめる年で (a) 消した馬の馬券外率が全体より高く、(b) 買い分けの回収率が全部を複勝だけで買うのを上回る、の両方を満たせば採用する。候補は方針を決める年だけで比べて1つに絞り、確かめる年は1回だけ見る |

用語の意味は [02-glossary.md](02-glossary.md) を参照。評価のクラスは [04-classes.md](04-classes.md#evaluation--掛け金と成績の表)、評価の流れは [05-sequence.md の図2](05-sequence.md#図2-1年ごとの評価) を参照。**設計書には、評価の数値を書かない。** 数値は PR と Git の対象外の `reports/1番人気を買うか消すかを予想/` に置く。

## 1. 1年ごとの評価（ウォークフォワード）

```powershell
uv run python -m yosou.favorite_buy_or_fade evaluate --out reports/1番人気を買うか消すかを予想/evaluation.md --rows-out reports/1番人気を買うか消すかを予想/evaluation-rows.csv
```

（1年ごとの評価をして、3つの表を `--out` に、判定した1番人気1頭ずつの表を `--rows-out` の CSV に書くコマンド）

| 評価する年 | 学習に使う期間 | ウォームアップ |
|---|---|---|
| 2019年 | 2017年1月〜2018年12月 | 2016年 |
| 2020年 | 2017年1月〜2019年12月 | 2016年 |
| … | … | … |
| 2026年 | 2017年1月〜2025年12月 | 2016年 |

- 評価する年ごとに、単位の決め方・物差し・3つのグループのモデルを、その前年までのデータだけで作り直す（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 7・8）。評価する年のデータは、その年の学習に入らない。
- 年の範囲は、設定ファイルの `[evaluation]`（`train_first_year`・`first_year`・`last_year`）で変えられる（[14-hyperparameter-settings.md](14-hyperparameter-settings.md#設定ファイルの形)）。
- **1つの年だけで決めない理由。** 1年ぶんの1番人気を単位で分けると、単位ごとの頭数は少なく、偶然の幅が大きい。年ごとに結果が同じ向きかを見るために、8つの年で評価する。
- **評価の成績は、本番より少し良く出る。** 評価の1番人気は確定単勝人気で選ぶためである。本番では締め切り前の人気で選ぶので、選ぶ馬が少し違う（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 6）。オッズは距離に使わない（オッズなしで予想する）。どれだけ違うかは、下の「7.」で確かめた。
- **方針を選ぶのに使った年は、未知のデータとして読まない。** 初めの方針（消しの線 5点）は、2025年の評価の結果を見て決めた。そこで、方針を決める年と確かめる年を分けた（下の「6.」）。

## 2. 出す表

| 表 | 1行 | 作るクラス |
|---|---|---|
| 年ごとの結果 | 評価した年1つ（最後に全部の年を合わせた「全体」の行） | `EvaluationTables.by_year()`・`DecisionSummary` |
| 判定ごとの成績（全部の年） | 判定1つ（消す・単勝と複勝・複勝だけ）と「全体」 | `EvaluationTables.by_kind()`・`KindSummary` |
| 単位ごとの結果（全部の年） | 単位1つと「全体」。単位は評価の年ごとに決め直すので、年によって入る距離が違うことがある | `EvaluationTables.by_unit()`・`DecisionSummary` |

年ごとの結果と単位ごとの結果の列（`DecisionSummary`）:

| 列 | 意味 |
|---|---|
| 1番人気 | 判定した1番人気の頭数 |
| 消した数・消した馬の馬券外率・全体の馬券外率 | 消した1番人気が、本当に馬券外になりやすかったか |
| 単勝も買った数・単勝も買った馬の勝率・全体の勝率 | 「単勝と複勝」にした1番人気が、本当に勝ちやすかったか |
| 買い分けの投資・買い分けの回収率 | 判定どおりに、下の「4.」の掛け金で買ったとき |
| 全部を単勝と複勝で買った回収率・全部を複勝だけで買った回収率 | 同じ1番人気を全部、同じ買い方で買ったとき（比べる相手） |

判定ごとの成績の列（`KindSummary`）は、頭数・勝率・複勝率・馬券外率・単勝回収率・複勝回収率である。回収率は、どの判定の馬も単勝・複勝を 100円ずつ買ったとみなしたもので、判定が着順を分けられているかを見るためのものである（掛け金の配分は使わない）。

## 3. 表の見方

| 見ること | 見る列 | 良い向き |
|---|---|---|
| ① 消しは当たっているか | 消した馬の馬券外率と、全体の馬券外率 | 消した馬の馬券外率が、全体より高い |
| ② 単勝を足すのは当たっているか | 単勝も買った馬の勝率と、全体の勝率 | 単勝も買った馬の勝率が、全体より高い |
| ③ 買い分けると儲かるか | 買い分けの回収率と、全部を同じ買い方で買った回収率 | 買い分けの回収率が、どちらの全部買いよりも高い |
| ④ 判定が着順を分けているか | 判定ごとの成績の、勝率・複勝率・馬券外率 | 「消す」の馬券外率がいちばん高く、「単勝と複勝」の勝率がいちばん高い |

- 払戻は、評価用の列の確定の払戻（100円あたり）を使う。7頭以下のレースの複勝は2着までしか払戻が無いので、3着の1番人気の複勝は外れになる。
- **良いと判断する目安。** 全体の行で ①〜③ がそろって良い向きで、年ごとの結果でも、多くの年で同じ向きになっていること。1つの年や1つの単位だけで良く見えても、頭数が少ないと偶然の幅が大きい。
- 方針（線・重み・k など）をいくつも試して、いちばん良かったものを選ぶと、その成績は本番より良く出る（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 9）。方針を比べるときは、方針を決める年の行だけを見る（下の「6.」）。

## 4. 買い方と掛け金

判定ごとに、単勝と複勝にいくら賭けるかを決める（`StakePlan`。設定ファイルの `[stake]`）。

| 判定 | 単勝 | 複勝 | 1頭あたりの合計 |
|---|---|---|---|
| 消す | 0円 | 0円 | 0円 |
| 単勝と複勝 | 100円 | 200円 | 300円 |
| 複勝だけ | 0円 | 300円 | 300円 |

- 買う1番人気の合計をそろえるのは、単勝を足すかどうかだけで比べられるようにするためである。
- 複勝を厚くするのは、1番人気の複勝は当たりやすく、単勝より払戻の上下が小さいためである。
- 払戻 = 掛け金 ÷ 100 × 100円あたりの払戻。回収率 = 払戻の合計 ÷ 投資の合計。

## 5. 単位で分けない場合との比べ方

芝ダート × 距離で分けることは利用者が決めた。分けたことが役に立っているかを確かめるために、分けない場合とも比べる（[15-decisions.md の 11](15-decisions.md#11-単位で分けない場合との比べ方)）。

設定ファイルで `[unit]` の `min_rows` をとても大きくすると、どの距離も頭数が足りなくなり、芝とダートがそれぞれ1つの単位になる（[06-flowchart.md の図3](06-flowchart.md#図3-使う単位を決める)）。

```toml
[unit]
min_rows = 1000000
```

この設定で `evaluate` を実行し、年ごとの結果の表を、初期値の方針の表と並べて比べる。比べた結果は PR に載せる。

## 6. 方針を決める年と確かめる年

方針（判定の線・k・重みなど）を評価の結果を見て選ぶと、選ぶのに使った年の成績は良く出る。どの年も方針選びに使うと、未知のデータでの成績が分からなくなる。そこで、評価の年を2つに分ける（`EvaluationPeriods`。設定の `[evaluation]` の `tune_last_year`）。

| 期間 | 年 | 使い方 |
|---|---|---|
| 方針を決める年 | `first_year`〜`tune_last_year`（2019〜2023年） | 方針をいくつも試し、この期間の行だけを見て、どれにするかを選ぶ |
| 確かめる年 | `tune_last_year` の次の年〜`last_year`（2024〜2026年） | 選んだ方針のまま評価し、方針を決める年と同じ向きの結果が出るかを見る。**この期間を見て方針を選び直さない** |

- 年ごとの結果の表には、年ごとの行のあとに「方針を決める年」「確かめる年」「全体」のまとめの行が並ぶ。判定ごとの成績と単位ごとの結果は、期間ごとに別の表になる。
- 学習のしかたは変わらない（評価する年ごとに、その前年までで学習し直す）。分けるのは、結果の読み方である。
- 方針を比べるときは、変えたい項目を書いた設定ファイルを `--config` で渡して `evaluate` し、方針を決める年の行を並べる。`last_year` を `tune_last_year` と同じにすると、確かめる年を計算しないので、見てしまうこともない。

### 確かめた結果（2026-09-30）

方針を決める年だけで、k（5・10・20・30）と消しの線・単勝の線の組み合わせを比べ、先に決めておいた選び方（消した馬の馬券外率が全体より高く、5年のうち3年以上で両方の全部買いを上回るもののうち、買い分けの回収率がいちばん高いもの）で選び直した。選んだのは k = 30・消しの線 7.5点・単勝の線 5点だった。数値は `reports/1番人気を買うか消すかを予想/残課題の確認（2026-09-30）.md`。

| 方針 | 確かめる年で、消した馬は馬券外になりやすかったか | 単勝を足した馬は勝ちやすかったか | 買い分けると回収率は上がったか |
|---|---|---|---|
| 今の方針（k 10・消し 5点・単勝 0点） | 少しなりやすかった。ただし消した馬の勝率はむしろ高かった | いいえ（全体と同じくらい） | いいえ。全部を複勝だけで買うより低かった |
| 選び直した方針（k 30・消し 7.5点・単勝 5点） | 少しなりやすかった。ただし年によっては逆だった | はい。ただし単勝を足す馬がとても少ない | 変わらなかった。ほとんどの馬を複勝だけで買う形になり、全部を複勝だけで買うのと同じだった |

- **結論: 今の方針の買い分けは、確かめる年では効いていない。** 消した1番人気が少し馬券外になりやすい、という向きは確かめる年でも残ったが、回収率を上げるほどではなかった。方針を選び直しても、「全部を複勝だけで買う」と同じところまでしか届かなかった。
- 方針を決める年で差が出ていた組み合わせも、差はごく小さかった。線や k を動かすだけでは、この予想の回収率は上がらないと考える。近さの測り方（特徴量の重み・単位の分け方）を見直すのが次の手になる。
- 初期値（`default_settings.toml`）は変えていない。選び直した方針は `reports/1番人気を買うか消すかを予想/方針を決める年と確かめる年/選び直した方針.toml` にある。

## 7. 締め切り前のオッズで1番人気を選んだとき

評価の1番人気は確定単勝人気で選ぶが、本番では締め切り前のオッズで選ぶ。その違いで、判定と回収率がどれだけ変わるかを確かめる。

```powershell
uv run python -m yosou.favorite_buy_or_fade evaluate --favorite-odds 締め切り前 --out reports/1番人気を買うか消すかを予想/締め切り前のオッズでの評価.md
```

（1番人気を、発走の 10分前までに発表された締め切り前の単勝オッズで選んで判定し、確定オッズで選んだときとの違いの表も出すコマンド。`--minutes` で何分前かを変えられる）

| 決めたこと | 内容 |
|---|---|
| 締め切り前のオッズ | 元DB の時系列オッズ（`o1`・`o1__単勝オッズ`）の、データ区分 1（中間）・2（前日売最終）の断面のうち、発走の `--minutes` 分前（既定 10分）までに発表された、いちばん新しいもの（`PreDeadlineFavoriteRepository`）。データ区分 3（最終）は締め切りの時点の断面で、買う時点には見えないので使わない |
| 締め切り前の1番人気 | その断面で単勝オッズがいちばん低い馬。同じオッズの馬が並んだら、どれも1番人気にする（確定単勝人気で1番人気が2頭いるときと同じ扱い） |
| 学習 | いつも確定の1番人気で行う。締め切り前の断面は過去1年ほどしか無く、学習データの期間ぶんがそろわないため（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 6） |
| 比べるレース | 締め切り前の断面があり、その1番人気が出走したレースだけ。確定の1番人気も同じレースだけにそろえる（`FavoritePicks`） |
| 出す表 | いつもの3つの表（締め切り前の1番人気で判定したもの）に加え、1番人気と判定が変わったレースの数、選び方ごとの結果（同じレース・1番人気が入れ替わったレースだけ）（`PickComparison`） |

- 同じ馬なら特徴量も同じなので、判定も同じになる。違いは、1番人気が入れ替わったレースからだけ生まれる。
- 共通の `AnnouncedOddsRepository` は使わない。予測する1レースだけを読み、締め切りの時点の断面も含めて、何分前かで区切らずにいちばん新しい断面を選ぶためである。

### 確かめた結果（2026-09-30）

元DB に締め切り前の断面がある過去1年（2025年9月〜2026年9月）のほぼ全部のレースで比べた。数値は `reports/1番人気を買うか消すかを予想/残課題の確認（2026-09-30）.md`。

- **1番人気が入れ替わるレースは少なくない。** 入れ替わったレースの一部では、判定も変わった。
- **それでも、買い分けの回収率の下がり方は1点に満たなかった。** 確定オッズで評価した成績は本番より良く出るが、その差は小さい。消した馬が少し馬券外になりやすい、という向きも変わらなかった。
- 下がる元は、入れ替わったレースにある。締め切り前には1番人気だったが、確定では1番人気でなくなった馬は、勝つ割合がはっきり低い。単勝を足す買い方ほど、この影響を受ける。
- **結論: 確定オッズでの評価は、判定の良し悪しを読むのには使ってよい。** ただし回収率は、本番では少し下がる前提で読む。上の「6.」のとおり、今の方針は確定オッズでの評価でも全部を複勝だけで買うのを上回れていないので、締め切り前のオッズで選べばなおさら上回れない。

## 8. 近さの測り方を見直すときの、採用の基準と選び方

「6.」の結論（線や k を動かすだけでは回収率は上がらない）を受けて、近さの測り方（特徴量の重み・単位の分け方・距離の種類）を見直す。利用者が見直すと決めた（2026-10-02）。**k近傍法のまま直し、ほかの手法（勾配ブースティングなど）には置き換えない**（利用者の指定）。**採用の基準と選び方は、結果を見る前にここに固定した。**

### 採用の基準（確かめる年で、1回だけ見る）

選んだ1つの測り方を確かめる年（2024〜2026年）で評価し、次の**両方**を満たせば採用する。

| | 基準 | 見る列 |
|---|---|---|
| (a) 消しが効いている | 消した1番人気の馬券外率が、全体の1番人気の馬券外率より高い | 年ごとの結果の「確かめる年」の行 |
| (b) 買い分けると儲かる | 買い分けの回収率が、全部を複勝だけで買った回収率を上回る | 同上 |

- 確かめる年は、選んだ1つについて1回だけ見る。満たさなくても、確かめる年を見て選び直さない。
- 満たさなければ、**買い分けは使わない。** 消しの判定だけを参考として出し、設計書 01・15・16 と評価の表にその旨を書く。

### 選び方（方針を決める年だけで）

候補ごとに、方針を決める年（2019〜2023年）で評価し、次の順で1つに絞る。

1. 候補ごとに k を 10・20・30 で評価し、1頭ずつの3つの点数を残す。消しの線は 0〜15点（2.5点刻み）、単勝の線は 0・5・10点を、その点数から判定し直して振る。
2. 方針を決める年の合計で (a)(b) を満たし、(b) を5年のうち3年以上で満たし、消した数が1番人気の 5% 以上（ほとんど買い分けない形を除く）の組み合わせを残す。
3. 残った中で、買い分けの回収率がいちばん高いものを選ぶ。同じなら、消した馬の馬券外率が高いもの。
4. どの候補も 2. を満たさなければ、今の測り方のまま「買い分けは使わない」とする（確かめる年は見ない）。

### 候補

| 区分 | 候補 | 何を変えるか |
|---|---|---|
| 基準線 | 今の測り方 | 変えない（まとまりの重み A〜J 1.0、one-hot、標準化、単位は 500頭以上の距離） |
| 特徴量の重み | 列ごとの重み（馬券外との AUC） | 単位の学習データで、距離に使う列ごとに「馬券外か」との AUC を出し、\|2 × AUC − 1\|（0〜1。関係が無ければ 0）を重みにして掛ける。馬券外と関係の弱い列が距離に効かなくなる |
| 特徴量の重み | 列を絞る（AUC の上位） | 上と同じ AUC で、上位 20列だけを重み 1 で使い、ほかは使わない |
| 特徴量の重み | まとまりの重みの組 | 近走と人気の履歴を重く（D・E・J = 2）／レースの条件と馬のことを外す（A・B = 0）／この条件での経験を重く（F = 2）の3つ |
| 単位 | 粗く | 芝・ダートそれぞれ1つ（`min_rows` をとても大きく。「5.」と同じ） |
| 単位 | 細かく | `min_rows = 300` |
| 単位 | 単位なし | 全部を1つの単位にし、芝ダと距離は特徴量として距離に入れる |
| 距離の種類 | 順位で標準化 | 数の列を、学習データの中の順位（0〜1）に直してから、ばらつき 1 にそろえる。外れ値に引きずられない |
| 距離の種類 | カテゴリを馬券外率に | one-hot の代わりに、その値の学習データでの馬券外率（数の列として標準化） |
| 組み合わせ | 区分ごとの最良の組み合わせ | 上の区分（重み・単位・距離の種類）ごとに基準線を上回った候補があれば、それらを合わせた1つ |

- 列ごとの重みと馬券外率は、単位ごとに、その年の学習データ（評価する年の前年まで）だけから出す（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 8）。
- 候補の数値の表は Git の対象外の `reports/1番人気を買うか消すかを予想/近さの測り方の比べ/` に置く。設計書には、どれを選び、基準を満たしたかだけを書く（[15-decisions.md の 14](15-decisions.md#14-近さの測り方の見直し)）。
