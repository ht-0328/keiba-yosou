# 07 いつ予測するか

**この文書で決めること:** どの時点の特徴量で近さを測るか。予測のときに、どの馬を1番人気とするか。

**結論: 特徴量の時点は、当日（馬体重の発表のあと）を初期値にする。前日（出馬表）は設定ファイルで選べる。1つの設定で学習するのは1つの時点で、予測はその学習の時点を使う。木曜（出走馬名表）は、誰が1番人気かが分からないので使えない（設定に書くとエラー）。1番人気は、学習と評価では確定単勝人気が 1 の馬、予測では渡された人気か、単勝オッズのいちばん低い馬とする。**（主担当が決めた。[15-decisions.md の 2](15-decisions.md#2-特徴量の時点)）

用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに分かること

| 時点 | 分かること | まだ分からないこと | この予想で使えるか |
|---|---|---|---|
| 木曜（出走馬名表） | 出走馬、騎手、斤量、過去走、出走別着度数（20時ごろ）、それまでの調教 | 枠番・馬番、**単勝オッズ（誰が1番人気か）**、馬体重、馬場状態 | 使えない |
| 前日（出馬表） | 上に加えて枠番・馬番、前日発表の馬場状態、前日発売の単勝オッズ | 馬体重、当日の馬場状態、締め切り前のオッズ | 設定で選べる |
| 当日（馬体重の発表のあと） | 上に加えて馬体重とその増減、当日の馬場状態、締め切り前のオッズ | 確定オッズ、結果 | **初期値** |

**木曜に使えない理由。** この予想は、1番人気を選んでからその馬の買い方を決める。木曜は前売りが始まっておらず、誰が1番人気になるかが分からない。この予想はオッズなしで予想するが、1番人気を選ぶのにはオッズ（人気）が要る。

**当日を初期値にした理由。** 締め切りに近いほど、予測に使う1番人気が、学習に使った「確定の1番人気」とずれにくいためである（[11-leak-prevention.md](11-leak-prevention.md#決まり) の 6）。前日にも判定を見たいときは、`[features]` の `timing` を「前日」にした設定ファイルで学習し直す（[14-hyperparameter-settings.md](14-hyperparameter-settings.md)）。

## 予測のときの1番人気の決め方

`predict` は、次の順で人気を決め、人気が 1 の馬を1番人気とする（共通の `OddsResolver`・`PopularityApplier`）。

| 順 | 人気の元 | どの時点で使えるか |
|---|---|---|
| 1 | 利用者が `--pops 馬番:人気` で渡した人気 | 前日・当日。利用者が JRA の発表や投票サイトで見た人気を渡す |
| 2 | 利用者が `--odds 馬番:オッズ` で渡した単勝オッズの小さい順 | 前日・当日 |
| 3 | 元DB の締め切り前の単勝オッズの小さい順 | 前日の夜（前日発売のあと）と当日。予測の前に jvdata-store で `uv run jvstore realtime --date <開催日>` を実行して取り込んでおく |
| 4 | 元DB の出走の行に入っている単勝人気 | **終わったレースだけ**（確定単勝人気）。答え合わせのために使う |

```powershell
uv run python -m yosou.favorite_buy_or_fade predict --date 2026-09-27 --venue 中山 --race 11 --odds 1:12.5 2:3.8 3:2.4 4:25.0 5:7.1
uv run python -m yosou.favorite_buy_or_fade predict 2025052506050411
```

（1行目は、これから走るレースの1番人気（この例では 2.4倍の3番）について、単位・3つの点数・判定を出すコマンド。`--odds` は「馬番:オッズ」の組を並べ、1番人気を決めるためだけに使う。2行目は、終わったレースを rid で指定して、確定の人気で1番人気を選んで判定し直すコマンド）

- **オッズは、1番人気を決めるためだけに使う。** 近さの計算には使わない（オッズなしで予想する。[12-neighbor-distance.md の「4.」](12-neighbor-distance.md#4-特徴量の重み)）。`--odds` を渡すなら、1番人気がどの馬か分かるよう、少なくとも人気の上位の馬を含めて渡す。
- 人気もオッズも分からないレースは止めて、`--pops` か `--odds` を渡すよう案内する。
- 予測したあとにオッズが動いて、1番人気が別の馬に替わることがある。そのときは、締め切りに近い時点で予測を出し直す。

## 時点ごとに使う特徴量

| 時点 | 使わない特徴量（[09-features.md](09-features.md) の 78個のうち） | 距離に使う特徴量の数（名前の5個・人気順位・K の3個を除いたあと） |
|---|---|---|
| 前日（出馬表） | 馬体重、馬体重の増減 | 67 |
| 当日（馬体重の発表のあと） | なし | 69 |

- 前日の馬場状態は、前日発表の値を使う。学習データの馬場状態は発走時点の確定の値なので、当日に馬場が変わると少しずれる。理由は [手本の 07 の「時点ごとに使う特徴量」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量) と同じである。
- 単位の中でどの行も同じ値になる列（まとめていない単位の「距離」、単位の中の「芝ダ」など）は、距離に差を生まない（[12-neighbor-distance.md の「3.」](12-neighbor-distance.md#3-尺度をそろえる標準化)）。

## 時点ごとにモデルを分ける理由

考え方は手本と同じである（[手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由)）。k近傍法では、距離は列ごとの差を足して測る。前日の予測で、学習のときにあった「馬体重」の列を空のまま測ると、距離の意味が学習と変わってしまう。そこで、学習した時点の列だけで行列を作り、予測も同じ列で測る（`SimilarityModelSet` が、学習した方針の時点の列だけを使う）。
