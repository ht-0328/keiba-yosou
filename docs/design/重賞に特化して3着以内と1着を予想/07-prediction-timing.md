# 07 いつ予測するか

**この文書で決めること:** 予測をいつ行うか。いつ行うかで、特徴量に使える情報が変わる。

**結論: 手本と同じく、木曜（出走馬名表）・前日（出馬表）・当日（馬体重の発表のあと）の3つの時点のどれでも、予測を出せるようにする。時点ごと・目的変数（3着以内・1着）ごとに、その時点で分かる特徴量だけで学習した別のモデルを使う。材料は時点ごとに手本と同じ組み合わせで、どの時点にも重賞の格と実績（W）とその重賞の傾向（K）を足す。当日に券種のオッズが無いレースのために、N を使わない当日のモデルも持つ。モデルは、4つ（木曜・前日・当日・当日の券種オッズなし）× 目的変数2つ × LightGBM と CatBoost で 16個になる。前日・当日は、オッズから作った基準（3着以内は `Top3Baseline`、1着は `WinBaseline`）を出発点にする（手本と同じ）。**

- 時点ごとに分かること（出走馬名表・出馬表・速報で何がいつ分かるか）は、[手本の 07 の「時点ごとに分かること」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに分かること) と同じである。
- 用語の意味は [02-glossary.md](02-glossary.md) を参照。

## 時点ごとに使う特徴量

| 時点 | 材料（[09-features.md](09-features.md)） | この予想で使わない特徴量 | 特徴量の数（3着以内 / 1着） |
|---|---|---|---|
| 木曜（出走馬名表） | 手本の木曜と同じ（M・O・P・T）に W と K | 手本の木曜と同じものと、**K のうち枠・単勝オッズ・人気の切り口の 12個**（枠番とオッズがまだ無い） | 223 + 14 + 39 = 276 / 276 |
| 前日（出馬表） | 手本の前日と同じ（M・O・J。3着以内のモデルは S も）に W と K。オッズから作った基準を出発点にする | 手本の前日と同じ（M のうち馬体重を使う3個） | 215 + 65 = 280 / 210 + 65 = 275 |
| 当日（馬体重の発表のあと） | 手本の当日と同じ（A〜J・L・N・M。1着のモデルは Q も）に W と K。オッズから作った基準を出発点にする | なし | 285 + 65 = 350 / 295 + 65 = 360 |
| 当日・券種オッズなし | 上から N を外したもの | N の6個 | 279 + 65 = 344 / 289 + 65 = 354 |

- **手本の材料の時点ごとの分け方は、手本の 07 と同じである**（[手本の 07 の「時点ごとに使う特徴量」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量)）。手本の材料が変わったら、この予想の一覧も同じ形で変わる（一覧は手本の一覧に W と K を足して作る。[04-classes.md の 4](04-classes.md#feature--まとまり-w-と特徴量の一覧)）。
- **W の 14個は、すべて木曜から使える。** 格・重量種別はレースの条件で、出走馬名表の時点で決まっている。斤量（トップハンデとの差）も出走馬名表で分かる（あとで取消が出ると、いちばん重い馬が変わることがある）。重賞での実績・同じ重賞の経験・前走の格は、開催日より前の確定成績から数える。
- **K の 51個のうち 39個は木曜から使える。** 枠・単勝オッズ・人気の切り口の 12個は、自分の枠番とオッズが決まる前日からになる（[引退した予想の 07 の「時点ごとに使う特徴量」](../重賞の傾向と近走から3着以内を予想/07-prediction-timing.md#時点ごとに使う特徴量) と同じ）。
- いつから分かるかは、特徴量の一覧（`Feature.known_from`）に書く。時点のクラス（共通の `PredictionTiming`）は、時点の前後を答えるだけである。
- **買い目の確かめ（[16-evaluation.md の 6](16-evaluation.md#6-印からの買い目の確かめ)）は当日の予測で行う。** 本番で買うのは当日の予想だからである（今の買い方でも、確かめて買っているのは当日の予想だけ）。前日の予測は参考に同じ表を出す（[15-decisions.md の 13](15-decisions.md#13-買い目を確かめる時点)）。

## 予測のときのオッズの与え方

**手本とまったく同じである。** 利用者が `--odds 馬番:オッズ` で渡したオッズ → 元DB の締め切り前のオッズ（`jvstore realtime` で取り込む） → 無し（終わったレースなら確定オッズ）の順で決める。順序と理由は [手本の 07 の「予測のときのオッズの与え方」](../近走と適性から3着以内を予想/07-prediction-timing.md#予測のときのオッズの与え方) を参照。

```powershell
uv run python -m yosou.graded_race_top3_win predict 2026111506050811 --timing 当日 --odds 3:2.4 7:9.5 12:38
uv run python -m yosou.graded_race_top3_win predict 2025102605040811 --timing 当日
```

（1行目は、これから走る重賞の出走馬について、3着以内に入る確率と1着になる確率を出すコマンド。2行目は、終わった重賞を確定オッズで予測し直すコマンド。レースID は架空の例。重賞でないレースを渡すと「エラー:」の1行で止まる）

## 時点ごとにモデルを分ける理由

**手本と同じである。** 1つのモデルで済ませると、学習と予測でデータの様子がずれて予測確率が狂う。理由の説明は [手本の 07 の「時点ごとにモデルを分ける理由」](../近走と適性から3着以内を予想/07-prediction-timing.md#時点ごとにモデルを分ける理由) を参照。学習データは材料ごとに1つ作り、同じ材料の時点ではモデルに渡す列だけを変える（[08-training-data.md の 2](08-training-data.md#2-列の種類)）。

重賞は前日までに予想を立てて買い目を検討することが多く、木曜・前日の予測にも使い道がある。手本の決定（3つの時点すべて）をそのまま引き継ぐ。
