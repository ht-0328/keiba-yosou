# 12 LightGBM で学習・予測するための設計

**この文書で決めること:** 07〜10 で決めた学習データ（特徴量と目的変数と行の重み）を、LightGBM で学習・予測するために、LightGBM だけに必要なことを決める。**節の番号と題名は、手本の 12 とそろえてある。**

| 決めること | 結論 |
|---|---|
| 1. 学習データの渡し方 | 手本と同じ。**行の重みを、学習データは `sample_weight`、検証データは `eval_sample_weight` で渡す**（この予想で足す）。W の3個のカテゴリ特徴量は、ほかのカテゴリ特徴量と同じ渡し方 |
| 2. ハイパーパラメータの初期値 | **手本と同じ値**（学習の行が手本と同じだから）。早期終了は、重み付きのログ損失で見る |
| 3. カテゴリ特徴量の値の変え方 | 手本と同じ |
| 4.〜6. 学習・予測・保存の手順 | 手本と同じ。4つ（木曜・前日・当日・当日の券種オッズなし）× 目的変数2つで、8つのモデルを学習する。保存先は `reports/重賞に特化して3着以内と1着を予想/models/` |

- 用語の意味は [02-glossary.md](02-glossary.md) を参照。
- 学習データ・特徴量・目的変数・重みは CatBoost と共通で、[08-training-data.md](08-training-data.md)・[09-features.md](09-features.md)・[10-target.md](10-target.md) を参照。
- CatBoost の設計は [13-catboost.md](13-catboost.md) を参照。
- LightGBM の使い方の基本は [手本の 03 の「4. LightGBM の使い方」](../近走と適性から3着以内を予想/03-library-basics.md#4-lightgbm-の使い方)、重みの渡し方の例は [03-library-basics.md の「行に重みを付けて学ぶ」](03-library-basics.md#行に重みを付けて学ぶ) を参照。

## 1. 学習データの渡し方

**列の渡し方は手本と同じである**（数値はそのまま、カテゴリは `category` 型、出走の少ない値は「その他」にまとめる、ID 列と評価用の列は渡さない。[手本の 12 の「1. 学習データの渡し方」](../近走と適性から3着以内を予想/12-lightgbm.md#1-学習データの渡し方)）。この予想で足すのは次の行だけである。

| 列 | 渡し方 | 理由 |
|---|---|---|
| 行の重み（学習データ） | `fit(sample_weight=重み)` | 重賞の行を重く見て木を作る（[08-training-data.md の 4](08-training-data.md#4-重賞の行の重み)） |
| 行の重み（検証データ） | `fit(eval_sample_weight=[重み])`（検証データごとのリスト） | 早期終了が見る検証データの当たり具合を、重賞の行を重く見たログ損失にする。重みを渡さないと、早期終了は全レースの当たり具合で決まり、重賞の行の学びが足りないところで木が止まることがある |
| W の格・重量種別・前走の格 | `category` 型（ほかのカテゴリ特徴量と同じ） | 値は数個で、出走の少ない値を「その他」にまとめる線にはかからない |
| W の数値の 11個・K の 51個 | そのまま。欠損値も NaN のまま | 手本の数値特徴量と同じ |

前日・当日のモデルは、手本と同じく、オッズから作った基準を出発点にする（`init_score`・`eval_init_score`。木曜は基準なしで学ぶ）。予測（`predict_proba`・`predict`）には重みを渡さない。

## 2. ハイパーパラメータの初期値

**手本の初期値をそのまま使う**（`learning_rate` 0.05、`n_estimators` 2000、早期終了 100回、`num_leaves` 31、`min_child_samples` 100、`subsample` 0.8、`colsample_bytree` 0.8、`random_state` 42、`min_category_count` 2000）。値と理由は [手本の 12 の「2. ハイパーパラメータの初期値」](../近走と適性から3着以内を予想/12-lightgbm.md#2-ハイパーパラメータの初期値) と [「2000 にした理由」](../近走と適性から3着以内を予想/12-lightgbm.md#2000-にした理由) を参照。値は設定ファイルで変えられる（[14-hyperparameter-settings.md](14-hyperparameter-settings.md)）。

- **手本と同じ値にする理由:** 学習の行が手本と同じ（約70万行・約24万行）だからである。引退した予想は重賞の行（約2.5万行）だけで学んだので、木を小さく・正則化を強くしていたが、この予想ではその必要が無い。
- `min_child_samples` は、重みではなく行の数で数える（LightGBM の約束）。重み 5 の重賞の行が 20行あっても、葉の行の数は 20 である。重みで数える縛り（`min_sum_hessian_in_leaf`）は既定のままにする。
- 1 と 0 の数の偏りを直す設定（`is_unbalance`・`class_weight`）は使わない（[10-target.md の「1 と 0 の数の偏り」](10-target.md#1-と-0-の数の偏り)）。行の重みは `class_weight` ではなく `sample_weight` で渡す。
- 調整のやり方は [16-evaluation.md の 7](16-evaluation.md#7-ハイパーパラメータの調整のやり方) を参照。重賞の行の重みは、ハイパーパラメータの調整とは別に決める（[15-decisions.md の 2](15-decisions.md#2-重賞の行の重み)）。

## 3. カテゴリ特徴量の値の変え方（フローチャート）

**手本と同じである。** `LightGbmEncoder` が、騎手・調教師・父・父の父・母の父の値を変える手順は、[手本の 12 の「3. カテゴリ特徴量の値の変え方（フローチャート）」](../近走と適性から3着以内を予想/12-lightgbm.md#3-カテゴリ特徴量の値の変え方フローチャート) を参照。「その他」にまとめるかを数える出走数は、重みではなく行の数で数える（重賞の行を5回数えない）。

## 4. 学習のやりとり（シーケンス図）

**手本と同じである。** `TrainingWorkflow` → `LightGbmModel` → `LightGbmEncoder` → `LGBMClassifier` の呼び出しは、[手本の 12 の「4. 学習のやりとり（シーケンス図）」](../近走と適性から3着以内を予想/12-lightgbm.md#4-学習のやりとりシーケンス図) を参照。違うのは、`LightGbmModel` が `LGBMClassifier.fit` を呼ぶときに、学習データと検証データの重み（`TrainingData.weight`）も渡すことだけである。この流れを、時点ごと・目的変数ごとに1回ずつ行う。

## 5. 予測のやりとり（シーケンス図）

**手本と同じである。** [手本の 12 の「5. 予測のやりとり（シーケンス図）」](../近走と適性から3着以内を予想/12-lightgbm.md#5-予測のやりとりシーケンス図) を参照。`LightGbmModel` が返すのは、3着以内のモデルなら「3着以内に入る確率」、1着のモデルなら「1着になる確率」で、手本と同じである。

## 6. 保存

- 保存のしかた（`joblib.dump()` で、学習済みの `LGBMClassifier` とカテゴリの一覧を書き込む）は、[手本の 12 の「6. 保存」](../近走と適性から3着以内を予想/12-lightgbm.md#6-保存) と同じである。重みはモデルの中に残らないので、保存するものは増えない。
- 学習に使った設定（ハイパーパラメータと重賞の行の重み）を、モデルと一緒に保存する（[14-hyperparameter-settings.md](14-hyperparameter-settings.md)）。
- 保存先: Git の対象外の `reports/重賞に特化して3着以内と1着を予想/models/`（[04-classes.md の 3](04-classes.md#3-パッケージ構成)）。モデルは JV-Data から作ったもので、公開しないため。
